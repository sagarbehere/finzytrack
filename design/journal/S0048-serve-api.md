# S0048: Serve the API from the main sidecar

## Brief
- Goal: `app.main` serves `app.api.create_app` with uvicorn on the loopback socket it binds itself, in place of the stand-in `bind`/`serve` that answered 501 (BL-0105). The CLI args and the `FT_READY {"port","version"}` handshake stay as they are. The composition root builds the API's container: the app version, an `Ids` adapter (uuid7, `uuid-utils` as ARCHITECTURE §2.3 and §10 pin it), the `NoWorkspaces` gate (until BL-0102), and the `EventLog` as the container's log. Failure-modes M7's SIGTERM window is closed: no stop path (SIGTERM, SIGINT, a repeated signal, a signal at any line of the stop path, a server that fails) skips `engine.close()`, and uvicorn's own signal handling (it replaces the process's handlers while it serves, then restores them and raises the caught signals again) is checked against that. The acceptance harness checks that `/health` answers with the handshake's version before it announces a run; the M1a exit's `/health` timing during a 54k load is measured and recorded here.
- The cut (agent; each piece tied to its source):
  - **In:** uvicorn 0.54.0 (pinned in ARCHITECTURE §10) on a socket bound and listening before the handshake, so a connection made right after `FT_READY` is queued, never refused; uvicorn's logging, access log, lifespan, proxy headers, websockets and server header off (the structured log takes library records; the composition root owns start and stop; nothing proxies a loopback app); one stop handler owned by the composition root for the process's life, which only records the request and never raises, so nothing can cut the stop path between the server's end and `engine.close()`; the composition root's container; the harness's `/health` check; the e2e specs and backend tests that pinned the 501 placeholder; the measurement script.

Where the two meet, the built behaviour stays (the bounded `close()`, uvicorn's graceful wait for requests in flight) with a `TODO(BL-0109)`; the shell token and any guard on who may call the local API (see Open questions).

## Decisions
- **One stop handler that only records** (agent; failure-modes decision 6): `StopRequest` is installed for SIGTERM, SIGINT (and SIGBREAK on Windows) before the engine can start and never raises. S0038's handler raised `SystemExit`, and `signal.signal()` runs a pending handler before it changes the handler, so a SIGTERM landing at the line that switched to `SIG_IGN` left the `finally` before `engine.close()`. With a handler that cannot raise there is no `SIG_IGN` step and no window; the close sits in one `finally` that every path reaches.
- **uvicorn's signal handling is kept out** (agent; BL-0105 "uvicorn's own signal handling checked against it"): read in uvicorn 0.54.0's `Server.capture_signals`, it replaces the SIGINT/SIGTERM handlers while serving, then restores the old ones and calls `signal.raise_signal` for each caught signal. With the default handler restored that re-raise would end the process before the close; with S0038's raising handler it would raise into the stop path. `ApiServer` overrides `capture_signals` with a no-op; a test runs a real `ApiServer` in the main thread and checks the handlers stay the composition root's (it fails if an upgrade renames the method).
- **A second stop ends the requests in flight** (agent; found while writing the hand-off). uvicorn's `force_exit` only ends its own waiting loops; asyncio's `Server.wait_closed` (Python 3.12.1 and later) still waits for every open connection, so a handler that never returns held the process for ever, before the close (reproduced in the scratchpad: two SIGTERMs, process still running after 5 s). `ApiServer.shutdown` closes the open connections once `force_exit` is set, checking every 0.1 s (uvicorn's own shutdown tick, a poll interval, not a budget). Closing the connections is enough: `asyncio.run` cancels the handler's task with the loop's other tasks; cancelling the tasks as well was redundant (mutants F3 and F4 each survived alone), so only the close stays. The first stop still waits for requests in flight with no time limit (no fixed budget; the quit design of engine-jobs §9.3 replaces this rule, `TODO(BL-0109)`).
- **Socket bound and listening before the handshake** (agent): `socket.create_server` (SO_REUSEADDR on POSIX only, as the standard library decides; on Windows it would let another program take the port), passed to uvicorn with `sockets=[…]`. A client that connects right after `FT_READY` is queued in the backlog, never refused. `config.load()` runs before the handshake, so a configuration uvicorn refuses fails before `FT_READY`.
- **uvicorn settings** (agent): `log_config=None` (no `dictConfig`: library records reach the structured log through its root handler, which admits warnings and above; uvicorn's info lines are dropped by design, §6A.5), `access_log=False` (request logging arrives with the logging slice; an access log would write workspace keys from paths), `lifespan="off"` (the composition root starts and stops the engine outside ASGI, so the close does not depend on uvicorn running a lifespan; failure-modes decision 4 said the close might move into the API's shutdown: it stays in `main`'s `finally`, which also covers a server that never started), `proxy_headers=False` (nothing proxies a loopback app; never trust `X-Forwarded-For`), `ws="none"`, `server_header=False`, `http="h11"`, `loop="asyncio"`, no `[standard]` extras. No `timeout_graceful_shutdown` (it would be a fixed budget).
- **uvicorn imported only by `app.main`** (agent; ARCHITECTURE §2.2 puts uvicorn in the composition root); `uuid_utils` only by `app.platform.adapters.ids` (§2.3: adapters own outside libraries).
- **`Ids` adapter: uuid7 from `uuid-utils` 0.17.1** (agent; ARCHITECTURE §2.3 and §10 pin it). The stdlib has no uuid7 before 3.14; uuid4 would do for uniqueness but not for the time order the pin chose. Both dependencies were already pinned, so adopting them is not a stack decision. `h11` (MIT) and `click` (BSD-3-Clause) join the runtime closure through uvicorn; `licences.allow.toml` maps h11 0.16.0's trove name "MIT License" to `MIT` after reading its licence file; `THIRD_PARTY_NOTICES` regenerated.
- **`SidecarContainer`** (agent): a frozen dataclass in `app.main` implementing `ApiContainer` until BL-0102's `UserContainer`; not in `platform/state_registry.py`, since it holds no state (the `EventLog` it carries is registered). The stop request and the uvicorn server live in `main()`'s frame for the process's life; they are process lifecycle, not state across requests, and the registry's owners (`UserContainer`, `WorkspaceContainer`) do not fit them. Recorded here instead.
- **`stop_signals()` is a function** (agent): a module-level tuple built from a platform condition is "unknown module-level value" to the globals scan (INV-11); a function needs no allowlist change.
- **The harness checks `/health`** (agent; BL-0105 "the acceptance harness and the shell then see `/health` answer"): `launcher.probe(port, version)` refuses a run unless `GET /health` answers 200, in the envelope, `ok`, with the handshake's version (it accepted any status before). The shell's side is BL-0095 (no shell supervisor exists yet).
- **The measurement** (agent): `backend/scripts/measure_health.py` (report only, never fails). Run on this machine (Apple M4 Pro, 14 cores, macOS, Python 3.13.16), 54k demo ledger, probes on a new connection each, 10 ms apart, `bean-check --no-cache` loading the ledger five times in another process (1.5 s to 1.6 s per load). Two runs: idle median 1.66 / 1.63 ms, p99 3.51 / 5.58 ms, max 8.34 / 7.35 ms; during the loads median 0.78 / 0.55 ms, p99 1.00 / 0.94 ms, max 3.58 / 4.55 ms. All under the 100 ms target by more than 10 times. Unpaced probes gave a 0.26 ms idle median (power states: a paced probe finds an idle core). Without `--no-cache` the second load hit Beancount's pickle cache (0.41 s), which the engine never uses (ADR-0040), so the cache is off. Unpaced, the probes used up the loopback's ephemeral ports (EADDRNOTAVAIL) within seconds. Limit: the sidecar does no work of its own during a load yet; BL-0114 re-measures with mirror reads.
- **Security posture** (agent; inbox `20261028-local-api-callers.md`, BL-0115): serving the API makes it callable by any local program and, through CSRF and DNS rebinding, by web pages. Nothing is at risk while only `/health` is served; the guard is the owner's decision (rubric item 6) and blocks the first data route, not this slice.
- **Tests corrected while implementing** (agent; EP-29): the storm child first reported only the count of lines it hit; on the base the first handled signal raised inside the trace function, which turns tracing off, so the base failed for a weaker reason (one line). The child now records every line where a handled signal raised, and the test asserts none did: on the base it fails with `main:204:SystemExit` (start) and `_stop:189:SystemExit` (after serving). The after-serving storm test no longer probes `/health`, so on the base it fails on the window, not on the 501. The second-stop test gained "the connection is still open after the first stop" for mutant F2.
- **Deviation from ENGINEERING.md:** none.
