## Decisions
- **The save replayed through the engine, at the code's hooks** (agent): `engine/tests/ledger/test_save_conformance.py` runs each save of the corpus's worlds without boot journals through `ledger.save.run` over memfs (ports: the fake file system, ledger-set locks that report step 3, a fake observe and load reading the fake for steps 4-6, `job.gate()` and `job.committed()`), with the model's world 1 projected (`R` the root, replaced; `N` the include the first save creates and a later one replaces; `I` an include never written; value `v` of file `f` is `; f v`) and the plan in the model's order (`WOrd`: children first, root last; the code orders by the plan, so this is the caller's choice, as §6.1 step 8.3 says). Each file-system effect is classified to the model step it belongs to (`Driver.classify`; e.g. the staging file's create, write, data sync, the rename to the temp name and the folder sync are `S_TempStart`, `S_TempDone`, `S_TempSync`); at each hook the model is walked up to that step: outside edits written (durably), an engine death raised (`Crash`) or an I/O error raised before the effect (`OSError`), and the fake compared with the model's state just before its step (files, this save's record, its save and restore temps, its backup). A model step the code carries out without an effect (the displaced check, the read-back, `S_R4Check` with nothing owed, `S_Publish`, `RS_Sync`) is passed only if it changed nothing the view shows. The answer is compared with `gh.told`; after a death, `save.outcome`'s facts through `DISK` (the model's `DiskOutcome`). Rejected: replaying steps 1-7 on real APFS (the loader reads the disk; the injectable `Ports.load`/`observe` let the fake stand in, and the loader's own reading is `test_save.py`'s), and a step-by-step engine (the code runs one call; the hooks see it without changing it).
- **Where the model and the code differ, stop and count** (agent; the brief): `STOPS` names each (`swap_back`, `restore_swap_back`, `temp_rule`, `created_path`, `backup_check`, `r4_in_save`, `mirror`, plus `cut` and `after_stop`); a stopped save ends the replay of its trace. `backup_check` was found by the replay: an edit of a replaced file after the re-check is caught by the code's backup step (it reads and hashes the file, §6.1 step 8.1), while the model copies the plan's bytes unread and finds the edit at `S_Compare`; recorded on BL-0161 (the model should read the file at `S_Backup`). `test_a_stop_rule_fires_on_its_case_only` pins each rule against its neighbour that must be replayed.
- **Two mappings declared as equivalences, not stops** (agent): (1) the model's `RS_Temps` removes every name of ours at once after all restores; the code removes each file's as it settles it, root first (spec §8.1 step 3; a replaced file's save temp only after its pre bytes are back). Before `RS_Temps`, a code temp must equal the model's or be gone (`same`, `EARLY_RESTORE`); from `RS_Sync` on and at the end, compared exactly. (2) A save's `EngineCrash` ends the model's job and tells `DiskOutcome` with no engine; the code reads the outcome in a fresh engine: the replay calls `save.outcome` on the fake after the crash, and `test_the_outcome_after_a_save_death_is_the_models_disk_outcome` checks the sidecar's decision (`save.save_outcome`) against the model's told value for every crash the corpus has.
- **The corpus widened by branch** (agent; BL-0159): new worlds `S_close`, `S_cancel_bg`, `S_cancel_r4`, `S_recover_bound`, `S_recover`, `S_save`, `S_save_edit`, `S_save_edit_late`, `S_save_cancel`, `S_save_io`, `S_save_two`, `S_save_restore`, `S_save_late_crash`, `S_save_io_crash` (21 in all), steered by leave rules (`gen_traces.LEAVE`: an engine death only in a save, only past the commit point, only after the close, only in R4; edits only before or past the commit point; a second save only once the first ended and no R4 is owed; a Cancel only behind a background save or an R4; a closed tab only on a queued read); each still a behaviour of `Spec`. Guards are parenthesized in the trace module now (a guard with a disjunction failed to parse). Of the traces TLC walks for a world, those that add the most branches are kept (`select`, greedy, deterministic): the first long enough traces were alike, and a fault enabled at every step came early in each. Recover-all's death and its Cancel after the listing are no longer guarded out (`GUARDS`), and the queue replay maps them (the listing as `RecoveryListed`, a death or a Cancel after it as a fresh engine for the next journal, the unavailable branch as `EngineRefused` and the work's report).
- **The corpus format** (agent): the replays read files and records, so the corpus keeps them (`save_state`), only around saves (`prune`), and each trace as deltas (`delta`/`undelta`, copied into both tests, which may not import the generator): 1.3 MB instead of 4.4 MB. The reader reads functions (`:>`, `@@`) for the temps' tuple-keyed slots.
- **The code map** (agent; S0060's rule): the engine gets its own marker (`ledger_engine.tla`); marked: the save's `S_Locks`, `S_Gate`, `S_Load`, `S_Recheck`, `S_Commit`, `S_Saved`, the durable order's `S_Backup` to `S_CloseSync`, `RS_Write`, `RS_Swap`, `RS_Temps`, `RS_Sync`, `RS_Resolve`; `PARTIAL` with the row of the rest: `S_R4Check`, `S_Release`, `FreshEnd` (BL-0152), `S_Compare`, `RS_Compare`, `RB_Check` (BL-0161: only the branches the replay walks match the model); `PLANNED`: `S_Publish` (BL-0113), `S_WaitR4` (a seeded bug's action; BL-0152), `RC_*` (BL-0164, new). `S_Commit` leaves `PARTIAL` (the engine's `job.gate()` is marked and walked). The replay also asserts every ledger-set lock is released after each save (`S_Release`'s part).
- **Recover-all's tries through the engine left for BL-0164** (agent): the queue replay walks recover-all's branches; replaying `RC_*` and the restore on boot journals needs their records, backups and temps projected onto the fake, and the model's temp and created-path rules differ from the code's (BL-0161), so most boot-temp traces would only stop today. BL-0151 is closed with that row named.
- **The model-side DiskOutcome check** (agent): `test_the_disk_outcome_table_is_the_models` reads the model's `DiskOutcome` and `CL` lines, so a changed model fails it before `DISK` drifts.
