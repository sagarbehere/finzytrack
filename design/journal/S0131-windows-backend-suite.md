# S0131: the backend suite on Windows (M1b, BL-0290)

## Brief
- Goal: the whole backend suite runs on the Windows runner (`backend-windows` in `ci.yml`), each test passing or skipping with its reason, as S0127 did for the engine's suite. Today the job runs only S0129's tests; after this slice it runs `pytest` over all of `tests/`. Windows still refuses every file operation in the product until BL-0087: a test that needs the engine's write path skips there naming BL-0087, and each other skip names its reason from `tests/windows_pending.py`.
- **The `tzdata` item (BL-0290 kind 3): a fact checked at the brief changes it.** BL-0290 calls it "a product gap: the sidecar's civil dates need the `tzdata` package there". The code says otherwise: no module under `backend/src` imports `zoneinfo`. `app.domain.dates.civil_date` without a zone calls `datetime.astimezone(None)`, which reads the machine's zone through the C runtime (`localtime`), not through the IANA database; the system clock returns UTC instants. Only `tests/domain/test_dates.py` names zones (`ZoneInfo("America/Los_Angeles")`, `"Asia/Kolkata"`), and on Windows `zoneinfo` finds those only in the `tzdata` package. So `tzdata` is a test dependency today: it joins the `dev` group with the marker `sys_platform == 'win32'`, at ARCHITECTURE.md §10's pin (2026.5), and becomes a runtime dependency with the first product code that names a zone (ADR-0023's `today(tz, clock)` with the user's chosen zone; `pyproject.toml`'s rule: "runtime dependencies arrive with the slice that first uses each one"). A dev dependency is not bundled, so the licence check does not judge it; its licence (Apache-2.0, pending legal advice for the sidecar, ADR-0054) is the question of the slice that bundles it. ARCHITECTURE.md §10's row says so.
- Kinds of failure expected (BL-0290's inventory from the 2026-11-18 run 2, before S0129 landed; the first run of this slice re-takes it at the base):
  1. tests written in POSIX paths (`/L/...`, `/app-data/...`) that the sidecar's codec refuses on Windows since S0127: written on the host's path model instead;
  2. the engine's write path, refused on Windows until BL-0087: skip naming BL-0087;
  3. `tzdata` (above);
  4. the mirror's files: `test_files.py`'s rename over an existing name (`FileExistsError`), a URI path in `test_query.py`, `resource` in the query test;
  5. `test_main.py`'s sidecar-process tests (CRLF in stderr lines, the stand-in engines), the demo script's case rule, the TLA mapping scan's separators.
- **Product code:** none expected. If a failure shows a product defect on Windows (the sidecar doing the wrong thing there, not a test's assumption), it is fixed in this slice only when it is small and outside the write path; otherwise it becomes a backlog row and its tests skip naming it. A product fix here takes the review row "Other product code", with a fresh round after the fix.
- Implements: BL-0290; ADR-0061 and its amendment of 2026-11-14 (the Windows port); engine-jobs §15's test rule (each skip names its reason).
- Capabilities: none changes status.
- Invariants touched: INV-07 (the civil-date tests run on Windows, under `TZ=PST8PDT`), INV-24 (tests on scratch folders only), INV-23 (no runner path or run ID in the repo).
- Risk class / lane: Low / light: tests, CI and a test-only dependency. **Review budget row: "Tooling, gates, measurement"** (one verifier round; the fix round fixes only the stop rule's (1)-(3)). Why not "Other product code": the slice changes no product behaviour (above), and the dependency is a test dependency, not a runtime one. Should a product fix be needed, that part takes "Other product code" (above).
- The bytes it protects: none (no write path changes).
- Mechanism questions (PROCESS.md §3 step 2): no mechanism is added or hardened: each change makes a test run on Windows' path model or names why it cannot run there.
- What the check is a second opinion on (S0122's lesson): the Windows job is a second opinion on the sidecar's OS-dependent code (paths, the codec, the mirror's files and URIs, process I/O) that the macOS and Linux jobs exercise only in POSIX form. A test that skips on Windows is no opinion at all, so every skip names a reason that says which other test or row covers the same rule.
- Acceptance:
  - `backend-windows` runs the whole suite (`pytest -q -rs tests`) and is green; every skip there prints a reason from `tests/windows_pending.py` that names BL-0087, a POSIX-only rule with its Windows counterpart, or another open row;
  - `test_dates.py` runs on Windows with `tzdata` (it fails on the base with `ModuleNotFoundError: tzdata`);
  - the tests rewritten from POSIX paths pass on macOS and Linux unchanged in what they assert (no expected output changes except a path's spelling);
  - `pyright_platforms.py` 0 errors on Darwin, Linux and Windows; the macOS gates green; every other CI job as before (`engine-windows` red on exactly INV-03's five, BL-0282: "keep red").
- Expected doc impact: `ci.yml` (the job's comment and command); `backend/CLAUDE.md` (the Windows note: the whole suite runs there); `tests/windows_pending.py` (its reasons); ARCHITECTURE.md §10 (tzdata's row: a test dependency until first product use); BL-0290 closed; new rows for any product gap found.
- Open questions: none blocking. The `tzdata` reading above departs from BL-0290's wording and from the session's framing ("one new runtime dependency"); it is reported to the owner with the slice.
- Base: 668e64f9.

## Decisions
- **`tzdata` as a test dependency on Windows, not a runtime one (agent; facts above).** The product reads no IANA zone; a runtime dependency with nothing using it would fail `deptry`'s unused-dependency check and break `pyproject.toml`'s rule.
- **The 2026-11-18 run 12** (head fc17204a, the brief and `backend-windows` on the whole suite; the base): `backend-windows` 154 failed, 2802 passed, 68 skipped, 16 errors; `engine-windows` exactly INV-03's five (BL-0282); every other job green. By cause:
  - **POSIX paths the codec refuses on Windows** (about 110: `test_engine_protocol.py`, `test_recover_all.py`, `test_save_job.py`, `test_preview_job.py`, `test_rebuild_job.py`, `test_copy_job.py`, `test_create_job.py`, the API code tests): literals such as `/L/main.bean` and `Path("/app")` (which is `\app` on Windows) and the contract's examples. Fix: `tests/host_paths.py`, `host("/L/main.bean")` (unchanged off Windows, `C:\L\main.bean` there) and `hosted(...)` over the contract's examples, which the schema accepts in both spellings. A tokenize pass wrapped only plain double-quoted absolute literals, never text inside another string (the fingerprints' embedded JSON) or the lower-case ledger keys the sidecar compares itself.
  - **The promotion guard (a product defect, fails closed):** `writes._inside` uses `posixpath.commonpath`, so on Windows every test copy's file is outside its copy and every unpromoted confirm is refused (27 cases of `test_writes.py`, over the fake engine). On the write path, so not fixed here: BL-0295, before BL-0087; the cases where the guard must pass skip naming it, its refusals run.
  - **Texts that cut a path at `/` (a product defect, wording):** `save_text`, `recovery_text` (the name and the folder), `create_text` and `app_folder.refusal_text` named a file by its whole Windows path, and the app folder's parent as `/`. The tests had passed on Windows only because their POSIX paths matched that cut. Fixed here (below).
  - **CRLF in the engine's stderr lines** (a product defect, log text): `_pump_stderr` stripped only `\n`. Fixed here.
  - **The write path through the real engine** (`test_writes_end_to_end.py`, 16 tests and their setup errors: the venv's interpreter looked up at `bin/python`): skip on Windows naming BL-0087; the producer scan and the shipped-engine check run.
  - **No SIGTERM on Windows** (`test_main.py`, 4 tests asserting a graceful stop: exit 0 and `engine.closed`): `terminate()` is `TerminateProcess`. No row covered the sidecar's stop on Windows: BL-0296 (M2), and the tests skip naming it; six older skips there said "Windows is the manual CI run", untrue from this slice on, and now name their reason.
  - **Single causes:** `tzdata` (3, `test_dates.py`); the link-form pin (`mirror/test_files.py`; Windows' pointer form is `test_pin_windows.py`); `resource` (3 query probes); `?` in a Windows file name (the URI test: the name keeps `#` and `%` there); `SYSTEMROOT` missing from the measurement scripts' bare environment (`asyncio` cannot load Winsock); the TLA scan's `\` separators; `site.getsitepackages()` listing the prefix on Windows, which the report drops by S0114's rule (the self-check's expectations); `chmod(0o311)` (permission bits); `BUILD/` resolved to `build/`'s own spelling (the demo script).
- **The product part (agent; the brief's rule).** The texts and the stderr line are small, pure and off the write path's mechanics: fixed here, through one cut, `app.platform.engine_paths` (`last_name`, `folder_of`, by this OS's separator, macOS and Linux byte-identical to before), with both OSes' cases tested everywhere (`tests/platform/test_engine_paths.py`). That part takes the review row **"Other product code"** (verifier; a fresh round after any later fix that changes product code); the rest stays "Tooling, gates, measurement". The guard (`_inside`) is a write-path check, so it is BL-0295, reviewed with BL-0087's turn-on and its data-safety red team.
- **The 2026-11-18 run 13** (head 0ab56f10): `backend-windows` stopped at collection: `test_copy_job.py`'s module-level manifest raised `InvalidWorkspacePath` on `C:\data\ledgers\Main Books.beancount`. A third product defect of the same family: `creation.copy_manifest_files` cut the source root's name with `PurePosixPath(...).name`, the whole path on Windows, so no copy could start there (a refusal, never a manifest with a wrong name).
- **The guard and the manifest fixed here after all (agent; supersedes the guard's line above).** Read again, the review budget puts a corrected path rule in an existing write-path check under **"Hardening an existing write path"**: the verifier, with the data-safety red team joining at an (a) finding, and a fresh round after any later product fix. That costs less than carrying both into BL-0087, and leaving them would keep most of `test_writes.py` and all of `test_copy_job.py` off on Windows. `writes.is_inside(folder, path, platform)`: on Windows `path == folder` or `path` starting with `folder` and `\`, exactly (case, the other separator and a long-path prefix are outside: refused); on POSIX unchanged. `copy_manifest_files` uses `engine_paths.last_name`. Both OSes' cases run everywhere (`test_inside_the_copy_is_judged_exactly_as_the_os_spells_paths`, 15 cases; `test_the_copys_manifest_names_the_roots_file_as_this_os_cuts_its_path`). BL-0295 is done in this slice; the `GUARD_PATHS` skips are gone.
- **The 2026-11-18 run 14** (head 273f0390): `backend-windows` 41 failed, 2729 passed, 82 skipped, 1 error, in 59 of the job's 60 minutes (6 at the base). By cause:
  - **My tokenize pass also wrapped three URL routes** (`/api/test`, `/job/{name}`, `/contract/{name}`) in the API code tests: `A path prefix must start with '/'` (22). Unwrapped; every other wrapped literal checked to be a file path.
  - **Expected texts spelled with POSIX literals** (`/u/Books`, `/L`, `/app/...`) or cut with `MAIN.rpartition('/')`, the old product rule, while the product now names this OS's path (18 in the save, create and copy texts): the expectations name `FOLDER` and `host(...)`, and the file by its name.
  - **INV-07 east of UTC** (`test_dates.py`): the `kolkata` fixture raised on Windows on purpose ("it fails, never passes"), since Windows cannot move the zone inside a running process. Now the same checks also run in a child started with `TZ=IST-5:30` (UTC+5:30 in both the POSIX and the C runtime's form; the child first asserts its zone, so an ignored `TZ` fails), on every OS, inside the one test: in-process where the OS can move its zone (macOS, Linux), and the child everywhere. No skip, since INV-07's file may not switch a test off (the invariant check refused a first version that skipped the in-process form on Windows, caught by the Stop hook before the push gate).
  - **The 55-minute gap** fell in the last progress line, which has no failure: a test near the end of the order (`tests/workspaces/`) is slow on Windows but passes. `--durations=25` is added to the job to name it.
- **The 2026-11-18 run 15** (head 8c2bd16e): `backend-windows` **2771 passed, 82 skipped, 0 failed**, but in 59 of the job's 60 minutes. The verbose log's timestamps named the slow case: `test_measure_scripts.py::test_measurement_script_runs[measure_health.py]`, about 53 minutes (no single test in `--durations` took over 35 s). A tooling defect: `measure_health.py` ran `engine/.venv/bin/bean-check`, which on Windows is `Scripts\bean-check.exe`; its loader thread died before setting `done`, and the probe loop ran on until something else ended it. Fixed: the checker's path per OS, and `done` set in a `finally`, a checker that cannot start recorded as a failed load (the measurement then refuses, "nothing was measured").
- **The 2026-11-18 run 16** (head 7f66365a): `backend-windows` 1 failed, 2961 passed, 102 skipped, in 4 min 45 s; `engine-windows` exactly INV-03's five (BL-0282); every other job green. The failure: `test_the_shipped_engine_has_no_producer` keyed the engine's sources by `str(relative_to)` (`\` on Windows); now `as_posix()`. **35 skips named only `TZSET`** (`test_open_job.py`'s zone fixture), with no Windows test of the same rule: the fixture wants Los Angeles, and on Windows the whole process already runs there (`PST8PDT`, set before Python starts, checked by `test_runs_west_of_utc.py`), so it now keeps the process's zone there instead of skipping. `TZSET` is gone from `tests/windows_pending.py`.
- **The 2026-11-18 run 17** (head 1f3647f3): `backend-windows` 5 failed, 2992 passed, 67 skipped; `engine-windows` INV-03's five. Four were `test_open_job.py`'s, which now ran on Windows for the first time and had never had the host-path pass (its literals now `host(...)`). The fifth, the producer scan, imported every engine module but `ledger_engine.fs.posix`, the POSIX adapters' shared code, which refuses to import on Windows: it is left out there as the other OSes' adapters are, and the child's stderr now reaches the assertion.
- **The 2026-11-18 run 18** (head 97f4eafe): **`backend-windows` green**, 2997 passed, 67 skipped, 23 xfailed, in 4 min 34 s; `engine-windows` exactly INV-03's five (BL-0282, "keep red"); every other job green. The slice's acceptance holds on the runner.
