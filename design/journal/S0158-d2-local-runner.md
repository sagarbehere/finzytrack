# S0158: The D2 runner on copies of the owner's ledgers (local tier)

## Brief
- Goal: one command the owner runs to check D2 on copies of their real ledgers: the engine's overlay load gives exactly Beancount's own result (roadmap §4 M1b Exit: "D2 equivalence also on copies of your ledgers (local tier)"; ADR-0046: "D2 equivalence exact on every corpus ledger and real-ledger copy ... stay M1b exit criteria"). Today D2 is checked only on the repo's corpora (`engine/tests/ledger/test_overlay.py`, `test_parity_corpus.py`, both through `tests/ledger/parity.same`).
  - **What it compares:** per ledger, in a fresh process, the overlay load with no candidates and with every file's disk bytes as candidates (the two checks of the corpus tests that read only; the third, the round trip, writes and is left out), each against Beancount's own load of the same root. The comparison is the corpus tests' (`parity.same`), made countable: `parity.differences` gives counts by kind (entries, errors, options) and `same` asserts on the same normalized values, so the two cannot disagree.
  - **Beancount's own load without the pickle cache:** `loader.load_file` reads a `.picklecache` file beside the root (a pickle, which runs code), writes one when the load takes over a second, and deletes it when the cache is switched off. The runner calls the loader's `_load` (what `load_file` runs after the cache step) and never decrypts.
  - **Reads only inside `FT_LOCAL_TIER_DIR`:** the oracle harness's rule (`scripts/oracle/copies.py`: `local_tier_dir`, `refuse_local_tier_source`) is reused, with a new keyword that turns off its exception for the repo's `corpora/` (this runner reads no repo ledger). Each root given must be a file inside the tier; then the overlay load runs under a confining `LoadPolicy` that refuses any file, `pythonpath` folder or documents root outside the tier before it is read, and Beancount's load runs only after the overlay load was allowed (it follows the same includes).
  - **Writes nothing beside the copies:** no mirror, no cache, no pickle, no bytecode (`sys.dont_write_bytecode` and `-B` in the child, `PYTHONDONTWRITEBYTECODE` in its environment).
  - **Output:** counts, case IDs (L1, L2 … in argument order) and verdicts only: EQUAL, DIFFERENT (with the kinds of difference as counts), REFUSED (with a generic reason, no path) or ERROR. Never an amount, account, payee, narration, file name or path. Exit 0 when every ledger is EQUAL, 2 when any input is refused, else 1.
- Implements: ADR-0010 guardrail 1 on real-ledger copies, ADR-0046 (M1b exit), ADR-0043; PROCESS.md §6 T-local row, §8 (real-ledger copies print counts and case IDs only); INV-23, INV-24.
- Capabilities: none (tooling of the local tier; no capability row).
- Invariants touched: INV-03 (parity; the comparison is shared), INV-23 (output), INV-24 (reads only copies in the T-local folder).
- The bytes it protects: none (a read-only check). It guards real data and privacy: what it reads (inside the T-local folder only) and what it prints (counts only).
- Real setup / policy: the owner's copies of their own ledgers, which may use plugins and includes; a ledger reading outside the T-local folder is refused (policy: copy the whole ledger into the folder). Family history: the oracle's copy guard (S0030) had one verifier fix (F3, other spellings of a folder); not two rounds.
- **Review row:** tooling that reads real-ledger copies, a guard of real data and privacy (INV-23, INV-24): the verifier only, with a fresh round if a fix changes the guard (PROCESS.md §3 review budget).
- Risk class / lane: Medium / light (reads only; no ledger write, no finance meaning).
- Acceptance tests (each fails on base ef4cf0d6):
  - `engine/tests/ledger/test_d2_local.py`: corpus ledgers copied into a temp T-local folder give EQUAL, exit 0, a plugin ledger among them; nothing is written in the T-local folder (tree and bytes unchanged, no `__pycache__`, no `.picklecache`); a deliberately different overlay result (monkeypatched) gives DIFFERENT with its kinds counted, exit 1, and no account, amount, narration, file name or path of the ledger in the output. Must-not-pass, each exit 2: `FT_LOCAL_TIER_DIR` unset; the T-local folder set to the repo; a root outside the T-local folder; a root inside the repo; a root that is a link out of the folder; a ledger whose include or documents root lies outside the folder (refused by the policy, Beancount's load not run), a file a plugin adds to the includes outside the folder (never read), the policy's three questions; a plugin that prints every entry on both outputs (none of it in the run's output); a child's answer carrying any other kind, reason or value (ERROR, never echoed).
  - `engine/tests/ledger/test_parity_differences.py`: `differences` is empty exactly when `same` passes, and counts each kind; the uncached load equals `load_file`.
  - `scripts/tests/test_oracle_copies.py`: `refuse_local_tier_source(..., allow_repo_corpora=False)` refuses the repo's `corpora/`.
- Expected doc impact: roadmap §1 (the D2 runner exists; the owner runs it); PROCESS.md §6 T-local row names the tool; `engine/CLAUDE.md` (the runner beside the parity comparison); the script's docstring holds the exact command. User docs: none.
- Open questions: none on the rubric.

## Decisions
- **The comparison is shared, not copied** (agent): `parity.same`'s comparison moved into `_comparable` (entries as they are, errors by type, source and message, options key by key with `dcontext` by its text); `same` asserts on it (pytest still shows the diff) and `differences` counts on it, so the runner and the corpus tests cannot disagree on what "equal" means. No price-map kind: Beancount builds the price map from the entries, so equal entries give an equal price map.
- **Beancount's load without the pickle cache** (agent): `loader.load_file` reads a `.picklecache` beside the root (unpickling runs code), writes one when the load takes over a second, and with the cache switched off deletes it. `parity.beancount_load` calls `loader._load` (what `load_file` runs after its cache step; the loader stub already declares it) and refuses a file Beancount would decrypt. Its equality with `load_file` on four corpus cases is a test. Not `beancount_port.real_load` (V1-6), though the boundary would allow it: the overlay and `real_load` both live in the engine's port (its decimal context, its decryption and recording swaps), so an oracle built on `real_load` would share any fault of the port with the load it judges; the oracle stays Beancount's own `_load` plus the one swap the run needs (never decrypt). The cost is about fifteen lines.
- **The runner lives in `engine/scripts/` and imports the engine's tests** (agent), as `gen_mirror_checksums.py` does: `engine/scripts` may not import `beancount` (`check_engine_boundary.py` rule 2), `engine/tests` may. The oracle's copy rule is imported from `scripts/oracle/copies.py` (standard library only), not re-implemented; it gains `allow_repo_corpora=False` (default unchanged for the harness), because this runner reads no repo ledger.
- **Pyright's `extraPaths`** (agent; the pinned config in `tests/architecture/test_type_gate.py` changed with it): `["src", "../scripts/oracle"]`. `src` is the root pyright assumes only while no extra path is set (without it, `ledger_engine` resolves as an installed library and dozens of private-import errors appear); the oracle's folder types `copies`. Paths only: no check is loosened. Found on the way: pyright resolves `beancount.parser.booking` from its source instead of the stub when a file that imports `beancount.parser.options` or `parser` (no stubs) is checked before `tests/architecture/test_load_rule.py` (on base too: `pyright tests/ledger/test_parity_corpus.py tests/architecture/test_load_rule.py` gives 2 errors). The full run is clean as long as no top-level `tests/test_*.py` imports `tests.ledger.parity`, which is why the runner's test is `tests/ledger/test_d2_local.py`. Not a gate gap of this slice (the full run, which the gates use, is clean); a stub for the two modules would end it.
- **Input: root files as arguments** (agent), the simplest form for a non-developer: no manifest to write, and the folder rule needs no separate `--ledger`: the T-local folder is the boundary, and the policy confines every read to it. Case IDs are the argument order.
- **Every input is checked before any ledger is read** (agent): one refused root stops the run with exit 2 and "nothing was loaded".
- **Three loads per ledger, in a fresh process** (agent): the overlay with no candidates (under the confining policy, first, so a ledger reading outside is refused before Beancount reads it), Beancount's, the overlay with every file's disk bytes as candidates (the corpus tests' second check; their third, the round trip, writes). Between the loads, `parity.fresh_plugins(tier)` drops modules imported from the folder, as the corpus tests do. The candidates come from Beancount's `include` list, which a plugin can extend, so each is checked against the folder before it is read.
- **What the child may say** (agent): its answer is one JSON line on a duplicate of its standard output, made before both outputs are pointed at the null device; the parent decodes it field by field (verdict, counts, known kinds, known reason) and turns anything else into ERROR, so no text from the child or a plugin can reach a printed line.
- **Encrypted ledgers are REFUSED (exit 2)** (agent): the overlay refuses them by design (ADR-0059) and the runner never decrypts, so there is nothing to compare. The overlay refusing a ledger Beancount loads (`beancount-failed`, `number-failed`, `not-reached`) is DIFFERENT (`plain.refused`); Beancount's own load raising is ERROR with a fixed reason.
- **The strict plain-copy rule** (owner, 2026-11-26, in session, after round 2's High). Offered: "the runner accepts only a plain, self-contained copy (made with cp -RL). Any symlink at all, any file with a second hard link, any folder it can't list or file it can't read, any include or documents path that is absolute or has '..', any `option "include"` → the whole run is refused with a fixed reason, nothing loaded; every error during the check → refused, never a crash. Simpler code than today's (no link resolving). Cost: a ledger that uses absolute or '..' includes is refused; you'd edit those lines in the copy. One more verifier round." Owner: "Strict plain-copy rule (Recommended)". Implemented as `refuse_tree` (round-2 fix): it replaces round 1's link resolving, lexical and physical joins and glob-prefix logic, all deleted (EP-30). Every `option "include"` refuses the run whatever its value, as the accepted text says ("any `option \"include\"`"), with its own fixed reason `option-include` (write it as an `include` line in the copy); the coordinator relayed the correction after 728dda51 had judged it like an `include` line. Also refused: a path starting with `~` or `$`, a backslash anywhere (Beancount's escapes, Windows separators), a drive letter, and anything that is neither a file nor a folder. The tier's own path may be spelled through a link (`/tmp` on macOS); nothing below it may.
- **PROCESS.md §6 T-local row** names the folder variable and the two tools (descriptive; no rule changes).
