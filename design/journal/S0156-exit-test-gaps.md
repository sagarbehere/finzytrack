## Decisions
- **`check_invariants.py` counted only files whose every parametrize is a non-empty literal list** (agent; superseded in round 1 by V1-2, below; found while marking the lines, not stated on BL-0022): `test_contract.py`'s refusal cases are typed lambdas held in names, and `test_writer.py`'s sweeps are parametrized from effect counts (`range(len(clean_run()...))`), so neither file can be named in backticks on an Enforced-by line. Not changed in the checker (a gate's rule, outside a test slice). Instead: (1) the prepare's per-step fault tests moved, unchanged but for a literal step list pinned to `FAULTS` and `contract.STEPS`, to `engine/tests/ledger/test_contract_faults.py`; (2) the gate's fault list written in the decorator; (3) `test_save_outcome.py`'s `CHAIN` and `test_create.py`'s and `test_copy.py`'s `_FOREIGN_AT` parametrizes written as literal lists of the same values; (4) `test_contract.py` (each refusal, the D1 corpus) and `test_writer.py` (every effect's crash, I/O error and power loss) named without backticks as "not counted here", with the reason, as INV-04's and INV-05's lines name their macOS-only files. Their guard is real (they run in every pre-push), and the engine's pytest configuration fails an empty parameter set at collection (`empty_parameter_set_mark = "fail_at_collect"`), the static rule's purpose; they are just not in the `--ran` proof. Rewriting `test_writer.py`'s sweeps as loops in one test body (as `test_publish_crash.py` does) would put them in the count, at the cost of per-effect test ids; not done here.
- **INV-01 marked `enforced`** (standing rule, owner, 2026-11-09, IMP-0057; BL-0001's row and roadmap §1 planned it for this point). What exists today, by behaviour: the prepare (steps 1, 2, 2b, 3), the confirm's acknowledgement and promotion guard, the save's gate (step 4), the durable order with backup, journal and read-back, recovery, and the create's and copy's own steps (engine-jobs §8.2 applies the contract's checks to every file of a new folder). Each has tests that run in pre-push. Not built: no mutator is registered (`preview.PRODUCERS` is empty in the shipped engine) or promoted (`PROMOTED` is empty), so the per-mutator oracle comparison and each mutator on the D1 corpus are listed as planned under BL-0001 (M3).
- **INV-22's line dropped `test_writer.py` from the count but named it** (agent; superseded in round 1, V1-2 and V1-3: it is counted, with `test_restore.py` and `test_recover_all.py`): the writer's effects are not validators; its rollback on an I/O error is INV-01's atomicity. The checks a fault can hit before any write (the contract steps, the gate, the use-case steps) are each in a counted file.
- **BL-0277 (2)'s case is a unit case of `handles.move` and `keep`, not a save** (agent): in SWAP mode the writer places a created file with `rename_excl` directly (`writer._replace`), never through `move`; SWAP mode reaches `move` only through `keep` (an outside save met at a temp name, `writer`, `restore`), and on such a volume the staging rename (`_stage`) raises `NotOffered` first. So no save over the fake reaches the line; the fake's new form (`outside_excl_refused_at_use(..., swap=True)`, with a self-test in `test_memfs.py`) and the two direct calls are the cheapest honest case.
- **BL-0195 fixed by the row's test-only hook** (agent; IMP-0075: a Low (c) is fixed or dropped, never a new row): `backend/tests/platform/held_leaders.py` wraps `PosixGroupOps.wait_leader` and `reap` for each test of `test_engine_client.py` (an autouse fixture); a hang path signals under the same lock and only a leader still held. No product code changes. Left as it was: the `finally` of `test_close_returns_while_a_call_waits_on_an_engine_our_signal_cannot_end` (`Unendable`: its drain never reaps, so the leader is always held there) and the signals sent to a running engine at a test's start (no wait before them).
