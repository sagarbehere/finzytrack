## Decisions
- **BL-0271: wording, not putting the plan back** (agent). The row's other option (the gate's refusals return the plan to the store) changes what a later confirm does, which is a write-outcome change with a red team; the wording option makes the safe path (a new preview) the one the user is told. "Preview it again" is always safe after a confirm's `WARMING`: from the workspace gate the plan was never taken, from the save's gate nothing was written. `PLAN_ALREADY_CONFIRMED`'s own text stays: "already sent to be saved" is still true after the gate's refusal.
- **BL-0271: one text for every caller** (agent). The registry has one next step per code; `WORKSPACE_NOT_READY` is also the answer of every gated route (reads) and of the preview. The new next step keeps "Wait a moment and try again." first and adds "If you were saving a change, preview it again." A per-caller text would need a second code or a text keyed by details, which is more than a class (d) row is worth.
- **BL-0278: no system message** (agent). The option says "plus the system's message"; this refusal has none: macOS answers a capability bit and Linux a refused `renameat2` flag (`NotOffered`), and the engine sends no `detail`. The cause is known exactly (the volume has no exclusive rename), so the text says it in plain words.
- **BL-0278: the next step is "Copy the diagnostics and report a problem."** (agent). No OS-specific how-to and no setting to move the folder (the owner's option), but refuse first (IMP-0075) asks that a refusal tell the user what to do, and a report is how a user asks for the accommodation refuse first waits for. The registry's existing wording is reused.
