# S0053: The engine job queue's decisions, the engine lock, and the model's code map

## Brief
- Goal: the first verifiable piece of BL-0109 (the engine-jobs slice; `design/specs/engine-jobs.md` draft 5 with simplification B, ADR-0064 and its amendment of 2026-10-28; checked by `formal/tla/engine-jobs/`). It builds the decisions every later piece runs through, and the one cross-session guarantee that needs no job to exist:
  - **The queue table** (spec §3, §4, §5.1, §5.2, §12): `app.platform.engine_jobs.queue`, a pure `transition(policy, state, event) -> Step(state, effects)` with no clock, environment or global, carrying a `TABLE_VERSION`. It decides: dispatch (the oldest queued waited-for job, else the oldest background job; a running job is never interrupted), one job and one engine at a time (a new engine only once the previous one has ended and its group is drained, and only once the sidecar has waited out the engine lock), an engine reused only after parse-only work and retired after a job that ran user code, `WORKSPACE_NOT_OPEN` for a job of a workspace that is not open, `ENGINE_QUEUE_FULL` beyond `max_queued`, at most one queued `r4` and one queued background save per workspace, the switch's exclusive window (only its own jobs start), Cancel of a queued job with **the one rule** for the job running ahead of it, Cancel of a running job by its own requester, a client that goes away, **the commit-point step** (`gate` → `proceed`, or "too late" after it), and the quit advice on the timer only for a process we signalled that has not ended or for the engine lock held by an earlier session. Every mechanism names its spec line in the code.
  - **The engine lock** (spec §5.1, §5.5 bullet 6; ADR-0064 amendment of 2026-10-28): every engine started with `--engine-lock PATH` takes a whole-file `flock` on it after its handshake and before it reads any other request, and holds it for its life; the sidecar waits for the lock at start, before its first engine, and releases it at once (`app.platform.adapters.engine_lock.wait_engine_lock`, called by `EngineBoot.run` before the first start). The composition root names `app_local_data/locks/engine.lock`.
  - **The model's code map** (ADR-0050; ARCHITECTURE.md §8.3 "Code mapping"): a no-op `@tla_action("…")` marker (`app.platform.tla`), placed on the queue's functions that carry out `Dispatch`, `AdviceTimer`, the commit-point step (`S_Commit`, `CR_Commit`, `CP_Commit`) and the app's side of `UserCancelQueued`, `UserCancelRunning` and `UserCloseTab`; and a two-way check (`backend/tests/architecture/test_tla_mapping.py`): it parses `Next` of `EngineJobs.tla` and every marker in `backend/src` and `engine/src`, and fails on a marker that names no action, on an engine or app action that has neither a marker nor a row in the planned list, and on a planned row whose action is already marked or whose backlog ID is not open. The planned list names, per action, the backlog row of the piece that builds it, so the list shrinks to nothing as BL-0109's pieces land.

## Decisions
- **The cut, against the suggested first piece** (agent): the suggestion put the §5.5 client changes in this piece. They move to piece 2 (BL-0150) because they are one coupled change: dropping the time limits removes `TimedOut`, `start_timeout` and the `longest_*` bounds from the statechart, the client, the self-check, the acceptance launcher, failure-modes E2/E6 and `check_retired_terms.py`'s `AFTER_ENGINE_JOBS` together, and `Cancelled`/`Retired` only mean something once a shell feeds the queue's `EndEngine` to the client. The table is verifiable without them (exhaustive and property tests), and the engine lock is the one cross-session guarantee that needs no job.
- **The table has no holder yet** (agent; INV-11): `queue.py` is pure and stateless at module level, so nothing joins `platform/state_registry.py` until piece 2's shell holds a `QueueState` in the user container.
- **One `Cancel(job_id)` event for queued and running jobs** (agent): the requester does not know whether its job has started; a Cancel that races the dispatch lands on the running job by the same rule. The two halves carry the model's `UserCancelQueued` and `UserCancelRunning` markers.
- **The commit point is the event order on the one scheduler thread** (agent; spec §4 "a Cancel arriving in the same step as `gate` wins"): a Cancel processed before the `Gate` event ends the engine, so the `gate` that engine may still send finds no running job (or a slot not `busy`) and changes nothing; after `Proceed` the Cancel is `TooLate`. A `gate` from an engine being ended (slot not `busy`) is ignored too, so a stale `gate` can never turn the user's Cancel into "too late" (mutant Q15's test).
- **A crashed engine is drained before the next one starts** (agent; spec §5.2 "drain before the reap", §5.1): `EngineDied` leaves the slot `ending` with `EndEngine("crashed")`, as for our own ends. The model frees the slot at the crash (`CrashEng`); the code is stricter, never looser: a plugin child of the dead engine can still hold a lock.
- **An ask for a fresh engine is kept even while the old engine runs** (agent; found by mutant Q22, which survived the first run because dropping the "slot busy" guard only made the table more robust): `EngineNeeded` sets `wants_engine` whenever the job runs; the dispatch starts the engine once the slot is free. A guard that ignored an early ask could leave a job waiting for an engine nobody starts.
- **The advice timer carries an epoch** (agent; §5.2, N3): every new `ending` slot (and the boot's lock wait) arms a timer with a new epoch, and a timer from an earlier process shows nothing; the advice is cleared only when nothing holds the slot or the lock.
- **`max_queued` bounds every job, the switch's own included** (agent; spec §3 makes no exemption). Whether a full queue may refuse a switch's `recover_all` is left as a test of the switch piece (noted on BL-0154); `max_queued` defaults to 64 and the queue is empty at boot.
- **Recover-all's Cancel ends the job in this piece** (agent): its per-journal continuation (§8.1) needs the save piece's recovery; `TODO(BL-0151)` in `_cancel_running`, and `UserCancelRunning` is in the code map's `PARTIAL` list for BL-0151. Nothing submits a `recover_all` in the product yet.
- **The engine takes the lock after its handshake reply, before it reads the next request** (agent; spec §5.1 "after its handshake and before any ledger work"): so the handshake (and the protocol check) is never held by an earlier engine, and no request is served without the lock. Opened with `os.open` (non-inheritable on exec, inherited on fork), as the ledger-set locks will be (piece 3). The packaged self-check passes no lock: it does no ledger work.
- **Windows: no engine lock yet** (agent; recorded gap): `fcntl.flock` is POSIX; on Windows both sides return at once with `TODO(BL-0087)`, where the spec puts Windows' write path (§15, M1b). Nothing writes a ledger before M1b.
- **The code map** (agent; ARCHITECTURE.md §8.3): the required set is `EngineStep` ∪ `AppStep` ∪ {`AdviceTimer`} (MAPPING.md §1.2 lists `AdviceTimer` among the app's actions, though the model puts it in `EnvStep`); actions are read as the disjuncts of each step (a bare `\/ A` or `\/ \E x \in S : A(x)`), intersected with the model's operator definitions. `PLANNED` (51 actions, each with the BL row of its piece) and `PARTIAL` (9 marked actions whose rest is planned) live in the test, so a stale row fails it. The check lives in `backend/tests/architecture/` (ARCHITECTURE.md §11 already planned "tla mapping" there) and reads `engine/src` as text, never importing the engine.
- **Conformance tests from TLC traces: piece 2 for the queue, piece 3 for the save path** (agent): the projection of the model's state onto the queue (`q`, `runs`, `eng`, `ses.advice`) needs the shell that feeds the table the model's events; the save path needs piece 3's fake file system. TLC was not run in this slice (no model change).
- **The decision tables in one data file** (BL-0109's "if cheap"): not cheap; not built (see the cut).
- **BL-0118 and the `input_hash` note** (agent): neither falls in this piece; BL-0118's row now carries the S0051 verifier's note (the adopted digest leaves out `options["input_hash"]`, an md5 of each included file's name, mtime and size, read in Beancount 3.2.0's `loader.compute_input_hash`: every save changes the mtimes, so a digest with it would make every R4 a false mismatch) and points to piece 4, BL-0152.
- **Backlog IDs used:** BL-0150 to BL-0154 (new); BL-0109 set `in-progress`; BL-0118 and BL-0154 annotated.
- **Deviations from ENGINEERING.md:** EP-28 (waits on a condition with a deadline): three "this did not happen" assertions use a bounded window (0.5 s in the two lock tests, 1 s in `test_main`'s engine-lock test), since an absence cannot be awaited; each is far above the time the event would take (an engine starts in about 0.1 s).

## Verifier
- **Round 1** (head f8007574; report and repros in the private archive `m1a/s0053-verifier/`): PASS WITH FINDINGS, 0 High, 3 Medium, 6 Low. Every finding reproduced on f8007574 before the fix (the four table repros, `boot_lock_error.py`, `engine_missing_dir.py`, the parser toy; the verifier's 8 surviving mutants). What was done:

Test `test_the_boot_opens_the_exclusive_window_so_only_its_own_jobs_start`.
  - **F2 Medium** (EP-13, EP-15): `EngineBoot.run` catches an `OSError` of the wait, starts no engine (an earlier engine may still run), sets `EngineDown(start_failed)` and logs `engine.start_failed` through the sink the composition root now passes.
