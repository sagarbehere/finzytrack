# S0030: The acceptance-suite harness and the INV-24 test guards

## Brief
- Base: `a431e70c`.
- Goal: the acceptance-suite harness (roadmap §1 "Left in M0" item 4; review:27 §1(d); review:L8 §6; review:20 §6) and BL-0024 (INV-24 enforcement: the harness's port and data-dir checks, the local-tier path guard). Each Playwright worker gets its own run: a fresh temp root, a fresh demo workspace from the generator, the main sidecar started by the harness on an OS-assigned loopback port with its data dirs inside that root, a frozen clock on both sides, `TZ` west of UTC (plus one project east of UTC for the after-midnight case), an OpenAI-compatible LLM stub with scripted replies, and in every test axe, console errors, page errors, failed requests and requests to any origin that is not ours as hard failures. Chromium and WebKit projects. S0029's temporary `WS` constant is replaced by the harness fixture (the integrity flows stay pending).
- What exists (orient): no backend process at all. `backend/src/app/` holds `content` (demo generator), `domain` (empty), `platform` (state registry only); there is no `app.main`, no HTTP server, no `Clock` port. ARCHITECTURE.md §2/§5 names them: `main.py` is the composition root and sidecar entry (CLI args, roots, port 0, the `FT_READY {"port","version"}` stdout handshake); `platform` holds the `Clock` protocol with `FrozenClock` as its test double. The FastAPI app and `/api/boot` are M2 (L1-07, L10-09). Playwright is configured with Chromium and WebKit (S0009); `@axe-core/playwright` 4.13.0 is pinned in ARCHITECTURE.md §10 but not installed.
- Implements: ARCHITECTURE.md §2.3 (the `Clock` port and `FrozenClock`), §5 (sidecar CLI args, port 0, handshake), §2.4 rule 1 (`app.main` joins the layers contract); ENGINEERING.md EP-10 ("acceptance runs with `TZ` west of UTC and a frozen clock on both sides"); PROCESS.md §4 (UI testing), §8 (agents and real data: T-local reads copies only from a folder named by an environment variable, prints counts and case IDs only).
- Capabilities: none (test infrastructure; no capability row).
- Invariants touched: INV-24 (enforcement grows: the harness checks and the local-tier guard); INV-07 (a frozen clock and a non-UTC zone in every acceptance run); INV-11 (new backend modules hold no module state); INV-12 (`app.main` in the layers contract).
- Risk class / lane: **High** / full. It is the INV-24 guard for tests: a loose check here lets a test run touch the owner's data dir or app. It touches no ledger and no finance semantics, so per ADR-0058 a fresh verifier round follows only a High fix.

No user docs.

## Decisions
- The main sidecar entry `app.main` is created now, with the shell's CLI args (ARCHITECTURE.md §5: `--app-local-data`, `--app-cache`, `--port 0`, `--workspace`), the loopback bind and the `FT_READY` handshake, and a placeholder HTTP server with **no routes** (every request is answered 501) until the FastAPI app arrives (L1-07, L10-09, M2). Deviation from ARCHITECTURE.md's "main.py … uvicorn", recorded here: adding FastAPI and uvicorn, the API envelope (ADR-0038) and the OpenAPI export for a harness skeleton would build M2's API edge without its spec; the placeholder is stdlib, about ten lines, and M2 replaces `serve()` only (agent).
- The backend's frozen clock arrives through a test-only CLI arg `--frozen-clock <ISO instant with offset>`: the shell's CLI is the only channel between a parent and the sidecar (ARCHITECTURE.md §5, "No other channel"), and an environment variable would be a second one. The composition root builds `FrozenClock` from it, else `SystemClock`. Nothing in the backend reads the clock yet, so the end-to-end proof waits for the first route that shows a date; until then the wiring is tested in-process (agent).
- The harness launcher is Python stdlib (`scripts/acceptance/harness.py`), started once per Playwright worker by a worker-scoped fixture, so each worker (and so each project, with its own zone) has its own temp root, demo, sidecar and stub, and the guards can be mutation-tested with `scripts/mutants.py`. The launcher watches its stdin: when the worker closes it or dies, the launcher stops its children and removes its root (agent).
- Data-dir check by class (EP-30): no data dir is ever taken from outside. The harness creates the temp root with `mkdtemp`, creates each dir itself with `mkdir` (so it is fresh) as a direct child of the root, records each dir's identity (device, inode), and refuses to pass any path to the sidecar that is not one of those, is a symlink, has another parent, or lies in (or contains) the repo, the live data folder or the legacy worktree, compared resolved and case-insensitively (agent).
- Port check by class: the harness never chooses a port; it passes `--port 0` and accepts only the port in its own child's handshake, refused when it is 8001 (the owner's), privileged or out of range, or when the child has exited. The sidecar binds only `127.0.0.1`. In the browser, every request to an origin other than the preview server and the harness's sidecar is aborted and fails the test, so a page can never reach the owner's app (agent).
- Process ownership by class: the harness signals processes only through the `Popen` handles it created and refuses any other; its source never calls `os.kill`, `killpg` or a name or port lookup (a test scans for them) (agent).
- Frozen instants per zone: Los Angeles at 21:30 local on 2026-03-31 (UTC is already 2026-04-01); Kolkata at 00:30 local on 2026-04-01 (UTC is still 2026-03-31). Each catches a "UTC today" bug on a month boundary. The demo is anchored at the local date (agent).
- The local-tier guard lives in `scripts/oracle/copies.py` beside the other copy guards and is called by the oracle harness, today's only runner that reads ledger copies from a folder: `--ledger-dir` must be repo corpora or inside the folder named by `FT_LOCAL_TIER_DIR`, which must be an existing folder outside the repo, the live data folder and the legacy worktree. `copies.refuse_dir` also becomes case-insensitive, and refuses the default live data folder even when `FT_LIVE_DATA` names another (tightenings; agent).
- The demo is generated into a staging folder and its plain files copied into the harness-made `workspace` folder, because `gen_demo.py` renames its output into place (a new inode) and the data-dir check accepts only folders the harness made itself (agent).
- The harness's own hard failures are tested in committed specs (`frontend/e2e/harness.spec.ts`): each provokes the problem, asserts it was recorded, then clears it; the teardown checks themselves (a recorded problem or an unscripted LLM call left at the end fails the test) are proven by a nested Playwright run of `e2e/harness/selftest/leak.selftest.ts` that must fail. `test.fail` is not used: S0029's checker refuses it (agent).
- The `request` fixture is wrapped with the same origin rule as pages; S0029's A4 flow now reads the profile through it instead of `page.request`, which no guard sees (BL-0071 records the static ban on `page.request`, `context.request` and raw `fetch`). An ESLint rule refuses value imports from `@playwright/test` in specs, so no flow can bypass the harness by importing the plain `test` (agent).
- The browser's HTTP-error check counts every response of 400 or more; `vite preview` answers unknown paths with the SPA page (200), so it is proven with a routed 404 (agent).
- CI (run by hand, ADR-0060): the repo-checks job syncs the backend venv before the meta-tests (so the end-to-end launcher test runs, not skips), and the frontend job syncs it before Playwright (agent).
- Screenshot baselines (in review:27 §1(d)'s list) are not taken: the only screen is a heading, and baselines from macOS cannot gate the Linux CI job; BL-0071 (agent).

## Hand-off (PROCESS.md §3 step 4; ADR-0057)
(The verifier reads only the Brief, so this section does not steer its attacks; it is the implementer's own record.)
- Checks that accept, tag or refuse, each with its must-not-pass test:
  - Temp root never in or around the repo, the live data folder or the legacy worktree (also other case spellings, `/`) → `TempRootTest.test_a_root_is_never_created_in_a_forbidden_place` (nothing created there).
  - `make_dir`: one plain name, fresh → `test_make_dir_takes_one_plain_name`, `test_make_dir_creates_a_fresh_child_once`.
  - `check_own`: only harness-made, unchanged, non-link folders → `test_check_own_accepts_only_folders_the_harness_made` (planted dir, nested dir, links in and out, outside, live folder, other case, `..` spelling, never made), `test_a_made_folder_that_was_replaced_is_refused` (re-made, swapped for a link to the live folder).
  - `remove` only its own root → `test_remove_deletes_only_its_own_root`, `test_remove_refuses_a_root_that_was_swapped_for_a_link`.
  - `check_port` / `parse_handshake` → `PortTest` (8001, 0, 80, 1024, 65536, bool, str, float, None; 12 malformed or wrong handshakes incl. an extra `host` key). OWNER_PORT pinned to the guard hooks' value.
  - `Children.stop` only its own handles → `test_stop_refuses_any_process_it_did_not_start` (a stranger `Popen`, its pid, our pid, None: still running after), plus the source scan for pid, name and port lookups.
  - Sidecar argv and env: port 0, folders checked, small env with HOME inside the root → `LaunchSpecTest`.
  - Zone profiles: UTC and unknown zones refused → `test_a_zone_without_a_profile_is_refused`, `EndToEndTest.test_a_run_refuses_a_zone_without_a_profile`.
  - LLM stub: unscripted 500 and recorded, streaming 400, malformed script 400, unknown path 404 → `LlmStubTest`.
  - `copies.refuse_dir` case-insensitive and keeps the defaults under env overrides → `test_refuses_another_spelling_of_a_forbidden_folder`, `test_the_default_live_folder_stays_refused_when_ft_live_data_names_another`.
  - Local tier → `LocalTierTest` (outside, `..`, other case, link out, unset, empty, relative incl. one that exists from the cwd, missing, live, inside live, containing live, repo, corpora, legacy; entries never shown inside the tier); oracle wiring → `test_harness.py::test_a_ledger_dir_outside_the_local_tier_folder`, `test_no_local_tier_folder_set`.
  - Sidecar entry: loopback only, port range, offset-less instant, missing roots → `backend/tests/test_main.py`; `FrozenClock` refuses a naive instant → `test_clock.py`.
  - Browser: `requestAllowed` / `parseReady` → `tests/unit/e2eHarness.test.ts` (owner port even when listed, other ports and hosts, schemes, foreign blob, userinfo trick; owner port, non-loopback, workspace outside root, naive instant, unknown zone); fixtures → `e2e/harness.spec.ts` (owner port and other origin aborted, console and page errors, HTTP 404, axe, unscripted LLM, request fixture, teardown via the nested run); spec imports → `gates.test.ts` `[INV-24]` cases.
- Self-mutation (High): Python, `scripts/mutants.py` (plan in the session scratchpad, `s0030/plan.toml`, run over scripts/tests, the oracle harness tests and the backend tests): 33 tried, 29 killed in the first run; survivors handled: `tier-relative-ok` → new test (a relative tier that exists from the cwd), `own-parent-unchecked` → the redundant clause removed (only `make_dir` records paths, always `root / name`); second run 32 tried / 30 killed, 2 equivalent: `port-bool-allowed` (a bool is 0 or 1, refused by the range check anyway), `own-symlink-ok` (a link at a made path never has the made folder's identity). Frontend by hand in a scratch copy (the runner cannot link node_modules): fixtures 10 tried / 10 killed (route guard off, allow every origin, console, pageerror, HTTP ≥ 500 only, axe without assert, request fixture unguarded, clock not frozen, teardown problem check removed, teardown LLM check removed); policy 8 tried / 6 killed in the first run, `blob-any` → new test (a foreign blob URL), `any-scheme` was equivalent (an origin carries its scheme) and the redundant line was removed; second run 7 / 7 killed. The route-guard mutant ran only the other-origin test, never the owner-port one.
- Population: none claimed.
- Engines: the full suite ran locally in Chromium and WebKit (Los Angeles) and Chromium (Kolkata): 30 passed, 21 pending flows skipped (fixme); no temp root or sidecar left behind.
