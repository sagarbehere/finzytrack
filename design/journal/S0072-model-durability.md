# S0072: the engine-jobs model checks durability only

## Brief
- Goal: BL-0180 (ADR-0068 D5, owner, 2026-11-01: "I agree with 3,4,5,6, and 7." and "Yes, go ahead with all of those"; EP-19) with BL-0161: cut `formal/tla/engine-jobs/` to durability. Keep save, rollback, recovery, power loss, the outside editor, create and copy, their durability mutants and the save's conformance replay. Remove the queue, switch, boot screens, quit, advice and screen actions, the liveness worlds (`LS_*`), `LM_free`, the queue's trace replay, `R4_*` (the code's rebuild, which writes no ledger byte), `S_Load` and `S_Recheck` (no effect since S0070), the save's ledger-set locks (S0071, D3) and the legacy-lock try (D4). Bring the save, restore and recovery to the code as built (`engine/src/ledger_engine/ledger/{writer,restore}.py`, `core/recovery.py`; the code decides where BL-0161's row differs): kept-name moves instead of swap-backs, the staging-name temp rule (S0061 round 3), the created path that is never touched (`created_path_taken`), the backup step that syncs and reads the file, recovery's kept-copy stop. The save's replay must no longer stop at kept-move branches.
- The bytes it protects: none directly; the model is a check, not a write path. It checks that no committed change (ours, or an outside program's durable save) is lost or torn, and that recovery returns a committed state. No product write path changes (D6a): only test, replay-harness code and no-op `@tla_action` markers and comments.
- Implements: ADR-0068 D5; EP-19; spec `design/specs/engine-jobs.md` §13 (scope paragraph only; the full rewrite is S0073, BL-0181); ADR-0013's kept-name amendment (2026-10-29) and ADR-0012's staging-name amendment (2026-10-30, round 3) in the model.
- D2 (no-swap volumes): decided by reading the model: it never modelled S0065's no-swap fallback (no such action, constant or rule in `EngineJobs.tla`; MAPPING.md §3 already lists the best-effort mode as outside the model). So nothing to remove and nothing to add: the best-effort mode stays outside the model, a stated limit (spec §6.8, §13) checked by the fake's sweeps.
- Capabilities: CAP-DATA-ENGINE-JOBS (its model clause, if any).
- Invariants touched: none changed. The model's properties check INV-01 and INV-22 (durable save, recovery), INV-32's "recovered before work" and "writes only recorded paths" clauses.
- Risk class / lane: Medium / verifier only (ADR-0068 D6a: the slice neither writes ledger or user data nor gates a write). Not Low: the model and the replay are the checks that guard the write path's durability, and a vacuous model would hide a real loss.
- Acceptance tests (must fail on fcf96576): the save replay walks the kept-move branches (`swap_back`, `restore_swap_back`, `temp_rule`, `created_path`, `backup_check` stops gone from `STOPS`; the base corpus still stops there); every base config PASSes and every kept mutant VIOLATEs its property on the small tier; `scripts/tests/test_tla_engine_jobs.py` (names in step with §13 and MAPPING.md) on the new model; `backend/tests/architecture/test_tla_mapping.py` (actions ↔ markers both ways) on the new model; the retired-terms check refuses the removed model names.
- Expected doc impact: MAPPING.md (rewritten to the new model), HOW_TO_RUN.md (new times, the "ahead of the code" note gone), spec §13 scope paragraph, ARCHITECTURE.md §8.3 if it lists removed parts, EP-19's "other properties stay" sentence, backlog BL-0110, BL-0161, BL-0180, BL-0185 (grep of source docstrings), `scripts/check_retired_terms.py`.
- Open questions: none for the inbox. Within D5 the agent decides which properties are durability (Decisions); the counts in and out are in the Hand-off.

## Decisions
- **Rewritten, not pruned** (agent): the model kept only its file system, journals, the save, the restore, recover-all, create, copy and the environment; the queue, sessions, screens, engine processes and the job ids went whole, so a pruned 2,000-line module would have kept their scaffolding. Variables: `fs, jr, env, tgt, app, run, ctl, n, gh` (`app`: `recover` runs recover-all before any other work, `run`, `dead`). The save's state the replay reads keeps its old names (`fs.cur/tc/bk`, `ctl.plan/s/fi/rj/rbt`, `gh.told`).
- **Which properties are durability** (agent, within D5 and EP-19's "no committed change lost or torn, recovery returns a committed state"). Kept: `SavedSurvivesPowerLoss`, `BackupDurableBeforeReplace`, `JournalDurableBeforeFirstReplace`, `PartJournalNeverBlocks`, `ExternalEditNeverSilentlyLost`, `NoTornLedgerAfterRecovery`, `RecoveryNeverClobbersForeignBytes`, `RecoveryWritesOnlyRecordedPaths`, `CutTempNeverBlocks`, `EveryJournalRecoveredOrBlocking` (INV-32: no work in a session before every journal from before its start was tried), `BlockedOnlyForCause` (causes `stopped` and `failed` only: a false stop leaves an uncommitted mix for Keep), `NoCopyOverOpenJournal`, `NoManifestOverIncompleteFolder`, `NonEmptyTargetUntouched`, `DroppedFileNeverReplaced`, `ForeignOverwriteCaughtByReadBack`. Removed (queue, outcome, screen, liveness): `AtMostOneEngine`, `AtMostOneJobRunning`, `AtMostOneOpenWorkspace`, `OnlyOpenWorkspaceRunsJobs`, `WaitedForFirst`, `NoOwnEndAfterCommitPoint`, `CancelReachIsTheOneRule`, `CancelBeforeCommitLeavesDiskUnchanged`, `OutcomeTruthful`, `UnchangedOnlyAfterRehash`, `CommittedCombinationChecked` (the save's load, gone with D1), `StrictRecovered`, `BlockedScreenHasReason`, `KeepOnlyJudged`, `NoOpenOverUnresolvedJournal` (the open is gone; the save's gate in the model refuses on any unresolved journal naming a file of W1's set, which abstracts recover-before-open's block and the save's own check), `OtherNamesDoNotStop`, `DeleteAdviceOnlyForOwnFiles`, `InstallerNeverOverOpenJournal` (the update is quit's), `NoAdviceOnTimerForSlowWork`, `EveryWaitHasAnExit`, `QuitAnywayAlwaysEnabled`, `AssessNeverWaits`, `OpeningHasItsJob`, `NoEngineStall`, `AppScopedWaitsForRecovery`, `NotesAnsweredByRecovery`, `JobIdsBounded` and the liveness properties `EveryBootEnds`, `EveryWaitedForJobEnds`, `EverySwitchEnds`, `EveryQuitEndsOrOffersQuitAnyway`, `EngineCanAlwaysBeFreed`.
- **New property `KeptFilesDurable`** (agent): `keep_no_sync` (N1) stopped breaking `SavedSurvivesPowerLoss`. Its old trace needed a restore swap left unsynced when Keep ran; since S0061 round 4 the code syncs each restore swap at once and every folder before its first removal, so what can still be unsynced at Keep is only the save's own swaps cut before their folder sync. Keep without its sync then lets a power loss bring back a mix of that save's pre and post bytes after the journal says kept: no journal names it any more, so recovery can never return a committed state. That is durability, so the property states it ("what the user keeps is what a power loss leaves"), and `keep_no_sync` must break it (it does). Not a vacuity fix by weakening: the old target is unreachable by the code's design.
- **`swap_back_unsynced` is retired, not renamed `kept_move_unsynced`** (agent; BL-0161 asked that the renamed mutant still fail): equivalent in the kept-name design. The kept move is one rename; whatever a power loss keeps of the swap and that rename, the outside bytes stand at the file, the temp or the kept name (four combinations, none loses them), and the rollback that follows stops on the kept copy at its check before writing anything (`kept_copy`), so no removal of ours can come before a folder sync. The sync in `handles.keep` is defence in depth. Flagged to the owner in the report.
- **`no_displaced_check` covers both displaced checks** (agent): the code has one function (`writer._check_displaced`) for the swap's check and the temps' clean-up check, so the seeded bug disables both; disabling only the first is caught by the second (the model then holds the outside save in the temp until the clean-up keeps it), which is the code's behaviour, not vacuity.
- **D2 (best-effort drives)**: the model never had S0065's no-swap rules (Brief); nothing removed or added. The best-effort mode stays outside the model.
- **Vacuity witnesses** (agent): 23 `WIT_*` configurations (kind `witness`), each a base world with the negation of a branch it must reach as its invariant, which TLC must report violated: a save lands, a rollback resolves, puts bytes back, cannot resolve, keeps an outside save, stops on a taken created path; recovery resolves, keeps, fails, stops on the path guard; Keep (also of a torn journal); a cut staging write meets recovery; copy and create reach their ends; the second save lands and its rollback restores both files; the weaker file system's accepted loss. All reached on the small tier.
- **Abstractions kept or added** (agent; MAPPING.md §3): the restore's staging write, rename and sync are one step (`RS_Write`), and a restore temp is durable once written (a cut write there is the staging rule's, as the save's); the outside editor writes only the ledger files' own names (never a temp: the clean-up's re-checks therefore never find outside bytes, `S_RemoveTemps`' kept branch is reached only after a seeded bug); an editor's unsynced write is kept or dropped whole, never torn; the save backs up R only (N exists only from the second save, whose N backup the model does not check); the user's delete of a kept copy or of a file at a created path (the blocked screen's actions) is not modelled: only Keep leaves a stopped journal; the rollback after a failed close (`.closed` back to `.open`) is not modelled (no I/O error at `s_close`).
- **Product code touched, no behaviour** (agent; the brief's stop rule is for write-path changes): no-op `@tla_action` markers and docstrings only. Engine: `save._run`'s marker (`S_Locks`, `S_Release`) removed, `save._gated` names `S_Gate`, `S_Saved`; `restore._check` is `RS_Check`, `restore._restore_all` is `RS_Sync`, `RS_Clean`, `RS_Temp`, `RS_All`; `rebuild.run`'s `R4_*` marker removed; `recover_all` docstring. Backend: every marker removed (the model has no queue or app action left) with the marker module `app.platform.tla`; docstrings of `engine_jobs.queue`, `scheduler`, `save` no longer cite removed model actions. The removed module and markers are decorators that return the function unchanged: nothing runs differently.
- **The queue's trace replay is removed** (`backend/tests/platform/test_engine_jobs_conformance.py`, D5). Its one check outside the queue, the sidecar's decision after a save's engine death against the model's `DiskOutcome`, is the sidecar's own table test `backend/tests/platform/test_save_job.py::test_save_outcome_is_the_disks_answer` (agent).
- **The save replay** (agent): no stops but `cut`; the model's commit point is the end of `S_Gate` (the code's `job.gate()` has no hook any more, so an I/O error the model makes at the backup step is raised at the code's first backup effect, inside the save); new worlds `S_save_kept`, `S_save_kept_io` (an outside save at the swap; an I/O error before the displaced check, kept by the rollback's check), `S_save_created_taken`; the view compares kept copies and, at a name of ours, the temp else the staging file; new branches "an outside save moved to its kept name", "Unfinished: the rollback could not resolve", "a file at the path the save creates is never touched" (the last two were `NOT_WALKED_BRANCHES` before).
- **Spec §13** (agent, within "only as far as it states the model's scope"): the scope paragraph, world, actors, property list, seeded-bug list and "Not modelled" are rewritten to the durability model; the file-system assumptions paragraph is kept; the history of the two executable scratch models and the "former fix switch" paragraph went (their mutants are in MAPPING.md §5). Elsewhere in the spec only the stale pointers to the queue replay and `OutcomeTruthful`/`DispatchUnavail`/BL-0161 were fixed; the rest is S0073's (BL-0181).
- **BL-0185's grep** (agent): removed model actions, properties, worlds and the queue replay's names over `engine/src`, `backend/src`, `scripts`, `formal` (`*.py`, `*.sh`, `*.tla`): 26 hits; fixed the stale ones (`queue.py` 13, `scheduler.py` 1, `save.py` 1, `recover_all.py` 1, `run_all.sh` 1); left: the queue's own code names (`AdviceTimer` event class, `EngineGroup.drain`) and the retired-terms check's lists. Recorded in BL-0185's row, which stays open for its decision.
