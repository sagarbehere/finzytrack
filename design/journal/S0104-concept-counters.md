# S0104: Concept counters

## Brief
- Goal: BL-0116, the last row of the owner's M1a item c (owner, 2026-11-10, in session: "c. Architecture items: L1-02, L1-05, L1-10, L11-03, BL-0116"). Base commit `4ec85fa4`. Build `scripts/concept_counters.py` (EP-23, EP-03; ADR-0024 Consequences: "Concept counters guard tolerance, balance-check and account-grammar implementations at one each"): each kernel concept's one home carries an `@concept <name>` marker, and the check fails when a second implementation of the concept appears outside it. It recognises an implementation by what the code does (AST shapes), so a second home without a marker is still caught: a regex on account names, a hard-coded root name compared with an account, a tolerance computed from a number's scale, a magnitude compared with a threshold, a sum of posting amounts compared with zero, a number grammar in a regex. Default-deny: a shape outside a home fails unless it is a reviewed site with its reason, and a reviewed site that no longer has the shape is stale and fails.
  - **Inventory first, by behaviour** (concepts from EP-23, EP-03, ADR-0024, INV-02, ARCHITECTURE §2.6; code read in `engine/src`, `backend/src`, `frontend/src`, `shell/`): where each concept lives today and whether a second implementation exists. Counts in the Hand-off.

  - The frontend (no product code yet; ADR-0024 rejected a frontend account regex) gets the same shapes as ESLint AST bans in `frontend/eslint.config.js`, tested in `frontend/tests/unit/gates.test.ts`; the counter also counts `@concept` markers there (no home today, so any marker fails until a planned port declares its home).

It is planned enforcement due at M1a, not gate self-defence.

## Decisions
- **Seven concepts, three engine homes** (agent). From EP-23's rule, EP-03, ADR-0024 and INV-02: account grammar, currency grammar, the root names and the balance check in `ledger.grammar`; the tolerance and number reading in `ledger.beancount_port`; the account kind in `mirror.core.rows` (ADR-0024: "the mirror computes a canonical account kind"; BL-0116 names only grammar and the port, but the kind's one implementation is the row builders, and moving it would mean moving `KINDS`, `HOLDING_KINDS` and `CATEGORY_KINDS`, whose labels the mirror's rows use). The main sidecar and the frontend have no home: they ask (ADR-0054, ADR-0024). The balance check's home is `grammar` (`transaction_balance`, `balance_assertion`, the API ARCHITECTURE names), the tolerance's the port (`check_transaction`, `balance_tolerance`, `quantize_fill` wrap Beancount's).
- **EP-23's other concepts are mapped, not re-checked** (agent): "today" stays with `check_money_dates.py` and the frontend's lint (INV-07), SQL runners with `test_one_query_runner.py` (S0103); amount parse and format on the sidecar and the frontend, metadata-key filters, LLM prompt loaders, tree builders and draft converters do not exist on `next` and join with their home (BL-0250, M9; the verifier's `[EP-23]` question covers each until then). `concept_counters.EP23_COVERAGE` holds that map and a meta-test reads EP-23's list from ENGINEERING.md, so a concept added to the rule without a line fails (S0094's "claims exact").
- **Second implementations found and fixed** (agent; no user-visible change):
  - `backend/src/app/content/demo/ledger_text.py` had its own account regex (hard-coded default roots), a currency regex (`[A-Z]{3}`) and a per-currency exact balance sum. S0027 made them "deliberately narrower" guards for located messages; by behaviour they are what ADR-0024 rejected ("own validators, regexes and tolerance math"). Removed. Beancount stays the gate: `scripts/oracle/tests/test_demo_generator.py` loads every size with 0 errors and plants an unbalanced transaction (pre-push, T1). The generated bytes are unchanged (`backend/tests/content/test_demo_pins.py` green). The builder keeps the checks that keep its own text well formed (two decimals, two postings, the flag, unsafe text). The two backend tests of the removed guards are narrowed: `test_an_unbalanced_transaction_is_refused` is gone and four account and currency cases of `test_a_malformed_posting_is_refused` with it (justification: they pinned the second implementation; Beancount's refusal is pinned by the oracle test's plant).
  - `mirror.core.rows.root` split account names at `:` outside the grammar; it is now `grammar.account_root` (behaviour-neutral: the mirror tests, the INV-21 goldens and the mirror checksums are unchanged).
- **Reviewed sites, four** (agent), each a shape that is not the concept: the app folder's `DEV:INO` split (`protocol.app_folder.parse_identity`), `precision._LONG_RUN` (only picks which lines Beancount's lexer reads), `rows.account_balance_rows` (a zero-sum filter of the `account_balances` table, judging no entry), `errors.registry.CODE` (the shape of our error codes).
- **Wiring through the existing runners, no new hook line** (agent): the real-tree test in `scripts/tests/test_concept_counters.py` runs in `scripts/run_meta_tests.py`, which the pre-push hook, the Stop hook and T1 already run; adding a line to the pinned hooks would change `scripts/tests/hook_pins` for nothing. The frontend's shapes are ESLint `no-restricted-syntax` selectors in `src` (and in templates), the repo's style since S0092; they run in `pnpm lint` and `pnpm test` (pre-push, T1).
- **jscpd was claimed and never built** (agent; found while updating EP-23's line): ENGINEERING §0, EP-23 and PROCESS §6 name duplicate-code detection; nothing runs it and no row tracked it. The docs now say "not built yet" and BL-0251 (M2) builds it. Not built here: it is a separate check with its own threshold design.
- **Invariant**: INV-02's "Enforced by" lists the counters; its rule and status are unchanged.
- **Round 1 fixes** (agent; EP-30: shape detection is never complete, so the shapes a person would really write are closed and the rest stated as limits in the script's docstring, EP-23's line and the ESLint comment; no general data flow):
  - Names are read through one plain assignment in the function, the class or the module, and through constants imported from modules of ours (`from m import X`, `m.X`, relative imports; an index of every product module's text constants), and `.format`'s receiver (F1, F2's `ZERO`, F3's root constant).
  - An eighth concept, `number-format` (F7): the engine's one home is `rows.number` (marked); `precision`'s two warning texts and the demo builder's ledger text are reviewed sites. "Amount parse/format" in `EP23_COVERAGE` now says what exists: the engine's reading and writing counted, the sidecar's demo ledger text reviewed (BL-0063), the sidecar's and frontend's parse and display format not built (BL-0250). `EP23_COVERAGE` holds concept names as data, so the test checks single-word names too.
  - Reviewed sites are keyed by their shape as well (the verifier's question): seven sites now.
  - Frontend (F5): the bans moved to blocks covering every script suffix and `.vue` under `src`, `src/platform` and `src`'s own tests included; F6's decimal.js forms added.
  - F9: the oracle demo test loads the smallest size at five more anchors (a month end, a year end, a new year, a leap day and the day after); 0.9 s.
