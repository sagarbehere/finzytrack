# S0067: R4 follow-ups (BL-0172, BL-0173)

## Brief
- Goal: R4 really compares a save that creates files under a documents root, whatever spelling names the root; the Lows S0066's round 2 left; and the owner's decision of 2026-10-31 on the parse digest and the 5 s target ("Drop digest; 2 jobs (Recommended)").
- Base: a915e7a4 (pushed, tree clean).
- **What it builds:**
  - **BL-0172 (a), the prediction sees the created files.** The overlay's documents step (Beancount's `ops.documents`, run inside `run_transformations`) walks the listing the overlay took of each documents root, with the files the save creates under it added, instead of walking the disk (`beancount_port.run_transformations(..., documents=)`: Beancount's own `find_documents` and `account.walk` run unchanged; the port answers their `os.walk` and `path.exists` from that listing, for the roots only, during the call). The post fingerprint's listings (`ledger_set.as_after`) take the same additions from the load (`Loaded.created_documents`), so the prediction and the record cannot disagree. A save that creates the documents root, or a dated file in an account folder under it, then ends R4 `pass`, never `nondeterministic`.
  - **BL-0172 (b), another spelling.** A created file belongs under a root when its `path_key` lies under the root's `path_key` (case on APFS, NFD vs NFC, the root named through a link, the file named through a link to the root); its name in the listing is its canonical path's tail (the stored spelling of folders that exist, the written one of folders the save creates). A link *inside* the root (a folder of the root that links elsewhere, the file named through the target) is not matched: the record's listing lacks the file, the disk's has it, so R4 is `superseded` (never a false pass); spec §15 says so.
  - **Other root kinds**, checked, not changed: a plain include of a created file (passes today); a created file reached by a plain include that an `include` glob also matches: the prediction parsed it once, Beancount after the write twice; R4 is `superseded` (the glob's answer moved), never a pass; that prediction is BL-0117's (M3), whose row gains this case. A `document` directive naming a created file: the record's `document_files` says absent, the disk present: `superseded`.
  - **Lows of BL-0172:** a test killing `second_parse_no_moved`; `save._unavailable` worded by cause (a fresh engine that crashed during its start is `ENGINE_STOPPED`, an incompatible one `incompatible`, also when the scheduler refuses the engine for that reason); the overlay's plugins run under the same no-decrypt swap as R4's load, and an `EncryptedFileMet` escaping them refuses the load (`encrypted`); the overlay refuses a missing or dangling `.gpg` include, and a missing `.asc` one, before checking existence (Beancount's loader would decrypt or open it first: R4 could never run); `r4._open_journal` reads every key folder before raising on an unreadable `.open` (a readable one of the workspace lifts R4 wherever it is listed); a 54k replica-vs-loader digest equality test in `test_digest.py`.
  - **BL-0173 (owner, 2026-10-31: "Drop digest; 2 jobs (Recommended)").** The save stops computing the parse digest (the overlay's `key_of`, `Loaded.parse_digest`, the record's `parse_digest`); the confirm's `nondeterministic` rests on Beancount's parse and the replica's agreeing, the replica having read exactly the record's post bytes (`read_other`), the fingerprint unchanged. **Journal format 3** (the field is gone): a version 2 record is `Unreadable`, so R4 counts it as a failure to run and it ends "could not check" (Resume saving), never a pass; version 2 was written only since S0066 (2026-10-31) and nothing in the product saves yet (no route calls `submit_save`; BL-0106), as version 1 before it. The save always computes the adopted digest (so `not_computed` and its branch in R4 go: every record carries a digest). A save that runs the previous save's R4 first shows "Checking your last change first…" while it does (`text.describe`, from the job's kind and the phase `checking_last_change`; the UI is BL-0092/BL-0170), and counts as two jobs for ADR-0008's 5 s (ADR-0008 amendment with the owner's words; spec §15).

## Decisions
- **The prediction walks the overlay's listing, not the disk** (BL-0172 a, the brief's preferred fix; no policy refusal, so no escalation): `beancount_port.run_transformations(..., documents=)` answers Beancount's documents step (`ops.documents`' own `account` and `path` names; round 1: never the shared `account.os`, see Round 1 fixes) from the listing the overlay recorded for each root, with the created files added; Beancount's own code (account names, NFKC, the dated-name test, the sort) runs unchanged. Swapping two module attributes for the call follows S0066's `_never_decrypt` (one op at a time on one thread). Side effect, on purpose: the step now reads exactly what the fingerprint recorded (before, Beancount walked the disk again after the listing), as every ledger file is already parsed from the bytes the overlay read. The pin test against `load_file` (the write corpus) stays green. (agent)
- **Matching by `path_key`, naming by the canonical tail** (BL-0172 b): a created file is under a root when its key's components start with the root key's; its listing name is its canonical path below the root (stored spelling of folders that exist, written spelling of new ones), which is how the walk of the root lists it after the write. The match is made once, in the overlay (`Loaded.created_documents`), and `as_after` takes it from there, so the prediction and the record cannot disagree; `as_after` no longer matches anything itself. Not matched (R4 `superseded`, spec §15): a link inside the root; a path that cannot be resolved; a `document` directive naming a created file by another spelling. (agent)
- **The glob root kind is left to BL-0117**: a created file reached by a plain include that a glob also matches is parsed twice by Beancount after the write and once by the prediction; R4 is `superseded` (pinned by a test), and the row gains the case. It is the write contract's validation of the candidate that is short here, not R4; nothing in the product creates such a file before M3. (agent)
- **A `document` directive or a plugin's `document` naming a created file**: the record's `document_files` flips to present only for an exact `root/name` the prediction added; otherwise it stays absent and R4 is `superseded`. Covering other spellings would need a resolve per document entry; it is not worth it for a save that names its own new ledger file as a document. (agent)
- **Missing encrypted names**: the overlay refuses a `.gpg` by name (as Beancount's `is_encrypted_file`, case-sensitive) and a `.asc` that is missing or has a PGP header, before the existence check, as root or as an include the glob lists (a dangling link). A missing include matches no glob, so neither loader opens it: still the glob's error, as Beancount's. The old test "a missing encrypted-looking file is a missing file" pinned the opposite; see Golden changes. (agent)
- **Plugins never decrypt in the overlay either**: the swap is inside `run_transformations`; Beancount turns a plugin's exception into an error whose text is the traceback, the same frames in both loads, so R4 passes (tested end to end); an `EncryptedFileMet` raised while a plugin is imported escapes Beancount and the overlay refuses the load (`encrypted`). (agent)
- **`save._unavailable` by cause**: `unavailable` → "stopped several times", `start_failed` → cannot start, `incompatible`, `closed` → closing, anything else (an engine that crashed or broke the protocol while it started) → `ENGINE_STOPPED {crashed}` (nothing written: the save never ran). **Not changed:** the scheduler words an `EngineRefused` of an engine it already knows to be incompatible as `unavailable`; the save after a passed R4 cannot reach it (no job failure is read between R4's end and the save's engine request, so the scheduler learns the incompatibility at that start, which `begin` reports as `incompatible`), and recover-all reports the kind as is; a Low dropped with this reason. (agent)
- **BL-0173, journal format 3** (the owner's answer, "Drop digest; 2 jobs (Recommended)", 2026-10-31, said no format change was needed; **the bump is the implementer's choice**, round 1 verifier F2): the field is removed, not left unfilled, so no reader can mistake an old value for a current one; a format 2 record is `Unreadable` ("unknown version"), so R4 counts it as a failure to run and it ends "could not check" (Resume saving), never `pass` (tested). Format 2 existed only since S0066 (today); nothing in the product saves (no route calls `submit_save`), so no user record is affected; a format 2 `.open` journal in a development folder is unreadable to recovery too (`recover_all`: `Refused("unreadable")`), so it blocks opening that workspace instead of being rolled back (fails closed). Rubric item 1 does not apply (app-local data, not the ledger). (agent)
- **`not_computed` removed**: the save always computes the adopted digest (the digest of an empty test load is a digest like any other), so every record can be compared and R4's "record without digests" branch is gone. (agent)
- **"Checking your last change first…"** is `text.describe`'s for a save in R4's phase (`checking_last_change`, which the engine already reports during the save's step 1), and a job waiting behind it reads "Waiting for: Checking your last change first…"; the background R4 keeps "Checking your last change…". No screen shows job texts yet (BL-0092, BL-0170), so the sidecar text and spec §11, §15 are what this slice delivers. (agent)
- **The 54k test runs the demo generator as its own program** (`backend/scripts/gen_demo.py`, this interpreter, `-I`): the engine may not import the sidecar (ADR-0054), and the generator is stdlib-only (the oracle environment runs it the same way). About 7 s in the engine suite; there is no larger-tier marker in the engine or backend suites (the oracle's 54k demo tests run in the pre-push hook), so it runs in the normal suite. (agent)
- **ENGINEERING.md**: no deviation. EP-03 (wrap, never re-implement): Beancount's documents code runs unchanged; only the two disk questions it asks are answered from the overlay's own record.

## Round 1 fixes (verifier r1, red team r1)
- **Red team F1 (High; reproduced by the orchestrator):** the swap replaced `beancount.core.account.os` for the whole of `run_transformations`, so a user plugin calling `account.walk` on a documents root saw the listing (no empty folders, `dirs` always empty, `followlinks` ignored): a deterministic plugin (Beancount's `validate_directory`) got a wrong prediction, R4 `differs`, the confirm `nondeterministic`, `.done`: a false "checked". Fixed: only `ops.documents`' own names `account` and `path` are swapped (`_AccountAnswers`, `_PathAnswers`); `_AccountAnswers.walk` runs Beancount's own `account.walk` over the listing with `account.os` answered only for that call, collected before any other code runs; every other caller sees the real modules. Other swaps checked: `_never_decrypt` (intended: no decryption anywhere) and `sys.path` (Beancount's own). A user plugin that calls `ops.documents.find_documents` itself sees the listing: equivalent to the disk for it (it reads only file names, walks with `followlinks=True` as the listing was taken, and empty folders give no entries; red team r1 "attacks that found nothing" compared them). Tests: `test_a_users_plugin_walking_a_documents_root_sees_the_disk_in_the_prediction[validate_directory_empty_folder|walk_empty_account_folder|walk_not_following_links]`, from the red team's probes; the probes pass on the fix.
- **Verifier F1 (Low):** `test_the_documents_step_orders_documents_as_beancount_does` (`Assets/Cash`, `Assets/Cash/Sub`, `Assets/Cash-Old`, two files in one folder, one date). Reversing the folders is killed; reversing the files is equivalent now (Beancount's `account.walk` sorts the file list in place, and the listing walk goes through it).
- **Verifier F2 (Low, doc):** the ADR-0008 amendment now says the format bump is the implementer's choice, outside the owner's paragraph, and that recovery cannot roll back a format 2 `.open` journal; Decisions above say the same.
- **Outside the slice:** the queue property failure reproduced deterministically (the counterexample replayed through `transition` and `check_step`); the oracle is stale, the queue right: BL-0174. Red team overflow: the version 2 `.open` (now in the ADR and Decisions); the confirm's `nondeterministic` for any drift after the parse and the plugin-added undated `document`: BL-0171 (9), (10).
- **Round 1 self-mutation** (plan `mut/r1.toml`): `walk-folders-reversed`, `account-os-swapped-for-plugins`, `documents-account-not-answered` killed; `walk-files-reversed` equivalent (above).
- **Round 1 tests on fa446aeb:** the three plugin cases fail (`differs` where `pass` is expected); the order test passes there by design (`@regression-guard`).
