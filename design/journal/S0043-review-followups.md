## Decisions

Recorded as IMP-0032; IMP-0030's status says it was narrowed. (owner, quoted; agent for the exact rule list)
- Rule list (agent): kept the brief's rules plus two the brief did not name but which are honesty, not format: a Test cell must be references only (prose such as "covered by the smoke run" would claim cover nobody checks), and `same as` must name a row of the same program that itself cites a test (a `same as` an `n/a` claims a test that is not there). Dropped: the cell count per program, the ID number matching the failure's number, a duplicate row ID (the pair rule still refuses two rows for one failure), an unknown failure name (a missing failure is still caught by the pair rule), the four-word `n/a` reason, every cell of a `same as` row repeating it. A cell count is not needed for parsing: the Test cell is the last cell and the States cell the one before it, and a row missing either fails as "not a reference" or "not a transition".
- Result on the real spec: the same 28 rows and the same counts as the S0041 check (n/a 2, planned 9, same as 4, tested and planned 13). Checker 322 to 234 lines, its tests 337 to 229 (21 tests). The review's estimate of about 80 lines assumed the transition check and the test-existence parsing would go; both stay by the brief.
- BL-0098 diagnosis (agent). The timer reaps its own check (`stop_group` waits on it) before it exits, so a check found alive after the timer exited was either a zombie of a check the timer gave up on after both grace waits, or a check the timer never stopped. Reading the signal path found two ways to the second: (1) a stop signal that lands after `Popen` has started the check but before `run_check` enters the `try` whose `except` stops it (under load the check can start and write its pid before the timer returns from `Popen`; the test sends the signal as soon as the pid file appears) raises out of `run_check` and leaves the check running; (2) a second signal during `stop_group`'s grace time (a second Ctrl-C) raises between SIGTERM and SIGKILL, and a check that ignores SIGTERM keeps running. Both are real defects in the gate (an aborted push could leave a check running), shown by new deterministic tests that fail on the base commit. The observed failure was not reproduced: 90 runs of a stress script that signals the timer as soon as the check's pid appears, 60 of them under extra CPU load (load average up to 86), left no check running and no zombie. So which cause the S0042 failure had is not known; the slice fixes both defects and makes the test wait by condition.
- Fix (agent): `gate_timer._Held`: while a check is being started and while it is being stopped, the stop handler records the signal instead of raising; it is raised as soon as the check is held (first statement inside the guarded `try`) or the stop is done. SIGINT now goes through the same handler (before, Python's default handler raised at once, outside the hold). The Stop hook uses the same `stop_checks_on_signals`, so it gets the fix too.
- Test waits (agent): `Signals` and `RunCheck.test_a_hung_check_and_what_it_started_are_stopped` wait by condition: the pid file appears or the timer ends; after the timer exits, the check has ended, where a zombie (state `Z` in `ps`) counts as ended; each wait fails only past a 60 s hang backstop, the value the other timer tests use for `timer.wait`. The hung-check test had the same fixed 5 s window for its grandchild (same flake class), so it was changed too.
- Backlog (agent, from the approved triage): F6 folded into BL-0082 (the engine refuses an oversized reply with a key such as `engine.result_too_large`, not a stop; paging or streaming with QueryRunner and BQL); F9 added to BL-0085 as question (3), checked on this machine: the engine's interpreter reports OpenSSL 3.5.9; F12 as BL-0099 (M2) right after BL-0093, facts checked in the code (`STDERR_LINES = 200`, `ledger_engine.protocol.server` builds `where` from pydantic's `loc` and `msg`, `DEBUG_CAP = 2000`). BL-0085's milestone stays M12 (the legal advice); its new item (3) says the interpreter must be judged before M11, the milestone of BL-0053's notices; the row's milestone was not moved, since only part (3) is earlier.

## Verifier
- Round 1, head 39458cff: pass with findings (one Medium, two Lows, two extras); report in the owner's private archive, `m1a/s0043-verifier/`. It confirmed both timer defects (the two new tests fail on the base commit). Tooling with no ledger or user data and no High: no further round (ADR-0058).
- F1 Medium: the rewritten `visible_lines` looked for `<!--` inside a code fence, so a fenced `<!--` swallowed the closing fence and a later fenced example row counted as real (a spec missing E7 passed; the base check refused it). Fixed: one state at a time, inside a fence only the closing fence counts, inside a comment only `-->`; test `MustNotPass::test_a_fence_and_a_comment_never_mask_each_other` (the verifier's cases plus a fence inside a comment), which fails on 39458cff.
- F2 Low: signals were held only from `stop_group`'s first statement, so a stop signal as `stop_group` was entered (after a hang or after a first interrupt) raised before any kill and the check outlived `run_check`. Fixed: each `except` body of `run_check` starts the hold with a plain store before calling `stop_group`, which keeps a hold its caller started (CPython runs a handler only at a call, a function's entry or a backward jump, so nothing can run between the exception and that store; stated in `_Held`'s docstring). Test `Signals::test_a_signal_as_the_stop_starts_is_held` (both paths; a profile hook sends SIGTERM at `stop_group`'s call event), which fails on 39458cff.
- F3 Low (EP-29): the rewrite had dropped S0041's test that a `def test_...` inside a comment or string is not a test; restored as `MustNotPass::test_a_name_in_a_comment_or_string_is_not_a_test`.
- Extra 1: `scripts/tests/test_claude_hooks.py::StopHookSignals::test_ending_the_hook_stops_its_checks` had the same fixed windows and the `os.kill(pid, 0)` zombie problem; it now waits by condition with a 60 s hang backstop, and a zombie counts as ended (the test only; the small helper is repeated there rather than shared between test modules).
- Extra 2: `.claude/hooks/stop_checks.py`'s docstring now names SIGINT too. Edited through a scratch copy that compiles, then copied in; the hook has no byte pin (`scripts/tests/hook_pins/` pins only the git hooks), and its tests pass.
- Mutants for the fixes (plan `mutants-s0043-r1.toml` in the session scratchpad): 6 tried, 6 killed, 0 survived (F1: a comment opener ends a fence, a fence inside a comment counts; F3: `def` anywhere on a line; F2: no hold after a hang, no hold after an interrupt, `stop_group` dropping its caller's hold).

## Retro
- Verifier findings: round 1, one Medium (F1, a regression the rewrite brought into a kept rule: a fence and a comment masking each other) and two Lows (F2, a third signal window in the timer; F3, a dropped negative test). F1 and F3 were both losses from rewriting a check's tests from scratch: running S0041's old tests against the new check, before deleting them, would have caught both. That is the cheaper gate for the next rewrite of a check.
- What a cheaper gate could have found: the two timer races were findable by reading the signal path against "every exit stops the check"; S0034's signal test only exercised a signal during `proc.wait`. A test that injects the signal at each step (start, wait, stop) is the cheaper gate, now added.
- Where time went: the BL-0098 diagnosis (a stress script, 90 runs, no reproduction) and the mutant run (about 20 minutes, mostly the timer tests' real processes).
- Orientation gap: the brief's zombie hypothesis did not fit the timer, which reaps its own check; reading `stop_group` settled that.
- Process cost: two implementer passes (the slice and the round-1 fixes), one verifier round.
