## Decisions
- V2-1 (agent): the two folders are `/w/L` and `/w/L/inc` on two drives (`outside_mount` of a second share drive, `remote`, `sync_refused`, `ntfs`). The refusal "otherwise" is an injected `EOPNOTSUPP` at the folder's own `sync` label (an `on_effect` hook, so the test does not depend on the effect order). **Both orders are tested** (`first`, `second`): the brief's "the second refusing" kills "sync only the first folder"; "sync only the last folder" survives it and needs the first folder refusing. A companion test holds that the two-share world lands without the refusal, so the refusal is what stops it.
- O-2 (agent): two helpers, `_missing_have_their_backup` (every replaced file a power loss left missing has its pre bytes in `<backups>/<record>/<n>-<name>`) and `_outside_the_targets_unchanged` (every entry of `/w/L` before the save that the save does not write is as it was), run in both RT1 tests on every power-loss state, and on the disk itself in the second. The first test now also requires the limit to be reached for `a.bean`, not only `main.bean`. Their must-not-pass is a unit test of the helpers (a changed `other.bean`; `a.bean` missing with its backup removed), since no product mutant breaks only those checks without failing earlier ones.
- V4-1 (agent): the cleanup is reached by two stops in each suite: before the commit point (`load_errors` for the create, `load_differs` for the copy) and at it (`manifest_taken`: another program's `.finzytrack`, so the temp manifest folder is cleaned up too). Another program's file is put nowhere, in the target, or in a nested folder of ours (`prices/` for the create, `documents/Assets/` for the copy), just before the stop. The errors are round 4's (`ENOENT`, `EACCES`, `EBUSY`, `EIO`, `ENOTEMPTY`, `EEXIST`), plus the clean cleanup (no error). "Ours" is every name the job makes before the stop (built from the plan's files and their folders, the target itself, and at the commit point the temp manifest folder); "named" follows `create._named`: a name is covered when it is in `left` or a name in `left` is inside it. `left` None ("check the folder") holds whatever the disk is (less, never false; owner, 2026-11-21). The shared check and the case list live in `test_create.py` (`check_left_holds_the_disk`, `cleanup_sweep`) and `test_copy.py` imports them, as `test_share_saves.py` already imports `test_create`.
- V4-2 (agent): two runner tests, each on every spelling of the share: the port's `rmdir` of a folder holding a file or a folder answers `ENOTEMPTY` and leaves both; and a create on the share stopped by its load's errors, with another program's file put into `prices/`, answers `left == ("prices",)`, so the cleanup names the folder rather than "check the folder". The second goes beyond the row; it is the end-to-end form of the same fact and costs one more share test.
