## Decisions
- The check is its own script run by the pre-push hook, not part of `scripts/check_push.py` (agent). `check_push.py` runs under the system `python3` (stdlib only) before any check and decides whether the checks see what is pushed; the parse needs a YAML library, and putting it there would make the tree rules depend on an environment. Not a T0 pre-commit check: the backlog row and the owner's brief name the push gate, and pre-commit's 30 s budget is the owner's.
- The YAML library is the oracle environment's `ruamel.yaml` 0.18.15 (agent): the only YAML library already in a project environment (the backend and engine environments have none; the system `python3` has none). No dependency added, so the licence list is unchanged.
- The parse is YAML 1.2 (`typ="safe"`, `pure=True`), which is what GitHub's parser reads (in YAML 1.1, `on:` would be the boolean true). The structural rule is deliberately small: a single document, a mapping at the top with `on` and a non-empty `jobs` mapping. GitHub's own schema (keys, expressions, action references) is not checked: a stated limit in the script's docstring (actionlint would check it; not adopted, it is a new dependency for a case not yet met).
- The folder is read from the working tree, which the push gate has already proved equal to HEAD (`check_push.py`); `*.yml` and `*.yaml` both, as GitHub reads both.
- BL-0302: the local `wait_until` idiom of the other platform test files (each file keeps its own copy; no shared helper exists), polling every 20 ms until the file's `DEADLINE` (20 s), then asserting. A poll step is not a time budget: the bound is the test's existing deadline, and a line that never arrives fails the test at that bound. Rejected: waiting on the callback (the pump drops a sink after its first exception, so the broken callback is never called for the second line); asserting after `close()` (it would test the last engine's tail, not the running one's, and `close` waits a bounded drain of its own).
- Also logged: IMP-0076 (the new pre-push check, a tightening of PROCESS.md §6).
