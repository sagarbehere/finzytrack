# S0042: The caller's time limit covers sending the request; no pipe operation in the engine client waits without a bound

## Brief
- Trigger: area review 2026-10-26 F3 (High), the first area review of the engine and backend core; report in the owner's private archive `m1a/area-review-engine/` (with the reviewer's repro). The finding: `EngineClient._exchange_any` writes and flushes the request on the caller's thread with no time limit; the caller's timeout starts only at the wait for the reply. A request larger than the pipe buffer (about 64 KiB) to an engine that is not reading (frozen by SIGSTOP, or stuck) never returns; it holds the call lock, so `close()`, and with it quit, hangs too. Repro: a SIGSTOPped engine, a 1 MB request with a 2 s timeout: still `Busy` after 20 s; it finished only after SIGCONT. This breaks `design/specs/failure-modes.md` row E2 ("never a hang") and the client docstring's bound ("a call returns within `longest_start` + its timeout"), which also leaves out the waits of a stop (`_exit_detail`, `_reap`). In M1b, write plans and import commits will be larger than 64 KiB.
- Goal: the caller's time limit covers writing the request and waiting for its reply, as one deadline. When it passes, the client observes a timeout (`TimedOut`, the S0040 table's existing event: a stop of kind `timeout`, the engine killed) and the call returns. `close()` never hangs on a frozen or stuck engine. The class is closed by structure, not by a special case for large requests: every blocking pipe or process operation in the client is bounded. Inventory (by behaviour, from `engine_client.py`): the request write and flush (unbounded: fixed by a per-engine writer thread that owns stdin, the caller waits for it against the deadline); the reply wait (bounded, now by the remaining deadline); `_exit_detail`'s wait, `_shutdown`'s waits, `_reap`'s wait and joins (bounded by `close_timeout`, `_reap`'s now under one shared deadline); `_reap`'s pipe closes (**unbounded today, same class**: closing a pipe whose pump thread is still inside `readline` waits for that thread's buffer lock, so an engine whose output is held open by a child it started, a user's plugin for example, hangs `close()` after the joins time out; seen in a scratch probe; fixed: each pump closes its own pipe when it ends, and `_reap` closes only pipes whose thread has ended); `_shutdown`'s stdin close (moved to the writer thread, the single owner of stdin); `proc.kill`, `proc.poll`, `terminate` (do not block); `Popen` itself (the OS's fork and exec; not a pipe wait, stated as the residual).
- Out of scope (an open owner decision, area review F1/F2, a separate slice): how timeouts count as stops, and the one-request-at-a-time model. This slice changes neither; it only makes the existing `TimedOut` observation happen on time, so it fits either outcome.
- Implements: ADR-0054 decision 4 (the sidecar supervises the engine); S0035's decision that the caller's timeout covers the call's own exchange and a start is bounded by `RestartPolicy.longest_start` (agent decision, journal S0035; extended here from "the wait for the reply" to "the write and the wait", which is what a caller means by its limit); S0040's table unchanged; `design/specs/failure-modes.md` rows E2, E3, E7; ARCHITECTURE §2.0; EP-13, EP-28 (no real waits for backoff), EP-29.
- Capabilities: none changes (no user-visible behaviour).
- Invariants touched: INV-10, INV-11 (bounded state: one more thread per engine, no new resident data), INV-23 (no data), INV-24 (tests stop only their own children).
- Risk class / lane: **Medium** / light. Process supervision on the future write path; no ledger write, finance or security code exists or changes. The verifier may raise the class.

## Decisions
- **A writer thread per engine, and the caller waits only for the reply queue** (agent). The request goes to a queue; the writer thread (`_pump_requests`) is the only user of stdin; a failed write is put beside the replies as the marker `WriteFailed`. The caller's one `replies.get(timeout)` therefore covers the write and the reply together, with no deadline arithmetic to get wrong. Rejected: (a) a non-blocking write with `select` and a deadline: `select` does not work on pipes on Windows, where the write path matters from M1b (ADR-0061); (b) a writer thread per request: it would still share the `BufferedWriter` and its lock with whoever closes stdin, the same hang; (c) a special case for requests over the pipe buffer: the buffer size differs by OS and a frozen engine can block a small write too once the pipe is full.
- **Each pipe is closed by the thread that uses it, and `_reap` closes none** (agent; same class as F3, found while listing every blocking operation). Probe in the session scratchpad: `BufferedReader.close()` from another thread waits while a `readline` is blocked on the same pipe, so the old `_reap` hung after its joins timed out whenever a child of the engine (a user's Beancount plugin, say) kept the engine's output open. A thread that cannot end is left with its pipe; it ends and closes it when that child exits. `test_close_returns_when_a_child_of_the_engine_holds_its_output` fails on the base.
- **`_reap` waits `close_timeout` in all** (agent): the exit and the three joins share one deadline (`join_all`), so the stated bound holds for any number of threads (before: `close_timeout` per wait, four waits).
- **The bound, stated honestly**: a call returns within `longest_start` + its timeout + 3 × `close_timeout` after any call ahead of it; `close()` within 4 × `close_timeout` after the call in flight. Counting: a dead engine noticed first (its reap, ≤ `close_timeout`); then the start or the request; then its stop (`_exit_detail` ≤ `close_timeout`, the reap ≤ `close_timeout`). Left to the OS: `Popen` (fork and exec). Written in the client's docstring, `EnginePort.call`, ARCHITECTURE §2.0 and the spec's row E7.
- **The marker is a class, not an instance** (agent): `tests/architecture/test_globals.py` refused a module-level `WRITE_FAILED = _WriteFailed()` (INV-11); the class itself is put in the queue, which the check allows.
- **A write that fails reports "closed its input"** (agent): `_exit_detail` names which end the engine closed, so a stop after a failed write no longer says "closed its output".
- **Brief's test list revised after the tests were written** (agent, recorded so the verifier sees it): the planned `test_the_time_limit_covers_writing_and_waiting_together` was dropped, because the chosen design has one wait and no shared-deadline arithmetic for that test to hold; `test_a_stopped_engine_leaves_no_thread_behind`, `test_threads_are_joined_under_one_deadline_not_one_each` and two `@regression-guard` tests were added for the new structure (each found as a gap by a mutant, Hand-off).
- **Not changed** (out of scope, area review F1/F2, the owner's open decision): timeouts still count as stops, and one request is in flight. The writer thread fits either outcome: a cancel or a second channel would reuse the same queue.
- **Risk class Medium** (agent): no ledger, finance or security code; the change is the supervision the M1b write path will rely on. The verifier may raise it.
