## Decisions
- **The rule, as built** (agent, implementing the owner's "Build BL-0047 now (Recommended)"): `classify.errors_after_undo`. New errors (the legacy result's error keys minus the source's, as before) are explained only when (1) the case has tagged causes and they are undone (`apply_undo`, unchanged) and the result booked again (`semantic_diff.book`), (2) its error keys are then exactly the reference's (`book` of the intended ledger, `_reference`), and (3) the undo itself removed every new error (new ⊆ legacy errors − errors after the undo). (3) is not in the option's wording; without it, an error the intended change itself makes (the reference has it too) would be "explained" by an unrelated undo, which breaks the 2026-11-16 rule "a class explains only by undoing its own cause" (pinned by `test_an_error_the_undo_did_not_remove_is_not_explained_even_when_the_reference_has_it`). All or nothing per case: one error the undo does not remove leaves every new error UNEXPLAINED (the option's "exactly").
- **The tag is the smallest set of classes whose undo alone meets the same test** (agent): the first run on the repo corpora tagged nasty ren-coffee's and ren-rent's errors "I10+I2+I3" (every class undone in the case), not I2 as the option said; the erasers already name the smallest set for an entry, so the errors follow the same convention. Cost: one more booking per smaller set tried, only in a case whose new errors the full undo explains (at most 2^k − 2 for k classes; nasty: 3 classes). Pinned by `test_the_error_is_tagged_with_the_smallest_set_of_classes_whose_undo_removes_it`.
- **One undo and booking per case**, shared by the errors and the booked comparison (`compare`'s `rebooked`), and `Report.undone` counts the causes undone when either used them (the T-local report's `undone`).
- **No pyright run on the oracle** (deviation from the brief's "pyright_platforms on Python"): `scripts/oracle` has no pyright in its environment and no type gate in the hooks (`pyright_platforms.py scripts/oracle` stops: no `.venv/bin/pyright`); unchanged here.
- **BL-0047's milestone column says M2**: the column has no G1 value (`check_invariants.MILESTONES`); M2 is the milestone running beside G1; the row says so.

### Stated limits (added by the verifier round)
1. A renamed entry in a glob-reached file that the old app neither rewrites nor copies into the root is I2 ("file not rewritten"); its error is explained by the undo though no copy exists. The error rule does not check that the undo restores the intended entry, and the booked comparison sees only money, so a lost note or balance assertion is not reported.
2. Condition (3) is pinned only for a single instance of an error key: duplicate keys, and which combined-tag causes the smallest-set search undoes, are not pinned.
