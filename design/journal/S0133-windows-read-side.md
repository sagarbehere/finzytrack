# S0133: the engine's read side on Windows (M1b, BL-0282)

## Brief
- Goal: every engine test that skips on Windows naming `BL_0282` runs there with a Windows answer, and the five INV-03 tests of `engine/tests/ledger/test_parity_corpus.py` pass on the runner, so the `engine-windows` CI job is green. `BL_0282` then leaves `engine/tests/windows_pending.py` and BL-0282 closes. Windows writes stay off in the product until BL-0087; this slice does not touch that switch.
- The skip sites at the base (grep `BL_0282` under `engine/tests`): whole modules `test_preview_ops.py`, `test_copy_v022_install.py`, `test_copy_ops.py`, `ledger/test_ledger_set.py`, `ledger/test_contract.py`, `ledger/test_create_conformance.py`, `ledger/test_copy.py`, `ledger/test_write_sequence_model.py`, `mirror/test_checksums.py`; single tests in `ledger/test_fingerprint.py` (2 sites, 3 cases), `ledger/test_plugin_fingerprint.py` (3 sites, 4 cases), `ledger/test_precision.py` (1), `ledger/test_copy_layout.py` (4), `ledger/test_rebuild.py` (2). The base's Windows run (the 2026-11-19 run at 90c05caf, the last before this slice; the engine has not changed since) fails exactly INV-03's five: `test_beancount_gives_each_load_case_the_errors_it_is_written_for`, `test_every_feature_is_claimed_and_found_where_it_is_claimed`, `test_a_false_claim_an_unknown_feature_and_an_unclaimed_one_are_found`, `test_a_feature_a_case_has_but_does_not_claim_is_found`, `test_a_recursive_glob_that_matches_one_depth_is_not_counted_as_recursion`.
- **Part 1, `entry_keys` (product code).** `ledger/core/entry_keys.message_without_locations` passes the error's file as `re.sub`'s replacement text. On every OS a path holding `\x`, `\1`, `\U` (any backslash before a letter or digit the template syntax rejects or reads) raises `re.PatternError`, even when the message names no location, and the contract refuses `fault`; `\n` and `\\` are rewritten silently, the same on both sides. Fix: a function as the replacement. This changes the keys of macOS and Linux names holding `\n`, `\t` or `\\` (those keys now keep the path as written).
  - **Is an error key persisted or compared across versions? Checked: no.** The keys are made only inside one `preview` (`ledger/preview.py`: `entry_keys.error_keys(base.errors)` over the baseline's raw `ledger_errors` rows, and the candidate's rows in `contract.prepare`; `semantic_diff.parse` keys both sides of step 1 in the same call). The mirror stores raw rows (message, file, line), never a key. The baseline is used only when the published generation is this ledger's and **this engine build's** (`preview.py` answers `stale`/`not_fresh` otherwise; engine/CLAUDE.md "`stale` unless fresh, this ledger's and this build's"), so a generation an older engine built is never keyed by a newer one. The sidecar keeps the key digests only in a `WritePlan` (`backend/src/app/platform/plans.py`), held in memory, bounded by a TTL and dropped by a switch, compared at confirm against the acknowledgment the same preview listed (`writes.py`: `acknowledged != frozenset(listed)`); no journal records one (`grep` of `engine/src` and `backend/src` for `error_key`, `new_errors`, `entry_keys`). So no handling is needed.
- **Part 2, Beancount on Windows (INV-03: parity with Beancount on the same OS).** Expected values come from Beancount's own loader on that OS, never from Finzytrack's output. Where Beancount behaves differently on Windows (a Beancount bug included), the product follows Beancount, and the difference is a stated limit in the spec it belongs to (engine-jobs §7, the loads). Known from the base's run and from Beancount 3.2.0's source:
  - Beancount's lexer unescapes a string (`\U` to `U`, `\n` to a newline): a Windows path written with single backslashes in `include`, `option "documents"` or `document` is not that path. A Windows ledger writes `C:/...` or `C:\\...`. The generated `absolute-paths` case wrote `str(path)`, so on Windows it named a mangled file (its `LoadError` and two `DocumentError`s). It gets this OS's spellings Beancount reads as the path: on Windows the documents root with `/` and the include with doubled backslashes (both forms covered), and on POSIX the same bytes as before.
  - The parity detectors count a match's depth by `/`; Windows' `glob` gives `\` (the recursive-glob claims).
  - The generated cases are written with `write_text`, which on Windows writes CRLF, so `bean-example`'s header line no longer matches `$` (the example-ledger claims). They are written with `\n` on every OS, so the generated example is the pinned text everywhere.
- **Part 3, the rest, found on the runner** (BL-0282 (2)-(4)): the copy and the sequence model over the fake load a POSIX tree with Beancount, which takes Windows paths there (`os.path` is `ntpath`; since Python 3.13 a path with one leading `/` is not absolute on Windows); a carry past 28 digits; a plugin's package data; a plugin's module written during its own load; the checksums' case-folder placeholder; the copy layout's `document` paths; the rebuild's two document-path cases. Each gets its own answer from the runner. A test written in POSIX paths that reaches Beancount gets this OS's form or a per-OS expectation, by S0131's `backend/tests/host_paths.py` rule.
- **Stop rules (from the orchestrator):** if our own observation of a ledger set (`ledger/fingerprint.observe`, `core/ledger_set`, the plugin module recording) disagrees with what Beancount reads on Windows, that is the save gate's freshness input, a product defect, not a test premise: it is reported with evidence before any fix, and a class (a) finding gives the owner the policy option before the first fix round. If a spec's model or an ADR needs a Windows variant that changes a decided rule, the slice stops and reports. BL-0299 (a test-order dependence in the module recording) is not this slice's; if it shows on Windows it is reported and left.

## Decisions
- **Tests first (agent).** On the base c7f454bf, macOS: the new `test_entry_keys.py` case fails (`re.PatternError: bad escape \x at position 4`); per path, `\x41`, `\1`, `\U` and the Windows path raise with and without a location, and `\n`, `\\` give `bad at /l/a<newline>ew/...:_` and `/l/a\b/...:_`. The parity corpus's five fail on the runner at the base (run of 90c05caf, above).
- **The `entry_keys` fix (agent):** `re.sub(..., lambda _: placed, out)` with `placed = source_file + ":_"`. A function's return is used as text, never parsed.
- **Probe first (agent; S0126's and S0130's lessons).** The first commit removes every `BL_0282` skip at once, with the `entry_keys` fix and the parity helpers' three known causes (above), so the runner gives the whole inventory in one run. Also known before the run: `test_plugin_fingerprint.py`'s list of plugin-running modules keyed them by `str(relative_to)`, `\` on Windows (now `as_posix()`).
- **The copy op's two modules skip on Windows naming BL-0087, not BL-0282 (agent).** `tests/test_copy_ops.py` and `tests/test_copy_v022_install.py` run the real `copy` op, whose "loads the same" check starts the fresh-load child (`ledger/fresh_load.py`) and reads its answer with `selectors` on a pipe, which Windows' `select` does not take (sockets only); `tests/ledger/test_fresh_load.py` already skips there for that reason (`COPY_CHECK`, BL-0087). The copy's job itself runs on Windows over the fake (`tests/ledger/test_copy.py`, turned on here), and the copy's layout reads through Beancount there (`test_copy_layout.py`). Making the child's read work on Windows is product code on the copy's write path, which stays off until BL-0087. `COPY_CHECK`'s text now says why. The orchestrator accepted it after run 5 and asked for a line in BL-0087's row naming the gap as a must-fix before writes turn on (added).
- **The 2026-11-19 run 5** (head a20b07ae): `engine-windows` 65 failed, 10523 passed, 46 skipped; no skip names BL-0282; **INV-03's five pass**; every other job green. Diagnosed by cause, each from the log and, where it could be, reproduced on macOS:
  - **Beancount's string escapes in the tests' own ledgers (test premises; 13 tests in `test_ledger_set.py`, 2 in `test_rebuild.py`).** A test wrote `str(path)` into a plugin's config or a `document` line; Beancount reads `\U`, `\r`, `\t` there as escapes, so the file it was given was another (`C:Users\r unneradmin...`, then "Invalid relative path for entry"). Each now writes `tests/beancount_text.escaped(path)` (each backslash doubled; the same text on POSIX), the expected messages still `str(path)`, as Beancount reads it back. `test_rebuild.py`'s `dotdot` case of `test_a_document_file_the_roots_listing_does_not_name_stays_in_the_stamp` had passed on Windows with the mangled path, testing nothing; it is escaped too.
  - **The include pattern as Beancount joins it (test premises; `test_ledger_set.py` 1, `test_preview_ops.py` 1).** Beancount records `os.path.join(folder, "years/*.beancount")`, which is `...\years/*.beancount` on Windows; the expectation was pathlib's `...\years\*.beancount`. Now Beancount's own join. Our record is the string Beancount globbed (correct: the observation globs that same string).
  - **`..` through a link (`test_fingerprint.py`, 3 cases): Windows' answer, not a disagreement.** Windows removes `linked\..` by the text before it follows the link, so Beancount's glob and its loader ask about the same file (`ws/common.beancount`): with `ext/common` present the glob matches nothing, with `ws/common` present the load has no error, and a file appearing at `ext/common` changes neither the load nor, asking the same question, the observation. The expectations are per OS; on Windows the test asserts the load is unchanged and the observation equals the fingerprint (run 6 confirms the observation's half).
  - **The plugin that writes a module during its own load (`test_plugin_fingerprint.py` 1): Windows' answer, not a disagreement.** On Windows the second import in the same load did not find the module either (`late` not in `sys.modules`). The record keeps the first answer (not found), which is what the load used; the next observation finds the file and differs, so the save gate sees a change. The test now asserts per OS: one import error and the module imported on POSIX, two import errors and no module on Windows; the record and the observation asserted alike on both.
  - **Package data (`test_plugin_fingerprint.py` 1, test premise):** `rates.csv` was written with `write_text` (CRLF on Windows) and compared with `\n` bytes by the plugin; written as bytes now.
  - **A carry past 28 digits (`test_precision.py` 1, test premise; a Beancount behaviour on every OS):** the file was CRLF on Windows, and Beancount 3.2.0's lexer refuses a one-letter currency before `\r` (`Invalid token: 'X'`; reproduced on macOS with `loader.load_string` over CRLF text), so the transaction never loaded. The test writes `\n`. Not our defect: the overlay equals Beancount there.
  - **`contract._normal` used `os.path`, not the path model (product, 1 test in `test_contract.py` and the whole sequence model: 13 headers).** Over the fake (POSIX paths, the POSIX model simulated on Windows) `ntpath.normpath("/L/main.bean")` is `\L\main.bean`, so every preview refused `path_not_normal` and no plan was ever made (reproduced on macOS by pointing `contract.os.path` at `ntpath`). In the product on Windows `os.path` and `host()` agree for the paths Beancount gives, so no real ledger was affected; but the check broke engine/CLAUDE.md's rule "every absolute path goes through `pathmodel.host()`" (S0127's inventory grepped `posixpath` and `/`, not `os.path`). Now `host().is_absolute` and `host().normpath`: the same functions as before on macOS and Linux (`startswith("/")` is `posixpath.isabs`); on Windows it is stricter than `ntpath` in three spellings, a device path (`\\.\`), a lower-case drive (`c:\...`) and the `\\?\` prefix, which it refuses (`path_not_normal`, fail closed; corrected after verifier F2, which found the last two; BL-0087 checks whether a root can reach the engine as `c:\...`). Review row: "Hardening an existing write path" (a gate's input). The contract test's own `odd` path used `/` and was the root itself on Windows; it uses `os.sep` now and asserts it differs.
  - **The copy over the fake (`test_copy.py` 20, `test_create_conformance.py` 5): the documents roots by Beancount's formula.** The copy's "loads the same" resolves each documents root as Beancount does (`overlay.documents_roots`, `os.path`), which on Windows turns the fake's `/s/books/../docs` into `C:\s\docs`, so every copy differed (`load_differs`, or `plugin_modules` when a plugin is named; reproduced on macOS by pointing `overlay.path` at `ntpath`). The product is right to use Beancount's formula. The fake's tests point `overlay.path` at `posixpath` on Windows (`test_copy.posix_documents_roots`, also used by the conformance replay), as `memledger` already does for its loads.
  - **The copy layout's four `document` tests (test premise):** Beancount resolves a `document` path with `ntpath` on Windows, while the module runs with the POSIX model there. They now run in this OS's paths: on Windows the Windows model, paths on `C:`, and absolute lines spelled `C:/...` (simulated on macOS with Beancount's `grammar.path` set to `ntpath`: all four pass).
  - **The checksums' placeholder (`test_checksums.py` 4, the generator's seed test among them; test premise):** a row's JSON and a message that prints an entry hold the case folder with each backslash doubled, so two runs in two temp folders differed. `checksums.normalized` now finds the folder as written, doubled and doubled twice (one spelling on POSIX); a new test pins the Windows spellings (it fails against the base helper). The unit tests' `FOLDER` is a `PurePosixPath`.
  - **`test_preview_ops.py`'s refusal test** named `/l/main.bean`, not absolute on Windows; it names this OS's path.
- **Found while diagnosing, not this slice's (agent): BL-0301.** The copy refuses (fails closed) a ledger whose moved `include`, `option "documents"` or `document` line spells its path with backslashes: its line shapes take no `\` in a string, and a Windows ledger may write `C:\\...`. Before BL-0087.
- **No class (a) finding, and no case where our observation disagrees with Beancount's reads (agent).** Every failure in the fingerprint, ledger-set and module-recording tests was a test premise (Beancount's escapes, its pattern join, a CRLF file) or a Windows behaviour in which the record and the observation follow what the load did (`..` through a link, the second import in one load).
