# S0093: Cache registry (INV-10)

## Brief
- Goal: BL-0010. Build INV-10's enforcement as far as the code it guards exists at M1a: "No resident parsed ledger. Every in-memory cache is per user, evictable and has a bound."
  1. **Inventory first, by behaviour** (what holds memory across requests or jobs, in the sidecar, the engine, the frontend and the shell; library caches included), with counts, recorded below and in ARCHITECTURE.md §2.5.
  2. **One registry:** `app.platform.state_registry` already is INV-10's and INV-11's registry (each entry: owner, bound, eviction; ARCHITECTURE.md §2.5). No second registry.
  3. **The cache registry test** (`backend/tests/architecture/test_caches.py`, extending the globals test's scan rather than a new script): (a) the composition root's long-lived object graph (`app.main.wire` and the log), walked at run time: anything that can change (a dict, list, set, deque, an object with a `__dict__`) must sit inside a registered holder, whose entry declares its bound and eviction; every entry must be reached from that graph (an entry nothing holds is stale); (b) the engine's source, scanned with the globals test's rules for caches: no memoizing decorator, no `global`/`nonlocal`, no module-level name written to after import (the engine is long-lived across jobs, and the globals test scans only `app`); (c) a bound that says there is none (`unbounded`, `none`, `n/a`, ...) is refused.
  4. **No resident parsed ledger in the engine** (`engine/tests/architecture/test_no_resident_ledger.py`): after a save and a rebuild through one `Engine`, no Beancount directive those jobs loaded is still alive. The sidecar never imports Beancount (`scripts/check_engine_boundary.py`), so it cannot hold one.
  5. **An unbounded cache found today:** bound it if mechanical, else stop and report.
  6. **The 54k memory regression check:** BL-0020's baselines do not exist (BL-0020 is open, M11; no baseline is tracked), so it is cut to BL-0020's row; no baseline is invented.
  7. **INV-10's "Enforced by" and status** set as far as the enforcement exists, the planned parts listed with their rows (the pattern the owner chose for INV-06/07 on 2026-11-09).
- Scope of "cache" (from INV-10's words, "Every **in-memory** cache"): on-disk caches (the mirror generations in the app cache, ADR-0015; the engine's bytecode folders; log files) are outside INV-10. They are listed in the inventory with their bounds so the population is complete, and checked elsewhere (the mirror's keep set: publish spec §6).
- Implements: ADR-0011 (no resident ledger; every other cache bounded and registered in the state registry), ADR-0064 (no process-wide state), ARCHITECTURE.md §2.5.
- Capabilities: none changes state.
- Invariants touched: INV-10 (enforcement and status), INV-11 (the same registry; its test shares helpers).
- Risk class / lane: Medium (gates and tests; no ledger write, no finance semantics) / light.
- The bytes it protects: none (no write path; the checks keep caches bounded and the ledger out of memory between jobs).
- Acceptance tests: `backend/tests/architecture/test_caches.py` (new: the real graph and registry pass; planted unregistered dict, list, lazily-grown object, closure-held store, unreached entry and boundless bound each refused; planted engine memoizer, `global`, module-level write refused; the real engine tree clean); `engine/tests/architecture/test_no_resident_ledger.py` (new: the real save and rebuild leave no directive alive; a planted retention is seen).
- Expected doc impact: `design/INVARIANTS.md` INV-10 "Enforced by" and status; `design/ARCHITECTURE.md` §2.5 (the test, the inventory's scope); `design/backlog.md` BL-0010 closed, BL-0020 carries the 54k check, new rows for what the inventory found; `backend/src/app/platform/state_registry.py` docstring; `design/specs/roadmap.md` if it lists BL-0010. No user docs (nothing user-visible).
- Open questions: none for the owner before coding. INV-10's status change records enforcement (the rule text unchanged), following the owner's INV-06/07 choice of 2026-11-09; it is named in the report for the owner to see.

## Decisions
- **One registry, extended** (agent): `app.platform.state_registry` already holds owner, bound and eviction per entry and ADR-0011 names it as the place every cache registers; a second "cache registry" would split one list. The new test reads it; entries now name a class (the docstring said "class or factory"; every entry was a class, and a factory matches no instance the walk can find, so it would read as stale).
- **Run-time walk, not a static scan, for instance state** (agent): the globals test sees module and class level only. Which objects live for the process is a fact of the composition root, so the test builds it (`app.main.wire` and `open_log`, both clocks) and walks what it holds. A static scan of `self.x = {}` could not tell a per-request builder from a long-lived holder. The walk refuses anything that can change outside a registered holder, so a lazily filled slot or attribute is refused too, not only a store present at construction.
- **Three long-lived classes made immutable rather than registered** (agent; mechanical): `Uuid7Ids` and `NoWorkspaces` got `__slots__ = ()` (they hold nothing), `FrozenClock` became a frozen slotted dataclass (one instant; same constructor, same refusal of a naive time; its private `_at` became the field `at`, used nowhere else). Registering them would have put three "holds nothing" entries in a list that should name real state.
- **The engine is scanned by the backend test** (agent): the globals test's helpers live in `backend/tests/architecture/test_globals.py` and the engine's environment cannot import them; reading the engine's source as text from the backend test reuses them without a new script (PROCESS.md §9; the brief preferred extending the existing test). The engine's 46 module-level values that the INV-11 rules would flag are import-time tables (handlers, schema, ISO lists, a `decimal.Context`); the INV-10 rule is the cache forms only: memoizers, `global`/`nonlocal`, and a module-level name written inside a function. A mutating method counts only on a name bound to a container, since `EXACT.add(a, b)` on the `decimal.Context` is arithmetic (found on the first run, with three closure false positives from a scan that descended into function bodies; both fixed and planted).
- **No resident ledger, tested in the engine by behaviour** (agent): INV-10's first sentence had no check. The probe counts live Beancount directives with the garbage collector after the open, a save and the rebuild in one `Engine`; it held on the base (tagged `@regression-guard`), and its twin with a kept `real_load` result proves it sees one. Skips use the one form `check_invariants.py` accepts in an enforcement file (`unittest.skipUnless(sys.platform == "darwin", ...)`): the write path is macOS-only (BL-0087).
- **On-disk caches are outside INV-10** (agent; from its words "Every in-memory cache"): listed in the inventory with their bounds; the one without a bound (old builds' bytecode folders) is BL-0228.
- **The 54k memory regression check is BL-0020's** (agent; BL-0010's own row said it "joins with the baselines of BL-0020"): BL-0020 is open (M11) and no baseline is tracked (`git ls-files` has no baseline, perf or RSS file); BL-0020's row now names the check. Not a deferral of BL-0010's own work: its row assigned that part to BL-0020 from the start.
- **INV-10 marked `enforced`** (agent; the rule text unchanged): the pattern the owner chose for INV-06/07 on 2026-11-09 ("Mark both enforced now, with the unbuilt parts listed as planned under their rows"); that approval was for INV-06/07, so it is named in the report for the owner to confirm or revert for INV-10.
- **Owner, 2026-11-09, in session, on INV-10's status**, choosing "Yes, standing rule (Recommended)": "INV-10 enforced. From now on an invariant is marked enforced when everything that exists today is guarded, with the unbuilt parts listed as planned under their rows; recorded once in INVARIANTS.md's rules with your words. You still see each one in the slice summary." Relayed by the orchestrator. Recorded once under INVARIANTS.md's "Status values", with the INV-06/07 quote beside it; INV-06, INV-07 and INV-10 point to it; IMP-0057. No ADR: it is a status rule of the file, not a change to any invariant's rule (INVARIANTS.md's "Changing this file" asks an ADR for adding, tightening or weakening an invariant).
- **Round 1, F1: the walk is default-deny by the type's layout** (agent): an object is entered only when it is immutable, a function, a lock (`STATELESS_C`), or its type has no storage beyond `object`'s header (`__basicsize__`, `__dictoffset__`, no slot); a container base (`STORES`) is refused even under a frozen dataclass. The heap-type flag cannot tell a Python class from a C one in 3.13 (`collections.deque` is a heap type, checked), so the layout is read instead. Class-level values of each object's classes are walked (staticmethod and classmethod through their function), and a function's `__dict__` (F3).
- **Round 1, F2: the engine scan follows stores, not names** (agent): a store is a module-level name, a class-level name (through the class, `cls` or `self`; a dataclass `field(...)` default is per instance), a default argument (bound to a store, or a container built in place), or a plain local alias of one; writes are item or attribute stores, a class attribute rebound, mutating methods (with the in-place dunders), `heapq`/`bisect`, `setattr`/`delattr`; `globals()`, `vars()`, `locals()` and `sys.modules` are refused anywhere (the engine uses none). The real engine tree stays clean. The forms still out of reach are stated in the test's docstring and in INV-10's text.
- **Round 1, F2: the `Engine` object is checked at run time** (agent): it is the engine's one long-lived object besides the server loop's channel (its two pipes); the probe now compares what it holds before and after the jobs (its attributes, a dict's contents copied), with planted stores made at construction and added on first use. Walking it with the backend's walker is not possible from the engine's environment, and the equality is stricter for the one object there is.
- **Round 1, F5: bounds as configuration is BL-0229 (M2)** (agent): `QueuePolicy`, `RestartPolicy` and `LogSettings` are injected values with desktop defaults but are not read from any configuration yet (no settings store exists); the stderr tail is the constant `STDERR_LINES = 200`. The row reads them from the deployment's settings when `settings.yaml` exists and makes the registry name each setting. Whether a fixed diagnostic ring may stay a constant is left to the owner (the row says so); not decided here.
- **Round 1, the verifier's question on `create`** (agent, checked): the create's load check (`ledger.create._real_load`, Beancount's own `real_load`) runs in an engine the sidecar retires after the job: `app.platform.engine_jobs.create` answers the job with `WorkResult(self._answer(answer))`, whose `ran_user_code` defaults to True (`scheduler.py`), and the queue retires such an engine (`queue.py` `_retire_engine`; `protocol/create.py` docstring). The open, the rebuild and the save answer `ran_user_code=True` too, so today every loading job's engine ends after it; the probe is a second line (its docstring says so). The create's load is the same `real_load` the probe's rebuild exercises, so it is not added as a fourth job.
- **Tests first** (run against `321be18d`'s source, an archive in the session scratchpad with the new tests copied in): `test_every_long_lived_store_of_the_product_is_registered` failed for both clocks (`Uuid7Ids`, `NoWorkspaces`, and `FrozenClock` under `--frozen-clock`); the planted cases are new tests of new code. Passing on the base, tagged `@regression-guard`: the engine tree scan, the bound check over the real registry, the no-resident-ledger probe.

## Verifier
- Round 1, head c862c4d7: 0H/2M/3L, one suggestion, one question. Fixed in the round-1 commit; repros copied in, run green, removed.
- F1 Medium: the walk took any object with no `__dict__` and no slot for empty, so `deque`, `defaultdict`, `array`, `SimpleQueue` and a slotted dict subclass passed. Fixed: default-deny by the type's layout, container bases refused, locks allowed by name; the repro's cases are must-not-pass tests.
- F2 Medium: the engine scan missed class-level stores, defaults, aliases, `heapq`/`bisect`, `globals()`/`sys.modules`, in-place dunders; the `Engine` instance was unchecked. Fixed: stores followed through classes, defaults and plain aliases; namespace calls refused; the `Engine` object compared before and after the jobs in the probe; the remaining forms stated as limits in the test and in INV-10.
- F3 Low: a function's `__dict__` was not walked. Fixed.
- F4 Low: "never", "forever", "no eviction", "not evicted" anywhere in an eviction, "infinite", "without limit", "no maximum" in a bound. Fixed.
- F5 Low: INV-10's "bounds are configuration values" was neither checked nor planned. BL-0229 (M2), listed as planned on INV-10; whether the stderr tail may stay a constant is the owner's, named in the report.
- Suggestion (the engine-held retention twin): adopted as `test_one_directive_kept_in_an_engine_module_is_seen`.
- Question (`create`'s load check): its engine is retired after the job (Decisions); not added.
