# S0127: Windows paths and types (M1b slice 8b-1, BL-0279 with BL-0260)

## Brief
- Goal: the first part of the Windows port (owner, 2026-11-17: "1a, split yes, keep red"). Make the engine, the write-intent journal, the protocol and the sidecar handle **Windows paths** correctly, make the engine's test suite **load and run on Windows**, and bring the **Windows type-check pass** to 0 errors. Windows keeps refusing every file operation (`engine.unsupported_platform`) after this slice: no write is turned on (BL-0280, BL-0281, BL-0206 follow).
- **Paths.** Today the engine's paths are POSIX strings throughout: the journal, `core/paths.py`, the writer, `posixpath` in the save, create, copy and copy layout, the protocol, and the sidecar's `engine_protocol.py`. The work:
  - **One path model, selected per OS:** drive letters and UNC roots, `\` separators, the `\\?\` prefix where Windows needs it, absolute and normalized as each OS defines it.
    - On macOS and Linux every path, journal record and protocol message is **byte-for-byte as today**: no format change, no journal version change. A test pins this with the existing journal and protocol fixtures.
  - **Names Windows cannot hold safely are refused** before anything is written, with a named reason: reserved device names (`con`, `prn`, `aux`, `nul`, `com1`-`com9`, `lpt1`-`lpt9`, with or without an extension) and names ending in a dot or a space. S0126's probe shows that without the prefix Windows opens the device or drops them.
    - State whether this check runs on every OS (a ledger that names `aux.beancount` cannot move to Windows) or only on Windows. That is the agent's call, recorded with its reason. It must never change what macOS or Linux write today.
  - **Path keys and folding:** `path_key` folds by ordinal upper case on Windows unless the folder is case-sensitive (engine-jobs §6.3), and `same_path` compares as Windows does. The real-disk side comes with BL-0280; this slice builds and tests the pure functions.
  - **The protocol** carries Windows paths unchanged, and the sidecar's codec reads them.
- **Tests on Windows:**
  - the engine suite loads on Windows: `tests/conftest.py`'s `time.tzset()` has a Windows equivalent, or the time-zone setting is done another way, so tests still run in Los Angeles (INV-07);
  - every real-disk write-contract test that cannot run before BL-0280 skips on Windows with one line naming BL-0280;
  - pure tests run;
  - the `engine-windows` CI job then runs and passes what can run.
- **Types (BL-0260):** `Windows` joins `scripts/pyright_platforms.py`'s platforms. Each POSIX-only module states its platform once or selects per platform, as `ledger_engine.fs.this_os` does, so `pyright --pythonplatform Windows` reports 0 errors in `engine/` (166 on 2026-11-17) and `backend/` (265). No `# type: ignore` to silence a platform name; a module that is POSIX-only says so at its top.
- Implements: ADR-0061 and its amendment of 2026-11-14; ADR-0069 (the Windows split); engine-jobs §6.3 (paths and keys), §14; BL-0279, BL-0260.
- Capabilities: none changes status.
- Invariants touched: INV-01, INV-22 (no write path changes behaviour on macOS or Linux: pinned by their unchanged gates and the byte-for-byte fixtures), INV-07 (tests still in Los Angeles on Windows), INV-23, INV-24.
- Risk class / lane: High / full: it touches the write path's paths on every OS. Review budget row: **Hardening an existing write path** (the path handling of the existing write path; no write is turned on): the verifier; the data-safety red team joins when the verifier reports a class (a) finding; a fresh round after any product fix.
- The bytes it protects: every path the journal records and every path the writer touches on macOS and Linux, which must not change; on Windows, nothing is written yet.
- Mechanism questions (PROCESS.md §3 step 2): which real setup needs this? Every Windows user (owner, 2026-11-14). Can a policy forbid the rest? Names Windows cannot hold are refused, not supported. Fix-round history of the family: the paths (S0061's `path_key` and canonical path rounds, S0089, S0100-S0102), the ports (S0125, S0126). **At the first class (a) finding, the policy option goes to the owner before the first fix round.**
- Acceptance (tests first; each fails on the base commit on Windows or macOS, as it applies):
  - the Windows path model's pure tests: drive letters, UNC, `\\?\`, normalization, reserved names and trailing dots and spaces refused, and `path_key` and `same_path` on Windows;
  - the journal and protocol fixtures of macOS and Linux byte-for-byte unchanged;
  - `pyright_platforms.py` 0 errors on Darwin, Linux and Windows;
  - the `engine-windows` CI job: the suite loads, pure tests pass, and real-disk tests skip naming BL-0280;
  - the macOS and Linux gates green;
  - the CI run, named by date and order, in the journal.
- Expected doc impact:
  - engine-jobs §6.3 (Windows paths and the refused names), §14, §15 (a Windows limit if any);
  - ARCHITECTURE.md (the path model's place);
  - `backend/CLAUDE.md` or `engine/CLAUDE.md` if a module's platform rule needs a line;
  - BL-0279 and BL-0260 closed or narrowed.
- Open questions: none.
- Base: 2e5b312f.

## Decisions
- The Windows port in four parts, this the first (owner, 2026-11-17, in session: "1a, split yes, keep red"); the ownership rule, the CI runs and the review of the ports are the owner's decisions of 2026-11-16 (S0125's journal). This slice changes no write on any OS, so it takes the Hardening row, not New write path.
- **Tests first (agent).** On the base 2e5b312f, macOS: `tests/fs/test_pathmodel.py`, `tests/ledger/test_journal_windows.py`, `tests/test_protocol_paths.py`, `tests/ledger/test_copy_layout.py` (its new Windows test; the module's import) and the backend's `tests/platform/test_engine_protocol.py` (`is_absolute`) fail at import: no path model, no codec function. The byte pins (`tests/test_posix_path_pins.py` with `tests/fixtures/posix_path_pins.json`, written once on the base by the module's own writer), the Los Angeles summer-time and child-process checks (`tests/test_runs_west_of_utc.py`) and the architecture guard against `simulating` in the product pass on the base: `@regression-guard`. Windows on the base: the 2026-11-17 run 1 (S0126; no engine, backend, scripts or CI change between its head and the base) shows the suite does not load (`time.tzset`), so every Windows acceptance test fails there by not running.

- **The path model's shape (agent).** One pure module, `ledger_engine.fs.pathmodel`, with two models: `POSIX` is the engine's rules before S0127 moved there unchanged (`split`, `join`, `check_name`, `normpath` by `posixpath`, `/`-joins), `WINDOWS` the new one. `HOST` is chosen once by `sys.platform`; every caller asks `host()` at the moment of use (a `ContextVar` whose default is `HOST`). On Windows the root (`C:`, `\\server\share`, `\\?\Volume{...}`) is the first component, so `Resolved.existing`, the journal's component checks and the writer's joins work unchanged with a root element; `is_root` replaces `not parts`. The prefix `\\?\` is taken off on input and added back by `extended` for the adapter (BL-0280). Rejected: a `model` parameter threaded through the journal, `core/paths`, the writer, the save, create, copy and copy layout (dozens of signatures for a choice that never varies inside one process); per-path detection (a `C:\x` would become absolute on macOS: a behaviour change).
- **The reserved-name check runs on Windows only (agent).** It is part of the Windows model's `check_name`, so it runs wherever a Windows path or name is split, reads included (a read of `aux.txt` without the prefix reads the device). On macOS and Linux it never runs: those systems hold such names, and refusing them there would change what macOS and Linux save, which the brief forbids; a ledger that names `aux.beancount` moving to Windows is a Copy concern (named in BL-0280's scope via engine-jobs §6.3). Refused set: `CON PRN AUX NUL CONIN$ CONOUT$ COM0-9 LPT0-9` and the superscript-digit forms, any case, spaces before the extension ignored (CPython's `ntpath.isreserved` takes the same set without `COM0`/`LPT0`; refusing those two too is fail-closed), a trailing dot or space, `<>:"|?*` and control characters. A name that is both reserved and trailing (`nul `) reports `reserved_name`.
- **Folding on Windows (agent).** `FoldRule` gains `upper` (default False, so every POSIX rule is the same value as before). `ordinal_upper` maps each 16-bit character to its one-character upper case, its one-character title case where the upper case is several characters (`ᾀ` to `ᾈ`, the simple mapping), else itself; no normalization. The journal's accepted key rules and its widest folding are per model (`rules`, `wide`): POSIX's are the old values; Windows' widest adds upper case, since NFD and casefold alone keep U+0131 and `I` apart (the exhaustive test over the 16-bit range shows it).
- **Relative paths are `/` on every OS (agent).** A plan's relative paths (create's and copy's files), the copy layout's places and its rewritten ledger lines use `/`; `handles.join` turns them into the OS's form. A rewritten include on Windows is therefore `outside/r.beancount`, which Beancount joins with `os.path` there.
- **The protocol (agent).** The contract states both spellings (`ABS_PATH_PATTERN`, `^(?:/|[A-Za-z]:[\\/]|[\\/]{2})`); each engine validates its own OS's (`HOST_ABS_PATH_PATTERN`: `^/` on POSIX, so validation and its error types there are exactly as before, pinned). The Windows pattern has no look-ahead: pydantic's regex engine refuses it (found by `tests/fs/test_this_os.py`, which imports the engine as on win32). No protocol version change: no POSIX message changes. The sidecar's codec takes `is_absolute(value, platform)`, the same rule.
- **The time zone on Windows (agent).** Windows' Python has no `time.tzset`, and its C runtime reads `TZ` only as a process starts and only in its POSIX-like form. So the CI step sets `TZ=PST8PDT` before Python starts; `tests/conftest.py` on Windows passes it on to every child and refuses to run (`UsageError`) unless the zone is UTC-8 in January and UTC-7 in July (Los Angeles with US summer time). Two new checks pin Los Angeles with summer time in the run and in a child process.
- **Tests on Windows (agent).** Real-disk write-contract modules already skipped off macOS and Linux; their reasons now name BL-0280. Modules with POSIX-only names skip with `raise pytest.skip.Exception(...)` before them (pyright follows a `raise`), reasons in `engine/tests/windows_pending.py` (BL-0280, BL-0281, no FIFO, no uid). Tests over the in-memory fake run on Windows with the POSIX model (`tests/conftest.py`: a module that names the fake): the fake is a POSIX file system; every other test there runs with Windows' model. `test_process.py`'s handshake, pipe and stdin tests stay on for Windows.
- **The sidecar on Windows (agent).** BL-0260's backend errors were all in the engine supervision and the app folder (BL-0281). Each function that uses a POSIX-only name starts with `if sys.platform == "win32": raise NotOnWindowsError` (an `OSError` `ENOTSUP`, `app/platform/adapters/windows_pending.py`): per-platform selection, no `# type: ignore`. In `backend/tests/domain/test_dates.py`, an INV-07 enforcement file where `check_invariants.py` refuses a skip, the east-of-UTC fixture raises on Windows instead (it fails, never passes).
- **Tests changed after the test-first commit (agent).** `test_journal_windows.py` built its record at import, outside the simulated model (fixed: built in each test), and lost one case, a key spelled with `/` (the journal compares components on every OS, as POSIX does with `//`; refusing it would need a normal-form rule POSIX does not have). `test_protocol_paths.py` was rewritten when the design moved from a validator reading `host()` to a static pattern per OS (both versions fail on the base at import). The Windows copy-layout case now expects `/` places. The privacy scan made the sample folders `Books` instead of `Users`; that turned the case-only-rename case of `same_path` into a different-name case, which the `same-path-ignores-names` mutant found; restored.
- **Concept counters (agent).** Two reviewed sites: the drive-letter regex in `pathmodel` and the sidecar's Windows absolute-path regex read as account grammar (a colon); they are not.

- **Windows skips and the invariants' enforcement files (agent).** The 2026-11-17 run 3 left 38 engine tests failing on the runner for reasons beyond the path model (BL-0282, new: Beancount's own paths, globs and messages on Windows, and a real `entry_keys` bug: a path used as `re.sub`'s replacement text) and four INV-10 tests that run real jobs (BL-0280). A first try skipped them from `tests/conftest.py` by name; `check_invariants.py` refuses any skip form in a conftest above an enforcement test, and in an enforcement file, so that was withdrawn. Now the skips are in the test files themselves: six modules that load real ledgers with Beancount throughout skip whole on Windows, and single tests elsewhere skip in their own body (the 2026-11-17 run 4 showed a by-name inventory from one run misses tests: 46 failures, many not in run 3's list); the eleven in enforcement files (`test_overlay.py` 2, `test_parity_corpus.py` 5, `test_no_resident_ledger.py` 4; twelve cases) do not skip and keep the `engine-windows` job red. Whether a Windows-only skip form may be allowed there is a gate loosening, the owner's: `design/inbox/20261117-windows-skips-in-enforcement-files.md` (recommendation: keep red until BL-0280 and BL-0282). The `entry_keys` fix is not made here: on macOS and Linux it would change what a ledger whose path holds a backslash does (today the contract refuses `fault`), which the brief forbids; it is in BL-0282.

- **CI runs (the manual run on `next`, by date and order; the 2026-11-17 run 1 is S0126's baseline).** Every run: repo-checks (pyright on Darwin, Linux and Windows for both packages), backend, engine on Linux, frontend, shell and oracle-unit green.
  - 2026-11-17 run 2 (head f37f8204): `engine-windows` red at collection: the suite loads (the TZ check passes), seven modules fail to import (worlds built at import with POSIX paths under Windows' model; `test_darwin.py` importing `fcntl` before its platform statement); 12 skipped, each line naming its row.
  - 2026-11-17 run 3 (head 242c4939): 177 failed, 9863 passed, 189 skipped: POSIX-path pure tests, Beancount on Windows, architecture tests' separators and encodings, the INV-10 real-disk jobs.
  - 2026-11-17 run 4 (head 86f1e98d): 46 failed, 9954 passed, 230 skipped: more tests over the fake that load real ledgers, the twelve enforcement cases.
  - 2026-11-17 run 5 (head 2a089535): 13 failed, 9764 passed, 206 skipped: the twelve enforcement cases (the inbox question) and one plugin-fingerprint test, now skipped (BL-0282).
  - 2026-11-17 run 6 (head 9bf202c0): 12 failed, 9764 passed, 207 skipped: exactly the twelve cases in the enforcement files (`test_no_resident_ledger.py` 5, `test_overlay.py` 2, `test_parity_corpus.py` 5), held for the owner's answer; everything else that can run passes; Linux and the other jobs green.

## Hand-off (PROCESS.md §3 step 4; ADR-0057)
- **Checks added or changed that accept, tag or refuse**, each with its must-not-pass test:
  - Windows `check_name` (reserved device names with or without an extension, a trailing dot or space, invalid characters, not one name): `tests/fs/test_pathmodel.py::test_windows_refuses_reserved_device_names_with_or_without_an_extension`, `..._a_name_ending_in_a_dot_or_a_space`, `..._characters_windows_names_cannot_hold`, `..._what_is_not_one_name`; and the look-alikes it must take (`test_windows_takes_names_that_only_look_like_reserved_ones`).
  - Windows `split` (relative, drive-relative, rooted without a drive, POSIX, device paths, a UNC root without a share, `/` under the prefix): `test_windows_refuses_what_is_not_an_absolute_path_it_can_hold`.
  - POSIX `check_name` and `split` take every name and path they took before, Windows' refused names included: `test_the_posix_model_takes_every_name_it_took_before` and the byte pins `tests/test_posix_path_pins.py` (the paths, the journal's bytes and refusals, the copy layout, the protocol's validation and its error types, all written on the base).
  - Windows `same_path` (a case-only rename, another name, another drive, another normalization, not a path: moved): `test_windows_same_path_compares_as_windows_gives_paths_back`.
  - The journal on Windows (a key not folded by Windows' rule, a reserved or trailing name, a POSIX path, two names of ours only Windows' upper case makes one): `tests/ledger/test_journal_windows.py::test_a_key_not_folded_by_windows_rule_is_unreadable`, `test_a_record_naming_a_path_windows_cannot_hold_safely_is_refused`, `test_the_widest_folding_on_windows_takes_ordinal_upper_case_too`.
  - The protocol's absolute path per OS (another OS's path, relative ones, a device path): `tests/test_protocol_paths.py::test_this_engine_refuses_another_oss_paths_and_relative_ones`, `test_the_windows_pattern_agrees_with_the_windows_path_model`; the sidecar's codec: `backend/tests/platform/test_engine_protocol.py::test_the_codec_reads_each_oss_absolute_paths`.
  - The product never simulates another model: `tests/architecture/test_platform_selection.py::test_the_product_never_simulates_another_path_model`.
  - The time zone on Windows (`tests/conftest.py` refuses a run that is not in Los Angeles): `tests/test_runs_west_of_utc.py` (summer time, a child process); run on the runner.
- **Loosening mutants** (`scripts/mutants.py`, plans in the session scratchpad; each run against the copy's own sources): engine 10 tried, 10 killed after one fix: `no-reserved-names`, `no-trailing-dot-space`, `no-invalid-chars`, `device-paths-taken`, `unc-without-share-taken`, `windows-keys-take-casefold` (the journal takes a casefolded key on Windows), `windows-wide-without-upper`, `posix-takes-any-absolute-spelling` (the POSIX engine takes the contract's union), `journal-relative-paths`, and `same-path-ignores-names` (names compared without case), which survived the first run: the privacy rename of the samples had turned its case-only case into a different-name case; restored, then killed. Sidecar 2 tried, 2 killed: `codec-takes-any-windows-text`, `codec-takes-device-paths`.
- **Population claims.** (1) "Every absolute path goes through the model": the inventory is a grep of `src/` for `posixpath`, `startswith("/")`, `"/".join`, `"/" + `, `rpartition("/")`, `rstrip("/")` and `split_absolute` at the base (about 60 sites in 21 modules: `handles`, `writer`, `save`, `create`, `copy`, `core/copy_layout`, `core/journal`, `core/paths`, `core/ledger_set`, `rebuild`, `restore`, `recover_all`, `history`, `mirror/publish`, `protocol/{server,preview,recovery}`, `fs/{port,posix,darwin,linux}`); after: every absolute-path site goes through `host()`, and the `/` that remain are a plan's relative paths (`create`'s files, `copy._reserved`, the copy layout's places) and the POSIX adapters (`fs/posix`, `darwin`, `linux`, POSIX-only by their platform statement). `os.path` uses (`protocol/app_folder`, `protocol/server`'s lock, `protocol/recovery`) are the OS's own module and stay. (2) The Windows type errors: 166 in `engine/` and 265 in `backend/` on the base (the brief's counts; 2026-11-17), 0 after on all three platforms.
- **Stated limits:** engine-jobs §6.3 "Limit (Windows names)", "Limit (Windows upper case)" (not probed against a real `$UpCase` table; BL-0280).
