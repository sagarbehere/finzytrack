# S0024: The Beancount domain vectors

## Brief
- Goal: write the last of M1's specs (roadmap §1 "Left" item 3; backlog WS-QA item 3; BL-0002): Beancount-generated domain vectors, the expected values the M1a code on both sides must reproduce so that INV-02 holds. Each vector is an input plus Beancount 3.2.0's output, produced by running Beancount in the oracle environment, committed as data, with a committed generator and a keep-honest test that reruns it. No product code.
- Implements: ADR-0024 (Beancount is the oracle; FE tolerance port pinned by vectors, "indeterminate" for postings that need booking; account grammar = parser grammar, not `account.is_valid`; one PriceIndex with price-map semantics; `gen_domain_vectors.py`), ADR-0023 (display precision per commodity from `dcontext`), ADR-0025 (as-of semantics for current values), ADR-0031 (every booking method Beancount books), ADR-0004 (Beancount 3.2.0 pinned; an upgrade reruns the generator); review:L3 §1.4, §1.5.2; review:L3-verif §2.4, §2.5, §3.2.
- Vector families (decided under Decisions): `tolerance` (transaction balance: inferred tolerances, residual, balanced, the one interpolated leg, the FE port verdict), `balance` (balance-assertion tolerance), `account` (account-name grammar incl. custom roots and Unicode), `currency` (currency grammar), `price` (price map: as-of, inverse, same-day duplicates, future dates, implicit prices), `precision` (`dcontext` display precision), `booking` (lot matching per booking method).
- Capabilities: none change status.
- Invariants touched: INV-02 (its vectors; it stays `pending` until the M1a code passes them on both sides; INVARIANTS.md is not edited), INV-23 (synthetic data only).
- Risk class / lane: **Medium** / specialist (finance semantics are pinned, but the expected values are Beancount's own output and nothing is computed by our code yet; the only app-defined rule is the FE port's "indeterminate" predicate, from ADR-0024). One verifier round; a fresh round after a High fix or three or more Medium fixes (ADR-0058, data-touching class because it pins finance meaning).
- Acceptance tests: `scripts/oracle/tests/test_domain_vectors.py` (the committed vectors equal a fresh run of the generator; every structural check passes on the real files; one must-not-pass test per check). Fails on the base commit (nothing exists there).
- Expected doc impact: new `design/specs/kernel/vectors.md` (Orientation block); `design/specs/README.md`; `corpora/README.md`; `ARCHITECTURE.md` tree (the generator's real home: the oracle environment, since the main sidecar has no Beancount, ADR-0054); `.githooks/pre-push` and PROCESS.md §6 if the test is fast (IMPROVEMENTS.md entry); BL-0002's row (done / owed by M1a); roadmap §1. INVARIANTS.md unchanged. No user docs (no user-visible behaviour).
- Open questions: none expected to hit the rubric (every family is Beancount's semantics under ADR-0024/0023/0031); checked per family while writing the cases, recorded under Decisions.
- Base SHA: 28df4a2c.

## Decisions
- **Families** (agent; from review:L3 §1.4 and §1.5.2, review:L3-verif §2.3–§2.5 and §3.2, ADR-0024, ADR-0023, ADR-0031, the WS-KERNEL acceptance line): `tolerance`, `balance`, `account`, `currency`, `price`, `precision`, `booking`. Left for later, each with its reason, in the spec's "Left for later": amount and date parsing (our parsers, not Beancount's semantics; with WS-KERNEL/L4), roots declared after first use (M3), same-day prices across files (the sidecar, M7/M8), labels, merges and partial lot specs (M8 lot picker), period balances against `bean-query` (M3), `infer_tolerance_from_cost` with total costs or prices.
- **Where they live** (agent): `corpora/vectors/` (one data set read by both sides) and the generator in `scripts/oracle/` (its environment pins Beancount 3.2.0, ADR-0004). Deviation from ARCHITECTURE.md's tree, which put `gen_domain_vectors.py` in `backend/scripts/`: the main sidecar has no Beancount (ADR-0054) and the engine environment does not exist yet; ARCHITECTURE.md corrected in this slice. Not registered in `check_generated.py` (stdlib, no Beancount), as S0022's goldens: the oracle test is the regeneration check.
- **Which tolerance is pinned** (agent): the balance check's, `infer_tolerances` on the booked postings (`validate_check_transaction_balances`), not the `__tolerances__` metadata the booking step computes earlier; the spec names the difference as a trap.
- **The port's verdict** (agent, implementing ADR-0024 as written): a posting needs booking when any number or currency of its units, cost or price is left out (Beancount's `MISSING`); `indeterminate` if any posting does, else Beancount's balanced/unbalanced. A transaction Beancount drops although every weight is known is refused by the generator, since the port could not reproduce it. The checks also require `balanced` to agree with Beancount's own "Transaction does not balance" error.
- **Grammar validity is the whole text** (agent): an account name is valid when the probe `open` line parses with no error and opens exactly that name (`Assets:Bank USD` parses cleanly as an open with a currency); a currency code when both a `commodity` probe and an amount probe parse to exactly that code (`USD ;x` parses as `USD` plus a comment). Both found by self-mutation.
- **The frontend's local grammar precheck** may accept a negative name or code but never refuse a positive one (agent; ADR-0024 rejects a frontend grammar port, review:L3-verif §2.4 recommends a lenient precheck). Not a finance meaning, so no escalation.
- **Numbers** are plain-notation strings with Beancount's exponent kept; consumers compare by value except where written scale is the point (agent).
- **No escalation** (agent): every expected value is Beancount 3.2.0's output under ADR-0024, ADR-0023, ADR-0025 and ADR-0031; the one app rule (indeterminate) is ADR-0024's. Checked per family: tolerance and balance (ADR-0024: "the backend wraps `infer_tolerances` / `compute_residual`"; the balance directive's tolerance is the same oracle), grammar (ADR-0024), price map incl. same-day and inverse merging (ADR-0024 "price-map semantics, same-day duplicates resolved (last by id)"; the vectors show "last" is Beancount's entry order), precision (ADR-0023 `dcontext`; both statistics pinned, no choice made), booking (ADR-0031).
- **The mirror's `prices` note** (S0021) said the same-day winner would be fixed with the PriceIndex; it now points to the vectors (`surface.toml`, regenerated `surface.md`) (agent).
- **Pre-push runs the test** (about 1 s): IMP-0024, a tightening (agent).
- **Fix round (verifier round 1):** the port is served the written numbers always (the price number is the written text; left-out parts are `"MISSING"`, unwritten parts `null`); its verdict is pinned only when Beancount reports no error other than "Transaction does not balance", and is `not-pinned` otherwise (coordinator's decision, agent-level within ADR-0024, 2026-10-25). `indeterminate` takes precedence over `not-pinned`: it depends on the written input alone, so the port can always report it (agent). The vectors, not ADR-0024's "(last by id)" or ADR-0031's "requires the lots to be named", are the authority on same-day prices and on STRICT booking; both ADR texts are the owner's and go to the coordinator's inbox question (not edited here). The balance family gained a consistency check (its tolerance and difference must explain Beancount's verdict), from the verifier's `balance_consistency.py` note (agent).
- **Risk class Medium kept** (agent): the values are Beancount's own; a wrong vector would mislead M1a code, but every vector is regenerated from Beancount on every push.

## Verifier
- Round 1, head 5317a341 (class Medium kept): PASS WITH FINDINGS. Fixed in the fix-round commit on top of 9ddb134c; a fresh round follows (three Medium on finance semantics, ADR-0058).
- F1 Medium: the inverted point wins on a shared day wherever it is in the file, and `price/both-directions` could not tell that from "last in entry order"; the surface note stated the wrong rule. Fixed: `price/inverted-wins-anywhere` (80, not 76), `price/double-inversion` (`75.99999999999999999999999998`); `surface.toml` note corrected and `surface.md` regenerated; the spec cites the vectors as the authority; behaviour checks "the inverted point wins wherever it is in the file" and "a point inverted twice".
- F2 Medium: only `{}` stood for costs the port cannot weigh. Fixed: `tolerance/partial-cost-currency-only` (`{USD}`), `-date-only` (`{2020-01-01}`), `-number-only` (`{100}`), `-total-only` (`{# 5.00 USD}`), all indeterminate, each a named behaviour.
- F3 Medium: the port was served Beancount's abs() of a refused negative price and given a verdict for an entry Beancount refuses. - F6 Low: STRICT and STRICT_WITH_SIZE book `{}` without a named lot, unlike ADR-0031's table; noted in the spec (the M8 lot picker starts from the vectors); ADR text left to the owner.
- Round 2, head 62c459c7: F1-F6 confirmed fixed, golden changes justified; three Medium and one Low new. Fixed in the round-2 commit on top of 2fbb1cac; a narrow round 3 on the fix diff follows.
