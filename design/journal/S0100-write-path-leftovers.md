## Decisions
- **BL-0163 (a), the app folder** (owner, 2026-11-10, in session: "Sidecar makes it once (Recommended)"; the option as put: "The sidecar creates the app folder at start and syncs its parent once; if that fails, the app says so at start. The save and recovery then write and sync only inside the app folder, never in or above its parent."). Recorded in ADR-0012's amendment of 2026-11-11 (ADR-0012 owns the journal and its machine-local folder; no ADR owned the S0063 parent sync, which lived only in spec §6.1 step 8) and in spec §6.1 step 8 and §15 ("Limit (app folder)"). Agent details: `app.main` calls `app.platform.adapters.app_folder.prepare` first, before the log; one `mkdir` of the leaf, mode 0700, never its parents; the parent `F_FULLFSYNC`ed at every start, made now or not (an earlier start may have died before its sync), and for a link at the path the real folder's parent too, since the save and recover-all follow it. A failure exits 2 before the handshake with `msg:start.app_folder` on stderr (the shell's screen is BL-0095). `--app-local-data` is now any absolute path. The engine's `hold_engine_lock` and the sidecar's `wait_engine_lock` make only `locks/` (they used `makedirs`, which would have made a missing app folder in its parent). Recovery, create and copy were checked: none opens or syncs the app folder's parent (`recover_all.list_journals` reads `local/`, the restore and Keep write only in `local/<key>/journal`, copy only reads journals, create writes only in its target). The mirror publish still makes the app *cache* folder in its parent (`publish.open_folder`): that is the cache, not the app folder, and it holds no journal; unchanged (agent).
- **BL-0162** (agent): the check is the journal's own (`journal.case_twin`, sharing `_temps` and `_clash` with `encode`'s `duplicate_temp`), so the writer cannot drift from the record's fold; a writer-side fold of the canonical paths would have refused two long names that differ in case, whose hashed temps `encode` accepts. Its outcome is a writer stop, `CHANGE_NOT_SAVED {case_twins}`, not `BadPlanError`: the backlog row named `BadPlanError`, but a `BadPlanError` past the gate reaches the sidecar as an engine refusal and is read from disk as `engine_stopped`, so it cannot carry "a code and a §11 text". Deviation from the row's wording, recorded here. The record is now also encoded before the backups (the backups' names are computed first, `_backup_names`), so no rule of the record's check can fail after an effect. On macOS a volume always folds normalization, so only case differences reach it; the text says "capital letters".
- **BL-0163 (b)** (agent): `NotSaved.changed` (writer and save), `SaveResult.changed` (protocol, additive; engine and sidecar ship together, `PROTOCOL_VERSION` unchanged), `SaveAnswer.changed`, `ChangeNotSavedDetails.changed` (required: the OpenAPI export refuses defaults). The re-hash goes on past a file it cannot read, so a later changed file is still named. §6.6's outcome now carries its changed file in `changed` too, so one rule words all reasons: "Your ledger is unchanged." / "<file> was changed by another program." / "could not check". **(c)** moot: since S0071 (ADR-0068 D3) the save takes no lock in `locks/`; a broken `locks/` folder fails the engine-lock wait, which already answers `ENGINE_UNAVAILABLE {cannot_start}` with a logged `engine.start_failed`. **(d)** the gate reports a file the observation found `Unreadable` (and the plan did not) as `io_error` naming it.
- **BL-0182** (agent): the text is right; two @regression-guard sweeps pin it (no editor: every failure point of a rolled-back save cut by a death at every later effect reads unchanged; with an editor: a changed file under `.resolved` holds the editor's bytes, never the save's).
- **BL-0183** (agent): a new `PausedReason`, `earlier_unfinished`, for the refused `unfinished_save` only (step 1 and step 4); this save's own open journal (`not_saved` with `open_journal`, `unfinished`, §6.6's `.open`) keeps `unfinished_save` and the Reopen text.
- **BL-0187** (agent): `Reason.FOLDER_APPEARED`, `path` the file, `entry` the folder; "Try again" is honest (the next save writes into the folder that is now there).
- **BL-0223** (agent): F4 "from its folder"; F3 "Before you copy a file back, check that the drive is the one you saved on.", said only when a backup is named; F2 the row's suggested promise ("copying every listed old version returns the whole ledger to before the save") is **not** made: only the files behind the drive are listed, another file may have no checked backup, and a created file may stand. The sentence warns instead: "Other files of this save may hold its new version, so copying back only a missing file can leave your ledger part old, part new.", said only when the save has other files.
- **BL-0224** (agent): `Keep(j)` enabled only when the journal is torn or `\A f \in jr[j].files : ~(PathMoved(f) /\ Guarded)` (`PathMoved` and `Guarded` moved above `Keep`, since TLA+ defines before use). A torn journal names no folder, so Keep of it is not guarded, as in the code (`recover_all.keep` reads no record and so no folder). **Fidelity look** (PROCESS.md "Designs checked by a formal model"): code → model, the code refuses `path_moved` for any recorded folder of the record not at its path (files' folders and created folders), the model's only moved folder is R's (`env.lnk`), so the guard covers the code's refusal in every world; the code also refuses when the journal folder itself moved, which the model does not model (the journal folder is never a link there): no new gap. Model → code, the guard only removes Keep steps, so no state the code cannot reach is added. Vacuity: `W_Keep` and `W_KeepTorn` still reached. In the replay, the link worlds (`S_recover_link`, `S_recover_relink`) now walk no Keep (the link never goes away there), as the code would refuse it; Keep is walked in `S_recover` (26) and of a torn record in `S_recover_torn` (4). Small tier: 65 configurations, all as expected (8 TLC workers, 3 min 51 s). Corpus regenerated (269 traces); `keep_not_over_link`, the replay's `keep_refused_path_moved` stop and `test_keep_over_a_link_is_refused_where_the_models_keep_is_not` dropped. The mirror-publish corpus was regenerated too: it records the engine-jobs generator's hash.
- **BL-0225** (agent): **F2** the open job is replayed as every second publish job (the first in odd traces, the second in even, so each position is both): `opening.run` with a load that returns `overlay.Loaded` stamped with what it read (`P_Obs` = `P_Read`); the replay now walks an open ending published, incomplete, moved and by a death (`BRANCHES`). `SqliteStore.build` stays walked by `test_publish.py` (SQLite does not run on the fake). **F4** is unreachable by design: the model's `SaveCut` runs only between jobs, so a job meets an `.open` journal only from its start, where the code pauses before its load; MAPPING.md says so and names the covering test. **F5**: the suppressed assert is replaced by a real one; each self-test regex now matches only its own divergence (the messages were read from each mutant's first failure). **F1 parked on a new finding (BL-0243)**, see below. **F3** (a recover world holding a `.part` journal) needs a boot `.part` state in the model: left open on the row.
- **New finding BL-0243 (High-class, not fixed here)**: building F1 (a recover world whose outside edit is not durable, `EdDurable` FALSE, as the model's own `S_fs_weak_recover`), the replay failed on `ResolveDurable`. Probe on the fake (`tests/ledger/worlds.world()`: the save crashed right after `inc/a.bean`'s swap and its folder sync; an editor rewrote `a.bean` in place with its pre bytes, unsynced; `recover` → `Resolved`): 4 of the power-loss states under `.resolved` hold `a.bean` at the save's post bytes (1) or torn (3), while `main.bean` is at pre. The restore syncs folders, not file data, before `.resolved`; the model's `SyncNamed` lets a folder sync make every named file's data durable, which POSIX and APFS do not promise. Not an owner question under the rubric (a durability tightening of code and model, no format or invariant change), so no inbox file: a backlog row (BL-0243, M1a, open) for the orchestrator to schedule as the next slice; the F1 world and its replay changes were reverted so nothing lands half-built.
