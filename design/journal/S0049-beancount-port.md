# S0049: The Beancount gateway, the overlay load and the domain vectors in the engine

## Brief
- Goal: the first piece of M1a's read core (roadmap §M1a, BL-0002 first). In the engine (`engine/src/ledger_engine/ledger/`): `beancount_port` as the single Beancount gateway (the only module that imports `beancount`, a typed facade); `overlay.load(root, overlay, policy) -> LoadResult`, the replica of Beancount 3.2.0's `loader._parse_recursive` with Beancount's own sort, booking, transformations and validation after it (ADR-0010); `LoadPolicy` with the desktop body, consulted at every point ADR-0010 names; `grammar` (account and currency grammar, transaction and balance-assertion tolerances, ADR-0024); an engine test that reads `corpora/vectors/vectors.json` and passes every vector the engine consumes through the overlay load and these wrappers; the AST test of the port wrappers' call sites (ARCHITECTURE §2.4 rule 4); INV-02 from `pending` to `enforced`.
- The cut (agent; each piece tied to its source):
  - **In:**
    - `beancount_port`: parser calls (`parse_file`, `parse_string`), the load stages the replica needs (sort, `booking.book`, `run_transformations` with the `pythonpath` insert, `validation.validate`, options aggregation, the input hash), `is_encrypted_file`, the tolerance and residual calls, the balance-assertion tolerance and the balance before an assertion, display precision from `dcontext`; the Beancount types other engine modules need, re-exported (ARCHITECTURE §2.2 "typed facade"). It exposes no `load_file` or `load_string` (see Decisions: Beancount's pickle cache).
    - `overlay.load`: files with candidate bytes are parsed from those bytes with `report_filename` set to their path, the rest from disk (ADR-0010); a candidate path counts as existing; returns `Loaded` or `LoadRefused` (EP-13). Refused, never partly loaded: any encrypted file in the include tree, the root included (ADR-0059; BL-0003 names the root case); a candidate for an encrypted-looking file (ADR-0010 guardrail 4); an overlay path the parse never reached (fail closed, INV-22: otherwise a candidate would be validated without its text); anything the policy refuses.
    - `LoadPolicy`: one parameter, consulted for every file read (root and includes), every user plugin, every `insert_pythonpath` directory and every documents root, before any plugin runs (ADR-0010; WS-ISOLATION "seam now", L11-02, L11-06, L11.M-1).     - ADR-0010 guardrail 1 on the D1 write corpus (S0020): `load(root, {})` and `load(root, disk bytes)` equal Beancount's `load_file(root)` on every `load` case; a candidate equals `load_file` after the same bytes are written; both `refuse` cases are refused and `asc-plain` loads (write-corpus spec promise 4). Planted must-not-pass cases in the same file.
    - INV-02: `enforced`, its Enforced-by line naming the files that now exist; `check_invariants.py` counts `engine/tests/` as a pushed test root (the pre-push hook runs it since S0035), with its meta-test.
  - **Out (later slices, with backlog rows):** the `price` family's consumer is the main sidecar's `PriceIndex` (L3-12, M7), not the engine; the frontend tolerance port (L3-09, M5) passes the vectors when it is built. The concept counters that EP-03/EP-23 and ADR-0024 name (`scripts/concept_counters.py`, never built, no backlog row): a new row. The hosted `LoadPolicy` body (ADR-0041, post-v0.4); confining `document` directive paths (not roots); a candidate for a new file reached only by a glob include (the replica globs the disk, so it is reported as not reached and refused; new files arrive with M3's mutators): a new row. The mirror build and publish (BL-0057, BL-0113), mirror reads, the QueryRunner and the workspace-format core: the next M1a slices. Nothing calls `overlay.load` over the protocol yet; the mirror-build slice runs it inside an engine job (`TODO(BL-0109)` at the module).

## Decisions
- **The cut** (agent): one slice for the gateway, the overlay load, the policy seam and the vectors, since the engine's vector wrappers need a full load and rule 4 allows a full load only in `overlay.py`; building the port without the overlay would have meant a `load_string` wrapper the rule forbids. Cut to later rows: the concept counters (BL-0116, never tracked before), a candidate for a new file reached only by a glob (BL-0117), R4's real-loader wrapper (BL-0118), the parity corpus (BL-0003 stays open).
- **No `load_file` or `load_string` in the port** (agent; ADR-0040 "No pickle cache is read or written next to a ledger"; L1-09). Read in Beancount 3.2.0's `loader.py`: `load_file` is wrapped at import by `pickle_cache_function`, which unpickles `.<root>.picklecache` from the ledger's folder when it exists (a file there runs code when unpickled), deletes it when stale, and writes a new one after a load of 1 s or more (a 54k ledger); with the cache off (`initialize(False)`), `delete_cache_function` still deletes that file. The replica reads only ledger files, so the port needs neither. This closes L1-09 for every path that exists. R4 (`design/specs/engine-jobs.md` §6.7 step 2) asks for "a full `load_file`": it must be Beancount's real loader (comparing the replica with itself could not catch replica drift) but not `load_file`: the uncached `loader._load`, as a load stage of the reconciliation job, BL-0118. ARCHITECTURE §2.4 rule 4 and step 5 of §9.2 now say so; the engine-jobs spec is being amended by the owner and is not edited here (BL-0118 names it).
- **Two classes of port function** (agent; ARCHITECTURE §2.4 rule 4): `LOAD_STAGES` (sort, book, transformations, validation, options aggregation, default options, input hash, the loader's own error) reachable only from `ledger/overlay.py`; `WRAPPERS` (parser-only and semantic calls) anywhere in the engine. Every public function of the port is in exactly one set (tested), so a new wrapper cannot slip past the rule unclassed. The AST scan fails closed on what it cannot follow: a star import, `getattr` on the port, or the port module used as a value.
- **The overlay takes bytes** (agent): candidates are `bytes`, parsed with `parse_string(bytes, report_filename=path)`, so a candidate is exactly what a write would put on disk (CRLF, no final newline, any encoding Beancount accepts); `parse_string` with `str` would re-encode.
- **Refusals refuse the whole load** (agent; ADR-0059 "never partly loaded"; INV-22 fail closed; EP-13): `LoadRefused(reason, subject)` for an encrypted file (Beancount's own `is_encrypted_file` on disk, the root included), a candidate the parse never reached, and each policy point. The policy is asked about plugins, `pythonpath` and documents after the parse and before booking, so a refusal comes before any user code runs (tested with a plugin that writes a marker file). The documents root is asked even under `plugin_processing_mode raw`, where Beancount would not scan it: a stricter question, never a looser one.
- **A candidate for a `.gpg` or `.asc` file is refused, in any letter case** (agent; ADR-0010 guardrail 4 "writes to encrypted files are refused"). After the write, Beancount judges such a file by its name and its new first bytes; deciding that for a candidate would mean re-implementing `is_encrypted_file` on bytes (EP-03). The conservative rule costs only writes to a plain `.asc` ledger file, which no mutator needs. Reversible if one ever does.
- **A candidate the parse never reaches is refused** (agent; INV-22): otherwise the write contract would validate the set without the candidate's text and call the result valid. A candidate for a file that does not exist yet is reached through a plain `include` of its exact path (as `glob` would find it after the write); one reached only through a glob pattern is refused for now (BL-0117, M3's first file-creating mutator).
- **The `LoadPolicy` seam closes L11-02, L11-06 and L11.M-1** (agent; WS-ISOLATION "Seam now: a `LoadPolicy` argument on every load path (includes, documents roots, plugin allowlist, `insert_pythonpath`, encrypted files)"; "Deferred (`post-v0.4`): ... the hosted LoadPolicy body"). The one load path has the argument; a refusing test policy shows each point refuses the load. Encrypted files are not a policy point: ADR-0059 refuses them under every policy in v0.4.0. The verifier may judge the closures premature; the rows then reopen.
- **`input_hash` kept** (agent): `_load` sets `options["input_hash"]`, a stat of the included files that only the pickle cache reads. The replica sets it too, so an empty-overlay load equals `load_file` in every option; for a candidate it describes the disk, not the candidate, which the tests that write after predicting leave out of the comparison and say why.
- **Pinned replica** (agent; ADR-0010 guardrail 2): a test hashes the source of `loader._parse_recursive` and `loader._load` in the installed Beancount and checks `BEANCOUNT_VERSION == "3.2.0"`; an upgrade fails it until the replica is re-mirrored and the hashes updated.
- **Local type stubs** (agent; EP-22 keeps pyright strict with no local loosening; S0037 Decisions planned them): `engine/typings/beancount/` declares the untyped Beancount names the engine and its tests use (`loader`, `interpolate`, `inventory`, `realization`, `balance`, `validation`, `booking`, `defdict`), each read from the 3.2.0 source. A stub replaces its whole module for pyright, so the port imports names from leaf modules.
- **Account grammar probe** (agent; ADR-0024): `parse_account(text, roots)` renders the ledger's five root names as options and asks the parser to open `text`; valid when there is no error and exactly `text` is opened (a newline or comment in `text` cannot pass). The roots come from the load's options, so a refused root option (`account/lowercase-root-option`) is the load's error, reported once; the test compares the load's errors plus the probe's with the vector's. `parse_currency` probes a `commodity` and a `price` directive, as the vectors do.
- **Vector and corpus tests loop, not parametrize** (agent): `check_invariants.py` refuses a computed `parametrize` in an INV enforcement file (an empty list would switch the test off); each family is one test that runs every vector both ways (disk, overlay) and names every failure, and asserts how many ran.
- **`engine/tests/` counts as a pushed test root** (agent; a correction to `check_invariants.py`): the pre-push hook has run the engine's pytest since S0035, but the check did not know it, so no engine test could enforce an invariant. Meta-test added.
- **Observed, not changed here:** importing a ledger's local plugin writes `__pycache__` beside it and keeps the module in the engine's `sys.modules`; the engine-jobs spec already plans the `-B` spawn flag and replacing an engine that ran user code (§5.1; BL-0109).
- **Deviation from ENGINEERING.md:** none known. EP-23's concept counters (BL-0116) are not built; that is a gap since M0, not a deviation of this slice.
