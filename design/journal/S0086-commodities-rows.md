# S0086: The mirror's `commodities` rows, and a complete build

## Brief
- Goal: build the mirror's `commodities` rows (BL-0120), so a build is complete: `rows.COMPLETE` True, `Built.complete` True, `meta.build_complete = 1`. The mirror publish (BL-0113, the next slice) refuses an incomplete build (`design/specs/mirror/publish.md` §4 step 4), so it needs this first. One row per commodity the ledger declares or uses; `is_currency` (cash 1, holding 0) by ADR-0025's amended rule, with the owner's answer on which ISO 4217 codes count as cash: every code that was ever a country's money, current and historic; metals, funds and accounting units are holdings unless the ledger declares `asset-class: "cash"`. The ISO list is pinned in the engine with its source, publication dates and file hashes, derived by a script from the ISO 4217 Maintenance Agency's own List One (current) and List Three (historic); nothing is fetched at run time. BL-0057's second half (per-table checksums over the corpus) is judged here and cut if large (Decisions).
- Implements: ADR-0025 and its amendment of 2026-10-25 (cash or holding), the owner's answer `design/inbox/answered/20261028-iso-currency-list.md` (option 2), ADR-0048 (v0.2.2 table and column names kept), ADR-0015 (a build that is not complete is never published), ADR-0024 (Beancount decides: the rows are a projection of the load); spec `design/specs/mirror/README.md` ("`is_currency`", "Metadata JSON") and `surface.toml` (`commodities`, `meta`).
- Capabilities: CAP-DATA-MIRROR (stays partial: the publish is BL-0113), CAP-INV-ASSET-CLASS (the mirror's half of the cash-or-holding rule; the screens and Allocation by Asset Class are M8), CAP-QUERY-SURFACE (the `commodities` view now has rows).
- Invariants touched: INV-05 (a build says truthfully whether it is complete; the publish relies on it), INV-21 (the `Commodity` directives' metadata JSON goldens now pass through the mirror), INV-23 (the pinned list is public reference data; no real data), INV-02 (Beancount only through the port).
- Risk class / lane: **High / specialist lane (finance)**. It sets what `is_currency` means for every commodity of every existing ledger: ADR-0025's one-time reclassification lands here (a USD bank account in an INR ledger becomes cash; an undeclared `VTI` becomes a holding; gold `XAU` stays a holding). It changes what a number means, so the finance red team applies (PROCESS.md §4). No ledger write, no write path, no user data written: no data-safety red team.
- The bytes it protects: none (no write path). The outcome it keeps truthful: the cash/holding split of every commodity, and `build_complete`, which the publish trusts.

## Decisions
- **The owner's rule** (owner, 2026-10-29, in session, answering `design/inbox/answered/20261028-iso-currency-list.md`, option 2): "Yes co every code that was ever a country's money (for currency codes that count as cash), moving BL-0119 to M4, to keeping the per-file locks as a second line and having retry recover first." (the other parts of the sentence answer other questions). Applied as the inbox file's "To apply" says: every ISO 4217 code that was ever a country's money, current and historic, counts as cash; precious metals, funds and accounting units are holdings unless the ledger declares `asset-class: "cash"`, which decides first; the list is pinned in the engine with its source date.
- **The source** (agent): the ISO 4217 Maintenance Agency's own files (SIX Financial Information AG): List One (current codes, published 2026-09-17) and List Three (historic codes, published 2026-01-01), downloaded on 2026-11-08 from the Agency's URLs, recorded in `ledger_engine.mirror.core.iso4217` with each file's SHA-256, so anyone can download the same files and check the pin. No copy existed on this machine (no `pycountry`, `babel` or ISO data file in the system folders; Java's and ICU's currency tables are derived copies, and incomplete for historic codes), so the files were fetched once, at development time, from the Agency itself; the engine fetches nothing at run time. The two files are not committed (their redistribution terms are not stated; the code list derived from them is facts, and the hashes identify the files).
- **Derived, not hand-typed** (agent): `engine/scripts/gen_iso4217.py` renders the module from the two files; `test_the_pinned_module_is_what_the_script_renders` refuses any hand edit of the module that the script would not produce; a refresh is download, rerun, review the diff. The rule, per code (the script's docstring): ISO's own fund flag (`IsFund`, spelt `true` in List One and `WAHR` in List Three) → not cash; ISO's non-country entries (`ZZnn_...`) → not cash; a few codes classified by hand; any other `X` code stops the derivation; every other code is a country's money. Anything the rule cannot place (mixed fund flags, an unknown flag value, a code both a country's and a `ZZ` entry, a new `X` code, a hand-classified code missing from both lists) stops it, so an update never classifies a new kind of code silently.
- **The codes classified by hand, each by the owner's own terms** (agent; the verifier and the owner can see each here and in `NOT_CASH`):
  - not cash, accounting units of international bodies, never a country's money: `XDR` (IMF Special Drawing Right), `XUA` (African Development Bank unit of account), `XSU` (the SUCRE regional payment unit), `XEU` (the ECU, a basket of currencies, never notes or coins);
  - not cash, listed under a country but not that country's money, of kinds ISO flags as funds elsewhere: `ECV` (Ecuador's inflation-indexed Unidad de Valor Constante, the kind of unit Chile's `CLF` is, which ISO flags a fund), `USS` (US Dollar Same day, a settlement variant; its sibling `USN` is flagged a fund), `CHC` (WIR Franc for electronic, the WIR Bank's complementary money; `CHE`, `CHW` are flagged funds);
  - cash, `X` codes that are money countries use: `XAF`, `XOF` (the two CFA francs), `XCD` (East Caribbean dollar), `XPF` (CFP franc), `XCG` (Caribbean guilder).
  - Judged cash without a hand rule, because they were a country's money though in a special market or form: the dual-market variants `BEC`, `BEL` (Belgian convertible and financial franc), `LUC`, `LUL` (Luxembourg's), `ZAL` (South Africa's financial rand), `ESA`, `ESB` (Spanish peseta accounts); the redenomination and transition codes (`BGJ`, `BGK`, `CSJ`, `ROK`, `GEK`, `LTT`, `UAK`, ...). These are rare in a personal ledger and an `asset-class` overrides each.
- **A consequence to know** (agent): a code outside ISO 4217 is cash only through `asset-class` or `operating_currency`: the offshore yuan `CNH`, a stablecoin `USDT` or `BTC` are holdings by default. That is the amended rule as written (ADR-0025, "else it is a holding"); stated in the README's "`is_currency`".
- **The row set gains the balance-assertion currency** (agent; the table was `draft`): the spec's own reason for the row set is "so a join on any currency column finds its row", and `balance_assertions.amount_currency` is a currency column (a zero assertion on a new account names a code nothing else may use). A code named only in metadata, an `open` directive's currency list or a `custom` directive gets no row: none of those is a currency column of the mirror. The table's status moves to `decided` with the owner's answer in.
- **A second declaration** (agent): the last in entry order is kept, as Beancount's own `getters.get_commodity_directives` and v0.2.2's exporter do; Beancount reports the duplicate in `ledger_errors`.
- **`asset-class` and `name` as text** (agent): their Python text (`meta_text`), as the ids read metadata; a number or a flag is never stored as a number (v0.2.2 bound the raw value: a `Decimal` would have failed its export). A blank `asset-class` (empty or spaces) is not a declaration, so the next rules decide; v0.2.2 treated spaces as declared (a holding), but v0.2.2's rule was the operating-currency whitelist, so nothing released depends on it. A non-text value is declared and is not `cash`: a holding.
- **A plugin's currency that is not text is no commodity** (agent): `used_codes` drops a currency that is not text (a plugin can hand over `Amount(1, None)`; Beancount's own failed bookings are dropped before the rows, checked). Without the filter the sort of codes raises and no mirror is built (`test_a_currency_that_is_not_text_names_no_commodity`). The same filter on `operating_currency` was dropped: the option is always a list of text (EP-30).
- **`COMPLETE` stays, True** (agent): the brief's goal. Every build now says `build_complete = 1`, so the publish's refusal of an incomplete build (`publish.md` §4 step 4, the model's `P_Check`) guards a case no build produces today. Whether it stays is BL-0113's call (EP-30: what requirement does it serve?), recorded in `publish.md`'s mechanism table; not changed here, since it is the publish's design and its model.
- **BL-0057's checksums cut from this slice** (agent): they stay on BL-0057 (open, M1a). Reasons: they need their own design (which of the 32 corpus roots: 19 write cases, 12 INV-21 cases, the oracle's ledger; the encrypted and plugin cases; the absolute paths inside the metadata JSON, `documents.filename` and `ledger_options` made relative; the build date and stamp fixed) and a judgement of what a whole-table hash adds over the row tests, which already pin every row rule; the publish (BL-0113, the critical path) needs only `COMPLETE`; and a tooling golden would blur a finance-semantics slice's review. BL-0120's row says so.
- **The slice ID** (agent): the S0085 documents planned the publish's code as "S0086"; the orchestrator gave S0086 to BL-0120. The current-state documents (`publish.md`, `MAPPING.md`, `ARCHITECTURE.md` §8.3, the roadmap, BL-0113's row, the publish meta-test's docstring) now name BL-0113 instead of a slice number; S0085's journal and the answered inbox file keep their words (history).
- **The privacy scan** (agent): the two SHA-256 values sit under a key named `sha256` (`Source(sha256=...)`), the scanner's designed form for a hash pin; no allow mark.
- **Engineering principles:** no deviation. The pinned module is rendered in `ruff format`'s shape, so it is formatted and linted like any other file, not excluded.
- **Tests first:** written before `rows.py` changed. On the base behaviour (the list present, `rows.py` unchanged) 30 tests failed: all of `test_commodities.py`, `test_a_build_with_every_table_is_complete`, `test_meta` (`build_complete` `0`), `test_the_directive_metadata_goldens` (no `Commodity` rows); with the list and the script removed, as on 6cd6af7a, `test_iso4217.py` and `test_commodities.py` fail at collection. `test_a_currency_seen_only_as_a_cost_has_a_row` was added after the mutant run (below); it fails on the base too (no rows).
- **Measured** (synthetic only): the 54k demo ledger builds in 1.2 s (rows 0.95 s), as in S0050; it and the small demo use only `USD` (`is_currency` 1), so the demo ledgers exercise little of the rule; the tests carry it.
- **Round 1, owner decision** (owner, 2026-11-08, in session, relayed by the orchestrator; the owner chose **"Held at cost = holding (Recommended)"**): "A code that any lot in the ledger holds at cost ({...}) is a holding, unless it is an operating currency or declares asset-class: \"cash\". Uses the ledger's own structure, no names. Fixes AMD/BND/BEL/ZAL as people record stocks. Cost: a foreign currency deliberately held at cost to track forex gains (USD {83 INR}) becomes a holding unless declared, as it was in v0.2.2. A ticker recorded without cost (10 BEL @ 250 INR) stays cash, with the docs saying so." Recorded with the 2026-10-29 answer as ADR-0025's amendment of 2026-11-08 (red team F6: that answer had no ADR record). It answers red team F1 and F2 (rubric items 2 and 4: it changes what `is_currency` means and ADR-0025's rule).
- **The final rule's order** (agent, red team F4; **decided by the owner in round 2**, "Operating first; tag wins", below; stated in the ADR amendment as an agent reading): (1) an operating currency is cash, whatever its `asset-class` (ADR-0025: "a non-ISO reporting currency is never demoted"; `asset-class: "fiat"` on INR made the reporting currency a holding); (2) a declared `asset-class` decides; (3) a code held at cost is a holding; (4) the ISO list is cash; (5) else a holding. The owner's words name both exceptions to (3); the order between (1) and (2) is the agent's, and is open to the owner.
- **"Held at cost", precisely** (agent): the units currency of any posting that carries a cost after Beancount's booking (`{...}` and `{}` alike, a purchase or a sale from a lot), in any transaction of the ledger, future-dated ones included, since a code is cash or a holding whatever the date (`is_currency` is not "as of today"). Not: the cost's own currency (`VTI {80 EUR}` leaves EUR cash), a price with `@` (`10 BEL @ 250 INR`: the stated limit), a `price` directive, a balance assertion. Beancount drops a transaction whose booking fails before the rows see it, so a failed lot never decides (checked in round 0).
- **The Agency's files are committed** (agent, verifier F1; **superseded in round 2** by the owner's "Keep out of the repo", below): `corpora/reference/iso4217/list-one.xml` and `list-three.xml`, byte for byte as downloaded (SHA-256 equal to the pin; `.gitattributes` `-text`, since they have CRLF line ends). The staged-file guard and the privacy scan accept them (no MANIFEST row: they are public reference data, not an export). `test_the_pin_is_the_derivation_of_the_agencys_files` checks the hashes and that the module is the script's output on them. Round 0 said the files would not be committed because their redistribution terms are not stated; that still holds (SIX publishes them for free download, with no stated licence), and the repo is public. Flagged for the owner with the release gate's legal review (ADR-0043); removing them later only loses the source test.
- **Verifier Q1, for the owner** (agent's classification, explicit): `USS` (US Dollar, same day) and `CHC` (WIR franc, electronic) are **not cash**: settlement and complementary-money units whose siblings (`USN`; `CHE`, `CHW`) ISO itself flags as funds. `ESA`, `ESB` (Spanish peseta accounts), `BEC`, `BEL`, `LUC`, `LUL` (Belgian and Luxembourg convertible and financial francs) and `ZAL` (South Africa's financial rand) are **cash**: tiers of a country's own money in a dual exchange market, and ISO does not flag them as funds. The line between the two is "a unit ISO flags as a fund, or one of its kind" versus "a country's money traded at a second rate". Under the owner's rule of 2026-11-08, `BEL` and `ZAL` held at cost (the Indian stock and the like) are holdings anyway.
- **One golden changed** (agent): `test_any_other_asset_class_makes_even_an_iso_code_a_holding` had `option "operating_currency" "USD"` on the code it declares `etf`; under rule (1) an operating currency stays cash, so the option is now `INR` and the code tested is still `USD` (see Golden changes).
- **Round 2, owner decisions** (owner, 2026-11-08, in session, relayed by the orchestrator, given with the options note PROCESS.md §3 step 7 requires for a second fix round on one mechanism):
  1. ISO source files, **"Keep out of the repo (Recommended)"**: "Remove the two XML files before pushing. The pinned code list (just the codes, facts) stays. The source test runs only when the files are present locally (T-local), otherwise it is skipped with its reason; the hashes in the module still name the exact files. Nothing of uncertain licence becomes public."
  2. Red team round 2 F1, **"Only-at-cost = holding (Recommended)"**: "A code is a holding only when the ledger holds it at cost and never holds it without cost in an account. Stock tickers (AMD, BEL) are always bought at cost: still holdings. USD with a Wise lot plus a plain bank balance: cash, and the lot's USD counts as USD cash too (it is money). Edge: a ticker that also sits somewhere without cost (padded, or transferred plain) counts as cash; the docs and the advice row say so."
  3. Order and the cash tag, **"Operating first; tag wins"**: "(a) An operating currency is always cash (confirm S0086's order). (b) Keep: the declared tag wins over held at cost; docs and advice warn that a fund tagged cash shows as units in cash and leaves net worth."
  All three are in ADR-0025's amendment of 2026-11-08, which now gives the order as the owner's.
- **"Held without cost in an account", precisely** (agent, decision 2): `rows.only_at_cost` reads every posting of every transaction after booking (future-dated and Beancount's padding transactions included). A posting with units holds its units currency **at cost** when it carries a cost (`{...}`, `{}`, a purchase or a sale from a lot) and **without cost** otherwise, in any account (Assets, Liabilities, Equity, Income, Expenses alike: the owner said "in an account", and a plain posting of a code anywhere is the ledger treating it as plain units). A price annotation is not a cost: `10 BEL @ 250 INR` holds BEL without cost, which keeps the owner's earlier "a ticker recorded without cost stays cash". The currency a cost or price is stated in is not held by that posting (`10 AMD {80 USD}` holds AMD only; the USD paid shows on its own plain leg). A code is held only at cost when it is held at cost somewhere and without cost nowhere. `pad` and `balance` directives themselves hold nothing; the padding transaction Beancount inserts does (no cost), which is the owner's "padded" edge.
- **The files leave the repository** (agent, decision 1): `corpora/reference/iso4217/`, its `.gitattributes` line and its `corpora/README.md` paragraph are removed in this commit; the orchestrator squashes the slice's unpushed commits before pushing, so the files never reach the remote (I did not rewrite history). The source test reads the folder named by `FT_ISO4217_DIR` (outside the repo, like `FT_LOCAL_TIER_DIR`), and skips with its reason when the variable is unset or the folder lacks either file. Stated limit: in a run without that folder, a hand edit that keeps the module consistent with itself (the `rerendered-zal-ggp` mutant) is caught by nothing; with it set, the source test kills it.
- **Two expectations from round 1 changed meaning, none their values**: `test_a_foreign_currency_held_at_cost_is_a_holding_unless_declared` is now `..._only_held_at_cost_...` (its ledger holds USD only as a lot, so it still expects 0); `test_a_ticker_recorded_without_cost_stays_cash` holds under both rules.
- **Round 3, owner decision** (owner, 2026-11-08, in session, relayed by the orchestrator; the owner chose **"One more fix: stricter reading"**): "Before landing, change the rule: a posting without cost counts only in an account that never holds that code at cost. Fixes the sale-without-{}, the split and the RSU leg, plus a pad into a lot account. Costs another fix round and a review round on this rule." In ADR-0025's amendment of 2026-11-08, whose rule step 3 no longer says "in any account".
- **Which accounts count, and a conflict for the owner** (agent; `rows.only_at_cost`, `HOLDING_KINDS`): a plain posting counts only in an account of kind Assets or Liabilities (by the ledger's `name_*` options, ADR-0024), and only when that account never holds the code at cost. Why the kinds: the owner's words fix "the RSU leg" and "a pad into a lot account", but each of those ledgers has a second plain leg in an account that never holds the code at cost (`Income:Div -10 AMD @ 80 USD`; the pad's `Equity:Opening -0.04 AMD`). Read as "any account", the rule leaves both tickers cash, against the owner's stated result; read as "an account that can hold a balance", both are holdings, and so is a fee paid in shares to `Expenses`. Two things conflict with this reading and go to the owner: (1) the orchestrator's note on verifier r3 F3 ("an Expenses/Income account: it does count, per the owner's words 'an account'") — under it the RSU leg would not be fixed; (2) round 2's `none_booking` ledger, listed to stay cash, becomes a holding: every USD posting there is in `Assets:US:Bank`, which holds a USD lot at cost (a short sale under NONE booking), or in `Equity:Opening`. No reading meets every listed outcome: "any account" keeps `none_booking` cash but leaves the RSU and pad cases cash too. I chose the reading that gives every result the owner's own words name. Liabilities count, so a plain USD credit card keeps USD cash beside a forex lot.
- **Pads into a lot account are error ledgers** (agent, found here): Beancount reports "Attempt to pad an entry with cost for balance" and still inserts the padding transaction, with plain legs in the lot account and in `Equity`; the tests assert that error and the padding legs.
