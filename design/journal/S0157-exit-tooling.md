## Decisions
- **BL-0254: notes keyed by (group, name, version)** (agent). The row's fork is real only in one shape: a universal resolution forks a package into two lines, one installed here and one bundled on another OS by its `[other_platform]` entry; a venv holds one version per name, and JavaScript and Rust texts are not read here (BL-0086). `evaluate` reads the note of each line by its own version, so a fork with no acknowledgment prints none even when its sibling has one. `THIRD_PARTY_NOTICES` is unchanged (the check passes and writes the same text). R2-F3's test (the installed fork's marker is not evaluated, the other's is) passes on base (`@regression-guard`); it kills the name-only `present` mutant, which made a legitimate fork fail closed as "not evaluated".
- **What `writes` means** (agent; `check_capabilities.py`'s docstring): `ledger` (a file of a ledger set: an entry, a directive, an option line, a new or copied ledger file, or the bytes a restore puts back), `config` (files on disk that are not ledger files: `.finzytrack/`, app settings and the registry, machine-local state, caches, logs, archives, document files), `none` (nothing on disk: reads, checks, browser-only UI state). A row whose flow may write the ledger is `ledger` also when it writes through another row's mutator (a dashboard's Update prices action, the AI's account proposals); a row that only hands drafts on (an import source, natural-language entry, AI events) writes what its own step keeps, and the commit (CAP-IMP-COMMIT, CAP-INV-STAGING) is the ledger writer. Not the `x-ft-writes` vocabulary of the API (ADR-0038), whose `config` is the workspace's tool state for cache invalidation; the words are shared, the scope is the capability's.
- **The check is a test in `scripts/tests/test_intent_table.py`** (agent), beside the table's other structural checks, so T1 already runs it through `run_meta_tests.py`: no workflow change (`check_workflows.py` not needed). `ledger_writer_problems` is pure and tested on small tables.
- **Cut and deferred rows need no line** (agent): they are not built, and `check_capabilities.py` already makes each cite the ADR that decided it; a line for one is refused as redundant. The row's "not built" line is kept for a planned row that will not get a mutator (CAP-WS-IMPORT: ADR-0043 defers it, though its status is still `planned`).
- **Two more kinds of line than the row named** (agent): the sweep found ledger writers that are not use cases: recovery, the contract, the engine jobs, the insert routing, backups and the restore of a run's backup, and the AI proposal store. Each writes ledger bytes with no intended change of its own (they put back recorded bytes or carry a mutator's change), so a mutator row would be wrong; they get `machinery: ADR-nnnn (why)`. Five planned rows whose write is real but unspecified get `pending: BL-0311 (why)`, and the check requires BL-0311 to be an open backlog row; this keeps the population named while its rows are written just in time (README rule 2). Stated limit: the check proves every ledger writer is named, not that a pending row's eventual mutator matches it.
- **Citations added to existing mutator rows** (agent; `caps` only, no `intent` or `meta` changed, README rule 3): `ws.create-ledger` +CAP-SETUP-WIZARD, CAP-WS-CREATE; `ws.seed-demo` +CAP-SETUP-WIZARD, CAP-SETUP-DEMO-MODE, CAP-WS-DEMO; `ws.refresh-demo` +CAP-WS-DEMO; `account.create` +CAP-ACCT-NEW-FROM-PICKER, CAP-AI-LEDGER-WRITES; `account.edit`, `txn.edit` +CAP-AI-LEDGER-WRITES; `txn.bulk-edit` +CAP-TXN-BULK-CATEGORIZE (categorizing replaces the unknown leg's account), CAP-AI-LEDGER-WRITES; `recon.proceed` +CAP-AI-LEDGER-WRITES, CAP-AI-ATTACH-INTENT; `import.commit` +CAP-IMP-FX-PENDING, CAP-AI-ATTACH-INTENT; `import.settle-pending` +CAP-IMP-TRANSFER-PAIR, CAP-IMP-FX-PENDING; `import.link-element` +CAP-IMP-TRANSFER-PAIR; `balance.add` +CAP-RECON-IMPORT-CHECK, CAP-RECON-AUTO-ACCEPT (the offered assertion; BL-0311 records that M6 decides whether it is written with `import.commit` instead); `price.write` +CAP-DASH-ACTION-PRICES, CAP-DASH-SEED-OVERVIEW, CAP-INV-HOLDINGS-VIEW, CAP-INV-COMPARE-BROKER, CAP-PRICE-AUTO; `inv.commodity-metadata` +CAP-INV-AMFI-FINDER (`fetch-symbol`), CAP-INV-EXPOSURE (`exposure`); `inv.booking-method`, `settings.booking-default` +CAP-INV-BOOKING-METHODS.
- **Rows of the safe reading** (genuinely unclear, set to `ledger` and listed): CAP-WS-SETTINGS (hosts Bring in; its documents-folder field may write `option "documents"`), CAP-WS-MULTI-ROOT ("a copied workspace" for another root copies ledger files), CAP-DASH-SEED-OVERVIEW (its text names the Update prices action), CAP-INV-COMPARE-BROKER (its Refresh), CAP-INV-BOOKING-METHODS (changing a method), CAP-AI-ATTACH-INTENT (routes to import or reconcile), CAP-NOTIFY-STARTUP (consented migrations), CAP-DATA-CURRENCY-UPGRADE (a migration that may write `asset-class`), CAP-DATA-MULTIFILE (routing every insert), CAP-DESK-AUTOUPDATE (restoring the pre-upgrade backup); among cut and deferred rows, which need nothing: CAP-HOSTED-WORKSPACES, CAP-BUD-GOALS, CAP-PHONE-UI. Judgement calls that do not touch the check (`config` against `none`): CAP-DOC-ORPHANS `config` (it deletes document files, never ledger files: its row excludes includes, the sidecar and any `*.beancount`); browser-stored UI state `none` (CAP-WS-UI-MEMORY, CAP-DASH-TABS, CAP-DASH-PARAMS, CAP-DASH-METAHINT, CAP-TXN-GRID, CAP-UI-THEME, CAP-UI-SIDEBAR-RESIZE); guards `none` (CAP-WS-SYNC-CONFLICT, CAP-DATA-EXTERNAL-EDIT, CAP-DATA-PLUGINS, CAP-DOC-PATH-SAFETY); CAP-BUD-DIRECTIVE `none` (how budgets are read; their writes are CAP-BUD-VIEW's and CAP-BUD-HISTORY's).
