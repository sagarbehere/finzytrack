## Decisions
- **The hook pin is the whole hook, byte for byte (agent; deviation from the brief's "a list of labels"; since fix round 2, owner direction).** Labels alone let `run "invariants" true`, a gate condition turned false (`if [[ -f backend/pyproject.tomlx ]]`), an `else` that moves checks into a dead branch, or `done <<< ""` that empties the range loop through. Round 1 pinned the code lines without `echo` lines (verifier F1: a message line is code too); fix round 1 pinned every line but blank lines and whole-line comments and relied on the hook being printable ASCII to keep those out safely. That claim was false: the test read the hook with `read_text()`, which turns a lone CR into a newline before the plain-text rule saw it, so `# note<CR>run "invariants" ...` was a comment to bash and a run line to the pin (verifier R2-1). Since fix round 2 each hook's bytes must equal its copy in `scripts/tests/hook_pins/<name>.pinned`, so no part of a hook is outside the pin, and every rule reads the bytes (`read_hook`). A copy rather than a sha256: the copy's diff shows a reviewer exactly what changed, and the failure prints a unified diff; a 64-hex value in a test would also need the secret scan's hash-pin form. A hook change means copying it to its pin in the same commit.
- **With the pin updated, only cheap forms are refused; the rest is review's (agent, owner direction, fix round 2, verifier R2-2).** Any loosening can land by editing a hook and its pin together; the shape rules refuse the cheap ones, deliberately coarse, reading bytes, and without modelling bash's quoting further: `$'...'`, `$"..."` and any backslash before a quote (the forms where the pin's quote reading and bash's differ); the `function` keyword, `()` and a command group `{` anywhere but the `run` definition line (a check in a function that is never called); a `|`, `&` (not `||`, `&&`, `>&`, `&>`) or backtick outside quotes, unbalanced parentheses on a line, or a `(` before a `run` on its line (a check in a pipeline, the background, a subshell or a substitution loses `fail=1`); `break`, `shopt`, `unset`, `enable`, `builtin`, `coproc`, and any `set` but `set -euo pipefail`; and trailing comments are no longer stripped before the rules read a line (bash's `\ #` is not a comment). The pipeline, subshell, `set`, `break` and comment rules go beyond the verifier's forms: they are the same class (a check that runs but whose failure is lost or skipped) and each costs one pattern. Shapes the current hooks need were checked first: none uses any of these outside quotes. What stays review's, like `if false` already was: a check removed, a gate made false, `done <<< ""`, `; fail=1` dropped from a tool-missing branch, and any quoting trick not in this list. The pin's diff makes each of those visible.
- **The statement rule is a new pattern in the privacy scan, not check_staged's (agent).** check_staged's `STATEMENT_LINE` needs a `,;\t|` delimiter, and plant A05 matched it only through the commas inside its amounts; a statement pasted as aligned columns (`01 Mar 2026  RENT  42000.00 Dr`) would pass. The new pattern takes two-space column gaps, `DD Mon YYYY` dates and Beancount directives excluded, needs three lines within six (A05 has three; lines 1, 3 and 6 are an excerpt, lines 1, 4 and 7 are not), and applies to Markdown, text files and messages only: code files will hold synthetic CSV test data (M6), and data files keep check_staged's sniff at five lines.
- **Beancount's own shapes are not statement lines (agent, fix round 1, verifier F4; narrowed in fix round 2, verifier R2-3).** Specs will hold bean-query register output, balance histories and price tables, which are date, text, amount in columns. A line with an ISO date (the only date Beancount writes) does not count when its text holds an account name under one of the five standard roots (case-sensitive: statement narrations are upper case, so `EXPENSES:FOOD` and `UPI:SWIGGY` still count), or it ends in one amount and an ISO 4217 currency code (verifier R3-1; fix round 1 took any commodity-shaped code other than `CR`/`DR`). Fix round 1 also excused a line whose text was one commodity-shaped token with no `Dr`/`Cr` (a price table without commodity codes); the verifier showed it excused real statement rows: hyphenated or dotted upper-case narrations and one-word narrations, with a running balance, in columns, CSV and a Markdown table. That excuse is gone (owner direction: conservative), and a code after the amount excused a line only when it had one amount (R3-1 narrowed it to an ISO 4217 code ending the line), since a statement row usually carries a running balance (a register line with a running balance keeps its account name). A price table without commodity codes carries the allow mark on its lines. Before the change the old and new rules were run over the tree and the whole history: no excerpt hit before or after (Fix round 2). Other date forms (`01 Mar 2026`, `01/03/2026`) are never excused. Stated limit: an ISO-dated statement row with one amount followed by a currency code, or with a narration that is a capitalised account name, passes. Considered and rejected: reading the table header for `price` or `commodity` (more code, and it misses plain-text price lists).
- **The account-number widening needs the word right before the digits (agent).** The existing rule takes 9 or more digits anywhere on a line with an account word (`card`, `bank`, `upi`, ...); 6-8 digits on such a line would hit counts and ids. So 6-10 digits count only right after `a/c`, `acct`, `acc`, `account` or `ac no`, with an optional `No`/`Number` and `#`/`:`/`-`.
- **UPI handles from a fixed list, placeholders excused (agent).** A `name@bank` without a dot is not an email, so the email rule never saw it. Telling a VPA from other `x@y` text needs the handle: the list holds the common PSP and bank handles; an unknown handle passes (stated limit); a handle followed by `.domain` is an email (the email rule's). Placeholder local parts (`name@okaxis`, `user@ybl`) pass so docs can show the shape.
- **New rules checked on the real tree and the whole history before landing (agent).** Over all 395 tracked files, the v0.4 range from the floor (1230 blobs and messages) and the whole history including legacy (5410 blobs): no hit from any of the three rules. No `HISTORY_BASELINE` row was needed.
- **E06 is closed by S0031 for test_contracts.py; the whole `backend/tests/architecture/` folder now has the same ban (agent).** The run-1 plant is refused by the enforcement-file ban (test_contracts.py is on INV-12's line). The folder's other tests (fixme marker, globals, gates) are the gates' own tests and were not on any line; none uses a skip today. "INV-tagged tests" in general was not widened: "tagged" means "mentions the ID", which takes in most of `scripts/tests`, where platform skips are legitimate.
- **E10 compares the remote's base with the pushed tip only, and only the backlog (agent).** A fixme's `due` must equal its row's milestone (S0029), so a fixme cannot move without its row. A fixme re-pointed to another, later row leaves the first row open at its milestone, so the exit run stays red; closing that row falsely is a different class (the verifier's). INVARIANTS.md pending dues are the owner's text and not compared here (stated limit).
