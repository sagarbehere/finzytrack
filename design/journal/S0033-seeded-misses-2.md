## Decisions
- **The hook pin is the hook's code, not a list of labels (agent; deviation from the brief's "a list of labels").** Labels alone let `run "invariants" true`, a gate condition turned false (`if [[ -f backend/pyproject.tomlx ]]`), an `else` that moves checks into a dead branch, or `done <<< ""` that empties the range loop through. So every code line is pinned, in order; a hook change means copying its lines into `PINNED` in the same commit. (Round 1 left `echo` lines out of the pin, and the verifier's F1 showed a message line is code too: `echo ... \` swallows the next check, `; fail=1` drops off a tool-missing branch, `echo x; exit` ends the hook. Since fix round 1 every line but blank lines and whole-line comments is pinned, and leaving those out is made safe by three shape rules: no line ends in `\` (comments included), no quote stays open across a line, and the hook is printable ASCII with tab and newline only, so Python and bash split the same lines and a `#` line is a comment to both.) The shape rules (no `exit 0`, `return`, `trap`, `set +e`, `alias`, here-document, `|| true` or `; true` outside an assignment, no function but `run`, `fail=0` once before the first check, a check only inside `run`, the last line `exit "$fail"`; since fix round 1 also: `exit` only with `1` or `"$fail"`, no `kill`, `eval`, `source` or `exec` but pre-merge-commit's, `fail` only as `fail=0`, `fail=1` or `exit "$fail"`) also run with the pin updated to match, so a loosening that edits both is still refused.
- **The statement rule is a new pattern in the privacy scan, not check_staged's (agent).** check_staged's `STATEMENT_LINE` needs a `,;\t|` delimiter, and plant A05 matched it only through the commas inside its amounts; a statement pasted as aligned columns (`01 Mar 2026  RENT  42000.00 Dr`) would pass. The new pattern takes two-space column gaps, `DD Mon YYYY` dates and Beancount directives excluded, needs three lines within six (A05 has three; lines 1, 3 and 6 are an excerpt, lines 1, 4 and 7 are not), and applies to Markdown, text files and messages only: code files will hold synthetic CSV test data (M6), and data files keep check_staged's sniff at five lines.
- **Beancount's own shapes are not statement lines (agent, fix round 1, verifier F4).** Specs will hold bean-query register output, balance histories and price tables, which are date, text, amount in columns. A line with an ISO date (the only date Beancount writes) does not count when its text holds an account name under one of the five standard roots (case-sensitive: statement narrations are upper case, so `EXPENSES:FOOD` and `UPI:SWIGGY` still count), or its amount is followed by a commodity code other than `CR`/`DR`, or its text is one commodity-shaped token with no `Dr`/`Cr` after the amount (a price table: `| 2026-03-01 | INFY | 1520.35 |`). By shape alone a price-table line cannot be told from `| 2026-03-01 | RENT | 42000.00 |`; it is excused only with an ISO date and no `Dr`/`Cr`, and other date forms (`01 Mar 2026`, `01/03/2026`) are never excused. Stated limit: an ISO-dated statement whose amounts carry a currency code, or whose narrations are single upper-case words, passes. Considered and rejected: reading the table header for `price` or `commodity` (more code, and it misses plain-text price lists), and leaving price tables to allow marks (a mark on every line of every price table in the specs).
- **The account-number widening needs the word right before the digits (agent).** The existing rule takes 9 or more digits anywhere on a line with an account word (`card`, `bank`, `upi`, ...); 6-8 digits on such a line would hit counts and ids. So 6-10 digits count only right after `a/c`, `acct`, `acc`, `account` or `ac no`, with an optional `No`/`Number` and `#`/`:`/`-`.
- **UPI handles from a fixed list, placeholders excused (agent).** A `name@bank` without a dot is not an email, so the email rule never saw it. Telling a VPA from other `x@y` text needs the handle: the list holds the common PSP and bank handles; an unknown handle passes (stated limit); a handle followed by `.domain` is an email (the email rule's). Placeholder local parts (`name@okaxis`, `user@ybl`) pass so docs can show the shape.
- **New rules checked on the real tree and the whole history before landing (agent).** Over all 395 tracked files, the v0.4 range from the floor (1230 blobs and messages) and the whole history including legacy (5410 blobs): no hit from any of the three rules. No `HISTORY_BASELINE` row was needed.
- **E06 is closed by S0031 for test_contracts.py; the whole `backend/tests/architecture/` folder now has the same ban (agent).** The run-1 plant is refused by the enforcement-file ban (test_contracts.py is on INV-12's line). The folder's other tests (fixme marker, globals, gates) are the gates' own tests and were not on any line; none uses a skip today. "INV-tagged tests" in general was not widened: "tagged" means "mentions the ID", which takes in most of `scripts/tests`, where platform skips are legitimate.
- **E10 compares the remote's base with the pushed tip only, and only the backlog (agent).** A fixme's `due` must equal its row's milestone (S0029), so a fixme cannot move without its row. A fixme re-pointed to another, later row leaves the first row open at its milestone, so the exit run stays red; closing that row falsely is a different class (the verifier's). INVARIANTS.md pending dues are the owner's text and not compared here (stated limit).
