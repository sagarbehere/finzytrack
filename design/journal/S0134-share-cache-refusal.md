# S0134: a mirror cache folder on a network share is refused; S0132's share sync mode removed

## Brief
- Goal:
  1. **The refusal** (BL-0298). The open and the rebuild refuse, before any effect in the mirror's folders, when a folder of the mirror's path is on a network share: a named refusal (`cache_on_share`) naming that folder, with one user text saying to keep Finzytrack's cache on a local disk, in place of today's `engine.internal`. The check is in `mirror.publish.open_folder`, which every open and rebuild passes through first (step 0) and which opens every folder handle the publish uses: each handle it opens (the cache folder's parent, the cache folder, `workspaces/`, `<key>/`, `mirror/`) is asked `DirHandle.remote()` right after it is opened and before any effect through it. Nothing else in the publish opens a folder by path: the cleanup's `open_child` never enters another volume (`EXDEV`), and the build writes into `mirror/`'s handle.
  2. **The removal** of S0132's mode, under the owner's condition (below: shown dead and unreachable once (1) is in).
- `DirHandle.remote()` (new on the port; a fact of the volume, asking writes nothing): Windows, the adapter's existing `_Handle.remote()` (`FILE_REMOTE_DEVICE`, which S0132's probe saw True on all three share spellings and False on every local volume); macOS, `fstatfs`'s `f_flags` without `MNT_LOCAL` (smbfs, nfs, afpfs, webdav; the flag `mount` prints as "local"); Linux, the mount's file-system type in a list of network types (`nfs`, `nfs4`, `cifs`, `smb3`, `smbfs`, `ncpfs`, `afs`, `coda`, `ceph`, and FUSE network types by name such as `fuse.sshfs`; the exact list is in code), since Linux has no local flag. Limit (stated): a Linux network file system not in that list is taken as local; its mirror then works or fails as on a local disk (a cache; no ledger byte). The fake: a drive in `MemFS.remote`.
- The bytes it protects: no ledger bytes; the mirror's cache only. The outcome kept truthful: the user is told why there is no mirror, instead of `engine.internal`.
- Mechanism questions (PROCESS.md §3 step 2): Which real setup needs this? None needs a share-hosted cache; the policy forbids it, as the owner chose (below). Has this family needed two or more fix rounds? Yes, the mirror publish: S0085 (1 round), S0087 (2), S0088 (2, 1 High), S0118, S0130 (1), S0132 (2 rounds plus the data-safety red team). This slice adds one check before the first effect and removes a mechanism; at a class (a) finding the slice stops for the orchestrator.
- What each check is a second opinion on (S0122's lesson): the runner test (the CI share's spellings in `FT_TEST_SHARE`, the drive and the UNC path, refused `cache_on_share` with nothing written) is a second opinion on the adapter's `remote()` for every spelling, against the fake's model of it (`MemFS.remote`). On macOS, a test compares `remote()` with `mount`'s own "local" flag on every mounted volume (a second opinion on the `statfs` decoding; no share is mounted on the owner's Mac or the hooks' machine, so it sees local volumes only: stated). The fake's sweeps are a second opinion on the order (no effect before the refusal).
- Implements: ADR-0015 (amendment of 2026-11-19, new: the refusal and the removal), publish.md §2 and §11, engine-jobs §11 (a new row and text).
- Capabilities: CAP-DATA-MIRROR.
- Invariants touched: INV-05 (the mirror published atomically, rebuildable), INV-23 (the refusal's folder is never logged: the decision and the sidecar's log carry the code only), INV-24 (tests on scratch folders and the CI share only).
- Risk class / lane: High / full. Review budget: "Hardening an existing write path" for both parts: the verifier; the data-safety red team joins at a class (a) finding; a fresh round after any fix that changes product code.
- Acceptance tests (new or changed; each fails on the base 6748b610):
  - Over the fake, every OS, both forms (`link`, `pointer`): a remote drive at the cache folder, and at `workspaces/`, `<key>/` and `mirror/` inside a local cache folder: `open_folder` raises `CacheOnShare` naming that folder, and the fake records no effect (no `mkdir`, sync, create, removal or rename) and every byte is as before (`engine/tests/mirror/test_publish_crash.py`).
  - The ops, every OS (they run on the real adapter): `open` and `rebuild` with the adapter's `remote()` answering True for the cache folder (monkeypatched, as S0132's ops tests did for `sync`): outcome `refused`, refusal `cache_on_share`, `refused` the folder, nothing written under the cache; the decision says `refusal` `cache-on-share` (`engine/tests/test_open_ops.py`, `test_rebuild_ops.py`).
  - The adapters: `remote()` False on a local folder (every OS); macOS, agreement with `mount`; Linux, the type list's pure function; Windows runner, True on each `FT_TEST_SHARE` spelling (`engine/tests/fs/`).
  - The runner: `publish_job` into a cache folder on each `FT_TEST_SHARE` spelling raises `CacheOnShare` and leaves the share's folder empty (`engine/tests/mirror/test_publish.py`; S0132's `PortStore` share publish test becomes this refusal test, and `PortStore` goes: it existed only to reach the share mode past BL-0298's build).

- Open questions: none blocking. One consequence to report (not a new decision): on Linux an NFS home makes `~/.cache` remote, so such a user gets no mirror; the save already refuses an app data folder there (`unsafe_app_folder`, owner, 2026-11-17: "C1"), so no setup that saves today loses anything. ### The removal: shown unreachable before anything is deleted
Inventory, by behaviour (`git grep -n -E 'SyncRefused|sync_refused|seen_on_a_share|SyncNote'` outside `design/journal/`, then each hit read):
- **Raise sites of `SyncRefused`:** product 1 (`WindowsDir.sync`, `fs/windows.py`: `ERROR_INVALID_FUNCTION` and `remote()`); fake 1 (`MemDir.sync` for a drive in `MemFS.sync_refused`); tests 2 (monkeypatched `sync` in `tests/test_open_ops.py` and `tests/test_rebuild_ops.py`). No other module raises it.
- **Catch sites:** product 1 (`mirror/publish._sync`); tests 0. No ledger module catches it: `tests/architecture/test_mirror_only_relaxations.py` refuses an `except` naming it anywhere but `mirror/publish.py`, and the grep finds none. `recover_all._tolerant_sync` catches `OSError` and tolerates only `EROFS`; `SyncRefused` was `EINVAL`, and the plain `OSError` the adapter raises without it carries Windows' own mapping of `ERROR_INVALID_FUNCTION` (`EINVAL`), so no ledger caller's behaviour changes (the same `OSError` S0128's adapter raised before S0132).
- **Syncs the mode tolerates:** the 3 call sites of `_sync`: (i) `_ensure`, on the handle `fs.open_dir` gives for the cache folder's parent, the cache folder and `workspaces/` (one call site, three handles); (ii) `open_folder`, on the handle `fs.open_dir` gives for `workspaces/<key>/`; (iii) `publish` step 6, on `mirror/`'s handle, which `open_folder` opened by `parent.open_child(FOLDER)` (no link followed) and refuses on another volume (`EXDEV`).
- **Each is on a handle (1) checks:** (1) asks `remote()` of every handle in (i) and (ii) right after `fs.open_dir` returns it, before its `stat`, `mkdir` or `sync`, and of `mirror/`'s handle after `open_child`; (iii) is that handle. So after (1) no `_sync` runs on a remote volume, and `WindowsDir.sync` raises `SyncRefused` only on a remote volume: the catch is unreachable.
- **A remote volume under a local cache folder:** on macOS and Linux a share can be mounted at any folder, and on Windows a symbolic link (whose local-to-remote evaluation is on by default) can lead a folder of the path to a share (a mount folder takes local volumes only; a junction cannot target a UNC path). The folders above `mirror/` are opened following links (they are the app's), so each handle is the share's own and is checked on its own: hence (1) checks each handle, not only the cache root. Inside `mirror/` nothing is followed: a link is removed as a link, the cleanup never enters a folder of another volume (`st.dev`, `EXDEV`), and no sync runs there.
- **Ledger callers:** none catches `SyncRefused` (above). Removing the subclass leaves `WindowsDir.sync` raising the plain `OSError` it raised before S0132 for every volume, which every ledger caller already meets as a failed sync.
- Conclusion: every part is shown, so all of it goes: the port exception; `WindowsDir.sync`'s raise; `publish._sync`, `SyncNote` and the `note` parameters; the `note` on the open's and rebuild's `Ports`; the decision field `sync_refused` (tables `engine.open` v4, `engine.rebuild` v5: the field gone and the new refusal value); the fake's `sync_refused` and `seen_on_a_share`; the `SyncRefused` half of the architecture test (its `clear_readonly` half stays); their tests and docs. `rename_shared`'s `remote()` check (S0132, BL-0294 (1)) stays: it is the adapter's own fact, used by every caller, and the brief's removal list does not name it.

## Decisions
- The refusal travels as the open's and rebuild's existing named refusal (`outcome` `refused`, `refusal` `cache_on_share`, `refused` the folder), not as a server refusal code, because the sidecar's open turns every `EngineRefusal` into `INTERNAL`, and the named refusals already carry a path for the open's screen (BL-0154) without logging it (agent).
- The path named is the remote handle's own (`DirHandle.path()`): the folder the user would look for (agent).
- `DirHandle.remote()` is a new port fact rather than reading `FolderMark.fs_type` in the publish: Windows' share reports `ntfs` (S0132's P6), so only the volume's own remote fact tells it apart there, and macOS has a flag for it (agent).
- `open_folder` now syncs `<key>/` after it has opened and checked `mirror/`, not before: a share mounted at `mirror/` made one sync of the local `<key>/` before the refusal (caught by the fake's "no effect" test). Opening a handle is no effect, so the durable order is unchanged; the `EXDEV` refusal of another local volume at `mirror/` now also comes before that sync (agent).
- The fake's `create` returned the identity `(1, ino)` whatever the folder's volume, so a generation built on a mounted drive of the fake was always `replaced`; it now returns the folder's device, as `fstat` would (test infrastructure; agent).
- Tests removed with the mode (each tested only `SyncRefused` or `sync_refused`): `test_on_a_share_that_refuses_folder_syncs_the_publish_is_best_effort_and_noted_once`, `test_a_local_volumes_failed_folder_sync_still_fails_the_publish`, `test_a_death_at_every_effect_on_a_share_that_refuses_syncs_never_leaves_a_reader_a_partial_mirror[0|1]` (all `test_publish_crash.py`, with `seen_on_a_share`, `assert_publishes_again_on_a_share`, `share_world`); `test_a_share_that_refuses_the_mirrors_folder_syncs_publishes_*` (`test_open_ops.py`, `test_rebuild_ops.py`: became the refusal tests); `test_a_save_on_a_share_that_refuses_folder_syncs_never_lands` (`test_writer_best_effort.py`: its subject, `MemFS.sync_refused`, is gone; a failed folder sync in the save is in the save's I/O-error sweeps); the `SyncRefused` half of `test_mirror_only_relaxations.py`. `test_a_refused_folder_flush_is_sync_refused_only_on_a_remote_volume` became `test_a_refused_folder_flush_is_a_plain_os_error_on_every_volume` (the removal's second opinion on the runner). The `remote` cases of `test_without_the_posix_rename_the_pointer_swap_takes_the_plain_rename` and `test_a_reader_holding_the_pointer_without_sharing_deletion_refuses_the_swap_and_changes_nothing` went: a cache folder on a share is refused before the swap; `rename_shared`'s own `remote()` refusal stays tested on the fake (`test_memfs.py`) and the runner (`test_windows.py`).
- S0132's share publish test (`test_on_windows_a_publish_into_a_cache_folder_on_a_network_share_lands`, with `PortStore`) became the runner's refusal test (`test_on_windows_a_cache_folder_on_a_network_share_is_refused_and_nothing_is_written`): the setup it served is now refused, and `PortStore` existed only to reach the share mode past BL-0298's build (agent).
- The CI share step now lists a third spelling in `FT_TEST_SHARE`, the UNC path by the machine's name (`\\<computer name>\ftshare`), which the probe alone used before; the probe takes it from `FT_TEST_SHARE`'s list (agent).
- Decision tables: `engine.open` v4, `engine.rebuild` v5 (the input `sync_refused` gone; `refusal` takes `cache-on-share`).
