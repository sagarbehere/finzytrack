# S0027: The demo generator skeleton (L10-18)

## Brief
- Goal: the skeleton of the one deterministic demo/corpus generator (ADR-0022; review:22 §1; review:27 §1(d)): the fragment interface (each fragment anchored at an explicit date and seeded by its own name), the background household fragment, a size parameter (`demo`, `5k`, `54k`), a build step that writes into an output folder with a recorded `generated-for`, and the gates: 0 Beancount errors, a byte-identical rebuild from the same inputs whatever the clock or time zone, one assertion per fragment checked on Beancount's own output. With it, L10-18 (two builds of one tag differ by build month; review:L10 §L10-18, review:L10 §1.5 "never rewrites a tracked source file during the build").
- Implements: ADR-0022 (generator half; the demo workspace and its replacement are M3), ADR-0026 (the demo writes only the metadata contract), ADR-0054 (the main sidecar never imports Beancount: the generator writes ledger text; the Beancount gates run in the oracle environment), EP-10 (no ambient clock or randomness), INV-07 (the anchor is an input, never a "today"), INV-23 (invented names and amounts).
- Capabilities: CAP-DATA-DEMO-GEN (planned → partial; the capability fragments arrive per milestone).
- Invariants touched: INV-07, INV-23 (no change to their text or status).
- Risk class / lane: Medium (test-data tooling and shipped content; no ledger writes, no user data) / light. One verifier round; a fresh one after a High fix or three or more Medium fixes.
- Acceptance tests: `backend/tests/content/test_demo_generator.py` (determinism, clock and time-zone independence, anchor input, seed isolation per fragment, size counts, interface checks), `backend/tests/content/test_gen_demo_script.py` (the build step: anchor required, output folder rules, `generated-for` record), `scripts/oracle/tests/test_demo_generator.py` (0 Beancount errors per size, one assertion per fragment, metadata contract, plausibility).
- Expected doc impact: ARCHITECTURE.md §2 (`content/demo` as built), `backend/.importlinter` (a `content` contract), capabilities.toml/md (row → partial), backlog (L10-18 done, a follow-up item for the later parts), roadmap §1, `.githooks/pre-push` (the new gate; T1's oracle-unit job already runs every oracle test), this journal. ## Decisions
- **Size = the household's transaction count, exactly** (agent): `demo` 2,000 transactions over 36 months, `5k` 5,000 over 60, `54k` 54,000 over 240. The review's numbers are transaction counts (review:backend-survival §6.2 "5k and 54k transactions"; spike S4's 54k corpus had 54,415 transactions). The fixed monthly items are counted first and everyday purchases fill the rest, so the count is exact and Beancount confirms it; later capability fragments add their own transactions on top. The `demo` size is deliberately smaller than the legacy demo (about 5.4k transactions): it is what users browse, and capability fragments will grow it. Consequence for INV-20 ("a write takes at most 1 s at demo size"): that figure was measured on the 5.5k-entry legacy demo, so the perf baseline (BL-0020) should measure "demo size" on the `5k` corpus until the shipped demo is at least that large. Recorded here for BL-0020; no change to INV-20's text.
- **The span ends on the anchor** (agent): from the first day of the month `months - 1` months before the anchor's month to the anchor itself, both inclusive. Nothing is dated after the anchor; the legacy generator's two-month "buffer" of future-dated entries is not carried over (future-dated entries interact with the mirror's as-of date, and nothing asks for them). The composer refuses any fragment directive outside the span.
- **`SOURCE_DATE_EPOCH` is read as a UTC civil date** (agent): the reproducible-builds specification defines it as seconds since 1970-01-01 00:00 UTC; the anchor is a build fact, not a user's "today", so INV-07 does not apply. Strictly decimal digits; anything else is refused. With no anchor at all, the build step refuses (exit 2); it never reads the clock.
- **Own SplitMix64 stream, not `random`** (agent): EP-10 bans ambient randomness; a seeded `random.Random` would be allowed, but its derived methods (`randrange`, `choice`, `uniform`) have changed between Python versions, which would break "same tag, same bytes" across a toolchain bump. SplitMix64 is 10 lines, checked against the published reference values, and seeded from `sha256("finzytrack-demo:" + name)`. Amounts are drawn in whole cents (`Decimal`, INV-06).
- **Assertions are pure checks on a Beancount-free view** (agent): each fragment states its assertion in one sentence and implements `check(view, span, size)`; the oracle-environment test loads the ledger with Beancount and hands the booked transactions over as `LedgerView`. The main sidecar stays free of Beancount (ADR-0054) and no new dependency (beanquery) is needed. When the mirror exists, assertions may become SQL over it (BL-0063).
- **The household writes no metadata** (agent): ADR-0026's contract is a whitelist; the empty set is inside it. The oracle test refuses any key outside ADR-0026 (app-written) and review:28 §4.2 (vocabulary), and names the retired keys explicitly.
- **Output location** (agent): `gen_demo.py` writes only into a new or empty folder, outside the repository or under the ignored `build/` (resolved through symlinks), so a build can never rewrite a tracked file (review:L10 §1.5). It writes `generated-for.json` (`anchor`, `size`, `fragments`, `generator`) beside the ledger; M3's content-pack record may embed it. Acceptance fixtures and perf corpora are generated into temp folders by the tests that need them.
- **Gate placement** (agent, measured): generation and a Beancount load take 0.02 s + 0.05 s (demo), 0.05 s + 0.12 s (5k), 0.6 s + 1.5 s (54k; 8.7 MB, 54,018 entries) on the owner's machine, so every size runs in the pre-push hook (the whole oracle test about 5 s) and in T1 (`ci.yml` oracle-unit already runs every oracle test). The backend tests (determinism, clock, interface, build step) run in the backend job and pre-push.
- **`content` import contract** (agent, a tightening): `backend/.importlinter` gains "content is pure": no `app.platform`, no package above it, and none of rule 3's I/O, clock or randomness modules; each ban has a planted case in `tests/architecture/test_contracts.py`. ARCHITECTURE.md §2.4 rule 7.
- **The build step is not type-checked by pyright** (deviation from EP-22's spirit, recorded): `backend/scripts/` is outside pyright's pinned `include` (src, tests); widening it means changing the pinned config and its test. The script is 90 lines, ruff-checked, and covered by subprocess tests; widening pyright to `scripts/` can come with the next backend script.
- Left for later milestones (BL-0063, from review:22 §1 and review:27 §1(d)): calling the build step from the release build with the tag's time and shipping its output as the demo pack (M3/M11); the `demo:` field check on the capability map; seed dashboards non-empty (M7); the finance red team's oracle totals; the multi-file variant; acceptance fixtures and perf baselines drawn from it; the capability fragments themselves (each milestone, ADR-0022); `development/building.md` §4 on the docs `v0.4` branch at milestone end.

## Hand-off (PROCESS.md §3 step 4; ADR-0057)
(The verifier reads only the Brief, so this section does not steer its attacks; it is the implementer's own record.)
- Checks that accept, tag or refuse, each with its must-not-pass test:
  - `anchor_from_epoch` refuses non-digits, signs, spaces, floats, hex, empty and out-of-range → `test_a_malformed_source_date_epoch_is_refused` (10 cases); UTC day boundaries pinned on both sides by `test_source_date_epoch_is_read_as_a_utc_civil_date`.
  - `anchor_from_iso` strict → `test_an_iso_anchor_is_read_strictly` (6 bad forms).
  - `gen_demo.py` refuses no anchor, a malformed env value, two anchor flags, a non-empty folder, the source tree (5 places incl. the repo root and `build-x/`), a symlink into the tree → `test_without_an_anchor_the_build_refuses`, `test_a_malformed_source_date_epoch_in_the_environment_is_refused`, `test_two_anchor_flags_are_refused`, `test_existing_files_are_never_overwritten`, `test_the_source_tree_is_refused`, `test_a_symlink_into_the_source_tree_is_refused`; must-pass: empty folder, temp folder, `build/`.
  - `generate` refuses non-kebab names (6), duplicate names, a directive after the anchor → `test_a_fragment_name_must_be_kebab_case`, `test_two_fragments_with_one_name_are_refused`, `test_a_fragment_writing_after_the_anchor_is_refused`.
  - `transaction` refuses unbalanced, non-two-decimal, malformed account or currency, unsafe text → `test_an_unbalanced_transaction_is_refused`, `test_a_malformed_posting_is_refused` (6), `test_text_that_would_break_the_string_is_refused` (3).
  - Reproducibility: `test_the_machine_clock_and_time_zone_do_not_change_the_bytes` (two fake clocks, 2000 and 2041, UTC+14 and UTC-10, compared with an unshimmed run), with `test_the_clock_shim_really_moves_the_clock` so the shim is not vacuous; `test_another_anchor_gives_other_dates`.
  - Seeding: `test_adding_a_fragment_does_not_reshuffle_another`, `test_the_order_fragments_are_listed_in_does_not_matter`, `test_each_fragment_draws_from_the_stream_of_its_own_name`.
  - Beancount gates (oracle): 0 errors per size ↔ `test_an_unbalanced_transaction_is_a_beancount_error`; household assertion ↔ a missing salary month, a doubled salary, a salary that is not a credit, plus the unchanged ledger passing; metadata ↔ five retired or unknown transaction keys, a retired posting key, and a vocabulary key accepted; plausibility ↔ `test_a_negative_day_is_found`.
  - Import contract "content is pure" ↔ six planted imports (random, time, pathlib, os, app.platform, app.boot) and an allowed one (app.domain, hashlib).
- Self-mutation: plan in the session scratchpad (`s0027/plan.toml`), command = backend content and contract tests (PYTHONPATH pointed at the copy) plus the oracle test. 31 tried, 29 killed. Survivors: `shared-stream` (every fragment seeded with one fixed name; the isolation tests still passed because each fragment had its own instance of the same stream) → `test_each_fragment_draws_from_the_stream_of_its_own_name` added, re-run killed; `rng-biased` (rejection sampling removed) is equivalent at these bounds: the bias is below n/2^64 per draw, unobservable in any test or output.
- Population: none claimed (one fragment; `default_fragments()` is the inventory and is pinned by `test_every_default_fragment_states_its_assertion`).
