## Decisions
- The pin table holds what the lockfile holds. "Pin" is the version in `frontend/pnpm-lock.yaml` for an installed library; a library not yet installed reads "pinned when first used" with the 2026-10-24 registry check kept as its candidate, so the decided candidates are not lost and no version is invented (agent). This applies to the framework-neutral rows too (tailwindcss, temporal-polyfill, decimal.js, ...), which are not installed either; one rule for the whole table.
- `features/<name>/hooks/` keeps its folder name: the planned integrity tests import `features/transactions/hooks/useEditBuffer` and `features/dashboards/hooks/useWidgetRun` (ARCHITECTURE §3.1 is their interface); the folder holds composables. Renaming it is a code change for a later slice, listed as an open item (agent).
- `useECharts` stays a thin own composable (ADR-0050 item 11, accepted). ADR-0053 says "`vue-echarts` or an own composable", so `vue-echarts` is not written as chosen; open item (agent; this deviates from the slice prompt's list, which named `vue-echarts`).
- Client state: ADR-0037's side-effect-free module stores are read through composables, the module-level `ref`/`reactive` allowed only in the listed stores (EP-04's lint, already in ENGINEERING.md); no `useSyncExternalStore` (agent, a restatement of ADR-0037 for Vue).
- §3's "React Compiler on, hooks rules strict" becomes what `frontend/eslint.config.js` runs: `eslint-plugin-vue` and `eslint-plugin-vuejs-accessibility` recommended rules with `--max-warnings 0`, `vue-tsc --noEmit` the type gate (agent; the built config, not a new rule).
- The retired-terms check (S0047) gets the React-target terms, and its document set grows by the files the sweep covered that agents read first: the four `CLAUDE.md` files, `design/README.md`, `design/process/PROCESS.md`, `.claude/agents/*.md` and `.claude/skills/*/SKILL.md` (agent; a gate tightening after a real escape, PROCESS.md §9, IMP-0046). Bare `hooks` is not retired (git hooks, Vue Query's own word); bare lowercase `react` is not retired (the verb), only `React` and `react` joined to a package or rule name.
- INV-18's "Enforced by" line names eslint-plugin-vuejs-accessibility (ADR-0053) and states that its recommended rules already run (S0009); the rule and the status (`pending (BL-0018, by M11)`) are unchanged, so this is no invariant change and needs no ADR (agent).
- EP-12 now reads "composables and `<script setup>` single-file components" in place of "hooks and plain function components (no class components)": the Vue form of the same idiom, as `frontend/src/App.vue` is written; no new ban is added (agent).
- No allowlist entries: the two history-flavoured lines the new terms hit (glossary's spike example, the roadmap's source note) were reworded to name Vue 3 only (agent).
- INV-12's rule text says "hooks"; it is owner-owned and ADR-0053's Consequences read "hooks" as composables, so the text is left as it is (open item: offer the owner the one-word change).
