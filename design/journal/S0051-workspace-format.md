# S0051: The workspace-format core: the manifest and the extended fingerprint

## Brief
- Goal: the first verifiable piece of M1a's workspace-format core (roadmap §M1a: "the workspace-format core (layout, manifests, extended fingerprint, persisted `ledger_version`)"): what identifies a workspace and where its ledger is (the manifest `.finzytrack/workspace.json`, read by a pure reader), and the extended fingerprint of its ledger set (what the load read, observed again on disk and reduced to one digest), each with golden and property tests. It serves two requirements: the mirror's freshness check at open (ADR-0015 "Freshness = the extended fingerprint") and the write gate's "nothing changed since the plan" check (ADR-0008 step 4; ADR-0013), and on the main side the open's NEWER_WORKSPACE / WS_CONFIG_INVALID decisions (ADR-0019, INV-17) and the lineage id (ADR-0017).
- The cut (agent; each piece tied to its requirement):
  - **In (engine, `ledger_engine/ledger/`):**
    - `core/ledger_set.py` (pure): `LedgerSet` = what one load read and looked for: the root, every file it named (loaded or expected but absent), every glob `include` with the matches the load saw, every documents root as the load resolved it. `Fingerprint` = one observation of a `LedgerSet` on disk: per file a SHA-256 of its bytes, `absent` or `unreadable {errno}`; per glob its match list now (in the order the loader gets it); per documents root its file listing or `absent`. `digest(fingerprint)` = `sha256:` + the SHA-256 of a canonical, versioned JSON encoding (the hash the mirror's stamp and `ledger_version` will carry).
    - `fingerprint.py` (shell): `observe(ledger_set) -> Fingerprint`, with the loader's own primitives (`glob.glob(..., recursive=True)`, `path.exists`, `os.walk(followlinks=True)`), so it sees what the next load would see.
    - `overlay.load` records the `LedgerSet` of each load (`Loaded.ledger_set`): only the load knows which includes were globs and which named paths were absent.
  - **In (main sidecar, `app/workspaces/format/` and `app/domain/`):**
    - `domain/paths.py`: `WorkspacePath` (ARCHITECTURE §2.6): a relative POSIX path that cannot leave the folder, validated on construction (ADR-0017: "`ledger_root` is relative and non-escaping"; INV-27: no absolute paths in the folder).
    - `workspaces/format/manifest.py` (pure, `domain` + pydantic only): the manifest model (`format`, `min_reader` per EP-14; `lineage_id` per ADR-0017; `ledger`: a root inside the folder, or `external` per ADR-0017) and `read_manifest(bytes) -> Manifest | ManifestNewer | ManifestInvalid`: a newer manifest (`min_reader` above what this app reads) is told apart before the rest is validated (INV-17, ADR-0019 NEWER_WORKSPACE); anything else malformed is `ManifestInvalid` with the field (WS_CONFIG_INVALID). `LineageId` (EP-21: never confused with `WorkspaceKey`).
    - `contracts/workspace-manifest.schema.json`, generated from the model (EP-14, EP-16) and listed in `scripts/check_generated.py`.
    - Golden fixtures `corpora/workspaces/manifests/` (EP-14: format fixtures read by every reader).
  - **Out (later slices; each with its row or a TODO citing it):**
    - The fingerprint keyed by `path_key` (engine-jobs spec §6.3, which also keys locks and journals): the key is the path as the load named it until `path_key` exists (TODO(BL-0109)); this is safe for equality (see Decisions).
    - The source files of plugins from outside the engine's packages in the fingerprint (engine-jobs spec §1, so an R4 after a plugin edit is superseded): with R4 (new row).
    - The persisted `ledger_version` (generation + fingerprint digest, monotonic across restarts) and the published generation carrying its `LedgerSet`, so the open observes without a load: with the publish (BL-0113; new row).
    - Calling the fingerprint over the protocol, inside the `open`/save/R4 jobs: BL-0109.
    - Reading the manifest from a folder, `assess_workspace`, registry dedupe, copy detection: M2 (BL-0102, BL-0029); writing a manifest (create, adopt; never newer, INV-17): M3 (L10-08, BL-0017); the rest of the layout (`settings.yaml`, `dashboards/`, `rules/`, `themes/`) arrives with the slices that own those files; the layout and portability tests: BL-0004, BL-0027.
- Implements: ADR-0017 (the manifest, the lineage id, relative non-escaping ledger root, `ledger: external`), ADR-0015 (freshness = the extended fingerprint), ADR-0008 step 4 (the full extended fingerprint of the ledger set), ADR-0064 / `design/specs/engine-jobs.md` §1 "Fingerprint" (SHA-256 per file), ADR-0019 and INV-17 (a newer workspace is told apart), EP-14 and EP-16 (versioned manifest, its JSON Schema generated), EP-21 (`LineageId`, `WorkspacePath`).
- Capabilities: CAP-DATA-MIRROR (partial; the freshness fingerprint added), CAP-DATA-EXTERNAL-EDIT (planned; the detection's input exists), CAP-DATA-NEWER-REFUSE (planned; the manifest tells a newer workspace apart), CAP-WS-PORTABLE (planned; the manifest holds no absolute path).
- Invariants touched: INV-01/INV-22 (the fingerprint is the write gate's input: a change it misses is a lost edit; fail closed), INV-05 (freshness), INV-17 (newer told apart), INV-27 (no absolute path in the manifest), INV-30 (nothing here writes the folder: the reader takes bytes), INV-02 (the observation uses no Beancount import; the load records the set), INV-10 (files hashed in streams; nothing kept), INV-23/INV-24 (synthetic fixtures, temp dirs).

  - `scripts/check_generated.py` lists `contracts/workspace-manifest.schema.json`.

## Decisions
- **The cut** (agent): the manifest reader and the fingerprint, nothing that opens a folder. Each is what a later piece calls: the open (M2) reads `workspace.json` and calls `read_manifest`; the open job, the save's gate and R4 (BL-0109) call `observe` and compare with the fingerprint the last load recorded; the publish (BL-0125, with BL-0113) persists the digest as `ledger_version`. Left out, with their rows: plugin sources in the fingerprint (BL-0124), `path_key` (BL-0109), the persisted `ledger_version` and the stored `LedgerSet` (BL-0125), the rest of the layout and the writers (the M2/M3 rows named in the Brief).
- **The load records what it read, from the bytes it parsed** (agent; INV-01, INV-22, ADR-0013). The overlay now reads each on-disk file itself and parses those bytes with `parse_string(data, path)`, which is what Beancount's `parse_file(path)` does after opening the file (read in `beancount/parser/parser.py`: `parse_string` wraps the bytes in a `BytesIO` and calls `parse_file` with the report filename). So `Loaded.fingerprint` is the SHA-256 of exactly the bytes parsed. The alternatives have a window: hashing after the parse can describe bytes the load never read (a save would then pass the gate over an outside edit); hashing before closes that but not an A-B-A edit. Guardrail 1 (equivalence with Beancount's `load_file` on every corpus case, `test_overlay.py`) still passes with unchanged assertions. Everything else the load looks at is recorded on the safe side: glob matches are the ones the load followed; a path found absent and later read in the same load stays `absent`; documents roots are listed after the policy allowed them and before Beancount scans them. A change during the load makes the next observation differ; none can hide one.
- **SHA-256 per file, not ADR-0015's `(path, mtime, size)`** (agent, following the accepted design): `design/specs/engine-jobs.md` §1 "Fingerprint", applied by ADR-0064 (Accepted, later than ADR-0015), defines the fingerprint with a SHA-256 per file, and the spec's `open` job uses it for the freshness check. Content hashing catches an edit that keeps the size within the clock's resolution and a tool that restores the mtime (`[an edit that keeps size and mtime]`). Cost measured on the 54k demo ledger (one 8.7 MB file, `gen_demo.py --size 54k --anchor 2026-10-28`, warm cache, macOS): observe + digest 2.7-3.2 ms over 5 runs; the load 1.38 s (S0050: 1.34 s, so reading the bytes ourselves costs nothing visible). ADR-0015's text is not amended here (changing an ADR is the owner's, rubric item 4); ARCHITECTURE §2.2 states the difference. No inbox item: a later accepted ADR covers it; the verifier judges whether ADR-0015 needs a pointer.
- **One fingerprint for both uses** (agent; simplify first): the freshness check and the write gate compare the same value; there is no stat fast path, a trade-off nobody needs at 3 ms.
- **What the fingerprint holds, tied to what the loader reads** (agent): the root path (ADR-0015); each named file: `sha256`, `absent` (the loader's own `os.path.exists`), or `unreadable {errno}` (it exists but the read fails: the next load would raise); each glob's match list in `glob.glob` order (the loader parses in that order, and Beancount's sort key has no file name, so the order can change entry order); each documents root's file names, or `absent` (Beancount reports an absent root as an error and an empty one as nothing). The listing holds every file name under the root, not only dated names in account folders: a superset cannot miss what Beancount reads; an extra file costs one rebuild or one re-planned save. Document contents are not hashed (Beancount reads names only). `os.walk(followlinks=True)` as Beancount's `account.walk`; no symlink-loop guard, since the load itself walks the same tree first.
- **Paths keyed as the load named them, not by `path_key`** (agent; the spec's keying waits for BL-0109, which builds `path_key` for locks and journals): the same ledger set is always observed under the names it was recorded with, so equality is exact; two names for one file only make two entries that change together.
- **The digest's encoding is versioned and pinned** (agent): canonical JSON (sorted keys, no spaces, ASCII escapes so undecodable file names survive), `v: 1`, `sha256:` + hex. The golden encoding was written by hand and its digest computed outside the code (`hashlib` over the literal bytes) before the module existed. Changing the encoding costs one mirror rebuild per workspace (a cache).
- **Hypothesis in the engine's dev group** (agent; the stack's property tool, ARCHITECTURE §10, which the engine's write model needs in M1b anyway, EP-18): `hypothesis==6.168.4`, as the backend pins it. A dev dependency is not bundled, so the engine licence list does not judge it (`check_licences.py` reads the runtime closure).
- **The manifest, format 1** (agent; no ADR or spec names its fields): `format` and `min_reader` (EP-14's words), `lineage_id` (ADR-0017), `ledger`: `{"root": <WorkspacePath>}` or `"external"` (ADR-0017's "`ledger: external`"). Nothing is released before v0.4.0, so the shape can still change at no cost.
  - A newer manifest is told apart first: `format` and `min_reader` are checked by hand (integers, not booleans, `1 <= min_reader <= format`), then `min_reader > FORMAT` is `ManifestNewer`, before anything else is validated, because a newer app may change every other field (INV-17, ADR-0019 NEWER_WORKSPACE).
  - Unknown fields are ignored at every format (forward compatible: a format-2 file with `min_reader: 1` is readable by design). Never rewriting a newer file is the writers' rule (INV-17, M3).
  - Refused as `ManifestInvalid` with the field: not UTF-8, a byte-order mark, not JSON, NaN/Infinity, duplicate keys (two readers could take different values), not an object, and any field that fails the strict model. The lineage id must be canonical lower-case UUID text, with no normalization, so two spellings of one id never pass.
  - `ManifestV1` (pydantic, strict, extra ignored) is the wire model and the source of `contracts/workspace-manifest.schema.json` (EP-16); the reader returns plain frozen values (`Manifest`, `Inside`, `External`). The schema cannot say `min_reader <= format` or the `WorkspacePath` rules; its descriptions name them.
- **`WorkspacePath` is lexical and holds on every OS a folder may travel to** (agent; INV-27, ADR-0017): relative, `/`-separated, no empty, `.` or `..` component, no `\`, no `:` (a drive or an alternate data stream on Windows), no component ending in a dot or a space (Windows trims them: `.. ` becomes `..`), no NUL. It lives in `domain` (pure, no `os`). `parse(text)` takes no root, unlike ARCHITECTURE §2.6's old `parse(root, text)`, since the check needs none (§2.6 updated). Symlinks out of the folder are the open's question; Windows device names (`CON`, `NUL`) are portability, not escape (`assess_portability`, BL-0027).
- **The workspace format is pure, enforced** (agent; ARCHITECTURE §2.3: "`format/` imports only `domain` + pydantic"; ADR-0017): a new import-linter contract `workspace-format-pure` forbids I/O modules, `app.platform`, `app.api`, `app.main` and `app.workspaces.access` in `app.workspaces.format`.
- **Pydantic config as class keywords** (agent): `model_config = ConfigDict(...)` is a class attribute that `tests/architecture/test_globals.py` counts as module state; the keywords give the same configuration. `MANIFEST_PATH` is a `Final` string for the same reason (a call at module level that is not on the immutable-call list, EP-04).
- **Round 1 (verifier F1, High): every read a load makes is recorded or shown irrelevant** (agent). Beancount's `ops.documents.verify_document_files_exist` runs on every default load and asks `os.path.exists` of the file of every `document` entry. The first fingerprint recorded none of them, so deleting or creating such a file changed the next load's errors and not the fingerprint (a mirror called fresh with a stale error list; with R4 a false mismatch). The sweep of every read of a Beancount 3.2.0 load (Hand-off round 1, "Read inventory") found two more of the class: an absent `include` and one that is a link to nothing give different errors ("does not match any files" against "does not exist": the loader's glob asks `lexists` of a plain path, then the loader asks `exists`); and a dated name in a documents folder that is a link to nothing becomes an entry whose file Beancount then reports missing, while the listing held only names. Fix:
  - `FileState` gains `BrokenLink` (`lexists` true, `exists` false). The load records it for a path a glob returned (its name existed then; the load does not ask again, so a link removed in between makes the next observation differ) and asks `lexists` for the root (never globbed), as `observe` does.
  - A documents listing maps each name to `os.path.exists` (listed before Beancount scans, as before).
  - `Fingerprint.document_files`: `os.path.exists` of the file of each `document` directive, asked after the parse and before the plugins run (a change between our question and Beancount's makes the next observation differ), plus the file of each `document` entry a plugin added that is not in a listing. Those are only known after the plugins ran, so they are asked then; Beancount checks them only when its documents plugin runs after the plugin (`plugin_processing_mode "raw"`, or `beancount.ops.documents` listed again).
  - Residuals, stated rather than hidden (round 0's "a change during the load makes the next observation differ; none can hide one" was too strong): a document file or documents name that changes and changes back while one load runs (between our question and Beancount's); the `.asc` head read by Beancount's encrypted-file test racing the read we parse; a plugin-added document's file changing between Beancount's check and ours. Each needs an outside edit inside a window of milliseconds and costs a stale view until the next change, never a write: a save's own candidate load reads and checks again. Closing them would mean replacing Beancount's documents plugin and encrypted-file test with our own (EP-03), so they stay.
- **The encoding stays `v: 1`** (agent): `v` tells stored digests apart, and none exists yet (the persisted `ledger_version` is BL-0125). The golden was rewritten by hand and its digest computed with `hashlib` over the literal bytes, outside the module, as in round 0.
- **`WorkspacePath` refuses Windows device names and the characters Windows refuses** (agent; reverses round 0's "device names are portability, not escape", verifier F4): `NUL` or `com1.txt` as a ledger root opens a device on Windows, so a manifest written on macOS would not open there. The rule is Python 3.13's `ntpath.isreserved` (device names with any extension and in any case, `CONIN$`, `CONOUT$`, superscript `COM¹²³`/`LPT¹²³`, control characters and `"*<>?|`) plus `COM0` and `LPT0`, which Microsoft's naming page lists; the Hypothesis property asserts `not ntpath.isreserved` for every accepted path. The sets are literals, since `tests/architecture/test_globals.py` counts a comprehension at module level as mutable state.
- **Commit message rows** (round 1 note): commit 5848c85f was cherry-picked after the backlog was renumbered. Its message names "plugin sources (BL-0123)" and "the persisted ledger_version (BL-0124)"; they are BL-0124 and BL-0125 in the backlog and everywhere else in this journal.
- **Deviation from ENGINEERING.md:** none known. EP-01: `ledger/core/ledger_set.py` imports no I/O module (the engine has no import-linter purity contract, a gap since S0049, not this slice's).
