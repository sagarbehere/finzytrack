# S0070: The save does no Beancount load; a rebuild after every save (ADR-0068 D1)

## Brief

## Decisions
- **The plan's fingerprint is `as_before(preview's Loaded.fingerprint)`** (agent): the preview loads the candidate, so its record has the candidate's bytes for the files the save writes; the gate needs the disk before the save. `ledger_set.as_before` stays for BL-0106; `as_after` (R4's post fingerprint) is removed. The engine's `test_save.plan_for` builds plans this way. An edit made and reverted during the preview's load is still refused at the gate: `Loaded.fingerprint` hashes the bytes the preview parsed.
- **Step 0, encrypted files** (agent; ADR-0059): with no load in the save, the save refuses a change whose name ends `.gpg`/`.asc` (any case, the overlay's candidate rule) as `encrypted_file`, before anything is read; the sidecar maps it to `INTERNAL` (`TODO(BL-0106)`), as it mapped `load_refused`: the preview refuses it first.
- **The save no longer refuses what a load would refuse** (agent, the consequence of D1): a candidate the overlay refuses (`not-reached`, a plugin import that decrypts) is the preview's to refuse; the save writes the plan (`test_a_candidate_a_load_would_refuse_is_saved_as_planned`).
- **The save's engine is still retired** (agent): the save runs no user code now, but `WorkResult`'s safe default stays and the model's `S_Load` still marks user code; S0072 can revisit.
- **The model is mapped, not renamed** (agent; the smallest change, S0072 cuts the model): `EngineJobs.tla`, its cfgs and the trace corpus are unchanged (`gen_traces.py --check`: current). The model's `R4_Start` is on `engine_jobs.rebuild.run_rebuild`, `R4_Load`/`R4_Check` on `ledger_engine.ledger.rebuild.run`; the replay maps the model's `r4` kind to the code's background `rebuild`. The model's `S_Load` and `S_Recheck` have no effect in the code: the save's one observation reaches the model's `s_gate`, then `s_load` and `s_recheck` when the model's save went on (`test_save_conformance.Driver.ahead`), so the code refuses at its one check where the model refuses at its gate or its re-check.
- **No `replace_queued`** (agent): a newer save's rebuild finds the queued one (`AlreadyQueued`) and gets its ticket; the queued one loads the disk when it runs, so it shows both saves. Its fingerprint is a hint only: a load that used a file, documents root or `document` file outside the set answers `moved` with the wider set (one more try). Same outcome as a replace, one mechanism fewer.
- **The rebuild's stop rule** (agent, as the brief and the area review's F2 recommend): every rebuild request is sent uncounted (`Send.counted`, `EngineClient.call(counted=False)`, `JobContext.call(counted=False)`); its engine still ends and the job is lost like a read; no stop is recorded, so a plugin that crashes in every load never makes the engine unavailable.
- **Each rebuild try runs in a fresh engine** (agent; §5.1): a plugin module imported by the first try would otherwise be reused by the second.
- **`LEDGER_CHANGING` is not added to the registry** (agent): the background rebuild has no requester; after 3 moved tries it logs `rebuild.not_loaded {why: changing}`. The code with its text comes with the waited-for loads (BL-0152) or the publish (BL-0113).
- **`PYTHONHASHSEED=0` kept** (agent): its recorded reason was R4's digest, but it also makes a load of the same bytes give the same result in every engine (set order), which the rebuild's screens and any comparison of two loads need; removing it would change the spawn environment and its tests for no gain. Reason restated in `engine_client` and the test.
- **`reconcile_load` renamed `real_load`** (`REAL_LOADS`; agent): "reconciliation" means something else in finance (bank reconciliation); only `ledger/rebuild.py` may call it (`test_load_rule.py`), no pickle cache (`test_rebuild.py`, `test_rebuild_ops.py`).
- **Journal format 4** (agent): no `post_fingerprint`, no `adopted_digest`; formats 2 and 3 are `Unreadable("unknown version")` and format-4-with-old-fields `Unreadable("malformed")` (`test_journal_record.py`): an older `.open` journal blocks its workspace on the recovery screen (Keep or delete ends it), a save counts one as an `.open` journal, an older `.closed` record is read by its name alone (§6.6), so it still says "saved".
