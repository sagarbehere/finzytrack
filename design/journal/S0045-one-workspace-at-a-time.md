## Decisions
(Round 0. The bullets on overlap, the per-file record, the claim and `LEDGER_SHARED` were superseded in fix round 1 by the territory rule, and that in fix round 2 by the recovery rule; they stay as the record.)
- One open workspace per instance, no file in two workspaces, no sharing anywhere (owner: "1. Yes to forbidding two workspaces sharing a file. If it'll help we can simplify further: No sharing anywhere, no multiple instances of Finzytrack anywhere. Period. Finzytrack is just about one instance, working with one workspace at a time. Switching between workspaces should work well, without issues. The switch should do whatever book-keeping that is needed. Fine to tell the user something like, "Just a moment.. switching workspaces." or similar, if the switch takes time.", 2026-10-27, in session). Recorded as ADR-0063.
- The switch assesses the target read-only before anything closes, then quiesces and shuts the current workspace, then opens the target; Stay until the current one has shut, Back to it if the target's open fails after (agent). This reverses ADR-0018's order ("after the backend has opened and validated B"), which would have two workspaces open during every switch.
- `409 WORKSPACE_NOT_OPEN {open_workspace, switching}` for a registered workspace that is not open; never routed to the open one (agent). The open workspace is a gate, not a target, so the bug class of ADR-0018 (a save built in A landing in B) stays impossible.
- No idle container kept warm (agent): ARCHITECTURE §2.5's "at most 1 idle container kept warm" would keep a second workspace half-open; a quick switch comes from the fresh mirror on disk.
- Overlap is defined over files, documents folders (same or nested) and glob matches, by the write path's `path_key`, plus device and inode for existing files (agent; inode only refuses more).
- The check compares a workspace's current set with each other registry row's machine-local record of its last known set, both ways, at open and at each rebuild; never by opening other workspaces (agent). Argument that a stale record is safe: only one workspace is ever open, and whichever of two workspaces computes the overlapping set is refused, so two workspaces never both write one file.
- An overlap found mid-session (outside edit) leaves the rebuild unpublished and refuses saves (agent); detection only at the next open would let the open workspace write another workspace's file in between.
- A workspace with an unresolved journal keeps its claim; forget is refused until recovered (agent; the scheduler spec draft 3 §4.9 already refuses that forget). Without it, forgetting a workspace with a half-applied save would free its files for another workspace to read and overwrite.
- Not added: a save-time refusal of creating a file another workspace's glob would match (agent): rare, and the outcome without it is a refusal at the other's next open, never two writers.
- "Copy to workspace…" (CAP-WS-COPY-ITEM, M7) is carried across a switch instead of writing a workspace that is not open (agent). The owner may want to see this: the user now lands in the target workspace to confirm.
- CAP-WS-MULTIWINDOW deferred → cut, on the owner's words "no multiple instances … one workspace at a time".
- Sharing a workspace between users in hosted mode moved from ADR-0041's deferred list to excluded (agent, applying "No sharing anywhere … Period."). The owner may want to confirm this reading: it narrows a deferred hosting item, though it builds or forecloses nothing in v0.4.0.
- CAP-WS-LIBRARY stays deferred, flagged as needing an ADR that revisits ADR-0063 (agent): it shares tool state, not ledger files, so only the owner's "no sharing anywhere", not data safety, argues against it.
- CAP-WS-MULTI-ROOT is narrowed: two roots that include a common file cannot both be in-place workspaces (owner's decision; agent: the way out is a copy). INV-03 is not narrowed: every ledger Beancount loads still opens.
- Invariant texts not edited (task rule and precedent `answered/20261025-inv-24-enforced-by.md`): INV-28 must change ("there is no server-side active workspace" is contradicted), INV-31 should carry the one-open rule, a new INV-32 should carry the no-overlap rule; all proposed in `design/inbox/20261027-workspace-invariants-one-open-no-shared-files.md`. No IMP entry, since no invariant changed.
- Milestone of the switch row: M2, not M3 as the slice request suggested (agent, pushing back): CAP-WS-SWITCH is M2 and the roadmap's M2 user flow switches ledgers, so the one-open rule must hold from the first switch; the save and R4 parts of the quiesce are tested when the scheduler's phase C lands (M1b). The overlap row is M2 as well, with CAP-WS-ADOPT; create and the test copy reuse the check in M3.
- The scheduler draft 3's INV-31 exception (owner answer (b), 2026-10-27: repair a closed workspace's interrupted save from the open one) is no longer needed and is not applied; review 4's owner questions (1) and (2) are moot (agent, a direct consequence).
- Engine-scheduler spec: the long list of draft-4 changes that stood here is dropped. Draft 4 (516a5441) was superseded before review by the owner's return to one engine doing one job at a time; draft 5 rewrites the spec for a single engine, following ADR-0063 as reworked in fix round 2. From this ADR, draft 5 must carry:
  - the switch's quiesce (decision 1 step 3): new work stops, what can end ends, a confirmed save and a running recovery finish, owed R4 checks run or stay recorded, Stay until the current workspace has shut, "Just a moment… switching workspaces.";
  - recover-all-before-open (decision 2): at start and at every switch, while no workspace is open, every journal under `local/` is recovered; an unrecoverable one blocks only the workspaces and copies using a file it names (`RECOVERY_BLOCKED`); its own workspace opens in ADR-0012's stopped state;
  - journals list every replaced or created file by canonical path, resolved when the journal is written; the save writes exactly those paths; recovery writes a path only while it still resolves to itself;
  - `WORKSPACE_NOT_OPEN` for a request naming a registered workspace that is not open.

## Retro
- What the verifier found: the High was a hole in my own overlap design. I checked files that exist, and did not follow a save that creates a file through a crash.
