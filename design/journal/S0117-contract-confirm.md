# S0117: the contract's confirm: a previewed plan saved, and nothing else (M1b, ADR-0008 steps 4-7, BL-0106)

## Brief
- Goal: M1b's third slice and its first new write path. In the sidecar: the `PlanStore` (ARCHITECTURE.md §4.2, the state table: `UserContainer`, keyed by workspace; TTL and count; texts and hashes, never entries), the preview use case that submits S0116's `preview` job and stores a `Prepared` answer as a plan, and the confirm use case that hands a stored plan to M1a's `save` job (`app.platform.engine_jobs.save`), with BL-0106's `ContractRefused` codes in the error registry (`ACK_REQUIRED {error_keys}` at 409, the refusals at 422) and the mapping of the preview's `stale` to `WORKSPACE_NOT_READY {WARMING}`; and ADR-0014's **promotion guard**, refusing by default. No HTTP route and no user-facing mutator (roadmap M1b: "No user-facing mutator"); the routes come with each mutator's slice.
- **The ownership rule** (proposed 2026-11-14; owner: "Yes"):
  1. A confirm writes exactly the files and bytes of one plan this app's preview prepared, and nothing else. The plan is held in the app's `PlanStore`, never sent back by the client, and holds texts and hashes, never entries.
  2. A plan is bound to its workspace and to the ledger state it was made on (its fingerprint and mirror generation); it expires (TTL), is used once, and a switch drops it (ADR-0063). A second confirm of the same plan is refused.
  3. The confirm carries the preview's hash; when the preview listed new errors, the request's acknowledgements must cover exactly those error keys, else `ACK_REQUIRED {error_keys}` and nothing is written. An accounting error never blocks (ADR-0067).
  4. Every file must be as the preview found it, checked again at the save's gate (engine-jobs §6.1 step 3); else `LEDGER_EXTERNALLY_CHANGED` and nothing is written.
  5. A confirm never writes a file outside the plan or outside the ledger set, and never an encrypted file (§6.1 step 0).
  6. **Until a mutator is promoted (ADR-0014), its plans are confirmed only on test copies** (`UNPROMOTED_MUTATOR_ON_REAL_LEDGER`), built in this slice and refusing by default: with no promoted mutator and no test-copy mark (CAP-WS-TEST-COPY, M3), every confirm on a real workspace is refused.
  7. "Saved" only once the save is durable (M1a's save, §6.1 step 9); a refusal says "your ledger is unchanged" only when the disk is.
- Implements: ADR-0008 steps 4-7 through M1a's writer (BL-0151), with ADR-0067 (acks) and ADR-0068 D1 (no load in the save; the preview's load stands, on the plan's fingerprint); ADR-0014 (the promotion guard); ADR-0063 (a switch drops the closed workspace's plans); ARCHITECTURE.md §9.2 steps 2-4; `design/specs/engine-jobs.md` §2 (`preview`, `save`), §6.1, §11; BL-0106; I9 (a write is refused when a file changed after it was read).
- Capabilities: CAP-DATA-WRITE-GATE (planned → `partial` if the contract now runs end to end on test producers; the verifier judges); CAP-WS-TEST-COPY stays `planned` (M3: the guard only reads the mark).
- Invariants touched: INV-01, INV-22 (each step fails closed), INV-11 (the plan store hangs off `UserContainer`, no module-level state), INV-32 if a shared file is in play (unchanged).
- Risk class / lane: High / full. Review budget row: **New write path** (a new way to write ledger data, and new outcome texts): verifier + data-safety red team; a fresh round after any fix that changes product code; in the fresh round only High and (a)/(b) findings are fixed, the rest become backlog rows; a second fix round on one mechanism needs the owner's options note (ADR-0068 D6).
- The bytes it protects: every ledger byte the confirm could write (only the previewed plan's, after the gate's check) and every byte it must not (any file outside the plan, any change after the preview, any real ledger while the mutator is unpromoted); and the truth of "saved", "not saved" and "unchanged".
- Mechanism questions (§3 step 2): which real setup needs this: every ledger write v0.4 makes. Rare setups (encrypted files, files outside the ledger set, a ledger changed by another program between preview and confirm) are refused, not supported. Fix-round history: the save it calls (S0063, then S0070, S0071, S0100-S0102) had several rounds, and is used, not changed; the plan store, the acks and the guard are new.
- Constraints: no test-only producer reachable in the shipped engine (the engine's `PRODUCERS` stays empty in the product; tests register their producer only inside the test process, or drive the engine through a test-only entry that is not packaged; say which and why). The plan store is bounded (TTL and count) and holds no entries (INV-10).
- Acceptance tests (tests first; each fails on the base commit):
  - End to end on a test copy (a temp workspace with a test producer): preview, confirm, "saved", the file's bytes equal the plan's text, and the background rebuild queued.
  - Must-not-pass, each with the disk byte-identical afterwards: an expired plan; a plan used twice; a plan of another workspace; a plan dropped by a switch; a wrong preview hash; acks that miss, add or differ from the new error keys; a file changed after the preview (`LEDGER_EXTERNALLY_CHANGED`); a plan with a file outside the ledger set or an encrypted file; any confirm on a workspace without the test-copy mark (`UNPROMOTED_MUTATOR_ON_REAL_LEDGER`), the guard's default.
  - Each `ContractRefused` code with its status (409 / 422) through the error taxonomy; the preview's `stale` mapped to `WARMING`; a fault injected in each use-case step fails closed.
- Expected doc impact: ARCHITECTURE.md §9.2 (what is built), §4.2's state table if needed; `design/specs/engine-jobs.md` §11 for new outcome texts; the error registry and its generated reference; `backend/CLAUDE.md`; backlog BL-0106 (done or narrowed), I9, BL-0001; the capability rows; ADR-0014 if the guard's reading of "test copy" before M3 needs a line.
- Open questions: none.
- Base: 0d627c2b.

## Decisions
- The ownership rule above is the owner's (owner, 2026-11-14: "Yes", answering the proposed rule, including the promotion guard in this slice rather than in slice 7).
- **Orientation** (agent): `orient` run on PlanStore, ContractRefused, BL-0106, ADR-0014, CAP-DATA-WRITE-GATE, CAP-WS-TEST-COPY; read ADR-0008 (with its notes), ADR-0014, ADR-0063, ADR-0064's parts the spec cites, ADR-0067, ADR-0068, ARCHITECTURE §2.2, §2.5, §4.2, §6.1, §9.2, engine-jobs §1, §2, §6.1, §6.6, §11, BL-0106, the S0116 journal and the save job (`app.platform.engine_jobs.save`). No question hit the escalation rubric: each choice below is inside the owner's rule, cheap to reverse and writes no format; the one place the rule's text could be read two ways (rule 2's "mirror generation") is held as written (below), not narrowed.
- **Tests first** (agent): the new tests and the changed ones were written before the product modules; run against the base sources (0d627c2b; only test files changed at that point): `test_plans.py`, `test_preview_job.py`, `test_writes.py`, `test_writes_end_to_end.py`, `test_contract_codes.py` fail at collection (`ModuleNotFoundError: app.platform.engine_jobs.preview` / `app.platform.plans`); `test_save_job.py` fails at collection (`cannot import name 'EncryptedFileDetails'`); `test_envelope.py` fails at collection (`ErrorClass` has no `CONTRACT_REFUSED`); `test_error_registry.py`: 2 fail (`test_every_tagged_code_is_in_the_registry`, `test_the_codes_of_architecture_6_1_…`); the frontend's `contract.test.ts` fails its typecheck on the base's generated client (the new codes and details). `test_manifest.py::test_format_1_carries_no_test_copy_mark` passes on the base by design (tagged `@regression-guard`: it pins that today's format carries no mark).
- **Homes** (agent; ARCHITECTURE §2.2, the layers contract): the plan store and plan values in `app.platform.plans` (ARCHITECTURE puts the PlanStore in `platform`); the preview job beside the other job works, `app.platform.engine_jobs.preview` (as `opening.py`); the use cases in `app.workspaces.writes`, the lowest layer that may read both the mirror (`app.mirror.files.pin`, for the generation) and the platform. `app.mirror.files.generation_number` reads N from a pinned generation's name.
- **The producer for the end-to-end test** (agent; the brief's constraint): the shipped engine is unchanged and its `PRODUCERS` stays empty. The test starts the real engine through a test-only entry: the sidecar's own `bootstrap_argv` and the venv's site, then a few lines that put `engine/` on the path, register `engine/tests/ledger/producer.produce_json` (S0116's) under `test.edits` in that process, and run `ENGINE_RUN`. Why this and not `--test-ops` or a registration in `src`: either would put the test producer in the built package (`ledger_engine` is the only module the build ships), reachable by a flag; this way nothing of it is in `src`, and `engine/tests` is not on the engine's path under the product's bootstrap. `test_the_shipped_engine_has_no_producer` holds it: under the product's bootstrap `PRODUCERS` is empty and `tests` cannot be imported, the product's argv names no producer, and no engine source writes into `PRODUCERS`.
- **The test-copy mark** (agent; the orientation's question): today's workspace format cannot carry one. The manifest's format 1 has no such field, its model ignores unknown fields (EP-14), and the registry does not exist yet (BL-0102). So the guard reads no file at all: its input is `WriteTarget.copy`, a value the sidecar builds from its own state (none does before M3), never a request field. A hand-written `"test_copy": true` in a manifest changes nothing (`test_format_1_carries_no_test_copy_mark`). With `PROMOTED` empty, every confirm on a workspace is refused, as rule 6 asks. The mark's writer and ADR-0014's "not in the file set of any non-copy workspace" are BL-0267 (M3). Recorded in ADR-0014's implementation note of 2026-11-14.
- **"Inside the test-copy folder"** (agent): judged on resolved paths (`os.path.realpath(strict=True)`), the file's and the folder's, by path components (`commonpath`, never a text prefix), because the save writes a linked file at its real path (ADR-0008 step 5); a resolution that fails refuses (INV-22). Limit: resolved when the confirm is asked; a link made in the copy after that is met only when it changes the plan's fingerprint.
- **Promotion state** (agent): the frozen set `writes.PROMOTED` (empty), code changed only with the owner's clearance page (ADR-0045); never a setting or a request field, so no client can set it.
- **Rule 2's generation** (agent; held as written): the plan records the generation the preview was made on, and the confirm's job reads the published generation (`pin`) before it calls the save, in the same job, so no publish (a job) comes between that read and the save's gate; another generation is `PREVIEW_STALE`. This refuses a few harmless cases (the same disk published again after the OS purged the cache), which costs the user one more preview; dropping it would have narrowed the owner's rule.
- **Used once** (agent): the confirm checks the plan before the queue (`find`) and takes it when its save job starts (`take`), so a confirm refused by the queue (`ENGINE_QUEUE_FULL`, Try again) keeps its plan, two confirms queued together save once (the second job finds it used: `PLAN_EXPIRED`), and a plan that reached the save is used whatever the save answered (the ledger is planned again after `LEDGER_EXTERNALLY_CHANGED`). Refusals before the queue keep the plan: `ACK_REQUIRED` must (the user's Save anyway follows), and a wrong hash does (it says nothing about the plan).
- **The acknowledgements** (agent): compared as sets with the listed keys (a key listed twice, a second copy of an old error, is acknowledged once); `ACK_REQUIRED.error_keys` lists each key once in the preview's order; acknowledgements where none is listed are refused too (`ACK_REQUIRED {error_keys: []}`), as rule 3 says "exactly". An accounting error never refuses: only the missing Save anyway does.
- **The order at the confirm** (agent): the plan, its hash, its own files, the guard, then the acknowledgements, so the user is never asked to Save anyway a change that would be refused anyway (`test_the_guard_comes_before_the_acknowledgements`).
- **Codes and statuses** (agent; ARCHITECTURE §6.1 as written): `ContractRefused` (new class `contract_refused`) holds `ACK_REQUIRED {error_keys}` at 409 and `WRITE_REFUSED_UNINTENDED_CHANGE {step}`, `WRITE_REFUSED_CHECK_FAILED {step}`, `ENCRYPTED_FILE_NOT_EDITABLE {path}` at 422; `status_for(error_class, code)` gives that class its two statuses by code (BL-0106), and every other class one. The confirm's other codes keep ARCHITECTURE's classes: `PLAN_EXPIRED` (`NotFound`, 404; one answer for expired, used, dropped by a switch, another workspace's or another root's: they need the same action, preview again), `PREVIEW_STALE` (`Conflict`, 409; a wrong hash or another generation), `UNPROMOTED_MUTATOR_ON_REAL_LEDGER` (`Forbidden`, 403). The brief's "the refusals at 422" is read as the `ContractRefused` refusals (BL-0106's wording), not these three.
- **How the engine's refusals map** (agent): `apply`'s `encrypted_file` and `load`'s `encrypted` are `ENCRYPTED_FILE_NOT_EDITABLE`; steps `apply`, `parse`, `diff`, `spans` that decided are `WRITE_REFUSED_UNINTENDED_CHANGE`; the plan, the load, the errors, and a `fault` or `undecidable` in any step are `WRITE_REFUSED_CHECK_FAILED` (a check that did not run is not a verdict on the text). `stale` is `WORKSPACE_NOT_READY {WARMING}` (the brief); `paused` is `WRITES_PAUSED {earlier_unfinished}` (the same journal the save's step 1 refuses on); `moved` is tried again in a fresh engine, at most 3 tries (§7, as the open), then `LEDGER_CHANGING`.
- **The words** (agent): none of the seven codes says "unchanged": they all refuse before any write and hash nothing, and §11 allows "Your ledger is unchanged" only after a re-hash; each says the change was not saved, which is true whatever another program did meanwhile. ARCHITECTURE §6.1's row said "always says 'your ledger is unchanged'"; corrected there. `data_safe` is true for all seven (nothing of the change was written).
- **The save's `encrypted_file`** (agent): mapped to `ENCRYPTED_FILE_NOT_EDITABLE {path}` (the `TODO(BL-0106)` closed); the confirm refuses an encrypted name first, so the save meets one only through a link made after the preview.
- **Rule 5, simplified** (agent, EP-30): I first parsed the plan's fingerprint in the sidecar to check every planned file is in its ledger set at its `pre` bytes. The end-to-end run showed the engine's save already refuses exactly that before writing (`ledger.save`: `BadPlanError("pre_not_the_plans")`, and `change_path` for a path twice, relative or not normal), so the sidecar's copy was removed: it coupled the sidecar to the engine's fingerprint encoding for no extra safety. `plan_problems` keeps what only the sidecar can check: at least one file, no encrypted name (the right code before the queue), and each text's SHA-256 equal to the plan's `post` (the save receives only the text). A plan with a file outside its ledger set therefore ends `INTERNAL` at the save, with nothing written (`test_a_plan_with_a_file_outside_the_ledger_set_writes_nothing`, real engine): only our own preview makes plans, so it is a bug, never a user's situation.
- **The plan store's bounds** (agent; INV-10: a setting): `PlanPolicy(ttl_seconds=900, max_plans=4)`; a plan's texts fit one engine reply (16 MiB), so at most 64 MiB of text. TTL by the injected clock (a system clock set back lengthens a plan's life by that much: accepted). Held by the composition root's `Wiring.plans` and registered in the state registry; the switch's calls are BL-0154 (`TODO(BL-0154)` in `app.main`).
- **What the confirm sends the save** (agent): the plan's root (bound: a target of another root is `PLAN_EXPIRED`), the plan's fingerprint, each file's path, `pre` and text; the target's lineage and folders; the session id from the services. The rebuild after a landed save is queued as `save.submit_save` does (its refusal is BL-0255's, slice 4).
- **Docs** (agent): ARCHITECTURE §2.2 (three modules), §2.5 (the PlanStore row), §6.1 (the ContractRefused row and the built line), §9.2 steps 3, 4 and 6; engine-jobs §2 (`preview`), §6.1 step 0, §11 (five rows and the code list); `design/generated/engine-job-texts.md` regenerated (the seven codes added to `gen_engine_job_texts.CODES`); OpenAPI and the TypeScript client regenerated, the frontend's contract test extended; `backend/CLAUDE.md`; ADR-0014's implementation note; backlog BL-0106 (narrowed: what is left), I9 (done), BL-0001 and BL-0154 (notes), BL-0267 (new, M3), the totals; CAP-DATA-WRITE-GATE `planned` → `partial` (the verifier judges), its code and tests listed; `capabilities.md` regenerated. No user docs: nothing user-facing.

  - **What a confirm confines to** (agent): an unpromoted mutator's save, the test copy's folder resolved at the confirm (`writes.confinement`); a promoted mutator's, nothing (null): a real ledger may include files outside its root's folder (`include "../shared.bean"`, a v0.3 ledger's documents folder: ADR-0063 decision 3), so the ledger's own folder would refuse valid saves, and a real ledger's save is held by its plan's fingerprint at the gate.
