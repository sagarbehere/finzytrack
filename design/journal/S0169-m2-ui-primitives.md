# S0169: UI foundations: theme tokens and the pre-paint script, button and input, Lucide, a strict CSP

## Brief
- Goal: M2's second slice (roadmap §4 M2, WS-UI phase 0 and WS-SECURITY's CSP item). The foundations every later screen is drawn with, and nothing that reads or writes data:
  1. **Theme tokens and a pre-paint script** (L9-11): CSS-variable tokens (shadcn-vue's names: `--background`, `--foreground`, `--primary`, `--muted-foreground`, `--border`, `--input`, `--ring`, …) with one dark-mode source (`.dark` on `<html>`), the indigo/gray look of today (ADR-0035), mapped into Tailwind v4 through `@theme inline`. A small classic script inline in `index.html`'s `<head>` reads the stored theme (`localStorage` key `ft/v1/app/theme`, JSON-encoded `"light" | "dark" | "system"`, ADR-0035, ADR-0036's key scheme), resolves `system` with `prefers-color-scheme`, and sets `.dark` before the first paint; a missing, unreadable or unknown value means `system`. `color-scheme` follows the tokens, so native controls and scrollbars match. Out of scope (CAP-UI-THEME's later slice): the toggle and following an OS switch live after load.
  2. **Button and input primitives** (L9-16): shadcn-vue's `button` and `input` (style new-york-v4) on Reka UI, vendored unedited into `src/components/ui/` exactly as the shadcn-vue 2.9.0 CLI writes them (their imports are `reka-ui`, `cn`, `class-variance-authority`, `@vueuse/core` and relative paths, so the CLI rewrites nothing). No iOS zoom on focus: iOS Safari zooms into a field whose text is under 16 px; the vendored input is 16 px below 768 px wide but 14 px above (`md:text-sm`), which an iPhone in landscape or an iPad crosses, so an unlayered rule in our theme sets fields to 16 px on coarse pointers (it beats Tailwind's layered utilities without editing the vendored file). The lint refuses raw `<button>` and `<input>` outside `components/ui` and `components/app` (ADR-0035's ban; `<table>` and `confirm()` join it with their primitives, L9-15 and the confirm slice).
  3. **One icon set** (L9-17): `@lucide/vue` (ADR-0035 amendment) is the only icon package; the lint refuses the other names a copied snippet brings (`lucide-vue-next`, the package's old name, and `@heroicons/*`, the legacy set).
  4. **A strict CSP** (BL-0032; security-relevant, INV-09): `script-src 'self'` plus the SHA-256 hash of the pre-paint script, nothing inline otherwise, `object-src 'none'`, on the desktop window (`tauri.conf.json`, Tauri's script rewriting off, ADR-0040 amendment) and as an HTTP header wherever the web page is served today: `vite preview`, which the acceptance harness loads, so a CSP violation there fails the acceptance run (the harness fails a test on any console error). One CSP string, in `tauri.conf.json`; the preview reads it from there. The dev server sends none (Vite's hot reload injects inline styles and opens a WebSocket); stated, since dev is not shipped. The backend does not serve the web page yet (headless mode is unbuilt); a new row makes it send the same header when it does. The security red team for M2's exit covers the CSP later (roadmap M2 exit); not this slice.
- Implements: ADR-0035 (theme, two layers, icons, the button/input ban) with its 2026-10-29 Vue amendment, ADR-0040 (CSP) with its 2026-10-25 amendment (hash test, rewriting off), ADR-0053, ARCHITECTURE.md §3.1 (`components/ui`), §5 (CSP), §10 (pins).
- Capabilities: CAP-UI-THEME stays `planned` (the toggle and live following are its remaining part); CAP-UI-A11Y stays `planned`.
- Invariants touched: INV-09 (its planned "the CSP" part: built for the desktop window and the preview), INV-12 (layer map: `src/components/ui` is already an element; the theme CSS sits in `src/app`), INV-18 (token contrast: text pairs ≥ 4.5:1, field borders and the focus ring ≥ 3:1 against the page, both modes; a step toward L9-12, which stays open for helper text in components), INV-23 (no data in tests).
- Kind: product code (shipped), frontend, read-only UI foundations; the CSP part is product security. Review row "Other product code": verifier; the security red team per §4 at M2's exit.
- Real setup / policy: every user sees the theme and these primitives; the iOS rule serves the planned phone and tablet use (ADR-0036). Nothing accommodates a rare setup. Fix-round history: new mechanism family (no earlier rounds).
- Risk class / lane: Medium / light (the CSP check is a security check: it gets loosening mutants at hand-off).
- Acceptance tests (must fail on base 80c1c9a2):

Must-not-pass: the script is missing; a second inline script; the script reads another key.

Must-not-pass: a token missing in dark; a pair under its ratio; the rule inside a layer or under 16 px.
  - `tests/unit/components/ui.test.ts`: the vendored button renders a `<button>` with its variant's classes and merges a caller's class; the input's `v-model` round-trips; a Lucide icon renders an `<svg>` hidden from assistive technology.

Must-not-pass: a stale hash, a second hash, `'unsafe-inline'`, a missing preview header.

## Decisions
- **Blocked on install (2026-11-28).** The sandbox refuses `pnpm add` (S0166). The owner runs, in `frontend/`:
  1. `pnpm add --save-exact reka-ui@2.11.0 cn@0.5.2 class-variance-authority@0.7.1 @vueuse/core@14.4.0 @lucide/vue@1.55.0`
  2. `pnpm add --save-exact -D tailwindcss@4.3.3 @tailwindcss/vite@4.3.3`
- **Versions** (agent, EP-24; checked on registry.npmjs.org 2026-11-28, cut-off 2026-11-14): the ARCHITECTURE.md §10 candidates where one exists: `reka-ui` 2.11.0 (2026-10-05, MIT), `@lucide/vue` 1.55.0 (2026-10-10, ISC), `tailwindcss` and `@tailwindcss/vite` 4.3.3 (2026-07-16, MIT; 4.3.5 of 2026-11-06 is old enough too, the reviewed candidate is taken, an upgrade is its own slice). Not in §10, required by the vendored files: `cn` 0.5.2 (2026-11-02, MIT, no dependencies, no install script, npm provenance from `shadcn-ui/cn`), `class-variance-authority` 0.7.1 (2024-11-26, Apache-2.0: pending legal advice in `licences.allow.toml`, passes with a warning), `@vueuse/core` 14.4.0 (2026-07-29, MIT; the 14 line, so it is the one copy `reka-ui` 2.11.0's `^14.1.0` also resolves to, not a second).
- **Why each package** (agent): `reka-ui`: the button's `Primitive` (shadcn-vue on Reka UI, ADR-0035). `cn`: shadcn-vue 2.9.0's registry imports `cn` from the `cn` package in every component (it replaced `clsx` + `tailwind-merge`; checked at the `v2.9.0` tag and in the CLI's import transform, which leaves it alone), so an unedited copy needs it. `class-variance-authority`: the button's variants. `@vueuse/core`: the input's `useVModel`. `@lucide/vue`: L9-17. `tailwindcss` + `@tailwindcss/vite` (dev, build time): the vendored classes are Tailwind v4 classes; Tailwind's licence comment stays in the built CSS. `tw-animate-css` (the style's dev dependency) is left until a component animates (dialogs).
- **The shadcn-vue CLI is not run** (agent): `pnpm dlx` and `npx` hit the same sandbox lock. The files are the registry items of the `v2.9.0` tag (`apps/v4/public/r/styles/new-york-v4/{button,input}.json` in `unovue/shadcn-vue`), written byte for byte; the 2.9.0 CLI's only transforms are alias rewrites of `@/` imports, which these files have none of. A `components.json` records the style and folders, so the next `shadcn-vue add` writes to the same place.
- **The pre-paint script stays inline with a hash, as ADR-0040 decided** (agent, noted): an external classic script in `<head>` (`/prepaint.js`) would also run before the first paint, need no hash and keep the CSP at bare `'self'`; the decided inline script saves one local request and its hash is held by a test. Not reopened: both are sound, and the ADR is the owner's.
- **Unblocked** (2026-11-28): the owner ran both commands; `package.json` and `pnpm-lock.yaml` changed, no build-script prompt, `pnpm-workspace.yaml` unchanged. The owner was told about `cn` (young, one maintainer, needed for unedited copies) and made no objection (coordinator, recorded here).
- **Parked on the owner: the vendored input fails the strict type gate** (`exactOptionalPropertyTypes` against VueUse's `useVModel` options; the `data-*` attribute errors are settled by a type declaration in our own file). Options note: `design/inbox/20261128-vendored-ui-strict-gates.md` (recommended: one recorded patch line, style lint and prettier off for `components/ui` only).
