# S0087: The mirror's generation publish, in code

## Brief
- Goal: the code half of BL-0113. Build exactly `design/specs/mirror/publish.md` (S0085): the mirror folder opened through one descriptor that follows no link, the cleanup (current, previous, at most 2 others younger than 10 minutes; everything else removed, a link removed as a link, a folder removed relative to descriptors), the generation name `gen-<N>-<tag>.db` above every number in the folder and the sidecar's floor, the build into its own name (exclusive create through the descriptor, SQLite's `mode=rw` open, the identity check), the refusal of an incomplete build, the file and folder syncs, the re-check before the swap (the ledger set observed again, no `.open` journal), the swap (the replaced generation's modification time, a temporary link renamed over `current.db`), the freshness short-cut (a rebuild that finds the published generation fresh builds nothing), the rebuild's publish after `loaded` (engine and sidecar), the `meta` keys of §8 (`ledger_version` = `<N>/<digest>`, `engine_build`, `as_of`), the save's gate reading the published generation itself and checking it fresh against the disk on its own ledger set (`SaveRequest.mirror` goes), the reader's pin (`app.mirror.files.pin`: one `readlink`, the generation's path for the whole request), and the `@tla_action` markers with the mirror-publish model's code map checked both ways.
- Implements: ADR-0015 (with its amendments of 2026-10-25, 2026-10-29, 2026-11-07 and 2026-11-08), ADR-0016 (the reads), ADR-0064, ADR-0068 D1; specs `design/specs/mirror/publish.md` §2 to §9, `design/specs/engine-jobs.md` §6.1 step 4 (the gate), §6.7 (the rebuild's publish), §7 (the re-check before a publish); `formal/tla/mirror-publish/MAPPING.md` §2.1 (the code column); EP-19, EP-29, EP-30.

It keeps two outcomes truthful: what screens, outside tools and the save's gate read is one whole, complete, committed generation; and the save's gate passes only when the published generation describes the disk the plan was made on. And it never touches a file outside the workspace's mirror folder: the cleanup removes a link as a link, never what it points to.

## Decisions
- **Owner's decisions applied** (ADR-0015 amendment of 2026-11-07, extended 2026-11-08, recorded in S0085): "Whole folder is ours" (with the orchestrator's rule: the cleanup never follows a link; a link at `mirror/` or inside it is removed as a link); "Grace period only (Recommended)"; "At most 2 extra (Recommended)"; "Random tag in name (Recommended)". No new owner question.
- **Two modules** (agent): `ledger_engine.mirror.publish` works only through the file-system port (it is now on `tests/architecture/test_write_port.py`'s write path: it imports nothing that touches files), so the in-memory fake's sweeps test it; `ledger_engine.mirror.store.SqliteStore` holds the one step that opens by path (SQLite cannot open relative to a descriptor): the create goes through the folder's handle, SQLite then opens `DirHandle.path()/<name>` with `mode=rw` (never creating), and the identity is checked through the handle.
- **The port gains** `symlink` (its target one name of the folder, never a path), `readlink`, `touch` (the entry's own time, never through a link), `open_child` (`O_DIRECTORY | O_NOFOLLOW` relative to the handle) and a mode for `mkdir` (spec's "the file-system port gains a link, `readlink`, `utime` and a folder removal that follows no link": the removal is `publish._remove_tree` over `open_child`, `remove`, `rmdir`).
- **The engine reads no clock** (agent, forced by the lint ban TID251, INV-07, EP-10): the sidecar sends `today` (its clock's instant in the local time zone) and `built_at`; the engine derives the cleanup's "now" from `built_at`. A frozen clock in the acceptance harness then keeps every replaced generation "young" (bounded by the cap of 2).
- **The mirror folder is derived, never named** (agent): the engine computes `<app_cache>/workspaces/<key>/mirror` from the request's `app_cache` and key (one name, never `.` or `..`); unlike `app_local_data`, `app_cache` is not anchored to the engine lock. **Limit:** a sidecar bug that sent another absolute `app_cache` would make the job clean a folder named `workspaces/<key>/mirror` under it; nothing else. The app's cache folder itself is made again if the OS purged it.
- **The protocol answer** (agent): one `publish` field (`published`, `fresh`, `inexact`, `replaced`, `incomplete`, or null) instead of a flag and a reason, because the sidecar's decoder must refuse exactly what the schema refuses (`test_the_decoder_refuses_exactly_what_the_schema_refuses_inside_a_recover_result`), and cross-field rules cannot live in the schema; the sidecar refuses only a loaded answer with no `publish` and a `fresh` that is not one. Nothing gates on these fields (they are logged).
- **Freshness short-cut built** (agent; publish.md §4 "A job that finds the published generation fresh builds nothing"; engine-jobs §2's idempotence): `publish.fresh` (the disk on the generation's own set, this engine's DDL and build, today) ends the rebuild after the cleanup with `fresh`. The same function is BL-0125's check, which the open will use (BL-0152).
- **`paused` is not tried again** (agent; engine-jobs §7: an `.open` journal refuses the job; only recovery clears it): the sidecar logs `rebuild.not_loaded {why: paused}`. A journal folder that cannot be listed is `paused` too (fail closed, as the save's step 1).
- **The gate** (publish.md §7): read after the disk's check, so an edit just before the gate is the disk's refusal; no published generation, one that cannot be read, has a journal beside it, says it is incomplete, or is not fresh on its own set is `mirror_stale`. The save now observes twice at its gate (the plan's set, then the generation's).
- **`build_complete = 0` refusal kept** (agent, EP-30 judged as §12 asked): one comparison; the model's `publish_incomplete` mutant shows what it guards.
- **The reader's pin without a descriptor** (agent): `tests/integrity/test_workspace_open.py` refuses any `os.open` in the sidecar outside its adapters (it cannot tell a read-only open). `pin` looks at `mirror/` with `lstat` (a link: `not_published`) and reads `current.db` with one `readlink`. **Limit** (spec §7): a link put at `mirror/` between the two leads that one read elsewhere, where the open's header and `meta` checks still apply; the sidecar never writes there.
- **`meta`'s new keys are required by the sidecar's `files.META_KEYS`** (agent): a generation an older build left without them reads as `not_a_mirror`, which the open rebuilds.
- **Cut** (agent, recorded as rows): the sidecar's floor holder to BL-0126 (it needs the workspace container that serves reads; the request's `floor` is 0 until then, so after a purge under a running app `N` may restart, and no screen reads it yet); the "Checking…" text to BL-0211 (no screen reads the mirror before BL-0126); a replay of the model's traces to BL-0210. **Deviation from S0060's marker rule** (engine-jobs markers only on actions a trace replay walks): the mirror-publish markers are on functions the §9 sweeps walk at every effect instead; recorded in `ledger_engine.tla` and BL-0210.
- **The sidecar's marker is `app.mirror.model_map.tla_action`** (agent): the platform-level name a sidecar marker module had until S0072 (ADR-0068 D5) is a retired term (`scripts/check_retired_terms.py`); this marker serves only the mirror-publish model's reader actions, so it lives with the reads.
- **INV-05 enforced, BL-0005 done** (agent; the rule unchanged): the sweeps and the view DDL golden are its enforcement files (the macOS-only real-disk tests do not count for the check: they carry a `skipif`).
- **Privacy-scan workaround** (PROCESS.md §8, one line each): the rebuild's `floor` bound is 999,999,999,999, not 2^53, because 2^53's 16 digits in the generated schema read as a card number to the scan's rule; 12 digits is far above any session's number of publishes.
- **Measured** (§12 asked): the folder sync of step 6 on the owner's Mac (APFS, `F_FULLFSYNC`, small ledger, 20 jobs): 1.9 ms median, 5.6 ms at most; a whole publish job 17 ms; two folder syncs per job (the parent's at the folder's check, step 6).
- **Engineering principles:** no deviation beyond the S0060 marker-rule one above.
- **Tests first:** written before the code and run on the base (6c71d450): the engine's new and changed test modules (`tests/mirror/test_publish.py`, `test_publish_crash.py`, `tests/ledger/test_save.py`, `test_rebuild.py`, `tests/test_save_ops.py`, `test_rebuild_ops.py`) failed to collect (`ImportError: cannot import name 'publish' from 'ledger_engine.mirror'`); the port tests failed 7 of their new 7 (`tests/fs/test_darwin.py` 4, `tests/fakes/test_memfs.py` 3); the sidecar's `tests/mirror/test_files.py`, `tests/platform/test_rebuild_job.py`, `test_save_job.py` failed to collect (no `pin`, no `RebuildTarget.lineage`, no `SaveRequest.app_cache`); `test_tla_mapping_mirror_publish.py::test_the_mirror_publish_code_map_holds_both_ways` failed (no markers). My own test bug found on the way: the first "replaced" test swapped the file after the identity check (undetectable by design); it now swaps it inside SQLite's write.
