# S0122: the oracle's outside-span byte check and its classes (M1b, BL-0045)

> **Reverted (2026-11-15).** The check was built (a9d48c73) and reverted before it was pushed, by the owner's decision below. This journal is the record of what was tried and why it was dropped; BL-0045 is closed, and its one useful finding is BL-0275.

## Brief
- Goal: M1b's seventh slice. The differential oracle (`scripts/oracle/harness.py`, ADR-0014) compares the legacy app's change with the intended change at the entry level (`classify.compare`) and tags each divergence (I2, I3, I10, M28, FIX-…, UNEXPLAINED, NOT_APPLIED). Changes the printer cannot see are counted only as a file-level comment count today:
  - an untargeted `@@` rewritten as `@`;
  - a comment inside an entry lost;
  - reformatting: indentation, alignment, blank lines, number spelling;
  - any byte outside the intended change.
  Add the D1 step-2b check to the oracle. For each file, the legacy's new bytes must equal the old bytes everywhere outside the **intended change's spans** (the target entries' lines in the original, and the inserted text's place). Every outside-span difference is reported as a divergence and classified:
  - into an existing class when one explains it (the legacy re-renders a whole file from loader output: I10 for comments and elided or booked amounts; FIX-L3-02 for a `@@` total; FIX-L3-05 for a decimal scale; FIX-L3-15 for typed metadata; I2 or I3 where those entries are the cause);
  - otherwise into a new formatting class only if it is purely whitespace or layout (name it, define it in `classify.py`'s docstring and in ADR-0014's expected classes; a new class is an ADR-0014 list change, so state it in the journal for the daily batch);
  - and UNEXPLAINED for anything else.
  The step-2b result joins the existing per-case report and the counts. A case's verdict blocks (UNEXPLAINED or NOT_APPLIED) exactly as today.
- Then **run the oracle on the repo's corpora and the generated demo** (`harness.py --demo`, the write corpus), on copies only, as the harness does. Report the comparisons per mutator and the class counts with and without the new check. The G1 criterion asks for at least 200 comparisons, none unexplained. Record how far today's corpus is from that and what the new check adds. **If the run finds UNEXPLAINED divergences, report them, do not reclassify them away**: a new class needs a stated cause.
- Implements: ADR-0014 (the old app as differential oracle; expected divergence classes; an untagged divergence blocks promotion), ADR-0009 and ADR-0008 step 2b (the outside-span rule the v0.4 contract already enforces, `ledger_engine.ledger.core.semantic_diff` `OUTSIDE_SPANS`), INV-02 (Beancount is the oracle), BL-0045.
- Capabilities: none changes status.
- Invariants touched: INV-23, INV-24. The harness reads copies only, and a non-corpus source must be inside `FT_LOCAL_TIER_DIR` (`copies.refuse_local_tier_source`). **This slice does not change those guards.** Reports for anything other than a repo corpus or a generated ledger carry counts, classes and case IDs only, and so does every new field the outside-span check adds: no bytes, lines or entry text in a T-local report.
- Risk class / lane: Medium / full: tooling, but its verdicts decide promotion. Review budget row: **Tooling, gates, measurement**: one verifier round; the fix round fixes only a shape the check's own docstring or must-not-pass list promises to refuse, a false statement of fact, or a finding in a guard of real data or privacy (INV-23, INV-24); a High is always fixed. A fresh round follows only if the slice or a fix changes a guard of real data or privacy.
- The bytes it protects: none; it reports. It must never let an outside-span byte change pass silently, and never put a T-local ledger's text in a report.
- Mechanism questions (PROCESS.md §3 step 2): it hardens a check that decides promotion. Real setup: every mutator promotion (ADR-0014). No policy can forbid it, since it is the check itself. Fix-round history: the harness and the classifiers (S0002, and later oracle slices: look them up and list them with their rounds in the journal).
- Constraints: the legacy app is launched only by the harness (`launch_legacy.py`), from the legacy worktree read-only, on its own ports and data folder, on copies. It never touches the owner's running v0.3 app or the owner's live data folder. Nothing is written into the legacy worktree.
- Acceptance (tests first; each fails on the base commit):
  - must-not-pass, one each, in `scripts/oracle/tests/test_classify.py` or its own test file:
    - an untargeted `@@` rewritten as `@`;
    - a comment inside an untargeted entry dropped;
    - a reindented untargeted posting;
    - a byte changed between two entries;
    - a changed line outside every entry;
    - an intended change exactly at its span, which passes;
  - each maps to its class (or UNEXPLAINED) as the docstring says;
  - a T-local-shaped report of an outside-span divergence carries no text;
  - the harness's existing tests stay green;
  - the run's numbers are in the journal.
- Expected doc impact: `classify.py`'s and `harness.py`'s docstrings; ADR-0014's class list, only if a class is added; `design/specs/` for the oracle if one exists; BL-0045 closed; the roadmap's M1b line if it names the classifiers.
- Open questions: none.

## Decisions
- (orchestrator) No policy question at the brief: BL-0045 states its own scope. The check decides promotion and cannot be forbidden by policy. It changes none of the harness's guards of real data.
- (agent) **Fix-round history** (the brief's mechanism question): S0002 built the harness and classifiers in two verifier rounds (round 1: five High, all over-permissive erasers or guards; round 2: six Medium/Low); S0004 (the intent table the models follow) two rounds, no High; S0030 (the harness's INV-24 guards) one round, no High; S0031 (oracle tests at push, the launcher's owner port) two rounds, no High. The classifier family has needed two rounds once (S0002). This slice adds a new check beside the erasers and changes none of the guards of real data (`copies.py`, `refuse_*`, `redact`'s list).
- (agent) **Where step 2b sits.** In `classify.compare`, after the entry-level pass, as `classify.outside_spans`; `refused` gets it through its own `compare` call. The entry-level pass records what it already accounted for (`_Roles`: each target, intended, created, moved, copied, generated, removed or unintended entry, and each untargeted entry paired with its rewritten form), so step 2b compares only the rest and never reports an entry twice. A pair's text is its step-2 class's; its comments are still compared.
- (agent) **The spans.** A target's span is Fava's entry lines (the engine's `source_edit.locate` rule), found from the parser's line numbers in the old text. A created entry's place is anywhere between units with one blank line as its separator: the oracle's model does not route inserts (the engine's `route_insert` does), so the place of a created entry is a stated limit, not checked.
- (agent) **Classes, smallest set first** (as `explain` does for entries): erasers I10, FIX-L3-02, FORMAT; the needed set is found by dropping each from the full set (fits grow with the erasers), with a full search as a fallback. A file that no set explains gets one UNEXPLAINED per run of changed lines (difflib on the compared units, under every eraser), and beside it each eraser that removed differences (an order-free count, linear; difflib on two sides with FORMAT taken out is quadratic, measured: minutes per demo case).
- (agent) **I10 is "comments lost", not "comments changed"**: it applies only when the new side holds no comment the old lacks (the legacy never writes one). A changed comment is one UNEXPLAINED. Lost comments are `;` comments anywhere (between entries, inside entries, after postings) and org-mode headings, which Beancount skips. A lost comment line takes one blank line next to it, as a removed entry does; so does a header line when step 2's header check already reported the header. This replaces the file-level count of lost comment lines (`SetDiff.comments_lost` is still computed, no longer reported), so the existing `test_i10_comments_lost` keeps its expectation `["I10"]`, now from step 2b.
- (agent) **FIX-L3-02 outside the change**: the legacy reprint writes an untargeted `@@` total as Beancount's per-unit quotient; the key is unchanged (the parser keeps only the quotient), so step 2 never saw it. The eraser masks the price of an unchanged entry whose old text used `@@`; a `@` price written another way stays UNEXPLAINED.
- (agent) **New class FORMAT** (ADR-0014 amendment of 2026-11-15; for the daily batch): the legacy printer's layout. Whitespace inside lines (indentation included: where indentation means something, the parse and so the key differ), blank lines, line ends; entries between two other lines in another order that Beancount sorts the same (its `entry_sortkey` is date, kind, line: two entries of one date and kind keep their order; the replacement's place among them is layout too); `option`, `plugin` and `include` lines moved among the entries in their own order (Beancount reads them in file order wherever they stand; plugins run in that order, a repeated option keeps the last). The note says when the order changed. Cause: the legacy writes whole files from the loader's sorted output (seen in every successful legacy write of the three corpora). Limit: Beancount also breaks ties between files by line number, which a reprint changes; FORMAT does not see that.
- (agent) **Not reclassified: `pushtag`/`poptag` (and `pushmeta`) folded into the entries' tags.** The keys stay equal, the bytes do not; it is neither whitespace nor layout, and ADR-0014's I10 text does not name it. It stays UNEXPLAINED and blocks; whether it is I10 (the same defect: the reprint writes the parser's values, not the source text) is the owner's call for the daily batch (BL-0273).
- (agent) **`ParsedFile` keeps the file's text and entries**, read as bytes and decoded: `read_text` turns `\r\n` into `\n`, which would have hidden a line end change (found by the line-end must-not-pass test).
- (agent) **Pre-existing step-2 UNEXPLAINED cases are reported, not touched**: they were UNEXPLAINED at the base commit, before step 2b, on the demo (`ren-002`) and the write corpus; listed with their case IDs under the run's numbers, held by BL-0274.
- (agent) **No Python lint gate covers `scripts/oracle`** (the hooks lint `backend/` and `engine/`; `pyright_platforms.py` checks those two only). Ruff's pyflakes and bugbear rules were run by hand on the changed files.

## Hand-off (PROCESS.md §3 step 4; ADR-0057)
- **Checks that accept, tag or refuse, each with its must-not-pass test** (all in `scripts/oracle/tests/test_outside_spans.py`):
  - `classify.outside_spans` (step 2b): no outside-span byte change is a MATCH. Brief's list: an untargeted `@@` rewritten as `@` → FIX-L3-02 (`test_an_untargeted_total_price_rewritten_as_a_unit_price_is_fix_l3_02`); a comment inside an untargeted entry dropped → I10 (`test_a_comment_inside_an_untargeted_entry_dropped_is_i10`); a reindented untargeted posting → FORMAT (`test_a_reindented_untargeted_posting_is_format`); a byte changed between two entries → UNEXPLAINED, and whitespace there → FORMAT (`test_a_byte_changed_between_two_entries_is_unexplained`); a changed line outside every entry → UNEXPLAINED (`test_a_changed_line_outside_every_entry_is_unexplained`); an intended change exactly at its span passes, one byte outside it does not (`test_an_intended_change_exactly_at_its_span_passes_and_one_byte_past_it_does_not`). Beyond it: the pushtag fold, a re-spelled number, a `@` price re-spelled (not FIX-L3-02), a line end, a comment written at the change's place, a changed comment, a same-date swap, header lines swapped, a file the change does not touch, a deleted file with no entry, a header line re-spaced, an inserted entry with more than its blank line, a `;` inside a string.
  - FORMAT's order rule (accepts a reorder): `test_entries_reordered_as_beancount_sorts_them_are_format`, `test_the_replacement_moved_past_an_entry_needs_format`; must-not-pass `test_two_untargeted_entries_of_one_date_swapped_is_unexplained`, `test_header_lines_moved_in_their_own_order_are_format_and_swapped_are_not`.
  - The must-pass shapes: `test_an_appended_entry_at_the_end_of_the_root_passes` (with and without a blank line; its twin re-spaces a line and is FORMAT), `test_an_untouched_included_file_passes` (its twin changes the file's comment: UNEXPLAINED).
  - `harness.result_fields` / `redact` (real-data privacy, INV-23/INV-24): a T-local report of a step-2b divergence keeps `classes_2b` counts and no text, file name or line (`test_a_t_local_report_of_an_outside_span_divergence_carries_no_text`). `redact` itself is unchanged (its list already drops `divergences`, where the new `text` field lives).
- **Self-mutation** (`scripts/mutants.py`, plan in the session scratchpad; the oracle's classify and harness tests as the command): 18 loosening mutants, 18 killed: slots ignored, residue not reported, I10 stripping every comment, I10 despite an added comment, ties ignored by the order rule, a whitespace-only difference skipping the file, header lines always dropped, a dropped entry taking every blank line, the `@@` mask on every price, every new entry taken as a target, `redact` keeping divergences, FORMAT ignoring comment text, FORMAT dropping non-blank lines, pairs hiding their comments, a missing file skipped, the comment split ignoring strings, header order ignored, blank lines ignored without FORMAT. Round 1 (13 mutants) left 8 survivors: the moved-replacement, tie (the order rule then got one sort key, so one mutant covers every run), untouched-file, header-line, `@`-price and string cases got tests (the string mutant tightened, turning an I10 into UNEXPLAINED, but the split must be right); "a drop always takes a blank" tightened and was replaced by a loosening one; "FORMAT collapses indentation" was the better rule and was adopted (where indentation means something, the key differs). Round 2 left 2 survivors (a drop taking every blank line, a missing file skipped): each got a test. Round 3 (after the header rule and a refactor): 18 of 18 killed.
- **Population:** none claimed beyond the run's inputs, listed with their counts above (the nasty cases file, the demo's generated cases, the write corpus's 17 `load` folders from `cases.toml`).
