# S0036: the manual CI run passes on Linux

## Brief
- Goal: fix the three causes of the failed manual CI run of 2026-10-26 (the first M0 run, dispatched from `main`'s `run-next-ci.yaml`, `ref: next`, `milestone_exit: M0`, testing `next` at 8434091d). (1) `scripts/tests/test_acceptance_harness.py` `test_a_made_folder_that_was_replaced_is_refused` failed on the ubuntu runner: `TempRoot.check_own` (`scripts/acceptance/launcher.py`) identifies a made folder by `(st_dev, st_ino)`, and ext4 gives a freed inode to the next new folder at once, so "rmdir, then mkdir at the same path" yields the same identity. The test is rewritten so it only asserts what the check can tell on every file system; the Linux limit is written in the docstring. (2) The `frontend` job was cancelled at 15m16s in "Playwright browsers": the browsers are cached keyed on the exact Playwright version, a cache hit installs only the Linux system packages, and every job's `timeout-minutes` in `ci.yml`, `nightly.yml` and `packaged.yml` becomes a hang backstop far above a normal run. (3) Roadmap §3.2 says where a milestone's green manual CI run is recorded (its journal entry, not a backlog row) and why BL-0076 is the M0 exception.
- Implements: ADR-0060 (manual CI before releases and at milestone exits); owner rule "no fixed time budgets" (S0034, IMP-0027).
- Capabilities: none (gate tooling; no capability row).
- Invariants touched: INV-24 (the harness never reaches live data: the symlink and device checks stay and are tested), INV-19 (roadmap updated in the same change).
- Risk class / lane: Medium (it changes a refusal test of an INV-24 check and the CI gate definitions; no ledger or user data) / light.
- Acceptance tests: `scripts/tests/test_ci_workflows.py` (new: every job in the three workflows has a hang-backstop `timeout-minutes` of at least 60 and the files say it is a backstop; the frontend job restores `~/.cache/ms-playwright` keyed on the Playwright version and installs browsers only on a miss, system packages on a hit; every remote action pinned by major tag as the repo does). `scripts/tests/test_acceptance_harness.py` (changed: the rmdir/mkdir case replaced by a folder renamed into place, whose inode differs on every file system; a device change; the symlink case kept).
- Expected doc impact: `design/specs/roadmap.md` §3.2; this journal. No ADR (no new decision: ADR-0060 stands; the timeout rule is the owner's S0034 rule).
- Open questions: none. Whether the Playwright cache alone keeps the job short is not known (see Decisions).

## Decisions
- Owner approval for all three fixes, verbatim, 2026-10-26: "go ahead with all three fixes" (after the agreed diagnosis of that run).
- Changing an expected outcome (PROCESS.md §8): the assertion "a plain folder removed and made again at the same path is refused" is dropped because the check cannot tell it on Linux (ext4 reuses the inode at once; macOS APFS does not, which is why it passed locally). INV-24's property does not depend on it: a replacement that leads anywhere else is either a symlink (refused by `S_ISLNK`) or a mount or other file system (refused by `st_dev`); a plain folder at the same path inside our own temp root is still our temp root. Comparing ctime or birth time instead was rejected: the app writes into these folders, which changes ctime, and birth time is not portable (owner diagnosis, same session). (agent, owner-approved above)
- In place of the dropped assertion the test now replaces the folder with one that existed at the same time (made beside it, then renamed into place): two folders that exist together never share an inode, so the identity check is still exercised on every file system, not only on macOS. (agent)
- The mount case is tested by giving `os.lstat` a different `st_dev` for the made folder (a real mount needs root, which the meta-tests do not have). (agent)
- The Playwright cache key is `playwright-<os>-<version>-chromium-webkit`, the version read from the installed `@playwright/test` after `pnpm install --frozen-lockfile` (so it is the lockfile's version). The cache holds the browser downloads only; `apt` system packages cannot be cached this way, so a hit still runs `playwright install-deps`. Which of the two took most of the 15 minutes is not known from the log; the timeout backstop is what keeps a slow first (miss) run from being cancelled. (agent)
- `timeout-minutes`: 60 for every job (packaged builds: 120, three OSes, Windows slow), as a hang backstop. GitHub offers no limit relative to past runs, so a fixed backstop far above normal is the closest fit to the owner's rule; the default (360) would let a hang burn six hours. The step-level 12-minute limits on the packaged smoke tests stay: they bound one fixed smoke run each, which does not grow with the code. (agent)
- Base commit: b9188aa4. Tests first: `test_ci_workflows.py`'s three workflow tests failed on the base (job limits of 10 to 45 minutes; no browser cache); its parser and action-pin tests and the three harness tests are `@regression-guard` (the checks they exercise exist on the base; the base's own harness test is the one that failed, on Linux only, in that run). The Linux inode reuse could not be reproduced on this Mac (no Linux file system or container here); the CI log is the evidence, and the new tests do not depend on how a file system hands out inodes.
- The roadmap rule and BL-0076: BL-0076's row still says "with `milestone_exit: M0` set"; it is not edited here (the orchestrator closes it after the green run, per the new §3.2 paragraph).

## Retro
- Escape: no gate ran the meta-tests on Linux before the manual run. The gate that caught it is the manual CI run, which by design (ADR-0060) is the only place Linux and Windows run; it found the bug at its first full run, which is its job. A cheaper gate is not warranted: a per-push Linux run is the T1 job ADR-0060 removed (the owner chose manual runs), and a local Linux container is not available on the owner's Mac without new tooling for every push. The cheaper lesson is in the test, not a gate: tests of file identity should not depend on how a file system assigns inodes (the new tests use folders that coexist, or set the stat result).
- The frontend timeout is the owner's "no fixed budget" rule (S0034) applied late: the 15-minute job limit was a budget that the first Linux install outran.
- Where time went: reading the launcher and the workflows; the mutant run found one real gap (the ext4 link case).
- Process cost: one implementer pass so far.
