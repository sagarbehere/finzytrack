# S0166: The frontend's data layer: one API layer, one error path, a bounded server-state cache

## Brief
- Goal: the first M2 slice (roadmap §4 M2, WS-FE-DATA). The frontend gets the foundations every later screen reads through:
  1. **One API access layer** (L2-06): `frontend/src/api/` is the only code that talks HTTP. `api/client.ts` wraps `openapi-fetch` 0.17.0 over the generated types (ADR-0038): it unwraps the envelope, turns every failure into one `AppError`, passes the caller's `AbortSignal`, and for a workspace-scoped call checks that `meta.workspace_id` is the workspace the path named (INV-28's planned client assertion, BL-0028/BL-0107). A lint rule refuses `fetch`, `XMLHttpRequest`, `EventSource`, `WebSocket` and an `openapi-fetch` import in `src/` outside `src/api/`.
  2. **One frontend error path** (L2-05 with its doubles L2-13 and L10-17; L8-30): the backend's error envelope (`app.api.errors`, ARCHITECTURE.md §6.1, §6.2) is decoded once, in `api/`, into one typed `AppError` (code, class, message, data_safe, next_step, issues, retryable, retry_after_ms, details, correlation_id); anything that is not a valid envelope becomes a client code (`CLIENT_NETWORK`, `CLIENT_DECODE`, `CLIENT_ABORTED`). One `presentError` (`app/errors/`) records each error **once** in a small per-app error sink (no toast design yet: L9-13/L8.M-15 come later); an aborted request is never shown; the query cache and mutation cache call it unless a query opts into `meta.errors: 'state'`.
  3. **The server-state cache** (L2-03): TanStack Vue Query, its query keys built from the operation's declared scope (`x-ft-scope`, generated into `api/generated/keys.gen.ts`): `['app', path, …]` or `['ws', ws, 'ledger'|'config', path, …]`, so keys carry the workspace taken from the same path parameter the request uses, and a switch never shows another workspace's data (ADR-0037, INV-28). One `QueryClient` factory with a declared bound: `gcTime` and a cap on cached queries with eviction of the oldest unobserved query (INV-10), and a check (lint plus test) that refuses a `QueryClient` made elsewhere and a query that sets `gcTime: Infinity`.
  The domain-event invalidation is shaped only as far as something exists: nothing serves `meta.ledger_version` yet (`app.api.envelope.meta_of` sends null until the mirror's reads, BL-0126), and its format's one exception (a purge resets the generation number, ADR-0015 amendment of 2026-11-08) needs a decision when it arrives, so the invalidation moves to a new backlog row with BL-0126 as its first producer.
- Implements: ADR-0037 (with its 2026-10-29 Vue amendment), ADR-0038 (openapi-fetch; keys from `x-ft-scope`; the decoding wrapper of its 2026-10-25 amendment), ADR-0039 (one frontend path), ADR-0053, ARCHITECTURE.md §3.1, §3.2, §4.1, §6.4; BL-0107 in part (client, `keys.gen.ts`, `errors.gen.ts`; the `x-ft-type` brands and `decode.gen.ts` stay open: no backend field carries `x-ft-type` yet).
- Capabilities: CAP-NOTIFY-ERRORS stays `planned` (no user-visible error UI yet); none other.
- Invariants touched: INV-10 (the frontend cache bound, its planned part "the frontend's server-state cache bound with its `QueryClient` (L2-03, M2)"), INV-12 (layer map: new files under `src/app` and `src/api`, both already elements), INV-28 (the planned `meta.workspace_id` client assertion; INV-28 stays `pending`, its other parts are BL-0028's), INV-23 (no data in tests: synthetic keys only).
- Kind: product code (shipped), frontend, read-only foundations: no ledger write, no write outcome, no finance meaning. Review row "Other product code": verifier.
- Real setup / policy: every user's frontend uses this layer; nothing here accommodates a rare setup. Fix-round history: new mechanism family on the frontend (no earlier rounds).
- Risk class / lane: Medium / light.
- Acceptance tests (vitest, must fail on base 30368ddc):
  - `tests/unit/api/errors.test.ts`: a valid error envelope decodes to its `AppError` field by field; must-not-pass: an unknown code, a code with the wrong class, a missing field, a non-JSON or HTML body, a 2xx answer without `data`/`meta` → `CLIENT_DECODE`, never a made-up server code; a network failure → `CLIENT_NETWORK`; an abort → `CLIENT_ABORTED`.
  - `tests/unit/api/client.test.ts` (over a stubbed `fetch`): success unwraps `data` and returns `meta`; an error answer throws the decoded `AppError` once; the caller's `signal` reaches `fetch`; a workspace call whose answer names another workspace (or none) is refused (`CLIENT_WRONG_WORKSPACE`), must-pass: the same workspace.
  - `tests/unit/api/keys.test.ts`: an app-scoped operation's key starts `['app']`; a workspace operation's key is `['ws', ws, scope, …]` with `ws` from the path parameters; two workspaces give two keys with no common prefix below `['ws']`; the scope table is the contract's (`keys.gen.ts` generated, never hand-written).
  - `tests/unit/app/errors.test.ts`: one error presented twice (the cache's handler and a caller) is recorded once; an aborted error is not recorded; a query with `meta.errors: 'state'` records nothing; a failing query records one entry; the sink is bounded.
  - `tests/unit/app/queryClient.test.ts`: the client declares a finite `gcTime` and cap, `staleTime: Infinity`, no automatic retry; adding more queries than the cap evicts the oldest unobserved ones and never an observed one.
  - `tests/unit/gates.test.ts` additions: the new lint bans (fetch and friends outside `src/api`, `openapi-fetch` outside `src/api`, `new QueryClient` outside its module, `gcTime: Infinity`), each with its must-pass twin.
- Expected doc impact: ARCHITECTURE.md §3.1 (built today; files as built), §3.2, §4.1 (BL-0107's part done), §6.4 (as built; client codes); `frontend/CLAUDE.md` (the API layer rule, the cache rule); INVARIANTS.md INV-10 planned part → built, INV-28 enforced-by line (client assertion built); backlog rows L2-03, L2-05, L2-06, L8-30, BL-0107, BL-0028; a new row for the event invalidation; `scripts/check_generated.py` (two new generated files); THIRD_PARTY_NOTICES (new packages); ARCHITECTURE.md §10 pins. No user docs (light lane; nothing user-visible).
- Open questions: none on the rubric. The libraries are the decided ones (ADR-0037, ADR-0038, ARCHITECTURE.md §10 candidates); the presentation table is ARCHITECTURE.md §6.1's per-class default.

## Decisions
- **Blocked: the two packages cannot be installed from the agent's sandbox** (2026-11-28). `pnpm add --save-exact @tanstack/vue-query@5.104.1 openapi-fetch@0.17.0` (and every `pnpm install`, even `--lockfile-only` with a store and `HOME` in the scratchpad, even in an empty project there) stops with `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK ... "pnpm-store-operation-locks": Operation not permitted`. The sandbox denies writes to the macOS per-user temp and cache folders (`getconf DARWIN_USER_TEMP_DIR` / `DARWIN_USER_CACHE_DIR`, checked with `touch`), which pnpm 12's native binary uses for that lock and which no pnpm setting moved. Not worked around (no hand-edited lockfile, no copied packages). The slice is therefore split into two commits: part 1 (this commit) holds everything that needs neither package; part 2 (the client over openapi-fetch, the QueryClient with its bound, and the cache's error hooks) follows once the owner has run the command above in `frontend/`.
- **Versions** (agent, EP-24): the candidates of ARCHITECTURE.md §10, `@tanstack/vue-query` 5.104.1 (2026-10-02) and `openapi-fetch` 0.17.0 (2026-02-11), both past 14 days and MIT; newer vue-query releases old enough exist (5.107.1, 2026-11-06), the reviewed candidate is taken, and an upgrade is its own slice.
- **The generated tables sit in `src/api/generated/`** (agent), not beside `client.ts` as ARCHITECTURE.md §3.1 drew them: that folder is the one never hand-edited, skipped by prettier and read only by `src/api` (layer map). Only two tables are generated: each operation's scope and writes (`keys.gen.ts`) and each error code's class (`errors.gen.ts`). The code union and each code's details already come from `openapi.ts`, and the presentation follows the class (§6.1), so no per-code presentation table is generated.
- **Client codes** (agent): `CLIENT_NETWORK` (unavailable, retryable), `CLIENT_DECODE` (internal: a body that is not a valid envelope, an unknown code, a code with another class, a 2xx without `data`/`meta`), `CLIENT_WRONG_WORKSPACE` (conflict: the answer's `meta.workspace_id` is not the workspace the path named; INV-28's client assertion), `CLIENT_UNEXPECTED` (internal: a thrown value that is not an AppError; its own message is never shown), `CLIENT_ABORTED` (never shown). Every client code says `dataSafe: false`, which means "no claim": the client cannot know whether a request it sent ran, and an outcome text ("saved", "unchanged") is the server's alone (PROCESS.md §3, outcome exact). `CLIENT_TIMEOUT` (ARCHITECTURE.md §6.2's list) is not made: the client has no time limit (no fixed time budgets) and the list is corrected.
- **Default presentation by class** (agent, ARCHITECTURE.md §6.1): invalid → toast until a form passes its context (the Field primitive comes with the UI kit), not_found → toast, conflict / contract_refused / forbidden / internal → modal, unavailable → toast, aborted → none.
- **"Once"** (agent): the sink remembers every object it was given (a `WeakSet`), so the same failure presented by the query cache and by a caller is one notice; two failures are two notices (coalescing similar ones is D11's later work with the toasts). The history keeps the last 50 (`NOTICE_HISTORY`, a fixed diagnostic ring, INV-10's clause).
- **One sink per app, provided** (agent, EP-04): `createErrorSink` + `installErrors(app, sink)` + `useErrors()`, never a module-level store.
- **The key shape** (agent, ADR-0037): `['app', path, query]` and `['ws', ws, scope, path, otherPathParams, query]`, `ws` taken from the request's own `{ws}` path parameter; a workspace path without a non-empty `ws`, an undeclared path or a path with no GET is refused (an error, not a guessed key).
- **`tests/fixme.ts`'s `planned()` counts only files** (agent): with `src/app/` created, on a case-insensitive disk its existence check took `/src/App` for the folder `src/app` and imported it (`tests/unit/fixmeHelpers.test.ts` failed); a folder is not a module.
- **Part 2, once the packages are installed** (the plan, so whoever continues builds the same thing): `src/api/client.ts`, `createApi({ baseUrl, fetch })` over `openapi-fetch` (no module global; provided like the sink): one `get(path, params, signal)` that returns `{ data, meta }` via `decodeSuccess`, throws `decodeError(status, body)` on a non-2xx answer and `failureOf(thrown, signal)` when the call throws, and for a path under `/api/w/{ws}/` throws `CLIENT_WRONG_WORKSPACE` unless `meta.workspace_id === params.path.ws`; `src/app/queryClient.ts`, `createAppQueryClient(bounds, sink)` with `CacheBounds { gcTimeMs, maxQueries }` (desktop defaults injected by `main.ts`, read from configuration later like the backend's, BL-0229), `staleTime: Infinity`, `retry: false` (Retry is the user's, §6.4), a `QueryCache`/`MutationCache` `onError` that calls `sink.present` unless `meta.errors === 'state'` (typed through Vue Query's `Register`), and on each `added` event the removal of the oldest unobserved queries above `maxQueries` (an observed query is never removed); `main.ts` installs both. Tests: `tests/unit/api/client.test.ts`, `tests/unit/app/queryClient.test.ts` as the brief lists. Then the docs, the backlog rows (with the new row for the event invalidation: `meta.ledger_version` by its generation number, with ADR-0015's purge exception decided then, `x-ft-writes`, config writes and the focus check; first producer BL-0126) and THIRD_PARTY_NOTICES (`python3 scripts/check_licences.py --write-notices`).
