# S0071: best-effort drives, no ledger-set locks, no legacy lock on a save

## Brief
- Goal: build ADR-0068 D2, D3 and D4 (owner, 2026-11-01: "I agree with 3,4,5,6, and 7." and "Yes, go ahead with all of those"; INV-26's narrowing: "Confirm (Recommended)"). D2: on a folder whose volume has no atomic swap (exFAT, FAT, HFS+, network shares; `handles.write_mode` stays) the save and the undo are **best effort**: journal, synced backups and read-back kept; each file's new bytes written and synced at its staging name, then a plain rename onto the file (a created file: `RENAME_EXCL` where the volume has it, else a plain rename), the folder synced; recovery and rollback put the backup's bytes back the same way, without ownership checks. S0065's ownership rules go: the re-hash before the plain rename, the exclusive-move-by-check (`move_excl` on `plain`), the in-place exclusive create of a created file and its part removal, the empty claim of a missing file and "Empty = never ours", a stopping try's put-back of missing files, Keep's refusal while a file is missing, the network-retry ownership (`_took_effect`, `made_by_retry`), windows W1-W4. D3: the `Locks` port, `DarwinLocks`, the save's ledger-set locks and their wait phase, recovery's lock try, `lock_held` go; the engine lock stays the guard (the save op already refuses `engine.no_engine_lock` without it). D4: the save tries no legacy lock (`legacy_locks` leaves the plan and the protocol; `LEGACY_APP_SAVING` leaves the save path); the legacy-lock adapter stays for Copy (BL-0026).
- The bytes it protects: D2's best-effort path protects the ledger's own bytes against a crash or power loss mid-save (journal, synced backup, recovery) and keeps "saved" truthful (read-back, durable close); it does not protect another program's same-instant save (the accepted, documented loss of D2). D3 and D4 remove mechanisms that protected nothing the engine lock and Copy do not already protect.
- Implements: ADR-0068 D2-D4; spec `design/specs/engine-jobs.md` §5.2, §6.1 steps 2-3, §6.8, §8.1 step 1, §11, §15; supersedes in code ADR-0013's 2026-10-31 amendment (fallback rules), ADR-0012 Q29's locks, ADR-0062 decision 2 for a save.
- Capabilities: CAP-WRITE-ATOMIC family rows that mention the locks or the fallback (checked in Hand-off).
- Invariants touched: INV-01, INV-22 (write path; the best-effort path keeps backup, journal, read-back, recovery), INV-26 (narrowed to Copy; the save no longer tries the lock).
- Risk class / lane: High / full.
- Acceptance tests (new or changed; must fail on 7af404ab): best-effort order (staging, plain rename, no temp, no re-hash) for replaced and created files; an outside save between the backup and the replace is overwritten and the save lands (D2's accepted loss; base: refused `changed`); an empty file at a replaced path stops `foreign` with no detail (base: detail `empty`); a `mkdir` answering `EEXIST` there is a stop (base: taken as a network retry); Keep with a missing file keeps (base: refused `missing`); the restore's best-effort order; the crash, power-loss and I/O-error sweeps on the best-effort path in both fake modes; the save tries no legacy lock and takes no ledger-set lock (base: it does); recovery and Keep take no lock (`lock_held` and the lock argument gone, so structural); the real-volume tests (exFAT, FAT, HFS+, APFS images; opt-in) adapted.
- Expected doc impact: spec §5.2, §6.1, §6.8, §8.1, §11, §13, §15; ARCHITECTURE; engine/CLAUDE.md; glossary; capabilities; backlog (BL-0179 done, BL-0166 notice text, BL-0026 Copy only, moot rows closed, docs-repo line); MAPPING.md (S_Locks has no effect in the code); retired terms activated; generated schema, OpenAPI and TS.
- Open questions: none (D2-D4 are the owner's; the in-slice choices are logged below).

## Decisions
- Best-effort writes go straight from the staging name to the file by a plain rename: no temp name in this mode, which spec §6.8 (S0069's text) already stated; the brief's "after its temp is written and synced" is the staging name, written and synced. Fewer effects, fewer crash points; a torn write is only ever at the staging name, which recovery deletes whatever it holds (agent).
- No re-hash just before the plain rename: D2 says "no detection of another program saving the same file at the same instant"; the gate's fingerprint check (step 4) still refuses anything before the commit point. Pinned by `test_an_outside_save_between_the_backup_and_the_replace_is_overwritten` so the accepted loss stays visible (agent, within D2).
- A created file: `RENAME_EXCL` of the staging name where the volume has it (HFS+), else a plain rename (exFAT, FAT, network shares); an `EEXIST` is a stop (`changed`), nothing touched, as on APFS. The in-place `O_EXCL` create and its part removal are gone (agent, the brief's "else a plain create").
- `handles.move` is the one rename to a name of ours or a created path: `RENAME_EXCL` on the swap path, and on a best-effort volume where it is offered; else a plain rename. `keep` uses it; on a best-effort volume without `RENAME_EXCL` a kept copy's move is a plain rename (agent). **Corrected in round 1 (red team F1, High):** the original line called that safe because a kept name in use stops the save (`kept_free`) and the try (`kept_copy`) before; it missed several keeps in one try (two foreign entries at names of ours beside one file), where `keep`'s first-free loop always landed on kept-1 and the second plain rename replaced the first kept copy. `keep` now checks that the kept name is free before the plain rename on such a volume (as the base's `move_excl` did); a same-instant outside write at that kept name is D2's accepted loss.
- A `mkdir` answered `EEXIST` is a stop everywhere (no network-retry ownership); a retried `mkdir` that took effect leaves an empty folder beside a "not saved" (no bytes; agent).
- Recovery: an absent replaced file on a best-effort volume stays `missing` (put back from its backup by a plain rename, `RENAME_EXCL` where offered); an empty file is judged like any other content (`foreign`, no `empty` detail); a stopping try no longer puts missing files back on the side (`_missing_back` gone); Keep keeps a missing file missing (D2 names Keep's refusal as removed; the old version stays in the backup). Hard-link and lock-flag checks before a put-back stay: they are the owner's rules for every volume, not S0065's (agent).
- The legacy-lock adapter (`LegacyLocks`, `DarwinLegacyLocks`, `DarwinLock`) is kept for Copy, with its tests moved to `engine/tests/fs/test_legacy_lock.py`; `LEGACY_APP_SAVING` leaves the error registry with the save path (dead code otherwise; Copy adds it back with its own text, BL-0026) (agent).
- The save's step 3 keeps one thing the locks did as a side effect: every path is resolved first, so a folder that denies lookups ends "not saved" naming the file (the existing test `test_a_ledger_folder_that_cannot_be_searched_is_not_saved_and_names_the_file`) (agent).
- The engine-lock refusal of the save op already existed (`engine/tests/test_save_ops.py::test_no_save_op_runs_in_an_engine_without_the_engine_lock`, S0063); kept, not new (agent).
- Formal model: unchanged. `S_Locks` keeps its `@tla_action` on `save._run` with no effect, listed `PARTIAL` (BL-0180) and `NOT_WALKED` in the conformance replay, the way S0070 left `S_Load`/`S_Recheck`; S0072 cuts it. No TLC run (no config changed).
- Lock files earlier development builds left in `app_local_data/locks/` stay; nothing reads them, no released build made them (spec §15) (agent).
- The notice's words live once, `app.platform.engine_jobs.save_text.BEST_EFFORT_DRIVE`, held equal to spec §11's row by a test (agent).
