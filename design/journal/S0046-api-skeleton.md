# S0046: The API skeleton with the offline OpenAPI export

## Brief
- Goal: the HTTP edge every vertical will plug into, built and checked but not yet served: `app.api.create_app(container_factory)` (FastAPI) with one envelope for every answer (success and error, unknown routes included), the error taxonomy and the first registry codes translated once at the edge, the workspace-addressing dependency for `/api/w/{ws}/…` with its four outcomes (served, `404 WORKSPACE_UNKNOWN`, `409 WORKSPACE_NOT_OPEN {open_workspace, switching}`, `409 WORKSPACE_NOT_READY {phase}`), a route-scope check that refuses a misdeclared route when the app is built, `GET /health`, the offline export `backend/scripts/export_openapi.py` → `contracts/openapi.json`, and `frontend/scripts/gen-api-types.mjs` → `frontend/src/api/generated/openapi.ts` (openapi-typescript), both registered in `scripts/check_generated.py` so drift fails T0 and T1.

## Decisions
- **Not served yet** (agent): `app.main` keeps its 501 stand-in. Replacing `bind`/`serve` with uvicorn changes the sidecar's shutdown path (uvicorn's own SIGTERM handling against `engine.close()`, failure-modes M7, BL-0095's requirement) and the handshake; it is its own M1a slice, BL-0105, which also measures the M1a exit's `/health` timing. The integrity test that plans `app.api.create_app` (`test_workspace_open.py`, L1-04, M2) still fails only with `PlannedMissing` (it needs `app.boot.demo` too).
- **`create_app(container_factory, routers=None)`** (agent; ARCHITECTURE §2.3 named `create_app(container_factory)`): the factory is asked once per request for the caller's `ApiContainer` (`app_version`, `ids`, `workspaces`, `log`), so a hosted build can return the calling user's container (ADR-0041) and `{ws}` resolves only there (INV-28). `routers` defaults to the product's; tests pass their own, and the route-scope check covers whatever is passed.
- **The registry is built by a function** (agent): `specs()` returns the tuple on each call. A module-level tuple of `ErrorSpec(...)` would need `ErrorSpec` on `test_globals.py`'s `RECORD_CALLS`, a widening S0040 treated as a loosening for the owner; a function needs nothing. The same for the per-code error models (built per app) and FastAPI's telemetry config (`no_telemetry()`, after the globals scan refused a module-level dict in the mutant baseline).
- **Taxonomy without `ContractRefused`** (agent): its codes split 409/422 by code, which the class -> status table cannot say; it joins with the contract (BL-0106).
- **`ROUTE_NOT_FOUND`** (agent; new code): an unknown path or a known path with the wrong method answers `404 ROUTE_NOT_FOUND` in the envelope, so every answer has one shape (ADR-0038). 405 is folded into it: no client of this local API needs `Allow`. Any other Starlette HTTP exception is not ours, so `INTERNAL`.
- **Error `meta` has the same four fields as success** (agent; ADR-0038 lists `{request_id, workspace_id}` for errors): one `Meta` schema, every field required and nullable. `meta.workspace_id` is the workspace that served the request: set by the gate on `Open`, null on app routes and on every refusal, so the client's planned assertion (a response for another workspace is a bug, ADR-0018) never sees a refused workspace named.
- **`WORKSPACE_NOT_OPEN.open_workspace`** (agent reading of ADR-0063, which names the field only): the workspace a request may name now, or, while a switch runs, the one being opened; null when none is open. The UI text ADR-0063 gives ("Finzytrack switched to *Business* in another window") needs the target. BL-0102 implements the gate and may refine it; the field's type does not change.
- **`WORKSPACE_NOT_READY.phase` is `WARMING | RECOVERING`** (agent): ADR-0019's workspace phases short of serving; a workspace in a failed phase is never open (INV-29), so these are the only ones the open workspace can be in. `retryable: true` for it alone.
- **Request id and correlation id** (agent): one server-made id per request (injected `Ids`, EP-10), in `meta.request_id`, as the error's `correlation_id`, and bound to every log line of the request (`bound_context`). A client-sent id is not accepted (it would put client text into the log).
- **Fail closed** (agent): a `DomainError` the registry does not describe (unknown code, another class, details of another type, the bare base class) and a gate answering "open" for another key are bugs, answered `INTERNAL` and logged (`api.internal_error`, its text only as `debug_detail`). `error(code, details)` refuses mismatched details at the raise site with `TypeError`.
- **When the container factory fails** (agent): the edge answers `INTERNAL` in the envelope with request id `unassigned` and re-raises, so the server's own log records it (nothing else could: the log comes from the container). An exception after the answer started is logged and re-raised (no second answer).
- **FastAPI's telemetry is off** (agent; security posture, no new egress): FastAPI 0.143 brings `opentelemetry-api` as a runtime dependency and native telemetry that records request bodies, exception messages and stack traces; `FASTAPI_OTEL_AUTO_CONFIGURE=true` would add OTLP exporters. `create_app` turns all of it off explicitly, whatever the environment says (test). `opentelemetry-api` (Apache-2.0) is in `THIRD_PARTY_NOTICES`; it warns as "pending legal advice" like the other Apache-2.0 packages. No SDK or exporter is installed.
- **FastAPI includes routers lazily** (agent): 0.143's `app.routes` holds `_IncludedRouter` objects, not the routes; the check walks `fastapi.routing.iter_route_contexts`, the walk FastAPI's own OpenAPI generator uses. A change there in an upgrade fails the route-scope tests.
- **No Starlette `TestClient`** (agent): Starlette 1.8 types it against `httpx2`, which is not adopted; the tests drive the app through `httpx.ASGITransport` (httpx 0.28.1, the pinned version), a dev dependency.
- **Edge models and `x-ft-type`** (agent): details are frozen dataclasses in `platform.errors` (no pydantic below the edge, EP-06); the edge turns them into the per-code schemas. `x-ft-type` annotations and brands wait for the client that reads them (BL-0107).
- **`check_generated` folder sources** (agent; a tightening): a source ending in `/` stands for every path under it. The contract's source is all of `backend/src/app/` (not only `schemas.py`/`http.py`/`errors`/`api` as ARCHITECTURE §4.1 listed: the registry lives in `platform`, and any import can change a schema), plus the export script, `pyproject.toml` and `uv.lock`; the types' sources are the contract, the generator, `package.json` and the lockfile. The pre-commit hook checks and refuses; it does not write the files (ARCHITECTURE §4.1 updated).
- **Generated TypeScript is not formatted by prettier** (agent): the generator's bytes are what `check_generated` compares, so `src/api/generated` is in `.prettierignore`; ESLint (strict) and the boundaries map still check it. `knip` now also reads `frontend/scripts/` (a tightening; `gates.test.ts` pins the new config deliberately), so the generator's dependency is seen as used. ESLint treats `**/*.mjs` like `**/*.js` (no type-checked rules) and gives `scripts/**/*.mjs` Node globals.
- **CI order** (agent): the frontend environment is installed before "Generated artifacts" in `ci.yml`'s repo-checks job, since the types are generated with it.
- **Tests corrected while implementing** (agent; EP-29: each against its spec line, none bent to the code): the registry-status test raised `WORKSPACE_NOT_OPEN` without its details, which the spec makes a `TypeError` (`INTERNAL`), so that row became `ROUTE_NOT_FOUND`; the odd-key test's `..` was normalized away by the HTTP client before reaching the app, so it became `...`; the factory-failure test asserts "answered, then re-raised" after the decision above. Added while implementing: the telemetry test, the late-exception test, the gated route without a workspace parameter, the nested-gate cases and the export-script refusal (the last four for mutants that would otherwise have survived).
- **Deviation from ENGINEERING.md:** none. `except Exception` appears only in the API's edge middleware (§6.3, EP-13).

## Verifier
- Round 1, head 28cd0bc8: PASS WITH FINDINGS, no High; 2 Medium, 6 Low (risk Medium, not raised). Attacks: 14 (trailing slash, mounts and websockets, dependency order, body precedence, an `Ids` failure, HEAD, an encoded slash, an extra prefix, non-envelope response models, mutants, request-context concurrency, telemetry override, spec cross-check, export determinism). Repros in the private archive (`m1a/s0046-verifier/`).
- F1 Medium (INV-28): the route-scope check asked only whether `open_workspace` was among a route's dependencies, so a router-level dependency listed before it ran on a refused request. Fixed: every workspace route is a `GatedRoute` (`workspace_router()` sets it as the route class); the gate runs as soon as the route matched, before the body and every dependency, and `open_workspace` only hands the admitted key on. The check refuses a workspace path that is not a `GatedRoute`. Tests: `test_a_dependency_listed_before_the_gate_cannot_be_built` (the verifier's A5), `test_on_a_workspace_router_no_dependency_runs_for_a_refused_request`, `test_a_workspace_route_that_is_gated_only_through_a_dependency_is_refused` (it replaces `…_gated_through_another_dependency_passes`: a gate reached through a dependency no longer counts, by F1), `test_a_gated_route_outside_the_workspace_prefix_is_refused`. Mutants F1a (any gated dependant accepted) and F1b (the route skips the gate) killed.
- F2 Medium (§6.6, EP-29): the mutants removing the log binding and mapping every HTTP exception to `ROUTE_NOT_FOUND` survived. Fixed with `test_the_internal_error_log_line_carries_the_correlation_id_the_answer_shows` (a real `EventLog`) and `test_an_http_exception_that_is_not_a_routing_refusal_is_internal`, from the verifier's proposed tests; both mutants killed.
- F3 Low: `contract_problems` checked only `default` and 2xx. Fixed: every declared non-2xx answer must be the error envelope (two plants). Mutant killed.
- F4 Low: a malformed JSON body to a workspace that is not open answered `422` before the gate. - F5 Low: `/health/` answered a 307 outside the envelope. Fixed: `redirect_slashes=False`; `test_a_trailing_slash_is_route_not_found_not_a_redirect`. Mutant killed.

## Retro
- What the verifier found: an ordering gap in a check that tested presence (F1), two log/HTTP paths no test pinned (F2), and edges outside the envelope (trailing-slash redirect, an `Ids` failure). The common class is "an answer or an effect produced outside the path the tests drive": a cheaper gate would have been a mutant per branch of the edge middleware and an attack list that walks Starlette's own answers (redirects, 405, mounts) before hand-off.
- What a cheaper gate could have found: F2 and F7 are exactly mutants I did not seed; seeding one per log call and per string transform would have caught them. F1 needed thinking about FastAPI's dependency order, which the brief did not name.
- Where time went: FastAPI 0.143's surprises (lazy router includes, built-in telemetry, Starlette's `TestClient` on `httpx2`), then the verifier round.
- Orientation gaps: ARCHITECTURE did not say whether the gate precedes body parsing; ADR-0063 names `open_workspace` without defining it while a switch runs (decided in Decisions).
- Process cost: one implementer pass plus one fix pass; one verifier round.
