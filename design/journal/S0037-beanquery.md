## Brief

## Decisions
- **Owner decision, verbatim** (2026-10-26, in session): "Please include the bin query in the engine, sorting out the license issues, make that a backlog item. I don't want functionality to be compromised during development because of legal questions." ("bin query" = beanquery.) It answers `design/inbox/answered/20261026-beanquery-tatsu-licence.md` with option 1 and amends ADR-0054 decision 5 (amendment section appended, 2026-10-26). The licence question is BL-0085 (M12, the ADR-0042 legal review), together with `regex`'s CNRI-Python part noted by the S0035 verifier. BL-0081 is closed.
- **Versions** (agent): beanquery 0.2.0 is ARCHITECTURE.md §10's pin and still PyPI's latest (2025-03-24); `scripts/oracle` pins no beanquery, so §10 is the reference. The lock resolved TatSu-LTS 5.16.0 (2026-01-14, TatSu-LTS has no required dependencies); click 8.5.0 and python-dateutil 2.9.0.post0 were already locked for Beancount. Both new packages are far older than the 14-day rule (`exclude-newer = "14 days"`). The legacy app ran beanquery 0.2.0 with TatSu-LTS 5.13.2; the smoke test shows 0.2.0 parses and runs with 5.16.0.
- **SPDX ids** (agent): TatSu-LTS's wheel licence is the 3-clause BSD text plus clause 4, "Redistributions of any form whatsoever must retain the following acknowledgment: ...", which is SPDX `BSD-3-Clause-Attribution` (the SPDX template's clause 4 is word for word the same, with another name). It is not on the engine's allowed list and passes only as a reviewed package. beanquery's wheel carries the GPL version 2 text with no "or later" and its modules say `__license__ = "GNU GPLv2"`: `GPL-2.0-only`. Both reported licences are trove-classifier names, so both get `[mapping]` entries for their exact versions (BL-0050).
- **The acknowledgment rule** (agent; a tightening of the licence check, which agents may apply, ADR-0042 "reviewed like any rule change"): TatSu's clause was nearly missed in S0035 because pip-licenses reports only "BSD License". The check now asks pip-licenses for each Python package's licence and notice texts (`--with-license-file --with-notice-file --no-license-path`) and finds every "following acknowledg(e)ment" clause. A bundled package with such a clause needs `[acknowledgment.<package>]` (version, text, source) whose text equals the sentence the licence quotes (whitespace normalized), so a shortened or paraphrased text is refused; the notices carry it as `  Acknowledgment: ...` under the package's line. An entry for another version, for a package not bundled, or for one whose text was not read is refused. Only the Python groups are read: JavaScript and Rust texts are BL-0086 (M11). Today the clause occurs only in TatSu-LTS: the backend venv (32 packages) and the engine venv (27 before this slice) have no other licence or notice text with "acknowledg" (scan of pip-licenses output, 2026-10-26).
- **Notices scope** (agent): `THIRD_PARTY_NOTICES` still lists names and licences only; shipping the full licence texts in the bundles (BSD clause 2 for every BSD package, not only TatSu) is CAP-DESK-LICENSE-NOTICES at M11. The acknowledgment line is what the owner asked for now.
- **The reviewed-package warning** now reads "reviewed engine dependency, ADR-0054; pending legal advice" (it said "dependency of Beancount", which TatSu-LTS is not: beanquery needs it).
- **No change to `scripts/check_engine_boundary.py`** (agent): rules 1 and 2 already treat `beanquery` like `beancount` (`BEANCOUNT = {"beancount", "beanquery"}`), with must-not-pass cases in `scripts/tests/test_engine_boundary.py` (`from beanquery import query`, `import_module('beanquery')`) and the main side's `find_spec("beanquery") is None` and lockfile tests in `backend/tests/architecture/test_contracts.py`. TatSu is not added to the boundary: it is an implementation detail of beanquery, licence-judged by the check above, and absent from the main sidecar's lock.
- **No gateway code** (agent): `ledger_engine/ledger/beancount_port.py` does not exist yet and no BQL operation is in scope. The smoke test lives in `engine/tests/` (the engine's tests may import Beancount and beanquery). It runs the BQL probe in a child `python -I` and reads JSON back, because beanquery ships no type information and parts of Beancount's API are partially unknown to pyright: a file-level `# pyright: basic` was tried first and dropped, since EP-22 keeps pyright strict and loosening it needs the owner. Local stubs under `engine/typings/` and the typed facade come with the first BQL slice (CAP-ENGINE-BQL).
- **Tests first** (base ea9133da, run in a scratch export of the base with the new test files and the base lock synced): `test_check_licences.py` fails at import on the base (`check_licences` has no `Acknowledgment`), so every test in it fails; `engine/tests/test_beanquery_env.py` (2 tests) and `test_the_engine_environment_has_beanquery` fail (no beanquery). The base export's `test_the_import_boundaries_hold_on_the_tree` also failed there only because the export is not a git checkout (unchanged test, passes in the tree).
