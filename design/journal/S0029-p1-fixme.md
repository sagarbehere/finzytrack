## Decisions
- **The exit rule reuses the backlog (agent).** Each `fixme` names a backlog row; the row stays open while the test is `fixme`, and the S0023 exit run (`FT_MILESTONE_EXIT=Mx`) already fails on an open row due by Mx. The only new machinery is one scan in `check_invariants.py` (run by pre-push and T1 already) that refuses a `fixme` whose ID is missing, unknown or closed, or whose milestone differs from the row's, and, in an exit run, a `fixme` due by Mx (belt and braces: it holds even if a row were closed by mistake in the same commit). No new hook line, no new script.
- **Open or in-progress counts as open (agent).** The scan accepts a row in `open` or `in-progress`: both fail an exit run, and the slice that builds a capability sets its row to `in-progress` while the test is still `fixme`. `done`, `removed`, `post-v0.4` and `parked` are refused.
- **Milestones from the backlog (agent).** Every marker's milestone equals the backlog row's (S0023 split M1). Appendix B and the backlog disagree once: L9.M-1 is M10 ("full page") in Appendix B and M2 in the backlog; the backlog's later triage wins, so the test is due by M2 and runs on a fixture tab set (the real Settings page arrives in M10, where A10 re-checks it). I4 is M1a (Appendix B: M1).
- **The six flows get backlog rows (agent).** A1, A2, A4, A7, A10 and A13 are flow labels, not backlog IDs, so they get rows BL-0064…BL-0070 (A4 is split as Appendix B splits it: the bulk part by M5, its autocategorize step by M6). Milestones from Appendix B: A1, A2, A4 M5; A4 autocategorize, A7 M6; A13 M7; A10 M10.
- **Frontend findings get vitest tests, not pytest (agent; deviation from the brief's "backend pytest").** I7, I8, L9-01, L9.M-1, L9.M-3, L8-01, L8-02, L8.M-1 and L3-01 are frontend behaviour (run token, generator readiness, Cancel focus, the unsaved guard, the edit buffer, undo, the sale form's units). A pytest cannot state them; their unit-level home is vitest against the composables ARCHITECTURE.md §3.1 and ADR-0035 name (`useEditBuffer`, `useUnsavedGuard`, `useConfirm` + `ConfirmHost`, the per-widget recipe query). The Playwright specs stay limited to the six flows, as review:27 asks.
- **How a test reaches a module that does not exist yet (agent).** Bodies obtain the planned symbol through one helper (`planned("app.importing.core", "match")` in Python, `planned<T>('…')` in TypeScript) instead of a static import, so the files type-check and lint today. When the capability lands, the helper call becomes a normal import; the arrange/act/assert stays. The TypeScript bodies declare the planned interface as a local type, which is the assumption the landing slice either meets or corrects.
- **fixme semantics (agent).** pytest: the marker becomes `xfail(strict=True)`, so the body runs and must fail today; a body that passes (a vacuous test, or the capability landed) turns red and forces the marker's removal. vitest: `it.fails`, same semantics. Playwright: `test.fixme` (the body does not run; the acceptance harness that would run it is not built yet).
- **Where the interface is not decided, the test says so (agent).** Names not fixed by an ADR or ARCHITECTURE.md are marked "assumed" in the test's docstring: L1-04's seeding entry point, L6-12's NL check, L3-01's sale form emit, L10-06's pristine check, L11.M-2's orphan scan result, I4's location (the build half of `mirror` moves to the engine environment under ADR-0054 / BL-0041, so that test moves to `engine/` tests then, a move plus import fixes).
- **A10 adapted to workspaces (agent).** L8 §1.8's A10 says a dirty section survives "a ledger switch". v0.4 has no ledger path in settings (INV-27); switching is a workspace switch behind the leave guard (review:23 §3.3 step 1). The flow states that: a dirty settings section asks before a workspace switch, and Cancel keeps it.
