# S0163: The G1 refusal-rate tool

## Brief
- Goal: ADR-0046's G1 criterion "under 5% unjustified refusals on copies of the owner's books" gets a tool. For N generated intents per mutator (update_transaction, rename_account, import_append) on a ledger copy, each case applies its intended change through the new write core as the product would: the engine's preview (the contract's steps 1-3) and the confirm's save, in a fresh test copy per case, with the engine's test producer (`engine/tests/ledger/producer.py`, "test.edits", registered as `backend/scripts/measure_write.py` registers it; the shipped engine has no producer). Each case's outcome is **saved**, **save_anyway** (the preview listed new errors; the tool acknowledges them as a user's Save anyway would, and the save landed; not a refusal), **refused** (with its code, contract step and engine reason) or **not_expressible** (the test producer's primitives cannot express the intended change: a rename that touches a metadata or `custom` value; not run, not in the rate). Each refusal is classified by a fixed table keyed by (code, step, reason): **justified** only for a decided refusal whose condition an independent check finds in the copy; everything else, unknown codes and internal errors included, is **unjustified**. Report: counts per mutator and outcome, refusals per key with their verdicts and case IDs, the model's label per case (`valid` or `not_comparable`, from `scripts/oracle/model.py` via `harness.expected_change`), and the unjustified rate = unjustified / cases run.
- Implements: ADR-0046 (G1 criterion 3); reuses ADR-0014's oracle (case generation in `scripts/oracle/harness.py`, the intended-change model in `model.py`), the S0119 wiring (`measure_write.py`), the copy rules of `scripts/oracle/copies.py` (`refuse_local_tier_source`, `refuse_dir`) and the harness's containment check; PROCESS.md §8 (real-ledger copies in T-local, counts and case IDs only); INV-23, INV-24.
- Capabilities: none (G1 evidence tooling, not shipped).
- Invariants touched: INV-23 (the output carries counts, fixed codes and case IDs only, for every source), INV-24 (the source is only read; every case writes in its own copy, confined by the engine to that copy's folder; real-ledger copies and their mirrors stay inside the T-local folder).
- Kind: a one-off tool, not shipped. The owner or the coordinator runs it once or twice at G1 on `cp -RL` copies inside `FT_LOCAL_TIER_DIR`, and on repo corpora. Review row: one-off tool, one verifier round (IMP-0079): High only if it can change the originals or copies, or put ledger content where it persists or leaves the machine.
- The bytes it protects: none in the product. The tool guards the owner's copies (read only; it hashes the source before and after the run and stops if they differ) and their privacy (the output).
- Which real setup needs this, and can a policy forbid the rest? The owner's copy as recorded at M1b's exit (`design/journal/M1b-exit.md`: roots set `option "documents"` to a folder beside them, `../…`): the tool takes the folder holding both (`--ledger-dir`) and the root's path inside it. A source with any link in it is refused (make the copy with `cp -RL`); an include that resolves outside the folder is refused (the harness's `check_contained`). Family history: the D2 runner's guard (S0158) took three failed rounds; this tool adds no new guard of its own beyond the no-link walk and reuses the existing rules.
- Risk class / lane: Medium / light (no product code changed; it reads real-ledger copies).
- Acceptance tests (each fails on the base, d3022ac4: the modules do not exist):
  - `scripts/oracle/tests/test_g1_refusals.py`: the classification table (each justified key with its condition present is justified, with it absent unjustified; an unknown code, `INTERNAL`, a known code with another step or reason are unjustified); the case translation (an update by location, a rename into token edits on every line naming the account, a rename touching a metadata value or a `custom` value is not_expressible, an import as an insert into the root); the guards before anything runs, each exit 2 with no runner started: `FT_LOCAL_TIER_DIR` unset for a non-corpus folder, a folder outside the T-local folder, the T-local folder itself as the source, a folder holding a link, an include leaving the folder, a root file outside the folder; the runner's answer decoded field by field (a reason or code with ledger text is never printed); an end-to-end run on a tiny ledger in a temp T-local folder: saved and save_anyway outcomes counted, a pushtag region at the end of the root makes the import refused and justified, the source unchanged, no work folder left, and no account, payee, narration, amount or path in stdout or stderr.
  - `backend/tests/test_g1_runner.py` (the backend half, `backend/scripts/g1_runner.py`): a tiny ledger's update, rename and import cases through preview and confirm are saved; a balance assertion the import breaks gives save_anyway; a malformed request is refused at the preview and recorded with its step and reason; what it prints is only fixed fields.
- Expected doc impact: roadmap §1 (the G1 refusal tool exists), PROCESS.md §6 T-local row (names the tool), `backend/CLAUDE.md` (the runner beside the measurement scripts), the tool's docstring (the exact command). User docs: none.
- Open questions: none on the rubric. The tool measures the write core with the test producer, because no real mutator exists yet (`preview.PRODUCERS` is empty until M3/M4); that is a property of what G1 can measure, stated in the report and the docstring, not a decision for this slice.

## Decisions
- **Two halves in two environments** (agent): the cases, the guards, the table and the report live in `scripts/oracle/g1_refusals.py` (the oracle's environment: the case generators, the model and the copy rules are there, and they need Beancount); the writes run in `backend/scripts/g1_runner.py` (the sidecar's environment, which never imports Beancount), started by the first with the cases on its standard input. The runner prints one JSON line per case with five fixed fields, and the parent decodes them field by field (`decode`), so the runner's answers cannot carry ledger text into the output.
- **Reuse, not copies** (agent): `measure_write.py`'s setup became two functions, `wire` (the app folder, the engine client on the producer-registering command, the scheduler, the bytecode wait) and `open_copy` (the open as an exclusive job, the test-copy mark, the published generation), which both scripts call; its measurements are unchanged (`open_ms` still times only the open job; `tests/test_measure_scripts.py` passes). The harness's three update edits became `harness.edited(t, i)`, used by `gen_updates` (unchanged behaviour; `test_harness.py` passes) and by this tool. Renames and imports come straight from `harness.gen_renames` and `harness.gen_imports`; the model's label from `harness.expected_change`.
- **Updates by place, not by legacy `id`** (agent): the harness picks transactions with a unique `id` because the legacy app addresses them so; the write core addresses an entry by file and line, and the demo ledger and most corpora have no `id` (the demo: 0 of 5,563). `gen_updates_at` takes every transaction, in the same deterministic order and with the same edits.
- **A rename is token edits; what they cannot express is not run** (agent): one `token` edit per line naming the account or a subaccount (an open, close, balance, note, document or pad line, a posting). When `model.renamed` (the intended change) also changes a metadata or `custom` value, the primitives cannot express it (no metadata primitive: BL-0313), so the case is `not_expressible`, not run and not in the rate. Sending a partial rename would measure a change nobody intends.
- **The model labels, it does not filter** (agent): a case the model cannot judge (`not_comparable`, e.g. an import into a ledger with Fava's `insert-entry` option) is still run; any refusal of it outside the table is unjustified. This can only raise the rate.
- **Save anyway** (agent): when the preview lists new errors, the runner acknowledges exactly those keys, as the user's "Save anyway" does (ADR-0067), and the case is `save_anyway` if the save lands; a refusal after that is a refusal.
- **The engine's reason** (agent): the sidecar folds the engine's preview answer into a code and a step (`preview.refusal_of`); the runner wraps that function in its own process to read the reason on the way. Without it, an insert into a push region and any other producer refusal both read `WRITE_REFUSED_CHECK_FAILED {plan}`.
- **The table** (agent; the verifier reviews it): three decided refusals, each with an independent condition. (1) `ENCRYPTED_FILE_NOT_EDITABLE`, any step: ADR-0059; the ledger set holds a file with an encrypted file's name. (2) `WRITE_REFUSED_CHECK_FAILED/plan/encrypted_file`: ADR-0010 guardrail 4 with ADR-0059, by name since S0049 and S0115; the case itself edits such a file. (3) `WRITE_REFUSED_CHECK_FAILED/plan/insert_in_push_region` and `WRITE_REFUSED_UNINTENDED_CHANGE/apply/insert_in_push_region`: ADR-0009 ("never inside a pushtag/pushmeta region"); a ledger file has a column-0 `pushtag` or `pushmeta` line. Left out on purpose: `LEDGER_FILE_TOO_LARGE` (about 240 MiB; a spec limit, engine-jobs §11, S0120, not an ADR; unreachable on the owner's books; if it ever fires it counts as unjustified, which only overstates the rate). Everything else is unjustified, including `MALFORMED` (an answer that did not decode), `NO_ANSWER` and `TOOL_ERROR`.
- **Rule (2) came from the first corpus run** (agent): the write corpus's `asc-plain` (a plain-text `notes.beancount.asc` include that Beancount loads) gave 3 refusals `WRITE_REFUSED_CHECK_FAILED/plan/encrypted_file`, first all unjustified. Two edit the `.asc` file itself (a decided refusal by name: rule 2 now justifies them). The third is an import into `main.beancount`: `source_edit._insert_options` parses every file to find `insert-entry` options and `Snapshot.parsed` refuses the `.asc` name, so the insert fails although nothing is written into that file. No decision covers that: it stays unjustified, and the product finding is **BL-0319** (M4, the owner's choice: read a plain `.asc` file's options, or refuse such ledgers at open by policy).
- **Guards: the existing rules, plus a no-link walk** (agent; the D2 runner's history, S0158): `copies.refuse_local_tier_source` (a repo corpus, or a folder inside `FT_LOCAL_TIER_DIR`), the source not the tier folder itself (the work folder goes into the tier), the root file a relative path inside the source, no link of any kind below the source (the file-system half of S0158's plain-copy rule, the half that held; `cp -RL` copies have none), and `harness.check_contained` (an include resolving outside refuses). Not reused: `d2_local.refuse_tree`'s text scan of include and documents lines. It lives in the engine's environment, it guards reads outside the tier (not this tool's High row, IMP-0079), and S0158's round 3 showed it does not close its class. The source is hashed before and after the run (`digest`), and a change stops it (exit 3).
- **Real-ledger bytes stay in the T-local folder** (agent): for a copy, the work folder (the cases' copies, their mirrors, the app folder with its journals and backups, the engine cache) is a fresh `.g1-work-*` folder inside `FT_LOCAL_TIER_DIR`, removed at the end; only a repo corpus works in the temp folder. A killed run leaves that folder in the tier (a stated limit).
- **One output for every source** (agent): counts, codes, steps, reasons and case IDs only, for corpora and copies alike; only the runner's error output, on a failure, is shown for a repo corpus (`may_show_entries`). Simpler than two report shapes, and corpus debugging needs no more (the case's edits can be regenerated from the seed).
- **Exit codes** (agent): 0 when the rate is under 5% (ADR-0046), 1 otherwise, 2 for a refused input (before anything runs), 3 when the run stopped (the runner failed, or the source changed).
- **Deviation from ENGINEERING.md** (agent): `g1_runner.py` imports `measure_write._Ids` (a private name, with a pyright ignore naming why) instead of a third copy of a five-line id source. A one-off tool's test-only wiring.

## Hand-off (PROCESS.md §3 step 4; ADR-0057)
- Checks that accept, tag or refuse, each with its must-not-pass test (`scripts/oracle/tests/test_g1_refusals.py` unless named):
  - `classify` and `JUSTIFIED` → `TableTest.test_each_justified_key_needs_its_condition` (each key, condition present and absent), `test_everything_else_is_unjustified` (9 keys), `test_an_edit_of_a_plain_asc_file_is_justified_an_insert_beside_it_is_not`; `facts_of` → `test_the_facts_are_read_from_the_copy` (a stray `.gpg` outside the ledger set does not count).
  - `refuse_source` and the read guard in `main` → `GuardsTest` (7 tests, each exit 2 with the runner never started: the tier unset, a folder outside it, the tier itself, a link, an include leaving the folder, a root file outside or absolute, a ledger that does not parse and an exception while reading, neither naming its text).
  - `decode` → `OutputTest.test_a_runner_answer_carrying_text_is_never_printed` (a bad code, step, reason, outcome and ID, each an unjustified refusal, none printed); the runner's error output → `test_a_failed_runner_shows_nothing_of_a_copy`; the source hash → `test_a_source_changed_during_the_run_stops_it`; the work folder in the tier → `test_a_copy_is_worked_on_inside_the_tier_and_the_work_removed`; the rate and exit → `test_the_rate_and_the_exit`.
  - `rename_edits` → `CasesTest.test_a_rename_the_primitives_cannot_express_is_not_run` (a metadata value, a `custom` value), `test_a_rename_is_one_token_edit_per_line_naming_the_account`.
  - End to end → `EndToEndTest` (the source unchanged, no work folder left, no ledger text or path in the output, a push-region refusal justified, Save anyway not a refusal); the runner → `backend/tests/test_g1_runner.py` (saved, save anyway, a refused request with its step and reason, the copy removed, the source unchanged).
- Self-mutation (`scripts/mutants.py`, plan in the session scratchpad; the parent's checks guard real-data privacy): 16 tried, 13 killed at first. Survivors: `decode-any-step` and `decode-any-reason` (the test's bad answers carried a bad step and a bad reason together, so either check alone refused them; split into separate answers) and `parse-error-text-shown` (no realistic parse failure quotes the ledger; a test now makes `generate` raise with ledger text). All 16 killed after. Not mutated: the runner's own reason check (`g1_runner.REASON`), a second layer behind `decode`, which re-checks every field (equivalent at the output).
- Population: none claimed. The table is a list of decided refusals, not an inventory of every refusal the core can give; a refusal it does not name is unjustified by construction.
