# S0084: The model's create and copy replayed through the engine

## Brief
- Goal: BL-0201. Replay the create and copy steps of `formal/tla/engine-jobs/EngineJobs.tla` (`CR_*`, `CP_*`, with the outside program's `EditorDrop` and `EditorOverwrite` and the engine's death) through `ledger_engine.ledger.create.run` and `ledger_engine.ledger.copy.run` over the in-memory fake, the way `engine/tests/ledger/test_save_conformance.py` replays the save (its `WALKED` / `NOT_WALKED` structure). Mark the create's and the copy's steps `@tla_action`; `backend/tests/architecture/test_tla_mapping.py` `PLANNED` keeps only `CR_Register` (BL-0102) and recover-all's `RC_Init`, `RC_Next` (BL-0164). The trace generator (`formal/tla/engine-jobs/gen_traces.py`) walks small create and copy worlds and drops `StartCreate`, `StartCopy`, `EditorDrop`, `EditorOverwrite` from `OUT`; the corpus is regenerated. Tests and markers only: nothing the create or the copy writes, removes or overwrites changes.
- Implements: spec `design/specs/engine-jobs.md` §8.2 and §13 (the model's create and copy), ADR-0050 (the code map), ADR-0064, EP-19 (the model checks durability only), PROCESS.md "Designs checked by a formal model".
- Capabilities: none new (CAP-WS-CREATE, CAP-WS-TEST-COPY stay planned; their engine halves gain a check).
- Invariants touched: INV-01, INV-22 (a write passes the contract and fails closed), INV-32 (`NoCopyOverOpenJournal`: no copy over an `.open` journal).
- Risk class / lane: Medium (tests and markers on a write path, no new write path; no data-safety red team, PROCESS.md §4) / full lane (it checks ledger-write code).
- The bytes it protects: none new; it checks existing ones (a new workspace's files and `.finzytrack/`, another program's entries in the target, the journals a copy reads).
- Acceptance tests: `engine/tests/ledger/test_create_conformance.py` (new): every create and copy of the corpus replayed; every step of its `WALKED` walked at least once and every branch of its `BRANCHES`; `WALKED | NOT_WALKED` equal the model's `CR_*` and `CP_*`; self-tests that a seeded divergence in the create (a skipped folder sync, a skipped manifest sync, a skipped read-back, a cleanup that removes another program's file) and in the copy (a skipped journal check, a write outside the target) is caught. `scripts/tests/test_tla_traces.py`: the generator's new state (`tgt`, `J`), the copy's journals kept, the job actions left out of worlds that do not name the job, and that such a world cannot start the job. `backend/tests/architecture/test_tla_mapping.py` with the shrunk `PLANNED`. The save replay stays green on the regenerated corpus.
- Expected doc impact: `formal/tla/engine-jobs/MAPPING.md` (§2.1 rows for `CR_*`, `CP_*`, `StartCreate`, `StartCopy`; §3 the differences; §7 the replay); the spec's Orientation "Not built yet" loses BL-0201; `engine/CLAUDE.md` names the new replay; BL-0201 closed "Done in S0084"; `design/capabilities.md` unchanged (no capability changes state).
- Open questions: none for the owner. The orchestrator's "known point" (the model's `CR_ManifestRename`/`CR_ManifestSync` against an exclusive create of `.finzytrack/`) is settled in Decisions below: the code does write `.finzytrack/` by a temp name and an exclusive rename.

## Decisions
- **The manifest step: code and model agree** (agent). The brief's premise that `Run._manifest` writes `.finzytrack/` "by exclusive create" is out of date: since S0080 it writes `.finzytrack.ft-<job>/` (folders made, files created and synced, each folder synced, files read back), renames it to `.finzytrack` with `rename_excl` (a `.finzytrack` that stands there stops the job, `manifest_taken`, and is left as it is), then syncs the target (`create.py` lines 561-597). That is `CR_ManifestRename` (the temp's work and the exclusive rename; the temp's name is not one of the model's `Names`, so its effects are classified to that step and the view does not show it) and `CR_ManifestSync` (the target's sync). No durability-relevant disagreement.
- **The cleanup of a stop is outside the model** (agent). The model's `CrStop` leaves the target as it is; the code then removes what this run made and only that (S0080 r2, the owner's middle path, 2026-11-07). After a stop the replay accepts a name the model has as ours being absent in the code, and nothing else: another program's entry must be exactly as the model has it (`DroppedFileNeverReplaced`, `NonEmptyTargetUntouched`). Removing a stopped create's own files loses no committed byte (the folder is not a workspace without `.finzytrack/`), so this is not a durability disagreement; the cleanup's own rules stay checked by `test_create.py`'s sweeps. MAPPING.md §3 states it.
- **Durability is compared, not assumed** (agent). At each step the code reaches, the replay compares the target as it is now and as a power loss could leave it: for each of the model's names, every value the fake's `power_loss_states()` gives there must be one the model's `tgt.pl` allows (the code may be more durable than the model, never less). So `CR_SyncA` and `CR_ManifestSync` change the view and can never be passed without the code's sync, with no separate list of sync steps.
- **The create's load check (step 5) and the commit point (step 6) are not model steps** (agent): they write nothing (EP-19). The read-back is reached at the code's first read of the file it wrote (`MemFS.on_read`, a new test hook of the fake), so `CR_ReadBack` is walked.
- **The copy** (agent). The model's copy is thin: `CP_Check` (no unresolved journal names a source), `CP_Load` and `CP_Manifest` (no effect in the model: the copy writes with the create's writer, which the create replay checks). The replay sets the fake's journals to the model's at the copy's start and checks: the code refuses (`recovery_blocked`) exactly when the model's `CP_Check` ends the job; it writes only in its target (an effect anywhere else is a divergence); after an engine death no `.finzytrack` of ours stands in the target; it answers created exactly when the model's `CP_Manifest` ran; the journal folders are byte-identical before and after. The sources stay off the fake (as in `test_copy.py`), so the copy cannot write them by construction. The code loads the source before it reads the journals, the model checks the journals first: both orders only read, and a refusal comes before any write in both (MAPPING.md §3).
- **The job actions are walked only in worlds that name the job** (agent; `gen_traces.py` `JOB_ACTIONS`, each world's `jobs`). A first regeneration that simply dropped them from `OUT` changed 122 of the 144 save traces (TLC's seeded walk depends on the disjuncts of `Next`, enabled or not), for no gain: no save world can start a create or a copy. Leaving them out there keeps every save trace byte for byte as it was (checked: 144 of 144 identical by action sequence), and `test_tla_traces.py` checks that each world that leaves them out cannot take them (`CreateTarget = "none"`, `MaxDrop = 0`, `DoCopy = FALSE`).
- **New worlds** (agent): `S_create_absent`, `S_create_empty`, `S_create_nonempty` (the model's create worlds, an engine death and drops only while the create runs), `S_create_land`, `S_create_land_empty`, `S_create_overwrite_late`, `S_create_late_crash` (so the corpus reaches created, created in an empty folder, an overwrite after the read-back, and a death after the manifest's rename), `S_copy`, `S_copy_crash`, `S_copy_insession` (a save's engine death with its journal `.open`), `S_copy_torn` (a boot journal whose file list cannot be read; added after the mutant `copy-unreadable-journal-ignored` would otherwise have had no trace to fail on). The save replay's `worlds()` now names its worlds by their constants (no create, no copy) instead of by `BootJ` alone.
- **`PowerLoss` and `AppCrash` stay in `OUT`** (agent): each ends the session, whose next start is recover-all's (BL-0164). A power loss is covered by the durable compare above at every step; an app crash leaves the target as an engine death does, which the replay walks.

- **No defect found** in the create or the copy: every create and copy of the corpus follows the model (69 jobs: 46 creates, 23 copies). Nothing was changed in what they write, remove or overwrite; the only source change is the no-op markers.
- Tests first: the new and changed tests were run against 0b9a6dc8's source (an archive in the session scratchpad with the slice's test files copied in): `test_create_conformance.py` fails at collection (the base corpus has no create world), `test_tla_mapping.py::test_the_code_map_holds_both_ways` fails (the create's and copy's actions are neither marked nor `PLANNED`), `test_memfs.py::test_on_read_runs_before_a_hashed_read_and_is_not_an_effect` fails (no hook). `test_tla_traces.py`'s new assertions fail on the base generator (no `tgt`, no `JOB_ACTIONS`). The save replay's `worlds()` change is behaviour-preserving on the base corpus.

## Hand-off (PROCESS.md §3 step 4; ADR-0057)
(The verifier reads only the Brief, so this section does not steer its attacks; it is the implementer's own record.)
- Checks that accept, tag or refuse, each with its must-not-pass test:
  - the create replay's step comparison (current values, folder, durable values ⊆ `tgt.pl`) → `test_a_skipped_folder_sync_is_caught` ("past the model's cr_ws (CR_SyncA)"), `test_a_skipped_manifest_sync_is_caught` ("the code ended before the model's cr_ms (CR_ManifestSync)");
  - the "does not reach" / passable rule → `test_a_skipped_read_back_is_caught`;
  - the relaxed comparison after a stop (only ours may be gone) → `test_a_cleanup_that_removes_another_programs_file_is_caught`;
  - the answer against the model's last step (`STOP_REASON`, created at `CR_Register`) → mutants `non-empty-target-accepted`, `manifest-plain-rename` (killed, below); `test_the_stop_reasons_are_the_models_stops` keeps `STOP_REASON` equal to the model's stopping steps;
  - the copy's refusal equivalence → `test_a_copy_that_skips_the_journal_check_is_caught`; its writes only in the target → `test_a_copy_that_writes_outside_its_target_is_caught`;
  - the step lists → `test_the_create_and_copy_steps_are_the_models` (`WALKED | NOT_WALKED` = the model's `CR_*`, `CP_*`), `test_the_replay_walks_the_create_and_the_copy` (every step and branch walked);
  - `test_tla_mapping.py` `PLANNED` shrunk: its own must-not-pass cases are unchanged (`stale-planned`, `unmarked-engine`), and on the base it fails as above;
  - `test_tla_traces.py::test_a_world_without_a_job_cannot_take_its_actions` → must not pass with a save world's `DoCopy = TRUE` (run by hand: fails with `'TRUE' != 'FALSE' : S_save`).
- Self-mutation (`scripts/mutants.py`, plan in the session scratchpad; command: the replay's `follows` tests only, the mutated source first on `PYTHONPATH`): 10 mutants, 8 killed: `manifest-unsynced`, `target-folder-unsynced-after-writes`, `parent-unsynced-after-mkdir`, `read-back-ignored`, `non-empty-target-accepted`, `manifest-plain-rename`, `copy-journal-match-ignored`, `copy-unreadable-journal-ignored`. 2 survived: `cleanup-identity-ignored` and `cleanup-bytes-ignored`. Each is the cleanup's two-part ownership check with one part removed; the other part still keeps the replay's foreign entries (an editor's save by rename gets a new identity and other bytes). The cleanup is outside the model (Decisions), so these are not the replay's to catch; both are killed by `test_create.py` and `test_copy.py` (second plan, same mutants: 2 of 2 killed). No test added.
- Population: the model's create and copy steps, read from `EngineJobs.tla` (`^(CR|CP)_\w+ ==`): 10 in, 9 walked, 1 not walked (`CR_Register`, BL-0102); held by `test_the_create_and_copy_steps_are_the_models`. The corpus: 217 traces (144 save traces unchanged); 69 jobs replayed (46 creates, 23 copies), 0 cut.
