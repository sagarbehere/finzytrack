# S0091: The recover-all and mirror-publish models replayed through the code

## Brief
- Goal: BL-0164 and BL-0210. (1) Replay the engine-jobs model's recover-all (`RC_Init`, `RC_Next`, the restore `RS_*` on the boot journals `BootJ`, `BootTemps`, `BootTorn`, `BootLink`, with Keep, Retry (`StartRecover`), the app's crash and the next start, the path changer and the unreachable disk) through `ledger_engine.ledger.recover_all.list_journals`, `restore.recover_journal` and `recover_all.keep` over the in-memory fake, playing the sidecar's part (the order of the tries, a death marks the journal in hand failed); mark `RC_Init` and `RC_Next`; `backend/tests/architecture/test_tla_mapping.py` `PLANNED` keeps only `CR_Register` (BL-0102). The trace generator walks recover worlds and walks the recover-all actions only there (as S0084's `JOB_ACTIONS`), so every save, create and copy trace stays byte for byte as it was (checked). (2) Give the mirror-publish model a trace generator (`formal/tla/mirror-publish/gen_traces.py`, its staleness in the meta-tests) and replay its traces through `ledger_engine.ledger.rebuild.run` (the cleanup, the publish, the swap) and `restore.recover_journal` over the fake, so its markers are walked by a replay (S0060's rule; S0087's recorded deviation ends). Tests, markers, generators and docs only: nothing recovery or the publish writes, removes or overwrites changes.
- Implements: ADR-0050 (the code map), ADR-0063, ADR-0064, ADR-0015 (the publish), EP-19 (models check durability only); specs `design/specs/engine-jobs.md` §8.1, §13, `design/specs/mirror/publish.md` §4-§7, §9; PROCESS.md "Designs checked by a formal model".
- Capabilities: none changes state (CAP-DATA-ENGINE-JOBS stays planned; its recover-all half gains a check).
- Invariants touched: INV-32 (every journal recovered or blocking), INV-01, INV-22 (recovery writes only recorded paths, fails closed), INV-05 (the mirror's readers see whole generations).
- Risk class / lane: Medium (tests and markers on write paths, no new write path; no data-safety red team, PROCESS.md §4) / full lane (it checks ledger-write code).
- The bytes it protects: none new; it checks existing ones (the ledger files a boot journal names, the outside saves recovery keeps, the mirror generation readers read).
- Acceptance tests: `engine/tests/ledger/test_recover_conformance.py` (new): every recover-all run of the recover worlds replayed; `WALKED | NOT_WALKED` equal the model's `RC_*` and `RS_*`; every step of `WALKED` and every branch of `BRANCHES` walked; self-tests that a seeded divergence is caught (a skipped journal-folder sync in the listing, a skipped restore sync, a journal resolved before its files are back, an unreadable record tried, a death not marked failed, Keep without its syncs). `engine/tests/mirror/test_publish_conformance.py` (new): every publish job and read of the mirror corpus replayed through `rebuild.run`; the model's `P_*` steps walked; self-tests (a skipped file sync, a skipped re-check, an incomplete build published, a cleanup that removes the current generation). `scripts/tests/test_tla_traces.py`: the recover worlds' projection, the recover actions only in recover worlds, every save/create/copy trace unchanged; new `scripts/tests/test_tla_mirror_traces.py`: the mirror generator's reader, wrapper and staleness. `backend/tests/architecture/test_tla_mapping.py` with `PLANNED` = {`CR_Register`}.
- Expected doc impact: `formal/tla/engine-jobs/MAPPING.md` (§2.1 `RC_*` rows, §3 differences incl. S0089's drive identity and evidence rule, §7 the recover replay), `formal/tla/mirror-publish/MAPPING.md` (the replay; the deviation note goes), `formal/tla/mirror-publish/HOW_TO_RUN.md` (the generator), `design/specs/engine-jobs.md` Orientation, `design/specs/roadmap.md` §1, `design/ARCHITECTURE.md` §8.3, `engine/CLAUDE.md`, `engine/src/ledger_engine/tla.py`'s docstring, BL-0164 and BL-0210 closed "Done in S0091". No capability changes state.
- Open questions: none for the owner. A real divergence between code and model found by the replay is recorded with a repro and a proposed backlog row, never fixed here.

## Decisions
- **Recover-all's actions are walked only in the recover worlds** (agent; `gen_traces.py` `JOB_ACTIONS["recover"]`: `StartRecover`, `Keep`, `Relaunch`, `AppCrash`, `PathChange`, `Unreach`). As S0084 found, dropping actions from `OUT` changes TLC's seeded walk of every world; leaving them out of the worlds that do not name the job keeps every save, create and copy trace byte for byte (checked: 217 of 217 rows identical to 06d538f0's corpus, the same SHA-256 over them; `scripts/tests/test_tla_traces.py` pins that digest). Unlike the create's and the copy's, some of these actions could be taken in a save world (an app crash, Keep of a save's stopped journal): there they stay left out exactly as `OUT` left them before (`INERT_ELSEWHERE` names the jobs whose actions no other world can take). `OUT` keeps `PowerLoss` only: the fake cannot be steered to the model's pick of one outcome per name (where the code is more durable than the model the pick does not exist); the replay checks the durable layer instead (the model's sync steps are never passed without the code's sync, and after a resolve every power-loss state of the fake holds `.resolved` over pre bytes and the outside edit).
- **The recover worlds** (agent): `S_recover` (b2 and b3, an outside edit of R, an engine death, the unreachable disk, Keep, Retry), `S_recover_temps` (what a crashed save left beside b2's files, an I/O error, the app's crash and the next start), `S_recover_link` (R's folder a link from the start), `S_recover_relink` (the link put in after the app's crash), `S_recover_torn` (b3's record unreadable), `S_recover_displaced` (an outside save between the try's check and its restore swap); no save, create or copy (`MaxSaves = 0`), so each replay meets its own job only (`test_a_recover_world_runs_nothing_but_recover_all`). Branches left out, each because the code does that step otherwise (each trace still a behaviour of `Spec`): `io_at_restore_write` (an I/O error only where the code always writes, so it has a hook to be raised at), `unreach_outside_try` (below), `keep_not_over_link` (below), `app_crash_in_recover`, `edit_at_restore_swap`.
- **The replay plays the sidecar** (agent): the listing, then each `.open` journal in the listing's order (the model's `JOrder`: `local/k2` before `local/k3`), a torn record stopped without a try, a death marking the journal in hand failed and a death in the listing listing again, as `app.platform.engine_jobs.recovery` does (its own table tests are `backend/tests/platform/test_recover_all.py`). Markers: `RC_Init` on `recover_all.list_journals`, `RC_Next` on `restore.recover_journal` (the engine's part of the step: the record read, unreadable a stop, else the restore), so `PLANNED` keeps only `CR_Register`. `RS_Check` has no hook when it only reads: it counts as walked when the code's answer is the model's stop there.
- **Outside acts at a segment's first point are written before the code starts** (agent): an edit or the disk going away made before the try's first step must be what the try's first look sees, and the code reads before its first effect (the first run found this: the model's disk went unreachable at `rs_chk`, the code's first hook was after its check). A death or an I/O error there stays for the code's first hook; a death after the code's last effect loses its answer (the sidecar marks the journal failed), as the model's `EngineCrash` does.
- **A real difference, recorded, not changed** (BL-0224; the brief's rule): the code refuses Keep while a folder the journal names is not at its recorded path (`recover_all.keep`: `path_moved`, red team r1 R1-3), the model's `Keep(j)` has no such condition. The first full run stopped 8 traces there (all 6 of `S_recover_link` and 2 of `S_recover_relink`). No byte is lost either way (the code writes nothing and the journal stays blocking), so it is a fidelity gap of the model; the link worlds now leave that Keep out (`keep_not_over_link`) so their traces go on (Retry, the app's crash, the next start), and `test_keep_over_a_link_is_refused_where_the_models_keep_is_not` is the repro: it pins both sides and fails once the model gains the refusal. Changing the model is not this slice's (PROCESS.md "Designs checked by a formal model": the small tier and a fidelity look).
- **Model abstractions met by the replay** (agent; MAPPING.md §3): (a) K's disk going away during a try past its check: the model's restore goes on writing K (only `Stops` reads `env.unr`); the code's next operation fails or its path guard stops the try (the first run met it: `stopped path_moved` where the model resolved). The code writes less, never more; the corpus walks the unreachable disk at a check and between tries only (`unreach_outside_try`). (b) S0089's drive check comes first in the code (every folder, before any file is judged), file by file in the model; S0089's evidence rule (`missing_unconfirmed`) and the drive stops have no counterpart (the model assumes the swap and never swaps drives): `test_restore.py` and `test_volume_identity.py` keep them. The replay's records carry the drive marks a save records (journal format 6), so every try passes the drive check as on the right drive.
- **The mirror-publish corpus** (agent): `formal/tla/mirror-publish/gen_traces.py`, modelled on engine-jobs' (whose TLC value reader and deltas it imports; its hash is in the header, so a change there makes the mirror corpus stale). Its reader of `Next` binds an existential for every disjunct of its line (`\E g \in Gens : P_CleanDb(g) \/ P_CleanJl(g)`), which engine-jobs' reader did not need. Worlds `S_publish`, `S_ledger`, `S_crash`; `OUT` = `PowerLoss` and `Purge` (the model ends a job at a purge, the code would go on writing into the removed folder; `test_publish_crash.py` and `test_publish.py` keep both). Branches left out: `whole_cleanup` (the model's cleanup may stop anywhere; the code's removes all it does not keep once the grace period is over, which every replayed job is), `names_left` (the model's `P_Create` ends a job when its world's names are used up; the code's are not bounded), `edit_outside_the_load` (below).
- **The mirror replay runs the rebuild** (agent): `rebuild.run` with test ports (the fake, a store writing the fake store's effects plus the rows the load read, the observation and load of the model's two files, the model's generation as the tag), so `StartPublish`, `P_Obs`, `P_Read` (marked on `rebuild.run`) and the publish's markers are walked; `opening.run` carries the same three markers and is left to its own tests (its overlay load needs Beancount's parse of real files). The rebuild differs from the model where it refuses earlier and builds less, never more (MAPPING.md §3): it looks for an `.open` journal right after the cleanup and ends `paused` before its load (the model builds a generation and refuses at `P_JCheck`: that generation is the model's alone until its next cleanup, `Replay.ghosts`); it skips the build when the published generation is fresh (each replayed job runs on another day, so none is); it observes the whole set before and after its load (no outside edit inside the load in the corpus). Readers: the resolve is the gate's `read_published` (marked `R_Resolve`); the reads open the pinned name with the store's `meta`, as the sidecar's `open_mirror` does: `R_Read1`, `R_Read2` stay walked by the sidecar's own tests.
- **Brief items not done as written** (agent): the self-tests "a death not marked failed" (the sidecar's, a backend table test) and "Keep without its syncs" (vacuous here: every boot state is durable when Keep runs, so a Keep that syncs nothing changes no power-loss state; the model's `keep_no_sync` needs a save's unsynced swap, `S_keep`, a save world, and `test_recover_all.py` keeps Keep's syncs) are not in the replay; "an unreadable record tried" is the mutant `unreadable-record-listed-readable` (killed). An I/O error swallowed and an unreachable folder tried are self-tests instead; the latter was dropped after it passed: the model's stop has no cause, so `unreachable` and `foreign` are one outcome to it (the same as the survivor below).
- **No defect found in the code**: every recover-all run and every publish job of the corpora follows the model, but where §3 says otherwise. Nothing that recovery or the publish writes, removes or overwrites changed: the only source change is two no-op markers and a docstring (`git diff 06d538f0 -- engine/src`).
- Tests first: the new and changed tests were run against 06d538f0's source (an archive in the session scratchpad with the slice's test files copied in): `test_recover_conformance.py` fails at collection (no recover world: an empty parameter set), `test_publish_conformance.py` at collection (no mirror corpus), `test_tla_mapping.py::test_the_code_map_holds_both_ways` (`RC_Init`, `RC_Next` neither marked nor `PLANNED`), `scripts/tests/test_tla_traces.py` (3 errors, 1 failure: no `env`, no `INERT_ELSEWHERE`, no recover worlds), `scripts/tests/test_tla_mirror_traces.py` (no generator).
