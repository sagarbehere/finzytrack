# S0060: The save's durable order over a file-system port, with crash and power-loss injection

## Brief
- Goal: the first of BL-0151's slices (`design/specs/engine-jobs.md` §6.1 step 8, §6.2, §6.3, §6.5, §10; ADR-0008 steps 5-6, ADR-0012, ADR-0013): the part of the save that writes, built and checked on its own, so that every later slice of the save, the rollback and recover-all stands on primitives already proven under crash and power loss.
  - **A file-system port for the engine** (`ledger_engine.fs`): every write goes through a handle on one directory (`DirHandle`), so a check of where the directory is and the write that follows use one descriptor (§6.3 "Path guard": `renameatx_np` on one parent descriptor). Its operations: read a regular file (never through a link), its mode, create a file exclusively with its data, `durable_sync` a file and the directory (§6.2), swap two names (`RENAME_SWAP`), rename without replacing (`RENAME_EXCL`), remove, make a directory, list, and the directory's current canonical path. Plus `resolve(path)`: the canonical spelling of the deepest existing ancestor, the rest as written, and each component's folding rule.
  - **The macOS adapter** (`ledger_engine.fs.darwin`): `F_FULLFSYNC` (falling back to `fsync` only where the volume refuses it, logged once per volume), `renameatx_np` with `RENAME_SWAP` and `RENAME_EXCL` on one directory descriptor, `F_GETPATH` on a descriptor opened with `O_EVTONLY` (no cloud download), `_PC_CASE_SENSITIVE`. Linux and Windows refuse (fail closed) until BL-0087 (spec §14: "the write path's OS parts on Linux and Windows from M1b").
  - **An in-memory fake with a separate durable layer** (`engine/tests/fakes/memfs.py`, test support; its own semantics in `engine/tests/fakes/test_memfs.py`): inodes, directories, links, case-insensitive and normalization-insensitive volumes; per directory the entries made since its last sync, per file whether its data is synced. **A power loss** yields every durable state §13's file-system assumptions allow: each unsynced entry operation kept or dropped on its own, a swap or exclusive rename kept or dropped whole, each file with unsynced data at its synced bytes, its current bytes or cut off (a directory entry kept before its data included). **A crash** (a `BaseException`, as a process death: no `except Exception` sees it) and **an I/O error** (`OSError`, `ENOSPC` by default) can be injected at any effect, a write cut at any offset. Outside programs (an editor's durable save, a folder replaced by a link) act on it between any two effects.
  - **`canonical_path` and `path_key`** (§6.3; pure folding in `ledger_engine.ledger.core.paths`, resolution through the port in `ledger_engine.ledger.paths`): macOS NFD always, plus `casefold` on a case-insensitive volume, per component by the rule of the directory that holds it; the key of an absent path equals the key of the same file once created, under any spelling the volume treats as equal.
  - **The journal record** (`ledger_engine.ledger.core.journal`): a versioned JSON format (an older app refuses a newer journal, ADR-0012) naming every file by `canonical_path` and `path_key`, pre and post hashes, backup and temp names, the directories the save creates, and every field of the future closed record (post fingerprint, adopted and parse digests, engine build, workspace registry key and lineage id); its name `<session>-<job>` and the suffixes of §6.5. Strict decoding: a torn or foreign record is `Unreadable`, never a partial record.
  - **The durable order** (`ledger_engine.ledger.writer.durable_commit`, §6.1 steps 8.1-8.5): the journal and backup folders resolved to their canonical paths; backups written, each synced, their folder synced (each backup hashed against the planned pre hash, ADR-0012 F-1); the journal as `.part`, synced, renamed `.open`, its folder synced; per file, children first and the root last: the path guard, the temp `.<name>.ft-<job>.tmp` written with the file's mode and synced, a swap (or for a created file an exclusive rename that fails if a file appeared), the displaced bytes hashed against the pre hash (other bytes: swapped back at once and the folder synced, §6.4, model F3), the folder synced; the directories the save creates made and their parents synced; read-back of every written file against its post bytes; our temps removed and their folders synced; the close (`.open` renamed `.closed`, its folder synced). It returns `Landed` exactly when the closed record is durable.
- **The step rule** (written before coding, from the S0057-S0059 lesson):
  - Effects that may raise: every port operation may raise `OSError` (any errno) and the process may die at any effect. A half-done effect leaves: an exclusive create with its entry and a prefix of its data, or no entry; a swap or a rename whole or not at all; a sync nothing visible (only durability changes). Pure steps (hashing, encoding) do not raise on valid input; a malformed plan is refused before the first effect (`ValueError`, nothing written).
  - What the writer returns after an `OSError` (refined while testing, see Decisions): before the first replace (the first swap or exclusive rename of a ledger file), **`NotSaved`**: no ledger file was replaced, so it is true whatever the journal's state; `unchanged` is true only after every target was hashed again and equals its pre bytes (§11's rule); `open_journal` says whether the journal may have been left `.open` (from the moment its rename is asked for), which pauses the workspace's writes until recovery resolves it. Backups, a `.part`, temps and a folder the save made may be left (a `.part` is removed only by recover-all, §6.1 step 8.2). From the first replace on, **`Unfinished`** with the step and the file: the journal is left `.open` (the spec's state after a failed rollback, §6.4), or `.closed` but not durable when the close's own sync failed, which is never "saved". **Interim until slice 2:** §6.4's in-engine rollback resolves the `.open` journal both outcomes can leave, wherever that rollback succeeds (`TODO(BL-0151)` at that seam). A displaced outside save at a swap is swapped back and its folder synced before anything else, so it is kept whatever follows. A crash leaves the disk at the effect it reached; recovery (slice 2) handles it.
  - **Round 1 addition (step 0, before the first effect):** every refusal that the disk or the plan can decide without writing is made before the first effect, in `_prepare`: a replaced path that is not a regular file, locked or hard-linked (the owner's rule, `_hard_links`), or not the object its canonical path names; an entry standing at a created path (a dangling link); a plan whose created paths collide, whose target sits at another's temp name, inside the journal or backup folder, or whose app folders sit inside a folder the save writes in; empty record fields. A plan error raises `BadPlanError`; a disk refusal returns `NotSaved` with the file's path.
  - **Round 2 additions to step 0:** a folder the save writes in must be on a volume with the swap (`_volume_without_swap`, the owner's interim refusal until BL-0160) and allow adding and removing entries; a replaced file must allow being moved away (no deny-delete ACL, no deny delete_child on its folder) and its extended attributes must be readable. **Choice for red team r2 L3** (xattrs unreadable): refuse before the first effect (`NotSaved(permission)`, unchanged), not land without them: a save that silently drops the user's tags is worse than a refusal that names the file, and the check costs one `access(2)`. A temp name must be free and unique. A path that is not UTF-8 is an outcome (`name_not_utf8`), not an exception.
  - Anything else raised (a bug) propagates: the engine job ends `INTERNAL`, which is never "saved".
- **The split of BL-0151** (agent, by the orchestrator's instruction "split it before you code"; written into BL-0151's row):
  1. **S0060 (this slice):** the port, the macOS adapter, the fake with its durable layer and injection, `canonical_path`/`path_key`, the journal record, the durable order with read-back, crash, I/O-error and power-loss tests at every effect. Reason for the cut: every later piece writes through these primitives and is checked against this fake, so they must be proven first; the cut is landable because no product path calls `durable_commit` yet (no route or engine handler writes a ledger file), and its failure outcome is the spec's own fail-closed state (journal `.open`, writes paused).
  2. **Slice 2:** the restore shared by the rollback (§6.4) and recovery's per-journal try (§8.1 steps 1-4: locks without waiting, the checks with the temp rule, restore temps written from the backup and synced, root first, the displaced check, `.resolved {not_saved}`), the rollback wired into `durable_commit` in place of `Unfinished`, and this slice's crash tests extended to "then recover": the ledger all pre or all post, idempotent when cut and run again.
  3. **Slice 3:** recover-all (§8.1): the listing after `durable_sync` of every journal directory, `.part` removal, each `.open` journal tried in an engine that ran no user code, Cancel per journal (`cancelled`), an engine crash (`failed`), `not_tried` while the engine cannot run, `RECOVERY_BLOCKED`, the quit-note answers' seam; the boot's `recover_all` gets its body (`TODO(BL-0151)` in the scheduler); and the gap the row names, closed by doing the listing and the tries inside the engine, which holds the engine lock first (test: an engine of an earlier session between its handshake reply and its `flock` cannot be beside the listing).
  4. **Slice 4:** the save job end to end (§6.1 steps 1-7, 9-11): R4 first if owed (the R4 itself is BL-0152: until it lands, an owed R4 refuses with `WRITES_PAUSED {check_pending}`), legacy-lock detection (ADR-0062), the ledger-set locks in `path_key` order, the gate on the records (§6.5 matching by key or lineage), the load, the re-check, the engine handler with `gate`/`committed`, the outcome after an engine death (§6.6) replacing `CHANGE_OUTCOME_UNKNOWN` at its seam; the codes `LEDGER_EXTERNALLY_CHANGED`, `WRITES_PAUSED`, `LEGACY_APP_SAVING`; the fingerprint keyed by `path_key`.
  5. **Slice 5:** the conformance replay extended to the save path (the model's `fs` and `jr` projected onto the fake) and BL-0159 (the corpus widened by branch, the branch-coverage assertion, the verifier's three mutants killed).

## Decisions
- **Where the save's code lives** (agent; ARCHITECTURE §2.2 already placed `writer.py` and `journal.py` in the engine's ledger kernel): the port in a new package `ledger_engine.fs` (only it does OS-level file work), the pure values in `ledger.core` (`paths.py`, `journal.py`), the resolution and the durable order in `ledger` (`paths.py`, `writer.py`). The fake lives in the engine's tests (`tests/fakes/`), as test support, not product code.
- **A handle per directory, not paths** (agent; spec §6.3 "The check and the write go through one descriptor of the parent directory"; ADR-0012's amendment of 2026-10-25: "the `FileSystem` port exposes `atomic_swap`, not `os.replace`"): every write is a `DirHandle` operation by name, and the writer checks `DirHandle.path()` (`F_GETPATH` on that descriptor) against the recorded canonical folder before every use. A folder replaced by a link after the check is never followed: the write lands in the folder that was checked, and the next check stops the save (test `test_a_folder_swapped_for_a_link_between_the_check_and_the_write_is_still_written_through_its_descriptor`). Rejected: path-based operations with a `realpath` check before each (the check and the write would resolve the path twice).
- **`create` writes and syncs in one call** (agent): the port has no "write" and "sync file" pair, so no file is reopened by name between its write and its sync; the fake still numbers the entry, the write and the data sync as three effects, so a crash can land between them.
- **The fake's durability is §13's assumptions and no more** (agent): a folder's sync makes only that folder's entry operations durable, never another file's data (weaker than macOS, where `F_FULLFSYNC` flushes the drive's whole cache, so more states are reached, not fewer); an outside program's save is durable (an editor that syncs), and one that creates an entry syncs its folder, which makes our earlier operations there durable too, as §13 states. A power loss is enumerated exhaustively (it fails the test past 200,000 states rather than sample).
- **Backups in machine-local state** (agent; the spec names no place; INV-27, INV-30: never in the workspace folder): `local/<key>/backups/<session>-<job>/<n>-<name>`, mode 0600, the folder recorded in the journal (`backup_dir`) and each file's name (`backup`). How many are kept is ADR-0047's setting; trimming is not built here (it comes with the save job, slice 4).
- **The journal's encoding** (agent; ADR-0012 "its format is versioned; an older app refuses a newer journal"): canonical JSON with `format` and `v`, ending in a newline; `decode` accepts only bytes equal to `encode(record)`, so a record cut off at any length, hand-edited or of another version is `Unreadable` (recovery will block on it, §8.1). The reasons of `.resolved {not_saved}`, `.mismatch {could_not_check}` and `.done {superseded_build}` are not encoded yet: a rename cannot change content, so they need a place (a suffix or a side file), decided with the slice that first writes them (slice 2 and BL-0152). Ids are `[A-Za-z0-9_]{1,64}`: `-` joins session and job.
- **`path_key` per component by the rule of the folder that holds it** (agent, reading §6.3's "every component folded by its volume's rule"): the name of an entry lives in its parent folder, so a mount point's own name folds by the volume above it; the components that do not exist yet fold by the deepest existing folder's rule. A `pathconf(_PC_CASE_SENSITIVE)` answer other than 1, or an error, counts as case-insensitive (merging is the fail-closed direction, §15).
- **The step rule, refined while testing** (agent): the brief first said `Unfinished` "from the journal's rename to `.open` on". The I/O-error sweep showed a failed rename (and any failure before the first replace) would then be told as "could not finish" although no ledger file was replaced; `NotSaved` is the true outcome there, and `open_journal` carries the one consequence (writes paused until recovery). Changed before landing; the brief above states the final rule.
- **The journal and backup folders resolved first** (found on self-review): `F_GETPATH` returns the canonical path, so a caller naming its own folders through a link (`/var` on macOS) would have been refused by the path guard at every save; the writer resolves them first, after the targets, so `unchanged` is still decided by hashing (test `test_the_journal_and_backup_folders_may_be_named_through_a_link`).
- **Not marked for the model's code map yet** (agent): the writer carries out the model's `S_Backup` to `S_CloseSync`, but they stay in `test_tla_mapping.py`'s `PLANNED` under BL-0151 until the save job runs them (slice 4) and the replay checks them (slice 5); a marker on a function no job calls would claim more than the replay can show.
- **Deviations from ENGINEERING.md:** none known. The fake's helper class reads the fake's private members (`# pyright: reportPrivateUsage=false` in `tests/fakes/memfs.py`: one fake in two classes).
- **Round 1: resolution through the folder** (red team 1, High; orchestrator's direction): a file's canonical path is its folder's `F_GETPATH` joined with the entry's stored name from the folder's listing (matched by folding, then by `(st_dev, st_ino)`), never `F_GETPATH` on the file; resolution, the backup and every swap check that the entry is the object the path named. `stat` (an `lstat`) replaces `mode` in the port and carries the identity, link count and lock flags.
- **Round 1: hard links** (owner, 2026-10-29: "Refuse to save it (Recommended)"; inbox answer and ADR-0013 amendment of that date): refused before the first effect, the message naming the file, in one function (`_hard_links`); checked again at the backup. The UI copy is in spec §11; the error code is slice 4's.
- **Round 1: a failed exclusive rename** (red team 5): `replaced` is still set before the rename (an exclusive rename that answers an error may have happened, now injected with `after=True`) and put back only on `FileExistsError`, which says it did not happen. This keeps the step rule truthful for both cases; setting it only after success, as the round-1 note read, would tell "not saved" for a rename that happened and answered `EIO`.
- **Round 1: metadata** (red team 10): `create(..., like=...)` copies the replaced file's extended attributes and ACL (`fcopyfile` with `COPYFILE_XATTR | COPYFILE_ACL`, not `COPYFILE_STAT`, which would copy the old modification time and make the new bytes look unchanged to sync tools); the owner and BSD flags are a stated limit (§15, ADR-0013 amendment).
- **Round 1: long names** (red team 11): derived names are shortened, not refused (`journal.temp_name`, `journal.backup_name`: 16 hex digits of the name's SHA-256 past 255 bytes), deterministic so strict decode can check them. APFS counts its limit in characters (255), so counting bytes is the stricter rule and fits every volume.
- **Round 1: an empty created folder after "not saved"** (red team 13): kept, stated in §15. It can only exist under an `.open` journal (folders are made after the rename), and recovery removes it if it is still empty (§8.1 step 3); removing it here would add a path for a case recovery already covers.
- **Round 1: no amendment to ADR-0008 step 6 or ADR-0012** (red team 9, orchestrator: "if their wording overclaims"): neither says the read-back reads the platter. ADR-0008 step 6 says the written file equals the intended bytes, which is what is checked, and ADR-0012 F-1 asks for the backup to be hashed against the pre hash, which it is. Amending an ADR is the owner's (rubric item 4), so the limit is stated in spec §15 instead.
- **Round 2: M1 as directed changes no outcome** (agent, reported to the orchestrator): the swap-back's displaced entry is now checked against our temp's identity and post bytes, and on anything else the save stops without swapping again. 4c275f57 already ended the same way (it swapped back once and stopped with CHANGED), so the new test is a `@regression-guard`. What the red team flagged, the newest outside save sitting in the temp while the file shows an older one, remains by the orchestrator's choice ("stop without swapping again"). It is safe from deletion: §8.1 step 2 stops a journal whose file holds neither pre nor post before step 3 deletes any temp, and §6.4 now says so. The blocked screen must show that temp as a version (slice 3, on BL-0151's row).
- **Round 2: the temp rule is not changed** (agent; pushback on the orchestrator's "a temp that holds bytes that are neither pre nor post must never be deleted"): that rule would make every temp cut off mid-write block recovery, which the owner's review-6 P1 rejected ("otherwise recovery deletes it, whatever it holds"; ADR-0064 decision 11, ADR-0012 amendment) and which the model's `CutTempNeverBlocks` forbids. Changing it is the owner's (rubric item 4). It is not needed either: the only case where an outside save ends up in a temp beside a file not at post is a journal that §8.1 step 2 already stops. The spec line was clarified, not changed.
- **Round 2: permissions by `access(2)`** (agent): the extended bits (`_DELETE_OK`, `_REXT_OK`) answer from the file's and folder's ACLs and modes, as probed on APFS (deny delete, deny delete_child, mode 0555, deny readextattr each answer False). This is a check, not a guarantee: an ACL changed after it is caught later as an I/O error (fail closed).
- **Round 2: volume capabilities by `fgetattrlist`** (agent): `VOL_CAP_INT_RENAME_SWAP` and `_EXCL`, both capable and valid; probed True on APFS and False on an exFAT image (`hdiutil create -fs ExFAT`, mounted in the scratchpad, then detached). The suite does not mount images; the APFS answer and the fake cover the code.
- **Round 2: a redundant check removed** (found by mutant `dir_at_temp_allowed`): a created folder at a temp name always has a target file inside it, which the temp check already refuses.
- **Round 2: the hard-link rule at the swap** (red team r2 M2, verifier r2 F1): `_displaced_is_ours` requires one link, so a link made after the check is swapped back (`Unfinished(hard_linked)`, both names at pre) or keeps the displaced file at the temp removal.
