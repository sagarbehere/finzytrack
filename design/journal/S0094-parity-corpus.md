# S0094: The parity corpus (INV-03)

## Brief
- Goal: BL-0003. Build INV-03's enforcement as far as the code it guards exists at M1a: a parity corpus that the overlay load (`ledger_engine.ledger.overlay.load`, ADR-0010) loads and round-trips with results equal to Beancount 3.2.0's own loader, and whose encrypted ledgers (an encrypted root, `.gpg` and `.asc`, and an encrypted file reached by a glob and by a nested include) are refused, never decrypted or partly loaded (ADR-0059).
  1. **Inventory first, by behaviour**, from Beancount 3.2.0's own code, with counts recorded below: the loader's file handling (`loader._parse_recursive`, `aggregate_options_map`), its plugin handling (`run_transformations`, `PLUGINS_PRE`/`PLUGINS_POST`, `plugin_processing_mode`), every public option (`parser.options.PUBLIC_OPTION_GROUPS`), every built-in plugin module (`beancount.plugins`), every directive type (`core.data.ALL_DIRECTIVES`), the documents step (`ops.documents`) and Beancount's encrypted-file test (`utils.encryption.is_encrypted_file`). The test reads the three Beancount-owned lists at run time, so a Beancount upgrade that adds an option, a plugin or a directive fails the population test until the corpus covers it.
  2. **The corpus:** hand-written synthetic cases in `corpora/ledgers/parity/<case>/` described by `corpora/ledgers/parity/cases.toml` (features, expect `load` or `refuse`, the refused file), plus cases generated at test time: Beancount's example ledger from its own pinned generator (`beancount.scripts.example.write_example_file`, seeded, fixed dates, its output's hash pinned), that ledger split into a recursive glob of files, that ledger under five custom root names, the cases that need an absolute path or no file at all, and a file that is not UTF-8. Each claimed feature has a detector that must find it in the case (Beancount's result or the case's files), so a case cannot claim a feature it lacks.
  3. **Equality is S0049's comparison**, moved unchanged from `engine/tests/ledger/test_overlay.py` into a shared helper both tests use: entries equal, errors equal by type, source and message, options equal key by key (`dcontext` by its text; `input_hash` left out only after a write). Per case: the empty overlay, every file's disk bytes as candidates, and a candidate for the root (an added `event` line) equal to Beancount's load after the same bytes are written (the round trip).
  4. **Finzytrack handles it:** the mirror's rows (`mirror.build.tables`) build without a refusal or an exception from every loaded case (INV-03 "Finzytrack handles it"; the mirror is the only consumer of the load today).
  5. **Must-not-pass cases:** seeded overlay divergences (a dropped entry, plugins not run, a non-recursive glob, options not aggregated from includes, an error dropped, an option changed, an encrypted file decrypted, a candidate ignored), each caught by the corpus check; loosening mutants of the comparison and the overlay with `scripts/mutants.py`.
  6. **INV-03's Enforced-by line and status** by the owner's standing rule (INVARIANTS.md "Status values", 2026-11-09): enforced when everything that exists today is guarded, the unbuilt parts listed as planned under their rows.
- Third-party ledgers (agent, checked before adding anything): **Beancount's example ledger** is the output of `bean-example`, which ships inside the pinned Beancount 3.2.0 wheel (GPL-2.0-only, already the engine's dependency): generated at test time, nothing committed. Beancount 3.2.0's CLI ignores `--date-begin`/`--date-end` (its `LiberalDate.convert` returns nothing), so the test calls `write_example_file` with fixed dates and a seed, which is deterministic across hash seeds (checked). **Fava's example ledgers** (`tests/data/example.beancount`, `long-example.beancount` in Fava's repository, MIT) are not in any installed package; their header shows they are `bean-example` output edited by hand. Not committed: Fava is not a dependency, and copying a third-party file needs its notice; the loader-relevant features they add (`custom "fava-option"`, `query`, metadata on `open` and `commodity`, budgets, `event`, `note`) are a hand-written case. **Beancount's repository examples** (`examples/tutorial`, `vesting`, `sharing`, `forecast`) are not in the wheel; their loader features (plugins with configs, includes, `pythonpath` plugins) are covered by hand-written cases. Nothing needs a MANIFEST row.
- Implements: BL-0003; ADR-0010 guardrail 1 (on the parity corpus, beside the D1 corpus), ADR-0059 (the encrypted refusal on the root and on included files), ADR-0024 (Beancount is the oracle), ADR-0031 (booking methods: the vectors' booking family, S0049, already guards it).
- Capabilities: none changes state (nothing user-visible; CAP-DATA-ENCRYPTED stays deferred).
- Invariants touched: INV-03 (enforcement and status), INV-23 (synthetic corpus only, generated ledgers never committed), INV-24 (every case loads from a temp copy).
- Risk class / lane: Medium (tests and corpus; no ledger write) / light.
- The bytes it protects: none (no write path); the checks keep the overlay's results, which every save preview and the mirror use, truthful against Beancount's.
- Acceptance tests (new; each must fail on the base 51f2c120, where the corpus, the helper and the generated cases do not exist): `engine/tests/ledger/test_parity_corpus.py`: every load case equal to Beancount's loader three ways; every refuse case refused with its file, nothing decrypted, and a file Beancount itself would decrypt; the mirror rows build from every load case; the population tests (options, built-in plugins, directives, features, cases and folders); the seeded divergences caught; the generator's output pinned. `engine/tests/test_open_ops.py`: the open of an encrypted root is refused with its file (a regression guard: it holds on the base, tagged `@regression-guard`; corrected after round 1, F4).
- Expected doc impact: `design/INVARIANTS.md` INV-03; `design/backlog.md` BL-0003 closed, rows for what is cut; `corpora/README.md` (the `parity/` folder); `design/specs/write-path/write-corpus.md` Orientation (the parity corpus beside it); `design/specs/roadmap.md` (the example ledgers line); `engine/CLAUDE.md` (where the corpus check is). No user docs (nothing user-visible). No ADR expected.
- Open questions: none for the owner before coding. INV-03's status change is named in the report (standing rule of 2026-11-09).

## Decisions
- **Generated, not committed: Beancount's example ledger** (agent; the brief's preference; orchestrator relaying the owner, 2026-11-10: "prefer generating samples at test time with `bean-example` so nothing third-party is committed"). `parity.example_ledger()` calls `beancount.scripts.example.write_example_file` with a seed and fixed dates and puts the global random state back; the text is the same across hash seeds (checked with `PYTHONHASHSEED` 1, 2, 3) and its SHA-256 is pinned. Beancount 3.2.0's `bean-example` CLI ignores `--date-begin`/`--date-end` (`LiberalDate.convert` has no `return`), so the CLI would end "today" and change daily; the function is called directly. A stub (`engine/typings/beancount/scripts/example.pyi`) types the one name.
- **Fava's example ledgers are not in the corpus as files** (agent): they are in Fava's repository only (MIT), not in any installed package, and their header (`;; Birth: ... ;; Dates: ...`) shows they are `bean-example` output edited by hand. Committing one would add a third-party file and its notice; adding Fava as a dependency for a test file is out of proportion. What they add for a loader (`custom "fava-option"`, `custom "budget"`, `query`, `event`, `note`, links, metadata on `open` and `commodity`, a `pad` with a balance) is the hand-written `fava-features` case. Named in the report as an open question for the owner, not escalated: BL-0003's words ("Beancount and Fava example ledgers") are met by the generated example plus Fava's additions unless the owner wants Fava's exact file. After round 1 the orchestrator's default is recorded: Fava's file is not committed (the generated example plus `fava-features` cover it), pending the owner's override.
- **The comparison is S0049's, moved, not rewritten** (agent; the brief): `same` and `load_file` went from `test_overlay.py` to `tests/ledger/parity.py` unchanged; `tests/conftest.py` registers the module for pytest's assert rewriting, so a failure still shows what differs.
- **Three checks per load case** (agent): the empty overlay and every file's bytes as candidates (S0049's two), and a round trip: a candidate for the root with an added `event` (it needs no account, so it fits every case, custom roots included) must appear in the prediction and equal Beancount's load after the same bytes are written. A comment line would have been invisible to the comparison, so a candidate the overlay ignored would pass; the `event` makes that a must-not-pass case.
- **Each claimed feature has a detector** (agent; PROCESS.md §3 step 4, population "by behaviour"): detectors read Beancount's own result and each loaded file parsed alone by Beancount's parser (its includes, options, plugins, entries), not the case's name, so a case cannot claim what it lacks; a planted false claim, an unknown feature and unclaimed features are refused (`test_a_false_claim_an_unknown_feature_and_an_unclaimed_one_are_found`).
- **The corpus is pinned too** (agent): each `load` row records Beancount's errors by type (`errors` in `cases.toml`; none for the generated example ledgers), so a case that stops loading as written, or a Beancount that reads it differently, fails `test_beancount_gives_each_load_case_the_errors_it_is_written_for` instead of passing as "both loaders agree on garbage".
- **Populations read from Beancount at run time** (agent): `parser.options.PUBLIC_OPTION_GROUPS` (28), the modules of `beancount.plugins` without `_test` (18), `core.data.ALL_DIRECTIVES` (12). Each has its count asserted, so an upgrade that adds one fails until a case covers it, and a planted test that removes the covering case names what goes missing.
- **"Finzytrack handles it" includes the mirror** (agent; INV-03's words): the mirror's rows (`mirror.build.tables`) build without a refusal from every load case; the mirror is the only consumer of a load today.
- **Encrypted refusals checked against Beancount's own test** (agent; ADR-0059): every `refuse` case names a file `encryption.is_encrypted_file` says Beancount would decrypt (so the refusal is not vacuous), the overlay refuses it with that file, also with every plain file as a candidate, and the rebuild's real load (`port.real_load`) meets `EncryptedFileMet` for the same file; decryption is patched to fail the test. The open's refusal of an encrypted root over the protocol is pinned in `engine/tests/test_open_ops.py` (it held on the base, so tagged `@regression-guard`; not on INV-03's Enforced-by line because that file's macOS `skipif` is not a form `check_invariants.py` accepts in an enforcement file).
- **Beancount facts found while building the corpus** (agent; recorded in the cases' comments, nothing changed in the product): an included file is parsed with its own options, so a ledger with custom root names must name them again in every file (`custom-roots/forgot-the-roots.beancount` shows Beancount's ParserError); plugins listed in an included file are ignored (only the root's run); `include "*.beancount"` in the root matches the root itself (a duplicate error); a `**` glob matches files at its own level too; the documents step adds a `document` entry for a file a directive already names (two entries); `long_string_maxlines` has no converter, so its value stays text. The overlay agreed with Beancount on all of them.
- **The plain message is not built here** (agent): ADR-0059's message for the open's screen has no text key yet (the copy's `msg:copy.encrypted` exists); the engine and sidecar refusal with the file's path exist (S0088). New row BL-0230 (M2, with the open screen); INV-03's Enforced-by line lists it as planned.
- **Tests first** (run against `51f2c120`'s source, an archive in the session scratchpad with the new tests copied in): `test_parity_corpus.py` fails at collection without `tests/ledger/parity.py`; with the helper but without the corpus, 10 of its tests fail (every corpus, refuse, mirror, population and divergence test); the generator pin is a new test of new helper code. `test_open_ops.py::test_an_encrypted_root_is_refused_with_its_file` passed on the base: `@regression-guard`.
- **Deviation from ENGINEERING.md:** none known.

## Hand-off (PROCESS.md §3 step 4; ADR-0057)

## Verifier
- Round 1, head 016aa5a1: 0 High, 2 Medium, 2 Low. Repros in the session scratchpad (`verif/`).
- F1 Medium: `same` loosened to compare errors without their source, or as a multiset ignoring order, survived every must-not-pass test. Fixed: seeds "an error's source moved" and "the same errors in another order" (a second unbalanced transaction in `options`, so the validation step returns two errors); both of the verifier's loosened comparisons now fail.
- F2 Medium: `options` set `render_commas "TRUE"` then `"SOMETIMES"`, which Beancount reads as false, so the option ended at its default everywhere, and the population counted option lines by text. Fixed: the refused value is now `name_assets "lowercase"` (Beancount reports it and keeps `Assets`); `options_missing` requires a non-default value in Beancount's result (the alias by its line and its target); a planted case where a later line puts the default back; the case's comments corrected (the old "a value Beancount refuses" was wrong: "SOMETIMES" gives no error).
- F3 Low: the negative detector test passed with loose detectors, and `example-ledger` read only one header line. Fixed: each case must claim exactly what the detectors find (four claims added that the detectors found: `precision-merged` in `custom-roots`, `plugins-local`, `example-split`; `documents-root` in `absolute-paths`); a near-miss test with the verifier's four loose detectors; `example-ledger` needs the generated header with its birth line, over a thousand entries and no error.
- F4 Low: the brief listed the open-op test among tests that fail on the base; it is a regression guard. Brief corrected.
