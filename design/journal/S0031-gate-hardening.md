## Decisions
- **H1 is a separate script, `scripts/check_push.py`, run first by the pre-push hook (agent).** The logic is tested in scratch repositories (`scripts/tests/test_push_gate.py`); the hook only feeds it git's ref lines and stops on refusal, before any check runs. A tag is peeled to its commit; a deletion pushes nothing and passes (the guard refuses deletions by agents; the owner may delete).
- **"Clean" means more than `git status --porcelain` (agent).** Ways the tree can differ from HEAD while status looks clean were listed and each is refused and tested: untracked files hidden by `status.showUntrackedFiles=no` (status is read with explicit flags), the file-system monitor (off), assume-unchanged and skip-worktree index entries, and ignored code a check could load (an ignored `conftest.py` in a folder called `data/` would be collected by pytest). Ignored source and config files are refused except in dot-named caches, `frontend/node_modules/` and the build folders, matched by place; inside `__pycache__` only bytecode. Stated limit: a forged `.pyc` with a tracked source's timestamp and size runs instead of the source; building one is deliberate (BL-0062 territory).
- **A new remote branch is scanned from the remote's own `next` (agent; deviation from the brief's "origin/next").** The brief asked for the merge base with `origin/next`. That is a remote-tracking ref in this clone, which a command can move (`git update-ref`) to shrink the range to nothing. The script asks the remote (`git ls-remote <remote> refs/heads/next`) and falls back to the whole history when the remote has no `next` or this clone lacks its commit. The whole-history fallback reads the legacy history too, which fails the scans: it fails closed, and only a push without a remote `next` hits it.
- **Range blobs come from every commit's diff against each parent (agent).** `git rev-list` plus `git diff-tree --stdin -r -m --root --no-renames`: a file added and removed again, two versions of one path, a rename onto a refused name, a blob that exists only in a merge's resolution are all returned. Blobs are read with one `git cat-file --batch` (the brief said `git show sha:path`; same content, one process). The tip's `corpora/MANIFEST.tsv` decides which exports are reviewed (stricter than each commit's own manifest). Range specs take only 40-hex commit names, never a ref.
- **Submodules are refused by the staged-file guard (agent).** Their content is outside every scan; none exist.
- **A pre-merge-commit hook execs pre-commit (agent).** Cherry-pick, rebase and revert run no commit hook at all; the pre-push range scan is what catches them.
- **The skip ban on enforcement files allows one form (agent).** `scripts/tests/test_oracle_copies.py` (on INV-24's line) had two `skipUnless(HAS_FIRMLINK)` tests for the macOS firmlink spelling. A skip that cannot fire where the hooks run (macOS) is not a way to switch enforcement off, so `unittest.skipUnless(sys.platform == "darwin", "...")` is allowed exactly (any other condition, alias, extra argument or `skipIf` is refused, each tested), and the tests now assert the firmlink exists on a Mac instead of skipping when it does not.
- **A test counts as enforcement only if the pre-push hook runs its folder (agent; part of M4).** Removing `ci.yml` from `RUNNERS` alone would leave a Playwright spec (run only by the manual CI) counting, because any test counted. `PUSHED_TEST_ROOTS` names the four test folders and the text in `.githooks/pre-push` that runs each. No enforced invariant lost its enforcement: INV-11, 12, 19, 23 and 24 each name a test in a pushed folder. No inbox note is needed.
- **The S0029 fixme/skip scan now covers `scripts/tests` and `scripts/oracle/tests` with its rules unchanged (agent).** Its protected-file rule gained the unittest forms (`skipIf`, `skipUnless`, `expectedFailure`, `SkipTest`, `skipTest`) and bare uses (`@expectedFailure`, `raise SkipTest`). One false positive: `scripts/tests/test_mirror_surface.py` mentions `I7` (a P1 ID) as table data, which made its clone-dependent tag skip "protected"; the data now uses `I3`, which is not a P1 finding.
- **Conftest files above an enforcement test are scanned for collection removal and skips, not for xfail (agent).** `backend/tests/conftest.py`'s fixme hook adds `xfail(strict=True)`, which fails a passing test, so it stays. A conftest hook that filters or marks items, the pytest configuration and string indirection stay out of a static scan; BL-0078 (run-time proof the enforcement tests ran) closes them.
- **Prettier joins the whole-tree checks at push (agent).** Not in the brief; it costs 0.3 s and closes the same partial-staging hole for formatting.
- **The oracle tests run as one discover (agent).** 243 tests in about 10 s, replacing four per-file runs; it adds `test_harness.py`, `test_adapters.py`, `test_classify.py`, `test_model.py` and `test_semantic_diff.py`.
- **M5's second half and M6's due-date moves are not built (agent).** "Every file on an Enforced-by line is a test or a hook-run check" would fail today on files the owner listed (INV-11's `state_registry.py`, INV-24's Claude hooks), so it needs the owner's text: noted on BL-0040 (parked). Due dates and pending-to-enforced flips moved in the same change stay with the verifier.
- **The M0 exit is red on purpose (agent).** `FT_MILESTONE_EXIT=M0` now fails on BL-0075 (the seeded-defect run) and BL-0076 (the manual full CI run), the two exit items that had no row.

## Verifier
- Round 1, head `d63e31f3`: pass with findings, no High; four Medium, each pushed end to end in scratch. Fixed in one commit on top (fix-round record below).
- F1 Medium: the skip ban missed an empty `parametrize` list, `__unittest_skip__`, `__unittest_expecting_failure__`, `__test__ = False` and TS `.only`. Fixed: refused in enforcement test files and conftests above them (a parametrize must take a non-empty literal list there); `.only` refused in every frontend test file (member, indexed and destructured forms; the word in prose passes); the run-time cases added to BL-0078.
- F2 Medium: `git replace` hid the pushed objects from every local read. Fixed: the hooks export `GIT_NO_REPLACE_OBJECTS=1`, `check_push.py` and `git_range.py` read with `--no-replace-objects`, and a `refs/replace/*` ref or `info/grafts` refuses the push.
- F3 Medium: the clean-tree check ran once, at the start of a long hook. Fixed: `check_push.py --still <HEAD at start>` is the hook's last check (HEAD unchanged, tree still clean). Stated limit: a change made and undone between the two checks.
- F4 Medium: commit and annotated-tag messages were never scanned. Fixed: `privacy_scan.py --range` also scans every commit message of the range, `check_push.py` names pushed tag objects and `--tag-message` scans their message (the header, with the tagger's address, is not scanned), and a new `.githooks/commit-msg` scans the message above git's scissors line.
- F5 Low: the remote's `next` was read at the fetch URL. Fixed: the hook passes the push URL; a whole-tree `check_staged.py --paths` over `git ls-files` runs as a backstop.
- F6 Low: the whole-history fallback could never pass. Fixed in part: `check_push.FLOOR` (the empty-tree start of v0.4, pinned by a test) is the base when the remote has no usable base. Pushback: the floor range still fails today on three blobs that later commits fixed (two name the live-data folder, one entropy hit). A remote without `next` receives that history, and those blobs are already public on origin, so failing there is right. The fallback is not made to pass.
- F7 Low: ignored Claude state and coverage/mutation output were refused. Fixed: `.claude/` (except `.claude/hooks/`), `backend/mutants/`, `mutants/`, `backend/htmlcov/` and `htmlcov/` are trusted. The verifier's probe I also showed ignored tool configuration passing (`.prettierignore`, `pyrightconfig.json`): JSON, YAML and dot-named `*ignore`/`*rc` files now count as code.
- F8 Low: the name rules hit non-test enforcement sources. Fixed: they apply to test files only (`skip = None` in a check script passes).
- F9 Low: no test for a file turned into a symlink (status T). Added.
- F10 Low: `LauncherOwnerPortTest` sat below `if __name__ == "__main__"`. Moved.
- Fix round: 24 mutants, one or more per finding (F1 6, F2 4, F3 3, F4 4, F5 2, F6 1, F7 2, F8 1, F9 1), 24 killed (plan `scratchpad/s0031/mut3.toml`). The verifier's probes, re-run end to end against the fix commit in scratch clones: S1 (empty parametrize plus a module global) refused by the invariants check; S2, S3, S5 refused by `check_invariants`, S4 (`skip = None` in a check) passes; replace refused (replacement ref) and its blob still refused by the range guard; TOCTOU refused by the final re-check; push-URL refused by the range guard and the whole-tree guard; a secret in a commit message refused by commit-msg, and when cherry-picked past it, by the range scan; a secret in a tag message refused at push. The end-to-end run found one more defect, fixed before landing: the hook's exported `GIT_NO_REPLACE_OBJECTS` leaked into the scratch-repo tests and failed every push; the tests now start from git's defaults.
- Pre-push after the fix round: 80 s for an honest one-commit push in a fresh scratch clone (cold caches); the verifier measured 100 s in its clone. The meta-tests take 35 s of it (the scratch-repo push tests about 16 s). Nothing was moved to the manual run.

## Retro
- Found by self-checks before the verifier: three mutant survivors (one equivalent clause removed, two tests added); a fake email (`\n@unittest...`) in a test string that the privacy scan caught in the end-to-end push, which pre-commit would also have caught; the end-to-end clone showed symlinked venvs count as untracked (the gate is right; scratch clones need them in `.git/info/exclude`).
- Pre-push: 57 s → 67 s (oracle tests as one run +6 s net, scripts meta-tests +14 s for the scratch-repo tests, lint +3 s).
- Where time went: listing the ways a "clean" tree can still differ from what is pushed; the end-to-end probes (each full hook run about 70 s).
- Process cost: one implementer pass (about 3 h), one verifier round (four Medium, six Low), one fix pass (about 1.5 h); a narrow round 2 follows.
- What a cheaper gate could have found: the env leak (a hook test run under the hook's own environment); the verifier's F2-F4 were classes the red team's probes did not try (object replacement, a moving tree, messages).
