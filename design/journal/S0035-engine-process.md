# S0035: The ledger engine as its own process: environment, protocol, client, supervision (BL-0041, first part)

## Brief
- Goal: the process boundary of ADR-0054, with no ledger work yet. `engine/` becomes its own uv project (Python 3.13.16, Beancount 3.2.0 with the oracle's pins, `uv.lock`) with a stdio JSON protocol server that answers a version handshake and `ping`, refuses unknown or malformed requests and a protocol-version mismatch with structured refusals (error key + message), and exits when its parent goes away. `contracts/engine-protocol.schema.json` is generated from the engine's message models and diff-checked. The main sidecar gets an `EnginePort` and its subprocess adapter `engine_client`: spawn, handshake, requests with timeouts, supervision (bounded restart with backoff; a crash mid-request is a structured failure, never a hang), clean shutdown. Architecture tests per environment and two licence allowlists enforce the boundary.
- Implements: ADR-0054 decisions 1, 2, 4, 5 (the process boundary; the operations come later), ADR-0042 (licence check per process), ADR-0004 (pins), ARCHITECTURE.md §2.0 (and the rewrite it asks of §2, §5, §10, §11), EP-06, EP-07, EP-13, EP-14, EP-16, EP-28, EP-30; spike S1's parent-death watchdog (S0001 journal: stdin EOF plus a parent-pid poll).
- Capabilities: none (no user-visible behaviour; the capabilities that use the engine arrive with their operations).
- Invariants touched: INV-02 (the engine-side gateway rule made ready: only `ledger_engine.ledger.beancount_port` may import Beancount; the main side cannot import it; status stays pending under BL-0002), INV-10 (the engine keeps no ledger: it has none to keep yet, stated in its server), INV-11 (the client's process handle is container-owned state, registered), INV-19 (the schema is generated and diff-checked), INV-23 (no data).
- Risk class / lane: Medium / full (process spawn and IPC on the future write path, release-gate licence checks; no ledger reads or writes yet). The verifier may raise it.
- Protocol (decided here, recorded under Decisions): JSON Lines over the engine's stdin and a private copy of its original stdout; fd 1 is pointed at stderr at start so a stray print (a user's Beancount plugin, later) cannot corrupt the channel; every message carries `v` (protocol version, 1), an `id`, the `op`; replies echo all three and carry `ok` with `result` or `error {key, message}`; at most 16 MiB per line; `handshake` must come first.
- Acceptance tests (new; each fails on the base, where nothing of this exists):
  - `engine/tests/test_protocol.py`: handshake and ping replies; must not pass: invalid JSON, not UTF-8, a non-object, duplicate keys, NaN, an over-long line, a missing or other `v`, an unknown or extra envelope key, an unknown op, bad params (extra key, wrong type), any op before the handshake; a handler exception is `engine.internal` and the engine keeps serving.
  - `engine/tests/test_schema.py`: the committed schema equals a fresh generation; every example in it validates against the engine's own models and against the schema; replies the engine produces validate against the schema; must not pass: a reply with a missing field or an unknown key, against the schema.
  - `engine/tests/test_process.py` (real process): handshake and ping over pipes; stdout noise from inside the engine does not reach the channel; the engine exits on stdin EOF; on POSIX it exits when its parent dies while its stdin stays open.
  - `scripts/tests/test_engine_boundary.py` (for `scripts/check_engine_boundary.py`, one static scan for all environments): no `beancount`/`beanquery` import outside `engine/`, `scripts/oracle/`, `corpora/`; inside the engine only `src/ledger_engine/ledger/beancount_port.py` (and the engine's tests); planted cases in other modules, `from` imports, `importlib.import_module("beancount…")`, `__import__`, nested and guarded imports; the engine importing `app`, and anything outside `engine/` importing `ledger_engine`, refused; similar names and relative imports pass; an unparsable file fails closed. `engine/tests/architecture/test_boundaries.py`: the scan holds on the tree, and the engine's environment has Beancount and cannot import `app`.
  - `backend/tests/platform/test_engine_protocol.py` (contract): every request the main side encodes validates against the schema; the schema's ops, refusal keys, version and line limit equal the main side's; each schema example decodes; mutated examples are refused by the decoder exactly when the schema refuses them.
  - `backend/tests/platform/test_engine_client.py` (real engine): start and handshake; ping; a refusal comes back as `EngineRefusal`; the engine killed mid-request gives `EngineFailure("crashed")` with no hang and the next request restarts it; a stalled request times out as a failure and the engine is killed; restart backoff delays and the bound (`unavailable` after the third crash in the window, again allowed after the window); an incompatible engine is never retried; `close()` ends the process; the spawned environment drops `FT_*` and `PYTHON*` variables.
  - `scripts/tests/test_check_licences.py` (extended): the engine group is judged by the engine list; must not pass: Apache-2.0 or LGPL-3.0 in the engine, a reviewed Beancount dependency whose licence changed, a classifier name with no reviewed mapping, a mapping for another version.
  - `scripts/tests/test_check_generated.py` (extended): a JSON artifact carries its header as a top-level `$comment`; must not pass: a JSON file without it.
- Expected doc impact: ARCHITECTURE.md §2.0 amendment replaced by the rewritten §1/§2 text, §2.2 package map (engine tree), §2.3 port table (`EnginePort`), §2.5 state table, §5 (supervision of the engine), §10 (engine pins, beanquery note), §11 (`engine/`, `contracts/engine-protocol.schema.json`); `engine/CLAUDE.md`; `backend/CLAUDE.md`; `licences.allow.toml`, `THIRD_PARTY_NOTICES` regenerated; backlog: BL-0041 closed with its rest split into new rows, BL-0050 narrowed, BL-0002 updated; INV-02 untouched (the owner's text; its status stays pending under BL-0002); `design/process/IMPROVEMENTS.md` entry for the new checks; no user docs (nothing user-visible).
- Open questions: `design/inbox/20261026-beanquery-tatsu-licence.md` (beanquery's TatSu-LTS has a licence with an acknowledgment clause; blocks the first BQL slice, not this one: beanquery stays out of the engine until answered).

## Decisions
- **beanquery stays out of the engine for now** (agent; pushes back on the request "Beancount 3.2.0 and beanquery pinned"). Locking it brought in TatSu-LTS 5.16.0, whose licence is BSD with a fourth clause ("Redistributions of any form whatsoever must retain the following acknowledgment: ..."); its metadata only says "BSD License". The FSF treats such acknowledgment clauses as incompatible with the GPL, and TatSu-LTS is on neither part of ADR-0054's engine list. Adding it would change ADR-0054's reviewed list (rubric 4), so it went to the owner (`design/inbox/20261026-beanquery-tatsu-licence.md`, blocks the first BQL slice, M7). Nothing before M7 imports beanquery. BL-0081. The legacy app already bundles beanquery with TatSu-LTS 5.13.2.
- **Beancount's dependencies are the oracle's pins** (agent): click 8.5.0, python-dateutil 2.9.0.post0, regex 2026.9.29, six 1.17.0, the same versions as `scripts/oracle/uv.lock`.
- **pydantic in the engine** (agent): the message models are pydantic models (strict, closed, frozen), so the engine validates requests with the same models the schema is generated from (EP-16); pydantic is MIT and its closure (pydantic-core, annotated-types, typing-extensions PSF-2.0, typing-inspection) is GPL-2.0-compatible. The main sidecar does not get pydantic for this: it decodes with a small strict stdlib codec held to the schema by a differential contract test (every mutated example refused by the decoder exactly when the schema refuses it). Generating Python decoders from the schema was rejected for now: another generator and generated file for two messages; revisit when the protocol grows.
- **Protocol** (agent): JSON Lines (one object per line, compact, UTF-8) on stdin and on a private copy of the original stdout; fd 1 points at stderr and fd 0 at the null device inside the engine (EP-30: a stray print or read by a user's plugin cannot reach the channel, instead of defending each case). Envelope `{v, id, op, params}` with exactly those keys; replies echo `v`, `id`, `op` and add `ok` with `result` or `error {key, message}`. `id` is an integer from 0 to 2^31-1; the client counts 1..2^31-1 and wraps (one request is in flight, so ids never clash). 2^53-1 was the first choice; its 16 digits in the generated schema read as an account number to the privacy scan (INV-23), and the smaller bound loses nothing. Duplicate keys, NaN and Infinity are refused (smuggling and non-JSON). Check order: line length, UTF-8 and JSON, object, version (so a valid id is echoed on a version mismatch), id, envelope keys, op, params object, known op, handshake first, params model, handler. A handler exception is `engine.internal` with a fixed message; the traceback goes to stderr. Limit 16 MiB per line; an over-long line is refused and skipped to its end. Test ops exist only with `--test-ops` and are not in the schema.
- **Watchdog** (agent; spike S1's approach): stdin EOF ends the read loop after the request in hand (graceful); on POSIX a thread compares `os.getppid()` with `--parent-pid` every 0.25 s, first at once, and exits with code 3 even mid-request. `--parent-pid` was added after the first process test failed: the engine read its parent after the parent had already died (a start-up race), so it watched the wrong pid forever. Windows has no re-parenting: there the Job Object of ARCHITECTURE §5 ends the engine with the sidecar; untested here (CI runs Linux).
- **Client** (agent): requests serialized, one in flight, each with the caller's timeout; a reader thread feeds a queue so every wait ends (reply, timeout, or end of stream when the engine dies). A timeout or an invalid reply stops the engine (its state is unknown). **No request is ever resent** (a write is not idempotent; the caller decides). Restart is lazy (the next request), after 0.5 s, 2 s, 8 s by the number of stops in the window; three stops in 300 s make it `unavailable` until the window passes or `reset()`. A handshake refused with `protocol.version_mismatch`, or reporting another protocol, is `incompatible`, never retried. The engine runs `python -I` with the parent's environment minus `FT_*` (the shell token) and `PYTHON*`. Time for the backoff is injected (`monotonic`, `pause`) so tests do not wait (EP-28).
- **Placement** (agent): `EnginePort` and its result types in `app.platform.engine`, the pure codec in `app.platform.engine_protocol`, the adapter in `app.platform.adapters.engine_client` (EP-07: adapters in `platform.adapters`). The composition root does not start the engine yet: wiring it into `app.main` now would make the packaged smoke test and the acceptance harness need an engine tree the bundle does not have (BL-0083).
- **One boundary scan, not one per environment** (agent; EP-23): the import rules are static and environment-independent, so they live in `scripts/check_engine_boundary.py`; each environment keeps only its `find_spec` checks. beanquery is held to the same gateway as beancount inside the engine (its results are Beancount objects); a BQL slice that wants another module must say so.
- **Licence lists** (agent, implementing ADR-0054 decision 5): `[engine]` is the shared list minus LGPL-3.0-or-later and minus everything pending (Apache-2.0); the reviewed Beancount dependencies pass with a warning only while their licence is exactly the reviewed expression. The main sidecar keeps the shared list unchanged ("main: as today"); moving Apache-2.0 to allowed for the GPLv3 sidecar, which ADR-0054 permits, is left to the legal advice. The per-version `[mapping]` (BL-0050, first part) was required because this slice lands the first runtime dependencies: six and python-dateutil report classifier names.
- **The registry's first entry** (agent; flagged): `EngineClient` is container-owned state and is registered. The globals scan flagged `REGISTRY` itself once it held a `StateEntry(...)` call; the scan now accepts a `StateEntry` call whose arguments are all constants (planted cases with a list, a dict or an unknown call still fail). This accepts more than before, so it is listed for the verifier; INV-11's text is unchanged.
- **INV-02's text and status are not touched** (they are the owner's); BL-0002 records that the import rule now exists.
- **Backlog IDs** (agent): the slice was built on 8434091d with BL-0080 to BL-0083 and IMP-0027, the next free IDs there. S0034 landed first and took BL-0080 and IMP-0027, so on the rebase onto 1d5ecd1d every S0035 ID moved up by one, in the journal, backlog, IMPROVEMENTS, ARCHITECTURE, code comments and commit messages: BL-0080 → BL-0081 (beanquery), BL-0081 → BL-0082 (overhead), BL-0082 → BL-0083 (the engine in the product), BL-0083 → BL-0084 (gate wiring), IMP-0027 → IMP-0028. The original commits are 91c322de and 233c5dbb.

## Hand-off (PROCESS.md §3 step 4; ADR-0057)
- Checks that accept, tag or refuse, each with its must-not-pass tests:
