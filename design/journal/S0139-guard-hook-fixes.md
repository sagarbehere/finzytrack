# S0139: Guard hook fixes (BL-0307)

## Brief
- Base: `d2f52ab0a65a1d992cc61c1fa469447f44563c5a` (`next`).
- Goal: the three parts of BL-0307. (1) The guard meta-tests write only inside their own temporary folder, so a stray file at a fixed global path (twice on 2026-11-21, a reviewer's copy of `design/generated/engine-job-texts.md` at a fixed temp path) can no longer fail the push gate and the Stop hook; no meta-test names a fixed path under the system temp folder. (2) `guards.path_problem`'s generated-file rule (INV-19) refuses a write only to a file under the repository, by every spelling (a symlink into it, `..`, a case variant on a case-insensitive volume, a relative path from another cwd); a GENERATED file outside the repository may be removed or written. (3) The writer branch of `guards.bash_problem` (`rm`, `tee`, `cp`, `mv`, `sed -i`, `npm --prefix` and the rest) reports the refusal's own reason (live data, legacy worktree, generated file, `.git/config`, the manifest), not the one fixed "legacy worktree or live data folder" text.
- Implements: BL-0307 (owner accepted it as written, 2026-11-21: "I'm accepting the inbox note as written", `design/inbox/answered/20261121-pace-and-scope.md`: "BL-0307: a guard of real data, its own slice"); INV-19 (the repository's generated docs); INV-24's enforcement (`.claude/hooks/guards.py`, `scripts/tests/test_guards.py`); ADR-0065 (the guard protects data, not the app).
- Capabilities: none (tooling).
- Invariants touched: INV-24 (its guard: every refusal of the live data folder and the legacy worktree stays as it is); INV-19 (the guard's generated-file rule: its scope is the repository, which is what INV-19 covers: "Generated docs are never hand-edited" names this repository's generated docs, so a copy outside it was never INV-19's; not a weakening of an invariant).
- Risk class / lane: Medium / full (a guard of real data). Review row: "Tooling, gates, measurement" with a guard of real data (INV-24): the verifier, and a fresh round after any fix to the guard (PROCESS.md §3 review budget).
- The bytes it protects: the live data folder's and the legacy worktree's (unchanged rules, regression-guarded here); the repository's generated files (a hand edit would drift from its source, INV-19).
- Which real setup needs this, and can a policy forbid the rest? Every agent session: a reviewer copies a generated page to a temp path to compare it, and then cannot remove it, and the meta-tests fail while it exists. No policy can forbid copies in the temp folder; the fix is to stop refusing what INV-19 never covered.
- Has this mechanism or its family needed two or more fix rounds before? Yes: the guard parser family. S0014 (two verifier rounds), S0054 (three rounds, the app rules removed by the owner after round 2, ADR-0065), S0105's BL-0054 part (two High rounds, reverted byte for byte by the owner, 2026-11-12: "Revert BL-0054 (Recommended)"). Those rounds were all on the command parser (quotes, heredocs, kills). This slice does not touch the parser: part (2) adds a scope test to one path rule, using the same `_under` comparison (resolved, lower-cased) that the live-data, legacy and manifest rules already use; part (3) changes only the text returned for a refusal the branch already makes. The policy option was offered and taken already: the owner accepted BL-0307's scope as written. No new question for the owner.
- Acceptance tests (new, in `scripts/tests/test_guards.py`; each fails on the base unless tagged `@regression-guard`):
  - no meta-test under `scripts/tests` or `scripts/oracle/tests` names a fixed path under the system temp folder (static scan);
  - a heredoc that writes over a GENERATED file outside the repository is allowed (the incident's shape);
  - writing or removing a GENERATED file outside the repository is allowed, by `path_problem` and by `rm`, `tee`, `cp`, redirection;
  - a GENERATED file in the repository stays refused by every spelling: absolute, relative from another cwd, `..`, a case variant, a symlink outside the repository pointing into it, a symlinked folder (`@regression-guard` for the spellings the base already refused; the real repository's own generated page is checked too, read-only);
  - each refusal names its own reason: the generated file's names INV-19 and not the live data folder or the legacy worktree; the legacy worktree's names it and not the live data folder; the live data folder's (through a symlink, so the early text rule does not catch it first) names it; for `rm`, `tee`, `touch`, `cp`, `cp -t`, `mv`, `sed -i`, `npm --prefix`, and a writer run with its cwd inside the legacy worktree;
  - the live-data and legacy-worktree refusals unchanged: the existing tests stay, unchanged in what they refuse.
- Expected doc impact: the docstring of `guards.path_problem` and the module's; `design/INVARIANTS.md` INV-19's "Enforced by" does not list the guard (unchanged); `design/backlog.md` BL-0307 to done. No user docs (tooling).
- Open questions: none.

## Decisions
- "Under the repository" means under the checkout the hook lives in (`guards.REPO`, resolved), plus folders a test names in `FT_GUARD_REPO` (a stand-in, like `FT_LIVE_DATA` and `FT_LEGACY_ROOT`; it only adds folders, so it can only refuse more) (agent). Rejected: any git work tree (other checkouts are not this repository's INV-19, and the legacy worktree already has its own, stricter rule); the repository that holds the cwd (an agent whose cwd is outside the repository would lose the rule).
- The scope test compares the resolved, lower-cased path (`_under`, as the other path rules do), so every spelling that reaches a repository file is refused; on a case-sensitive volume a case variant outside the repository is refused too (refuses more, never less) (agent).
- The scope test sits after the live-data and legacy checks, inside the generated-file clause only: the order of the other rules is unchanged (agent).
- ~~Stated limit: a hard link outside the repository to a generated file in it is not followed.~~ Withdrawn after round 1 (F1): it was a regression against the base, which refused it; a GENERATED file with another hard link stays refused.
- A writer's refusal reads `<cmd> refused: <arg>: <the path rule's own reason>`, or `<cmd> refused: it runs inside the legacy worktree, which is read-only` when only its cwd is the reason (agent). Which commands are refused is unchanged: the set of arguments each branch checks is the same as before, only the returned text differs.
- Left as they are (agent): the `.git/config`/`.git/hooks` and `corpora/MANIFEST.tsv` rules also apply outside the repository (they refuse more; no incident; not in BL-0307's scope).
- The other meta-tests searched for the same shape (a fixed path under the system temp folder): `scripts/tests` and `scripts/oracle/tests`, 13 lines on the base, 12 in `test_guards.py` (one in a docstring, one a `core.hooksPath` value) and one in `test_build_sidecar.py` (a tar member's absolute name, refused by name before any write; now `/escape`). None left.
