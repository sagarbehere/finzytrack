# S0139: Guard hook fixes (BL-0307)

## Brief
- Base: `d2f52ab0a65a1d992cc61c1fa469447f44563c5a` (`next`).
- Goal: the three parts of BL-0307. (1) The guard meta-tests write only inside their own temporary folder, so a stray file at a fixed global path (twice on 2026-11-21, a reviewer's copy of `design/generated/engine-job-texts.md` at a fixed temp path) can no longer fail the push gate and the Stop hook; no meta-test names a fixed path under the system temp folder. (3) The writer branch of `guards.bash_problem` (`rm`, `tee`, `cp`, `mv`, `sed -i`, `npm --prefix` and the rest) reports the refusal's own reason (live data, legacy worktree, generated file, `.git/config`, the manifest), not the one fixed "legacy worktree or live data folder" text.

- Risk class / lane: Medium / full (a guard of real data). Review row: "Tooling, gates, measurement" with a guard of real data (INV-24): the verifier, and a fresh round after any fix to the guard (PROCESS.md §3 review budget).

The policy option was offered and taken already: the owner accepted BL-0307's scope as written. No new question for the owner.

## Decisions
- "Under the repository" means under the checkout the hook lives in (`guards.REPO`, resolved), plus folders a test names in `FT_GUARD_REPO` (a stand-in, like `FT_LIVE_DATA` and `FT_LEGACY_ROOT`; it only adds folders, so it can only refuse more) (agent). Rejected: any git work tree (other checkouts are not this repository's INV-19, and the legacy worktree already has its own, stricter rule); the repository that holds the cwd (an agent whose cwd is outside the repository would lose the rule).
- The scope test compares the resolved, lower-cased path (`_under`, as the other path rules do), so every spelling that reaches a repository file is refused; on a case-sensitive volume a case variant outside the repository is refused too (refuses more, never less) (agent).
- The scope test sits after the live-data and legacy checks, inside the generated-file clause only: the order of the other rules is unchanged (agent).
- Stated limit: a hard link outside the repository to a generated file in it is not followed (only a command built on purpose has one, PROCESS.md §11).
- A writer's refusal reads `<cmd> refused: <arg>: <the path rule's own reason>`, or `<cmd> refused: it runs inside the legacy worktree, which is read-only` when only its cwd is the reason (agent). Which commands are refused is unchanged: the set of arguments each branch checks is the same as before, only the returned text differs.
- Left as they are (agent): the `.git/config`/`.git/hooks` and `corpora/MANIFEST.tsv` rules also apply outside the repository (they refuse more; no incident; not in BL-0307's scope).
- The other meta-tests searched for the same shape (a fixed path under the system temp folder): `scripts/tests` and `scripts/oracle/tests`, 13 lines on the base, 12 in `test_guards.py` (one in a docstring, one a `core.hooksPath` value) and one in `test_build_sidecar.py` (a tar member's absolute name, refused by name before any write; now `/escape`). None left.
