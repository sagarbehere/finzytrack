# S0039: The structured log on the main side (BL-0088)

## Brief
- Goal: the main sidecar writes every event as one JSON line to `<app_local_data>/logs/finzytrack.jsonl` (size-based rotation, 10 MB × 5 by default), through structlog on stdlib `logging`, and nothing it logs can carry financial content or free text outside debug mode. Events are declared in a registry (`app.platform.observability.events`): name, level, feature, source and typed fields. The redaction is default-deny: a field value is written as itself only when its event declares the field with a safe kind (`id`, `count`, `duration_ms`, `bytes`, `enum`, `safe_text`) **and** the value fits that kind; every other value is replaced by a marker of its type (`<money>`, `<text len=N>`, `<untrusted len=N>`, `<secret>`, `<path>` or an `app:/…` path, an exception's type and code locations only, `<value type=T>`). Unregistered events, undeclared fields, values bound in contextvars and other libraries' records (stdlib loggers, `warnings`, uncaught exceptions on any thread) go through the same final processor. Every line carries `ts`, `level`, `event`, `session_id` (`--session-id` from the shell, else generated per launch), `correlation_id` and `ws` when bound, `source`, `feature`, `app_version`, and `debug: true` in debug mode. A log path that leaves the app-local-data folder (a symlinked `logs/`) or lies inside the workspace folder is refused at startup. S0038's interim stderr sink (`app.platform.adapters.stderr_log`) is removed: `engine.ready`, `engine.start_failed`, `engine.stderr`, `engine.closed` move into the file, `engine.stderr`'s `line` is untrusted text and `engine.start_failed`'s `detail` free text, both shown only in debug mode. The acceptance harness reads the engine verdict from the log file.

## Decisions
- **structlog without global configuration** (agent; ADR-0039, ARCHITECTURE §6A.1 pin). `EventLog` wraps a private `logging.Logger` (not in logging's registry) with `structlog.wrap_logger`; `structlog.configure` is never called, so no structlog global holds our setup and tests build as many logs as they like. Every line, ours and other libraries', leaves through one `ProcessorFormatter` step, `EventLog._finish` → `redaction.redact_line`, which builds a new dict: nothing reaches the JSON renderer that redaction did not put there.
- **A safe kind is checked against the value** (agent; stricter than §6A.3, where a declared kind alone shows the value): `id` is an int ≥ 0 or 1–128 of `[A-Za-z0-9._+-]` starting with a letter or digit, never `UntrustedText`; `count`/`bytes` an int ≥ 0; `duration_ms` finite ≥ 0; `enum`/`safe_text` one of the declared values; bools never fit. A misfit is redacted by type. Stated limit, pinned by a test: a one-word `str` in an `id` field is shown. Text is read with `str`'s own methods (`str.__str__`, `str.__len__`), so a `str` subclass cannot lie about what is checked or written.
- **Undeclared fields and other bound context are counted, never written, not even by name** (agent; stricter than §6A.3's "redacted"): a dynamic key (`**balances_by_account`) would otherwise leak through its name. An `Event` not in the registry is written as `log.unregistered` with no name and no fields, so an inline declaration cannot get around the registry.
- **`UntrustedText` and `Secret` are frozen wrappers in `app.domain.text`, not `str` subclasses** (agent; ARCHITECTURE §2.6 calls `UntrustedText` a wrapper): a wrapper cannot be used as plain text by accident, and `repr` hides the content. The engine's stderr lines are wrapped where they enter (`app.main.wire`).
- **`code` is not a kind yet** (agent): with no error registry, a `code` check could only be a pattern, and a lower-case word such as a payee would pass it. It joins with the error registry (BL-0093). §6A.3 updated.
- **Debug mode is an injected predicate read per line, and nothing can switch it on** (agent; §6A.3 puts the switch in Settings → Diagnostics, BL-0093). No CLI flag: that would skip the warning and the time limit. A `debug_detail` field then shows text or a number, cut at 2000 characters (§6A.3 "never full file contents"); secrets, exceptions and other types stay redacted.
- **The rest of the process goes through the same redaction** (agent; §6A.1 "captures third-party libraries' records"): `capture_process` adds the handler to the root logger (other loggers' records only at warning and above, by a handler filter, so a library that lowers its own level still stays out), turns on `logging.captureWarnings`, and replaces `sys.excepthook`, `threading.excepthook` and `sys.unraisablehook`. The main sidecar keeps them until it exits, so an exception that leaves `main` is logged as its type and code locations and nothing is printed (a traceback quotes source lines and the error's message). Records of another library are `lib.record` (logger name as an `id`, message as `debug_detail`, exception).
- **Two stdlib paths that print raw records are closed** (agent; found while designing the handler): `Handler.handleError` prints the unredacted record on any write error (disk full, a failed rotation), so `_Handler` overrides it and writes one fixed notice once; and a logger with no handler falls back to `logging.lastResort`, which prints the raw record, so `close()` keeps the handler attached and later events are dropped. Both have must-not-pass tests.
- **Startup refusal** (agent; §6A.1 "a startup check refuses a log path outside the app dirs"): `log_file` refuses a log path that resolves outside the app-local-data folder (a linked `logs` folder or file) or inside the `--workspace` folder (INV-27); `app.main` then writes one line to stderr and exits with code 2 before `FT_READY`. The reasons name no path. Not handled: a symlink planted between the check and the open (anyone who can write there already controls the user's account).
- **`--session-id`** (agent; §6A.1 "the shell generates it"): 8–64 letters, digits or hyphens, refused otherwise (it is written into every line); without it the sidecar makes a uuid4 hex per launch (headless, development; the shell's M2 supervisor will pass it, BL-0093).
- **Log timestamps are real time, also under `--frozen-clock`** (agent; S0038's sink did the same): the frozen clock is for the product's behaviour; a log is about when things happened.
- **All levels of our own events are written** (agent): none is at debug level today; §6A.5 puts port timings there later, and their slice decides whether debug-level events wait for debug mode.
- **Enforcement** (agent; §6A.6, EP-15): an import-linter contract, "One logger", lets only `app.platform.observability` import `logging` or `structlog`, in place of §6A.6's AST check (a module that cannot import `logging` cannot call it); ruff `T20` and `G004` are on. The three `print` calls became stream writes (`FT_READY` in `app.main`, `app.selfcheck`'s report, `gen_demo`'s refusal). `test_contracts` now finds a broken contract by " BROKEN" anywhere in its line, since import-linter appends "(n ignored imports)".
- **INV-11 registry** (agent): `EventLog` is registered with owner `UserContainer`, following `EngineClient`'s precedent (one per launch, built by the composition root); the globals scan accepts `Event(...)` and `Field(...)` calls of constants (added to `RECORD_CALLS`, beside four planted mutable cases and a test that each record name is a frozen, slotted dataclass).
- **structlog 26.1.0 is the main sidecar's first runtime dependency** (agent; ARCHITECTURE §10 pin, MIT OR Apache-2.0, on the shared licence list): `THIRD_PARTY_NOTICES` regenerated; the macOS packaged build was run locally: the main site-packages holds `app` and structlog only, the exact-closure check passed, `--smoke-test` passed.
- **Not closed here:** L11-03 (a tenant's settings change reconfigures the process-wide logger) belongs to the settings store; this log is configured once by the composition root and nothing reconfigures it, but the row's own test arrives with `ConfigStore`. CAP-DATA-LOGS stays planned (its user-facing part is Report a problem and the logs page, M2). The harness's refusal now names only the failure's kind (the detail is redacted text).
