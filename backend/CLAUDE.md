# backend/ (Python sidecar)

Pointers only. Package map, dependency rules and pins: `design/ARCHITECTURE.md` §2 and §10. Principles: `design/ENGINEERING.md`. Write safety: the D1 contract ADRs in `design/decisions/` and INV-01, INV-22.

- Python and Beancount versions are pinned on purpose (ADR-0004); lock with `uv`, never install outside the lockfile.
- This is the main sidecar (GPLv3): it **never imports Beancount**; Beancount lives in the separate ledger engine (`engine/`, ADR-0054; `.importlinter`, `tests/architecture/` and `scripts/check_engine_boundary.py` enforce it). Ledger work goes through `app.platform.engine.EnginePort` only; never import `ledger_engine`. No module-level mutable state outside the allowlist (INV-11).
- The engine tests here (`tests/platform/test_engine_client.py`) spawn the real engine from `engine/.venv`: run `uv sync --locked` in `engine/` too.
- **Process tests** (S0147, BL-0309): a test file whose tests start a child the test itself must end (a stand-in engine, a sleeper, the sidecar, the real engine through an `EngineClient` it holds), or run `ps` or `os.killpg`, carries `pytestmark = pytest.mark.needs_process_control`. Where the OS refuses those (the agents' sandbox refuses `ps`), `tests/process_control.py`'s probe skips them with its answer named; with `FT_REQUIRE_PROCESS_TESTS` set (the pre-push hook, `ci.yml`) it fails the run instead. A child started with `subprocess.run` that ends by itself needs no mark.
- **Windows** (S0129): the engine's group there is a Job Object (`app.platform.adapters.windows_job`), the app folder's identity, its sync and the engine-lock wait are `windows_files`; both modules are Windows-only (their import fails elsewhere), imported only under `sys.platform == "win32"`. Their tests are `tests/platform/test_engine_windows.py`. The manual CI run's `backend-windows` job runs the whole suite there (S0131, BL-0290; `-v -rs --durations`): a test that cannot run on Windows skips with a reason from `tests/windows_pending.py` naming its rule's Windows tests or the open row; the engine's write path runs there since S0150 (BL-0087), so the end-to-end writes, the real-engine saves and the measurement scripts run on Windows too (a venv's interpreter is `engine_client.venv_python`; a child that uses the engine's port pins its placeholder mode first, as the test-copy mark's reader does). A test's absolute paths are this OS's: `tests/host_paths.py` (`host("/L/main.bean")`, `hosted(...)` over the contract's examples); a path the engine sent is cut for a text only by `app.platform.engine_paths` (`last_name`, `folder_of`), never at `/`; `zoneinfo` there needs `tzdata` (a test dependency until product code names a zone).
- **Paths to the engine** (S0146, BL-0087): on Windows `engine_protocol.encode_request` puts every absolute path of a request's params in the engine's normal form (`windows_paths.normal`; the positions are `ABS_PATHS`, held to the schema by `tests/platform/test_engine_protocol.py`, so a new path field fails there until it is listed). Never normalize a path elsewhere; the codec is the one boundary.
- Gates: `uv sync --locked`, then from `backend/`: `ruff format --check`, `ruff check`, `pyright` (strict), `lint-imports`, `deptry src`, `pytest`.
- Money is `Decimal` and dates are civil dates (INV-06, INV-07): "today" is `app.domain.dates.civil_date(clock.now())`; every JSON decode passes `parse_float=Decimal`; a `float(...)` that is not money says `# not money: <reason>`, and a `Decimal(...)` of anything but text or an int literal says `# exact: <reason>`; no date is cut from an instant's text or fields (`scripts/check_money_dates.py`). The tests run in Los Angeles (`tests/conftest.py`). Errors use the one taxonomy (ARCHITECTURE.md §6).
- The OpenAPI spec is exported offline and the TypeScript client regenerated in the same commit (ARCHITECTURE.md §4.1); there is no "restart the backend and regenerate" step. From the repo root: `backend/.venv/bin/python -I backend/scripts/export_openapi.py`, then `node frontend/scripts/gen-api-types.mjs`; `scripts/check_generated.py` refuses a commit without both.
- Backend-internal scripts go in `backend/scripts/` and run with cwd = `backend/`; pyright reads them too. The measurement scripts (`measure_health.py`, `measure_mirror_reads.py`, `measure_protocol.py`: the protocol's cost per write and the save until its publish, S0106; `measure_write.py`: one write's preview, save and rebuild through the scheduler, per ledger layout, with the engine's test producer registered by its own engine command only, S0119) each have a case in `tests/test_measure_scripts.py`, which fails on a `measure_*.py` without one. `g1_runner.py` (S0163) is the backend half of G1's refusal-rate tool (`scripts/oracle/g1_refusals.py` starts it): `measure_write.py`'s wiring (`wire`, `open_copy`), one fresh test copy per case; its test is `tests/test_g1_runner.py`.
- The mirror's read half (`src/app/mirror/`, S0052): the app's own reads go through `reader.Reader`, every user query through `query.QueryRunner` (ADR-0016), never a connection of its own. Measure on a built mirror with `scripts/measure_mirror_reads.py`.
- A test written before its capability exists carries `@pytest.mark.fixme(id=…, due=…, reason=…)` (a strict xfail that may fail only with `PlannedMissing`, S0032) and reaches planned modules through `tests/integrity/planned.py`, so once the module exists any failure is red; `id` is an open backlog row due by `due` (`scripts/check_invariants.py`, S0029). The landing slice removes the marker, imports normally and closes the row.
- **The write contract's sidecar half** (S0117; ARCHITECTURE.md §9.2): `app.platform.plans` (write plans and the bounded `PlanStore`), `app.platform.engine_jobs.preview` (the preview job), `app.workspaces.writes` (the preview and confirm use cases with the owner's ownership rule, and the promotion guard: `PROMOTED` is code, changed only with the owner's clearance page, ADR-0014; a `WriteTarget` and its test-copy mark are built from the sidecar's own state, never from a request). A test that needs a producer starts the engine through the test-only entry of `tests/workspaces/test_writes_end_to_end.py`, which registers the engine's test producer in that process only: the shipped engine's `PRODUCERS` stays empty (`test_the_shipped_engine_has_no_producer`).
