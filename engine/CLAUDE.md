# engine/ (the ledger engine)

Pointers only. The process split, protocol and supervision: `design/ARCHITECTURE.md` §2.0; why: ADR-0054. Pins: §10 (EP-24). Principles: `design/ENGINEERING.md`.

- A separate program with its own environment (`uv.lock`): Beancount 3.2.0 and beanquery 0.2.0 on Python 3.13 (ADR-0004), GPL-2.0-only as a whole. Every new dependency must pass the `[engine]` list in `licences.allow.toml` (GPL-2.0-compatible); `[engine.reviewed]` names the few that pass pending legal advice (ADR-0054 decision 5 and its amendment). A licence that requires an acknowledgment needs an `[acknowledgment]` entry, which `THIRD_PARTY_NOTICES` carries.
- It **never imports the main sidecar** (`app`), and nothing outside `engine/` imports `ledger_engine`; they talk only through the protocol. Inside the engine only `src/ledger_engine/ledger/beancount_port.py` imports `beancount` or `beanquery` (INV-02; the engine's tests may too), and only it may import or run code by name (`import_module`, `__import__`, `runpy`, `exec`, `eval`). `scripts/check_engine_boundary.py` enforces all four.
- **The ledger kernel** (`src/ledger_engine/ledger/`, S0049): the port's load stages (`beancount_port.LOAD_STAGES`) are used only by `overlay.py`, every other function in the port's `__all__` is in `WRAPPERS`, other modules use only `__all__` names (Beancount's own are imported under `_` aliases), and the port offers no `load_file`/`load_string` (`tests/architecture/test_load_rule.py`). Beancount modules without type information get a stub in `typings/` (pyright's stub path) declaring only the names used; a stub replaces its whole module, so import names from the leaf module (`from beancount.core.data import Transaction`). The overlay replica is pinned to Beancount 3.2.0's loader source (`tests/ledger/test_overlay.py`): an upgrade re-mirrors it first. The overlay parses every file from bytes it read itself, so `Loaded.fingerprint` hashes exactly what was parsed; `ledger/fingerprint.py` observes a ledger set with the loader's own calls (`core/ledger_set.py` is the pure value and digest; S0051). Keep the two in step: a new way a load reads the disk (the loader, Beancount's `ops` and built-in plugins) needs the same question in `observe`; the inventory for Beancount 3.2.0 is in the S0051 journal's Hand-off, and an upgrade redoes it.
- **The mirror build** (`src/ledger_engine/mirror/`, S0050): `core/schema.py` is the table list and the DDL (checked against `design/specs/mirror/surface.toml` by `tests/mirror/test_surface.py`; after changing it, regenerate `contracts/mirror-ddl.sql` with `.venv/bin/python -I -m ledger_engine.mirror.core.schema > ../contracts/mirror-ddl.sql`); `core/rows.py` the pure row builders; `build.py` writes a fresh file or none. Measure with `scripts/measure_mirror_build.py`.
- The protocol's single source is `src/ledger_engine/protocol/messages.py`. After changing it, regenerate `contracts/engine-protocol.schema.json` (`.venv/bin/python -I -m ledger_engine.protocol.schema > ../contracts/engine-protocol.schema.json`) in the same commit; the main side's codec (`backend/src/app/platform/engine_protocol.py`) and its contract test follow.
- The sidecar runs the engine with `-s -S -B -P` and a bootstrap that adds only the engine's site-packages: `sidecar/engine/site-packages` in the bundle, the venv's site-packages in development (`EngineCommand.for_packaged`, `for_venv`; ARCHITECTURE.md §2.0; S0038, S0057), never `-I` (it would ignore `PYTHONHASHSEED=0`). Nothing in the engine may rely on `site` having run (no `sitecustomize`, no user site); `.pth` files in its own site still work. The engine leads its own process group: its watchdog and its end of input end the whole group (`end_own_group`). A handler that writes gets a `JobContext`: it calls `gate()` before its first durable write and `committed()` after the save landed (protocol version 2, engine-jobs §4, §6.1).
- **Writes go through `ledger_engine.fs.port`** (S0060): a handle per directory (the path guard and the write use one descriptor), `create` syncs its data, entries are durable after the folder's `sync`, swap and exclusive rename only. `ledger/writer.py`, `ledger/paths.py` and `ledger/core/{journal,paths}.py` import nothing that touches files, and only `fs/` imports `ctypes` or `fcntl` (the engine lock in `protocol/server.py` excepted; `tests/architecture/test_write_port.py`). Test the write path over `tests/fakes/memfs.py` (crash, I/O-error and power-loss injection; its own semantics in `tests/fakes/test_memfs.py`).
- No resident ledger between requests (INV-10); no pickles, shared memory or callbacks across the protocol (ADR-0054 decision 2).
- Gates: `uv sync --locked`, then from `engine/`: `.venv/bin/ruff format --check --config ruff.toml .`, `.venv/bin/ruff check --config ruff.toml .`, `.venv/bin/pyright` (strict), `.venv/bin/python -m pytest -q`.
