# engine/ (the ledger engine)

Pointers only. The process split, protocol and supervision: `design/ARCHITECTURE.md` §2.0; why: ADR-0054. Pins: §10 (EP-24). Principles: `design/ENGINEERING.md`.

- A separate program with its own environment (`uv.lock`): Beancount 3.2.0 and beanquery 0.2.0 on Python 3.13 (ADR-0004), GPL-2.0-only as a whole. Every new dependency must pass the `[engine]` list in `licences.allow.toml` (GPL-2.0-compatible); `[engine.reviewed]` names the few that pass pending legal advice (ADR-0054 decision 5 and its amendment). A licence that requires an acknowledgment needs an `[acknowledgment]` entry, which `THIRD_PARTY_NOTICES` carries.
- It **never imports the main sidecar** (`app`), and nothing outside `engine/` imports `ledger_engine`; they talk only through the protocol. Inside the engine only `src/ledger_engine/ledger/beancount_port.py` imports `beancount` or `beanquery` (INV-02; the engine's tests may too), and only it may import or run code by name (`import_module`, `__import__`, `runpy`, `exec`, `eval`). `scripts/check_engine_boundary.py` enforces all four.
- **The ledger kernel** (`src/ledger_engine/ledger/`, S0049): the port's load stages (`beancount_port.LOAD_STAGES`) are used only by `overlay.py`, its real loads (`REAL_LOADS`: `real_load`, Beancount's own loader without the pickle cache, BL-0118, which never decrypts a file: `EncryptedFileMet`) only by `rebuild.py` (the rebuild after a save, ADR-0068 D1) and `create.py` (the create's load check, S0080), every other function in the port's `__all__` is in `WRAPPERS`, other modules use only `__all__` names (Beancount's own are imported under `_` aliases), and the port offers no `load_file`/`load_string` (`tests/architecture/test_load_rule.py`). Beancount modules without type information get a stub in `typings/` (pyright's stub path) declaring only the names used; a stub replaces its whole module, so import names from the leaf module (`from beancount.core.data import Transaction`). The overlay replica is pinned to Beancount 3.2.0's loader source (`tests/ledger/test_overlay.py`): an upgrade re-mirrors it first. The overlay parses every file from bytes it read itself, so `Loaded.fingerprint` hashes exactly what was parsed; Beancount's documents step reads the disk, as in its own load (S0068 removed S0067's listing swap: a user plugin could see it), and the plugins run without decrypting anything, as in the rebuild's load (`beancount_port.run_transformations`); `ledger/fingerprint.py` observes a ledger set with the loader's own calls (`core/ledger_set.py` is the pure value and digest; S0051). Keep the two in step: a new way a load reads the disk (the loader, Beancount's `ops` and built-in plugins) needs the same question in `observe`; the inventory for Beancount 3.2.0 is in the S0051 journal's Hand-off, and an upgrade redoes it.
- **The mirror build** (`src/ledger_engine/mirror/`, S0050): `core/schema.py` is the table list and the DDL (checked against `design/specs/mirror/surface.toml` by `tests/mirror/test_surface.py`; after changing it, regenerate `contracts/mirror-ddl.sql` with `.venv/bin/python -I -m ledger_engine.mirror.core.schema > ../contracts/mirror-ddl.sql`); `core/rows.py` the pure row builders; `build.py` writes a fresh file or none. Measure with `scripts/measure_mirror_build.py`. `core/iso4217.py` is the pinned ISO 4217 cash list (`commodities.is_currency`, S0086): never edit it by hand; download the ISO 4217 Maintenance Agency's List One and List Three (URLs in the module) into a folder outside the repo (never commit them: owner, 2026-11-08, their licence is not stated), set `FT_ISO4217_DIR` to it, and rerun `scripts/gen_iso4217.py` (its docstring has the rule); with `FT_ISO4217_DIR` set, `tests/mirror/test_iso4217.py` checks the files' hashes and that the module is exactly the script's output on them, and skips that test otherwise. The cash-or-holding rule itself is `core/rows.is_currency` (operating currency, `asset-class`, held only at cost, ISO list; ADR-0025 amendment of 2026-11-08).
- The protocol's single source is `src/ledger_engine/protocol/messages.py`. After changing it, regenerate `contracts/engine-protocol.schema.json` (`.venv/bin/python -I -m ledger_engine.protocol.schema > ../contracts/engine-protocol.schema.json`) in the same commit; the main side's codec (`backend/src/app/platform/engine_protocol.py`) and its contract test follow.
- The sidecar runs the engine with `-s -S -B -P` and a bootstrap that adds only the engine's site-packages: `sidecar/engine/site-packages` in the bundle, the venv's site-packages in development (`EngineCommand.for_packaged`, `for_venv`; ARCHITECTURE.md §2.0; S0038, S0057), never `-I` (it would ignore `PYTHONHASHSEED=0`). Nothing in the engine may rely on `site` having run (no `sitecustomize`, no user site); `.pth` files in its own site still work. The engine leads its own process group: its watchdog and its end of input end the whole group (`end_own_group`). A handler that writes gets a `JobContext`: it calls `gate()` before its first durable write and `committed()` after the save landed (protocol version 2, engine-jobs §4, §6.1).
- **Writes go through `ledger_engine.fs.port`** (S0060): a handle per directory (the path guard and the write use one descriptor), `create` syncs its data, entries are durable after the folder's `sync`, swap and exclusive rename only, except on a volume without the swap (`handles.write_mode`): a best-effort plain rename, the backup and the read-back kept (spec §6.8, ADR-0068 D2, S0071; its sweeps `tests/ledger/test_writer_best_effort.py`). `ledger/writer.py`, `ledger/restore.py`, `ledger/recover_all.py`, `ledger/save.py`, `ledger/rebuild.py`, `mirror/publish.py`, `ledger/history.py`, `ledger/create.py`, `ledger/copy.py`, `ledger/loads_same.py`, `ledger/handles.py`, `ledger/paths.py` and `ledger/core/{journal,paths,recovery,history,copy_layout}.py` import nothing that touches files, and only `fs/` imports `ctypes` or `fcntl` (the engine lock in `protocol/server.py` excepted; `tests/architecture/test_write_port.py`). The rollback and recovery's per-journal try share one restore (`ledger/restore.py`, S0061; it and recover-all's actions write only on the drive each journal records: `ledger/handles.Handles` with `journal.volumes`, `DirHandle.volume_id`, S0089; the temp rule only in `ledger/core/recovery.py`, the owner's hard-link rule and the write mode per volume only in `ledger/handles.py`). Recover-all's listing, Keep and the blocked screen's deletes are `ledger/recover_all.py` (S0062), served as the ops `recover_list`, `recover_try`, `recover_act` (`protocol/recovery.py`) only by an engine that holds the engine lock (`OpSpec.needs_engine_lock`; a new op that reads or writes ledger or journal files sets it). The save job around the durable order (an encrypted file name refused first, ADR-0059; the records, the gate, the commit point; no Beancount load since S0070, ADR-0068 D1; no lock of its own since S0071, ADR-0068 D3, D4: the engine lock is the guard) and §6.6's outcome reading are `ledger/save.py`, served as `save` and `save_outcome` (`protocol/save.py`, S0063); the fingerprint reads the disk with the loader's own calls, so the save's steps 0-7 are tested on real APFS in scratch folders (`tests/ledger/test_save.py`), the outcome over the fake. The rebuild after a save (S0070, ADR-0068 D1) is `ledger/rebuild.run`: the set observed, Beancount's real load, the set observed again; `loaded` with counts or `moved` with the set to try next (a moved disk, or a file or documents root outside the set); it writes only the workspace's mirror folder and is served as `rebuild` (`protocol/rebuild.py`, `OpSpec.needs_engine_lock`); tests on real APFS (`tests/ledger/test_rebuild.py`, `tests/test_rebuild_ops.py`). **The mirror publish** (S0087, `design/specs/mirror/publish.md`): `src/ledger_engine/mirror/publish.py` (the folder, the cleanup, the name, the publish, the swap, the gate's read, freshness), all through one folder handle of the port that follows no link (`DirHandle.open_child`; it is on the write path of `tests/architecture/test_write_port.py`), and `mirror/store.py` (SQLite's build into the created file with `mode=rw`, the identity check, the `meta` read); the rebuild publishes after `loaded`, the save's gate reads the published generation (`publish.read_published`, `fresh_on_disk`). **The open job** (S0088, `src/ledger_engine/ledger/opening.py`, op `open` in `protocol/opening.py`): the cleanup, the `.open` journal before any result, a fresh generation kept, else the overlay load (`overlay.load` with `DESKTOP`; its fingerprint is the stamp) and the same publish; what it shares with the rebuild (the target, the `.open` look, freshness with the hint within the stamp, the re-check) is `ledger/publishing.py`. It writes only the workspace's own mirror folder (owner, 2026-11-08); `tests/ledger/test_open.py` holds that as a must-not-pass test. The engine reads no clock: the rebuild's `today` and `built_at` come in the request. Tests: `tests/mirror/test_publish.py` (real disk: link rules, keep set, swap under concurrent reads), `tests/mirror/test_publish_crash.py` (§9 over the fake with `tests/mirror/fake_store.py`; `fake_store.outside_publish` gives the save's fake worlds a fresh mirror without counting effects). Its functions carry `@tla_action(..., model="mirror-publish")`. A save gates only on an `.open` journal (`ledger/save.records`). The `create` job (spec §8.2, S0080) is `ledger/create.py`, served as `create` and `create_outcome` (`protocol/create.py`, `OpSpec.needs_engine_lock`): an empty target, exclusive creates and `mkdir`s, read-back, Beancount's own load of the new ledger (no error, only the job's files), the commit point, `.finzytrack/` written under `.finzytrack.ft-<job>` and renamed exclusively last; a stop removes only what this run made (its identity recorded at the create, a file still holding the job's bytes, a bounded read) and names what it keeps, and `outcome` reads the target after its sync and removes nothing; its sweeps (crash, power loss, I/O error at every effect) are `tests/ledger/test_create.py`, the op on APFS with the real load `tests/test_create_ops.py`. The `copy` job (spec §8.2, S0081) is `ledger/copy.py` on the create's writer (`create.run_steps` with its own `Steps`: one cleanup, one outcome read), served as `copy` and `copy_outcome` (`protocol/copy.py`): the legacy locks tried and held through the reads, step 2 before step 1 (a refusal makes nothing), the source loaded once with the overlay load, no `.open` journal naming a source, the layout and the rewrites of moved `include`, `option "documents"` and `document` lines, decided from Beancount's parse (`ledger/core/copy_layout.py`, pure), every `document` entry's file copied in, every file streamed in chunks (`DirHandle.create` takes chunks; `DirHandle.sha256` reads back bounded), "loads the same" (`ledger/loads_same.py`) on a load of the copy in a fresh process (`ledger/fresh_load.py` starts `ledger/copy_check.py` as the sidecar starts an engine, in the engine's process group: nothing a plugin left in the engine reaches it; the child answers one line and ends itself, whatever a plugin left running, `tests/ledger/test_fresh_load.py`), then the source's fingerprint and documents checked again just before the gate; sweeps `tests/ledger/test_copy.py`, the op on APFS `tests/test_copy_ops.py`. After a landed save, in the same engine, the history trim (`ledger/history.py`, its pure choice `ledger/core/history.py`; spec §6.5, S0074) keeps the newest 16 of each kind in the key's journal and backups folders; it never touches an `.open` or `.part` journal or its backups, the save that just landed, or anything it cannot classify, orders by `EntryStat.mtime_ns`, and never fails the save; its sweeps are `tests/ledger/test_history_trim.py`. The save's steps, its rollback and the restore carry `@tla_action` (`ledger_engine.tla`, a no-op marker read from the source by `backend/tests/architecture/test_tla_mapping.py`); `tests/ledger/test_save_conformance.py` replays the model's saves (`formal/tla/engine-jobs/traces/corpus.json`) through `save.run` over the fake, so a change to the save's effects or their order must keep it green, or change the durability model with it (S0064; since S0072 the model follows the save as built and no save step stops the replay). The create's and the copy's steps carry `@tla_action` too, and `tests/ledger/test_create_conformance.py` replays the model's creates and copies through `create.run` and `copy.run` over the fake (S0084): a change to what they write, in which order, or to what the copy refuses must keep it green. Test the write path over `tests/fakes/memfs.py` (crash, I/O-error and power-loss injection, several faults at once; its own semantics in `tests/fakes/test_memfs.py`); the save's world and its one oracle are `tests/ledger/worlds.py`.
- No resident ledger between requests (INV-10); no pickles, shared memory or callbacks across the protocol (ADR-0054 decision 2).
- Gates: `uv sync --locked`, then from `engine/`: `.venv/bin/ruff format --check --config ruff.toml .`, `.venv/bin/ruff check --config ruff.toml .`, `.venv/bin/pyright` (strict), `.venv/bin/python -m pytest -q`.
